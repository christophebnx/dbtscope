#### 1.1 Detail "Group" vs universe "Domains": one word per concept

The two lists are one concept on most projects and two concepts on others: a detail group is the `group_by` value, a universe domain is resolved by D-015's order, of which `group_by` is the last step. Writing "Domain" in the detail of a project whose dbt groups or `domains` rules differ from `group_by` would be false; writing "Group" in the universe would drop the audience's word. So the page says the word that is true for it:

- **"Domain"** ("Domaine", "All domains", "dashed outline = other domain") when every detail table that is also a universe table has its group equal to its universe domain key (and at least one such table exists). The group select then shows each group by the universe domain's display name (`labelOf`), so the detail and the universe read alike ("Sales", not `sales`); the option values stay the group keys, so the layout keys (`group|focus|…`, D-013) are unchanged. `entityName` of a table of another group uses the same name.
- **"Group"** otherwise, with the select's `title` saying "Tables grouped by the group_by setting of dbt-erd.yml; a universe domain may hold several groups" (fr equivalent).

One pure helper, `common.js detailDomains(detail, universe)` → a `Map(group key → display name)` or `null`, computed once by `boot.js` and passed to `startDetail` as a new fourth parameter (`startDetail(DATA, LAYOUT, EXPORT, DOMAINS)`). M9.2 reuses it to preselect the detail's group when a domain is entered (review finding 3), so the answer to "is this group a domain?" has one implementation. Cost: one pass over the detail entities (under 1 ms at 1,500 tables).

### 2. Universe panel: Navigate / Display / Filters (D-085)

`page.html` regroups the existing controls (ids kept, so the existing handlers and browser tests still find them) into three titled sections, each `<section aria-labelledby>` with an `<h2>`:

1. **Navigate** ("Naviguer"): the Organise-by radios `#u-by` (hidden below two layers, as today), then the Domains list (`#u-domains`, its all / none) and the Source systems list (`#u-systems`). In M9.1 the rows are still filters; M9.2 gives them their "go to" action.
2. **Display** ("Affichage"): the **Show** select (`#u-detail`) always visible, then one native `<details id="u-more">` ("More display options" / "Plus d'options d'affichage"), **closed at every page load** (not remembered: no new stored state, D-013), holding in this order: the fold row (`#u-fold`), **Links** (`#u-links`), **Dependencies between domains** (`#u-routes-on-row`) with its inline **all (N)** toggle, **Summary cards** (`#u-cards-row`).
   - The inline toggle is the existing `#u-routes-box` moved into the Dependencies row (`#u-routes-row` disappears as a row). It is shown whenever the Dependencies row is; it is **disabled, not hidden**, when no dependency is hidden by the current set (layer mode included) or while dependencies are off, its `title` giving the one-line reason ("All 12 dependencies are drawn" / "Dependencies are off"). Its session value is kept as today (D-071, D-083).
3. **Filters** ("Filtres"): **Layers** (`#u-layers`) and **Table kind** (`#u-kinds`).

The hint leaves the panel (§ 4).

### 3. Controls that need a focus or a found table (D-085)

A control that needs a state the page is not in is shown **disabled with a one-line reason**, never inert and never silently hidden:

- **Detail panel.** The depth select "Around the focused table" (`#d-depth`) is disabled while no table is focused; the existing note `#d-depth-note` then reads "Focus on a table to use this" / "Ciblez une table pour l'utiliser" (and the passage note of D-076 once focused). The fold checkbox, already disabled under a focus, shows its reason (`T.foldFocused`) as a visible line in `#d-fold-warn` instead of only its `title`.
- **Detail toolbar.** **Clear focus** (`#d-clear`) is disabled while nothing is focused, `title` "No table is focused".
- **Universe toolbar.** **Lineage** (`#u-traj`) keeps its rule (enabled when `#u-q` holds an exact table name) and gains the `title` "Find a table first, or click one on the map" while disabled.
- **Detail Show select** (`#d-cols`): the toggle button becomes a `<select>` of two values (key columns, all columns), driving the existing `state.allColumns`; same id, same drawing keys.

### 4. Small defects (D-085)

- **Labels.** `aria-label` from the string tables on `#u-q` ("Find a table" / "Chercher une table"), `#d-focus` ("Focus on a table" / "Cibler une table") and `#d-q` ("Highlight tables whose name contains" / "Surligner les tables dont le nom contient"). Placeholders stay. Visible labels (review finding 7) are deferred: at 360 px the detail toolbar already wraps to several rows (roadmap "Later").
- **Tooltip on zoom.** `universe.js` hides `#u-tip` and clears `hover` (one redraw) on the d3 zoom `start` event; the next `mousemove` recomputes it. `flow.js` does the same for `#f-tip` (same defect, same fix through its zoom's `onZoom`/start hook). The detail has no custom tooltip.
- **Layer-mode rim arcs with cards.** `drawDomainBands` draws the rim arcs at `alpha * fade`, like the tints and the outline: they vanish with the disc when summary cards take over, and the card's domain rows are the legend (D-066). With cards off (`fade` = 1) nothing changes.
- **Layout ▾ menu.** The three layout buttons move into one native `<details id="l-menu" class="menu">` in the tab bar, summary "Layout" / "Disposition" with a ▾ mark (`aria-hidden`); `#l-reset`, `#l-export`, `#l-import`, `#l-file` keep their ids and handlers; the menu closes after an action. Reset still acts on the current tab, and its label says so ("Reset this tab's layout" / "Réinitialiser la disposition de cet onglet"; ui-designer to settle).
- **Help popovers.** The universe hint `#u-hint` and, for the same place in both views, the detail hint `#d-hint` (with its touch variant) move into a **?** control at the right of each toolbar, before Fit: a native `<details class="help">` whose `<summary>` is named "Help: gestures" / "Aide : gestes", the hint inside a small popover under the toolbar (outside `.canvas-box`, so never in an exported image). The ids `u-hint` / `d-hint` move with the text. No first-visit caption: it would need a stored "seen" state (a new localStorage key) for a gain M9.2's breadcrumb covers.
- **One closing rule for popovers.** A new `common.js dismissable(details)` closes a `<details>` popover on `Esc` (returning focus to its summary and calling `preventDefault`, so the universe's own `Esc` handler, which already ignores `defaultPrevented`, does not also leave the lineage) and on a pointer press outside it. Used by the two help popovers and the Layout menu; not by the Display group, which stays open until the viewer closes it.
- **Tab titles.** `title` on the two tab buttons: "Universe: the map of every table, by domain or layer" / "Univers : la carte de toutes les tables, par domaine ou par couche"; "Detail: the entity-relationship diagram of one domain (or group), or of one table's neighbourhood" / fr equivalent, using the word of § 1.1.

### 5. The way back from the Detail tab (D-086)

Built as the first segment of M9.2's breadcrumb, so that M9.2 extends it instead of adding a second mechanism:

- **Trail helper.** `common.js crumbs(nav, items)` renders a location trail into a `<nav>`: `items` is a list of `{label, title, go}`; an item with `go` is a button, an item without `go` is the current place (`aria-current="location"`); a back item (`back: true`) is preceded by `← ` in an `aria-hidden` span, as the flow's **← Universe** (`#f-back`). An empty list hides the `nav`. M9.1 calls it with one item; M9.2 calls it with `All domains › Vehicle › car_hub` in both tabs.
- **Detail toolbar.** A `<nav id="d-crumbs" class="crumbs" aria-label="Location">` ("Emplacement") right after ☰, hidden until a hand-off. `views.detail.focus(id, trail)` gains the optional `trail` and renders it; `focus(id)` without it (M9.1 has no other caller) leaves the trail as it is.
- **Hand-off.** `boot.js openInDetail(id)` (double-click on a universe table) calls `views.detail.focus(id, [{label: L.universe, back: true, title: L.backToUniverse(name), go: backToUniverse}])`. The trail stays while the viewer works in the detail (changing the focus, the group or the filters), and until a later hand-off replaces it. Opening the Detail tab by its tab button shows no trail unless a hand-off happened earlier in the session.
- **Return.** `boot.js backToUniverse()` shows the Universe tab and calls the universe handle's new `locate(id)` with the detail's current focus when it is a universe table (the viewer may have moved on), else with the hand-off table. `locate` is the body of today's `#u-q` `change` handler, extracted so search and return share it (tick back a filtered-out table, open its entity when folded, mark it with the `found` ring, zoom to it); it also writes the table's name into `#u-q`, which enables **Lineage** for it, and puts the keyboard focus on `#u-q`. The universe's camera, filters and lineage state are otherwise as the viewer left them.
- **Not in M9.1:** `Esc` in the Detail tab (M9.2 binds it to "step one level back", which calls the last `go` of the trail); preselecting the detail's group from a framed domain (M9.2, over `detailDomains`); the universe breadcrumb.

## Rejected options

- **"Domain" in the detail on every page.** False when dbt groups, `meta.domain` or `domains` rules differ from `group_by` (the select would list schemas or folders under "Domain").
- **"Group" in both views.** Drops the audience's word and the brief's "Dependencies between domains", "All domains › …"; "group" is also the dbt group.
- **Detail grouped by universe domain** (a payload or Python change). Changes what the detail draws and its layout keys; out of M9.1's "string-table change only".
- **"Group satellites and PITs into their hub" as the fold wording.** Data-Vault words in the code (only the config labels may be such words), and "group" is the glossary's word for `group_by`.
- **Renaming internal identifiers** (`trajectory`, `flow`, `routes`, `#u-traj`, `universe.routes`, `dbtscope-routes:`) to the new words. Protected keys need a superseding decision and a migration (D-013); ids and code names are not shown; the glossary maps code word to UI word.
- **Renaming the export file `-flow` to `-lineage`.** A user-visible file name change outside the brief's list, for little gain.
- **Hiding "Show all routes" in layer mode as today.** The review's finding 9: a control that vanishes reads as broken; disabled with its reason instead.
- **A first-visit caption for the hint.** Needs a stored "seen" flag (new viewer key) and is superseded by M9.2's breadcrumb as the way in.
- **Remembering the Display group's open state.** A new viewer key for a convenience.
- **Rim arcs redrawn on the card border.** New geometry (rounded rectangle vs band angles) for a mark the card's domain rows already provide.
- **A "← Universe" button separate from the future breadcrumb.** M9.2 would have to remove it; `crumbs` with one item is the same element M9.2 fills.
- **`role="menu"` for the Layout menu.** Needs arrow-key management; three plain buttons in a native `<details>` are keyboard-complete.

## UI design (ui-designer, 2026-11-17)

Task and decision. A viewer (engineer, analyst, architect) opens the page cold on up to 1,500 tables and must (1) tell what each control does from its words, (2) find the domain list without scrolling, (3) never meet a control that does nothing without being told why, (4) get back from the Detail tab to where they were. Everything below is the architect's decided scope; nothing is added to what the page can do. ### Keyboard, focus, aria

- Tab order, universe: tabs (Universe, Detail, **Layout** summary and, when open, its three buttons) → panel in DOM order (Organise by, Domains all/none and rows, Systems, Show, More display options and, when open, its controls, Layers, Table kind) → ☰ Panel → Find a table → Lineage → **?** → Fit → Export image. Detail: tabs → panel → ☰ → **← Universe** (when shown) → Focus on a table → Clear focus → Highlight → **?** → Fit → Exports. (The panel precedes the toolbar in the DOM today; unchanged.)
- `<details>`: Enter / Space on the summary toggles (native). `Esc` inside an open Help or Layout closes it, returns focus to its summary and calls `preventDefault` (so a lineage in progress is not left); a `pointerdown` outside (capture phase, canvas included) closes it without moving focus. Opening one popover closes the others.
- `← Universe`: Enter / Space; on activation the Universe tab opens and focus lands on `#u-q` (D-086). Focus is never left on a hidden element.
- aria: `#u-q` "Find a table"; `#d-focus` "Focus on a table"; `#d-q` "Highlight tables whose name contains"; `#l-menu summary` name from its text (▾ is `aria-hidden`); help summaries `aria-label` and `title` "Help: gestures"; `#d-crumbs` `aria-label` "Location"; sections `aria-labelledby`; `#d-cols`, `#u-detail`, `#u-links` keep `aria-labelledby` to their headings; the disabled toggle and depth select use `aria-describedby`. Tab buttons carry `title` only (their text already names them).
- Focus ring: the existing 2 px `--accent` outline (offset 2 px) extended to `.menu summary`, `.help summary`, `#u-more > summary`, `.crumbs button`, `.menu-pop button`.

### Contrast, targets, width

- Text: `--fg` on white or `--bg` (≥ 12:1), `--muted` `#5f6774` for reasons and counts (5.3:1 on `--bg`, higher on white): all ≥ 4.5:1 (D-037). Disabled controls' own text is exempt, so every reason is visible text in `--muted`, never only a `title`. The back and help buttons use the toolbar buttons' existing border; no new colour, so no new D-042 mark; the `?` glyph and ▾ are text, not marks.
- Coarse pointer (`pointer:coarse`): `.menu summary`, `.menu-pop button`, `.help summary` (44 × 44), `#u-more > summary`, `.crumbs button`, the "all (N)" row, `#d-cols` select: ≥ 44 px (D-035).
- 360 px: no horizontal scroll with panel open or closed; the toolbar wraps; pops are capped to the viewport (above); panel labels keep `ellipsis` except the fold row and the Dependencies row, which wrap (`white-space:normal`). Checked at 360 and 1280 px in the browser test (test plan 12).
