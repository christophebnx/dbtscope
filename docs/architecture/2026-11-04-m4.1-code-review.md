# M4.1 — Code review: duplication, weight, tests, practices, naming (design note)

Status: DONE (2026-11-04). Default suite 397 tests / 2.75 s → 346 / 1.9 s; browser suite 98 / 94 s → 84 / ~116 s (no time gain, see `docs/progress.md`). Pages byte-identical; JavaScript findings of § 6 deferred.

## Context

Request: audit `src/`, `tools/` and `tests/` and make the code leaner and more consistent without changing what dbtscope produces (brief `docs/briefs/2026-11-04-m4-review-cli-docs.md`, § M4.1; roadmap M4.1).

Hard limits for every item below:

- **Page bytes frozen.** `tests/fixtures/m3-reference-pages/` must pass unchanged; never regenerate it. `render/assets/*` (`boot.js`, `universe.js`, `detail.js`, `page.html`, `page.css`) are inlined in the page, so **no edit to any file under `render/assets/` is allowed in M4.1**, not even a comment or whitespace. JavaScript findings are recorded in § 6 for the next milestone that changes the page.
- **CLI frozen.** Option names, messages, summary lines and exit codes unchanged. `cli.py` is not touched (rewritten with Typer in M4.2); `cli.py` findings are handed to M4.2 in § 7.
- **Invariant 9 untouched:** payload JSON keys, `dbt-erd.yml` keys, file names, layout format, localStorage key.
- `domain/` stays pure.

Baseline: 397 default tests in 2.75 s, 98 browser tests in 94 s (`-n auto`). The architect had no shell: the developer runs the coverage report first (`uv run pytest -q -m "not live and not browser" --cov=dbtscope --cov-report=term-missing`) and adds to § 2 any unreferenced line it shows; the grep audit found no unused public function.

Order of work (each a commit, tree green after each): § 1 and § 2 (src + tools), § 3 (tests), § 4 (practices, mostly mechanical), § 5 (renames + glossary), docs.

## Chosen design

### 1. Duplicated code (same responsibility, two implementations)

**1.1 Page-data extraction in tests (three implementations → one).**
- `tests/conftest.page_data(page: str)`, the inline `split` in `tests/browser/conftest.build_page`, the inline split in `tests/unit/test_page.py::test_comment_and_script_open_in_the_data_are_escaped`, and `tests/reference_pages.data_block(page: bytes)` with its own `DATA_OPEN`.
- Keep in `tests/conftest.py`: `DATA_OPEN = '<script type="application/json" id="data">'`, `data_block(page: bytes) -> bytes` (moved from `reference_pages.py`, unchanged), and `page_data(page: str) -> dict` rewritten as `json.loads(data_block(page.encode()))`.
- `reference_pages.py` imports `data_block` from `conftest`; `test_reference_pages.py` keeps importing it through `reference_pages` or directly from `conftest` (either, one import).
- `browser/conftest.build_page` and `test_page.py` call `page_data` / `data_block`.

**1.2 Writing the `shop` project and its files (five places → helpers in `tests/conftest.py`).**
- Today: `conftest.dbt_project` fixture, `reference_pages.build_page`, `test_trajectory.py::test_table_without_lineage_shows_the_empty_state` (read/write **without `encoding`**), `browser/test_payload.py`, `integration/test_invalid_inputs._write_manifest`, `test_cli.py` (manifest and layout writes), `browser/conftest.build_page` (writes `dbt-erd.yml` itself instead of `write_config`).
- Add to `tests/conftest.py`:
  - `write_project(folder: Path, manifest: dict | None = None) -> Path`: `target/manifest.json` (`json.dumps(manifest or shop_manifest())`, UTF-8) and `dbt_project.yml` (`"name: shop\n"`); `mkdir(parents=True, exist_ok=True)`.
  - `write_manifest(project: Path, data: dict | bytes) -> None` (dict → `json.dumps`, bytes written as is).
  - `write_layout(project: Path, layout: dict) -> None`.
  - `write_config` stays.
- `dbt_project` fixture = `write_project(tmp_path)`. `reference_pages.build_page` uses `write_project`, `write_config`, `write_layout`: **the written bytes must stay exactly the same** (same `json.dumps` defaults, same YAML text), so the reference test keeps passing. `_write_manifest` of the integration file goes.

**1.3 Browser test helpers (duplicated across files → `tests/browser/conftest.py`).**
- `shop` fixture (`test_export.py`) and `shop_page` fixture (`test_trajectory.py`) are the same → one `shop_page` fixture in `browser/conftest.py`.
- `CENTRE_WAIT_MS` (test_export, test_trajectory), `NARROW` (test_export, test_page_styles), `scroll_width` (both), `close_panel` (two **different** implementations: `is_visible` vs `classList.contains('closed')`; keep the `is_visible` one), `show_detail` (two versions; keep one that waits for `g.node` and takes `exportable: bool = True`), the page background `(0xF5, 0xF6, 0xF8)` (`test_offline.BG`, `test_export` literal) → `PAGE_BG`.
- "Block every request but the page's own URL" is written three times (`open_page._open` offline branch, `test_export.py::test_detail_svg_opens_alone_with_the_same_look`, `test_offline.py::test_the_blocking_is_real_the_cdn_page_cannot_start`) → `only_own_url(page, url)` in `browser/conftest.py`.
- Table-name helpers `names` (test_trajectory, `{unique_id: distance}` → `{name: distance}`), `names_of` (test_export, ids → names through the payload) and `upstream_names` (test_offline, a third version of `names`): move `names` and `names_of` to `browser/conftest.py`; `upstream_names` becomes `set(names(p.state()["up"]))`.

**1.4 Empty payloads.** `test_page.DETAIL`, `test_trajectory_perf.DETAIL` build the same empty `DetailPayload` → `conftest.empty_detail(title: str = "x") -> DetailPayload` next to `empty_universe()`.

**1.5 The page JSON encoder (`render/page.py` vs `tests/unit/test_payload._json`).**
- Extract from `render_page` a public `embedded_json(payload: PagePayload | BaseModel) -> str`: `json.dumps(payload.model_dump(mode="python", by_alias=True), ensure_ascii=False, separators=(",", ":")).replace("<", "\\u003c")` (the exact current expression and comments). `render_page` calls it. `test_payload._json` is deleted and the test calls `embedded_json` (the escape does not affect its assertions: no `<` in its data).
- Responsibility map: new row "Serialise a payload for the page (one encoder, D-023 escape) | `render/page.embedded_json`".

**1.6 `tools/vendor_libraries.py` vs `render/page.py` vs `tests/unit/test_vendor.py`.**
- The list of vendored files is derived from `LIBRARIES` three times: `vendor_libraries._files` (name → URL, once each), `vendor_libraries._readme` (licences), `test_vendor.LICENCES` and the `(spdx, file)` parametrisation. Move `_files` to `render/page.py` as `vendored_files() -> dict[str, str]` (file name → URL it is fetched from; scripts first, then licences and notices, each once, in `LIBRARIES` order). The tool (`download`, `_fetch_all`, test_vendor_tool) and `test_vendor.py` use it; `test_vendor.LICENCES` goes (`vendored_files()` minus the script names).
- The "no `<!--` nor `<script` in an inlined file" rule is written twice (`vendor_libraries._problem`, two tests of `test_vendor.py`). Add `UNSAFE_MARKUP = ("<!--", "<script")` to `render/page.py`, next to `_inline` (the page is why the rule exists); `_problem` and the test read it.
- Responsibility map: "Every vendored file and where it comes from | `render/page.vendored_files`"; extend the `LIBRARIES` row.
- `render/page.py` changes are Python only; the page output is identical.

**1.7 Kind colour fallback (domain).** `Config._kind_colors` already gives every kind a colour, so `k.color or DEFAULT_KIND_COLOR` in `domain/detail.detail_data` and `domain/universe._kinds` is a second, dead implementation of the default: use `k.color`. `classify.OTHER.color="#777777"` repeats `DEFAULT_KIND_COLOR`: use the constant. Same bytes.

Not duplication (checked, kept): `detail.detail_data` and `universe._kinds` build different legends (the detail view has no resource-type kinds; changing that changes the page); `storage/project_files._read_*` already own file decoding; `classify.group_of` reuses `selectors.field_value`.

### 5. Naming

**Glossary** (to add to `docs/architecture.md` as a section "Glossary", after "Responsibility map"; record as decision D-027):

| Concept | Word | Not | Notes |
|---|---|---|---|
| A model, seed, snapshot or source of the manifest | **table** (`Table`, `tables`) | node, entity, model (except dbt's resource type `model`) | Identified by its `unique_id` (invariant 11). |
| A table as an item of the universe payload | **node** only as the payload key `nodes` and `UniverseNode` | — | Protected key; Python variables holding `UniverseNode`s are `nodes`. "Node" also stays for dbt's manifest `nodes` and `NodeHeader`. |
| A table as an item of the detail payload | **entity** only as the payload key `entities` and `DetailEntity` | — | Protected key; variables holding `DetailEntity`s are `entities`. |
| Business link declared by a `relationships` test or a `foreign_key` constraint | **relation** (`Relation`, `relations`) | relationship (except dbt's test name), FK link | |
| `ref` / `source` dependency | **lineage** (`LineageEdge`, `lineage`); one item is a **lineage edge** | dependency, parent link | |
| What the page draws for a relation or a lineage edge | **link** | edge (in UI text) | User-facing only: config `universe.links`, the page, the CLI summary ("lineage links"). In code, "edge" only for a lineage edge or a drawn graph edge. |

## Rejected options

- **Consolidating the JS helpers now** (`esc`, string tables): changes the page bytes, which the brief forbids in M4.1; recorded in § 6 instead.
- **Regenerating the reference pages after a "harmless" asset edit**: forbidden by the brief; it would also hide a real change.
- **A shared `domain/_config.py` holding both pydantic configs**: a module for two constants; `model.DOMAIN` plus the two documented open configs is enough.
- **Moving `vendored_files` into the tool and loading the tool from `test_vendor.py`**: tests would depend on a script loaded by path; `LIBRARIES` is already the one list, its derived list belongs next to it.
- **Removing `from __future__ import annotations` everywhere** (Python ≥ 3.12 needs it less): more churn in `src/` and loses lazy annotations in pydantic modules; enforcing it is one ruff setting with autofix.
- **Renaming `Table.group` to `dbt_group`**: touches the M3 allowlist, selectors docs and tests for a distinction the glossary already makes.
- **Dropping `test_performance.py` or `test_trajectory_perf.py`**: they guard different criteria (M3 parse bound, M1 criterion 4).
- **Dropping `Relation.origin`**: specified in roadmap M3 and read by the dedupe tests.
