# M9.4 — Schema tab: 3NF sheets on screen (design note)

Status: APPROVED FOR AUTONOMOUS MODE. Everything here is the brief's decided scope (`docs/briefs/2026-11-17-visualization-optimization.md` § 3 rows 5 and 6, § 8): a third tab "Schema", a scroll-first navigation recorded as a deviation from D-045 scoped to this tab (the brief asks for it), inter-lane summaries with a measured threshold. One payload key is added (`UniverseKind.bg`, extension, backwards compatible); no config key, no layout format, layout scope or localStorage key; nothing about the tab is saved.

## Context

Request: add a third tab **Schema** ("Schéma") that draws a chosen scope (whole project, one domain, one layer, or the universe's current filter set) as classic entity-relationship sheets: table boxes at one of the three Show levels, relations as FK → PK edges, on a grid of swimlanes (layers as columns in flow order × domains as rows), navigated as a document (wheel scrolls, ctrl+wheel / pinch zooms, drag pans, minimap, search, PgUp / PgDn), with the breadcrumb of M9.2 and image export; its drawing model must be the one M9.5 prints (paper size and tiling computed from it) (roadmap M9.4).

Current state (after M9.3):

- Two tabs (`page.html #tabs`, `boot.js showTab`, `views.universe`, `views.detail`); the flow view is an overlay of the universe. Scripts inlined in order `common.js`, `detail.js`, `universe.js`, `flow.js`, `boot.js` (`page.py` placeholders `COMMON_JS` … `BOOT_JS`).
- The **universe payload** carries every table of the universe scope (`UniverseNode`: `id`, `name`, `domain`, `layer`, `kind`, `desc` ≤ 400 characters, `cols` `[name, type, is_key]`, `parent`), all `relations` and `lineage` as `[child, parent]` index pairs, `domains` (label, colour, owner, `system`), `layers` (in flow order: `LAYER[key].rank` is the payload index; `other` last when present), `kinds` (label, colour, role; **no tint**). The **detail payload** adds, for the detail tables only, full descriptions, column descriptions and relation columns, read through `common.js detailIndex` (`boot.js DETAIL_INDEX`, M9.3). `DetailKind.bg` (the light tint of the table body) is computed by `domain/classify.background` for the detail's kinds only.
- **Graphviz card markup**: `detail.js nodeDot` (header cell in the kind colour, name in `CONTRAST.textOn`, body in the kind tint, key rows bold, types in `CONTRAST.ink(muted, bg)`, "+ N columns" note, border in `CONTRAST.edge`). Viz.js has a 16 MB heap: neato aborts the routing of 277 pinned tables (D-074), and the 138-table skeleton takes 0.3 s to a mounted SVG.
- **Grid dealing (M8.5, D-074)**: `detail.js skeletonColumns` (hubs dealt by degree in a snake over P column pairs [hubs | links], each link beside its first parent's hub column, P chosen for an aspect, six barycentre sweeps, `stack` least-squares column alignment), `skeletonPositions`, `SK` constants, `sizeOf` (estimated sizes). All inside the `startDetail` closure.
- **Zoom**: `common.js zoomOn` (the one way to attach d3.zoom; Safari gestures), `zoomHandle(box, layer, size, onZoom)` (`fit`, `get`, `set`, `centre`, `destroy`), `svgImage(box, zv, scale)` / `pngImage` (export of the visible part of an SVG whose tables are `g.node` and links `g.edge`), `ZOOM_EXTENT`. D-045: the wheel zooms in every view.
- **Location**: `common.js crumbs(nav, items)`; `universe.js location()` → `{level, inside, table, by}`; `boot.js locationKey`, `followUniverse` (the Detail tab follows the universe location when it changed, D-089). The universe's panel order of domains is `universe.js DOM_LIST` (business domains, then source systems, D-068).

Measured facts of the large project used below (`tests/fixtures/large-data-vault/notes.md`): 1,419 tables, 12 domains (5 business, 7 source systems), 4 layers (Sources, Staging, Raw vault, Data products), 978 relations (all from `relationships` tests, mostly inside one domain's raw vault; about one link in five references a hub of another domain).

## Chosen design

Layers touched: `domain/payload.py`, `domain/universe.py` (one field), `render/page.py` (one script placeholder), `render/assets/` (`page.html`, `page.css`, `common.js`, `detail.js` (refactor only), `universe.js` (two small additions, one refactor), new `schema.js`, `boot.js`). `storage/`, `cli.py`, `domain/config.py`, `flow.js`: unchanged.

### 1. Rendering technique (D-092)

**Own layout, own SVG, one emitter for screen, export and print.** The tab computes a **sheet model** (pure: positions and sizes of lanes, boxes, rows, edges and chips, in sheet units) and draws it with one **SVG emitter** that serves three uses: the screen (only the part near the viewport is in the DOM), the image export (the visible part) and, in M9.5, the print document (the whole sheet, or one tile's rectangle). Graphviz is not run in this tab.

Options weighed (numbers: the large project at key columns):

| Option | Whole project (1,419 tables) | Per-domain (~300) | Print reuse (M9.5) | Verdict |
|---|---|---|---|---|
| A. Graphviz (neato, pinned grid positions) per cell, SVGs tiled into the lanes | ~25 non-empty cells, sequential Viz.js renders; the 138-table skeleton takes 0.3 s, so ≈ 3–4 s for 1,419 tables before mounting (estimate from D-074's measure, linear); a Raw vault cell of ~260 tables at key rows is at the 277-table size where Viz.js's 16 MB heap aborted (D-074) | ≈ 1 s | SVG, but inter-cell edges and chips would have to be drawn outside Graphviz anyway (two drawing systems in one sheet) | Rejected: misses the 3 s opening budget, risks the heap abort, two drawing systems |
| B. Own layout + Canvas drawing (as the universe) | fast (the universe draws 1,419 tables in ~3–5 ms per frame) | fast | none: print needs vector output, so a second renderer (SVG) of the same model would be written for M9.5 and exports | Rejected: two renderers of one model (invariant 2), raster export of a document |
| **C. Own layout + SVG, virtualised on screen (chosen)** | model ≤ 100 ms (estimate below), first frame at Fit ≈ 6k SVG elements in simplified form | ≤ 50 ms model, first frame at reading scale ≈ 60–150 boxes in the DOM | the same emitter writes the print document and each tile (clip rectangle) | Chosen |

Why C meets "Graphviz card markup for the boxes": the box **is** the detail's card, reproduced from the same rules, not from Graphviz: header band in the kind colour with the name in `CONTRAST.textOn`, body in the kind tint (`bg`), key rows bold, types in `CONTRAST.ink(THEME.muted, bg)`, the "+ N columns" note at the key level, border in `CONTRAST.edge(color, THEME.bg)`, dashed border none (no foreign tables in a scope). The colour and contrast rules are reused functions (`CONTRAST`, `dotEdge`'s rule applied as an SVG stroke); only the markup differs (SVG elements instead of a Graphviz HTML-like label). Relations are straight light lines, which is D-074's rule for very large edge sets applied to every scope (no routing is ever attempted).

**Estimated costs (to be confirmed by the measurement plan, § 10):**

- Text widths: measured once per distinct string with `CanvasRenderingContext2D.measureText` on one offscreen canvas in the sheet's font (Arial, as the Graphviz views), cached in a `Map`: ~1,419 names + ~4,300 key rows ≈ 6k strings ≈ 10–20 ms; all columns ≈ 20k strings ≈ 40–80 ms. (Estimates, as `sizeOf` uses, would under- or overshoot by up to 20 %: a printed sheet must not let a name leave its box, so this tab measures. SVG text in the page and the print use the same browser and font, so measure and drawing agree.)
- Dealing: per cell, P scanned 1 to 30 × O(n), six sweeps O(n + e), two passes (§ 3): < 50 ms for the whole project.
- First frame at Fit (whole project, simplified form, § 5): ~1,419 `g.node` (2 rects each, rows as one path of bars), ~900 `g.edge`, ~60 chips, ~50 lanes: one `innerHTML` of a ~0.6 MB string, ≈ 100–250 ms to the first paint in Chromium.
- Scroll frame: one `transform` attribute on the zoom layer; a re-cull (new boxes entering the margin) every few hundred pixels: ≤ 30 ms.

The tab draws from the **universe payload** (the only one holding every table of the project) and reads the **detail index** for what only the detail knows:

| Sheet content | Source | Change |
|---|---|---|
| Box name, kind, domain, layer | `UniverseNode` | none |
| Columns, types, key flag (the three Show levels) | `UniverseNode.cols` | none |
| Relations (FK → PK) | `DATA.relations` `[child, parent]` (child = the FK side) | none |
| FK column of a relation (edge anchor row, edge tooltip) | `DETAIL.relationColumns(child, parent)` when both ends are detail tables; else unknown (the edge anchors on the box side) | none |
| Tooltip description | `DETAIL.entity(id).description` when a detail table, else `UniverseNode.desc` (the M9.3 rule, `tableDesc`) | none |
| Lane order | `DATA.layers` order (flow order, `other` last); domains in the panel order (§ 3) | none |
| Kind colour of the header | `UniverseKind.color` | none |

`UniverseKind.bg` is the only addition: the detail's kinds hold only the kinds of the detail scope (dimensions and facts of the large project are not detail tables), and recomputing the tint in JavaScript would be a second implementation of `background` (invariant 2). Serialised `bg`, after `role` (the comment "last key" moves). Structure only (a colour), invariant 8 holds. Every page's payload changes by that key only; the M3 reference pages are regenerated once, in the commit that adds it.

### 3. The sheet model (D-092)

All sizes in **sheet units** (u): 1 u = 1 CSS pixel at zoom scale 1 = 0.75 pt. Row text is `S.ROW_FONT` = 11 u, so scale 1 is the reading scale on screen and M9.5 prints at `minFont / S.ROW_FONT` pt per unit (7 pt default → 0.636 pt per unit). Every constant of the sheet lives in one object `S` at the top of `schema.js` (starting values; the ui-designer may tune them, every computation reads `S`):

`S = { ROW_FONT: 11, HEAD_FONT: 13, ROW_H: 18, HEAD_H: 24, PAD_X: 8, MIN_W: 120, GAP: 16, GUTTER: 48, LANE_PAD: 24, LANE_GAP: 32, TITLE_H: 28, ROW_HEAD_W: computed (widest domain label + 2 PAD), CHIP_H: 20, CELL_ASPECT: 1.6, READ: 0.9, GREEK_PX: 5 }`.

**Scope → tables.** `scopeTables(scope)` returns the universe nodes of the scope: `{kind: 'all'}` every node; `{kind: 'domain', key}` the nodes of that domain; `{kind: 'layer', key}` the nodes of that layer; `{kind: 'filter', ids}` the universe's passing tables (§ 6). The fold is never applied: the Schema is the exhaustive document (every satellite and PIT is a box).

**Lanes.** Columns = the layers that hold a scope table, in payload order (flow order; `other` / no layer last, header "No layer"); rows = the domains that hold one, in the **panel order** (business domains, then source systems). The panel order moves from `universe.js DOM_LIST` to a pure `common.js domainOrder(universe)` (returns the ordered domain list; the universe builds `DOM_LIST` / `DOM_POS` from it, output unchanged), so both tabs share one rule. A project without layers has one column (no column header), without domains one row: acme_retail and `shop` work.

**Cell packing: the M8.5 grid dealing, extracted.** `detail.js skeletonColumns` and `stack` move to `common.js` as the pure `gridDeal(tables, rels, size, fit, opts)`:

- `tables`: `[{id}]`, `rels`: `[{child, parent}]` inside the set, `size`: `Map(id → [w, h])`, `opts`: `{gap, gutter, minAspect, maxAspect, sweeps, scan}`.
- `fit`: `{aspect: a}` (today's objective: the P whose estimated W / H is nearest `a`, clamped to [minAspect, maxAspect], ties to the smaller P) or `{height: H}` (new: the smallest P whose tallest column is ≤ H; the largest scanned P when none is).
- Returns `{K, rows, widths, height, y}` exactly as today. `detail.js` calls it with its `SK`, its `sizeOf` and `{aspect: box.clientWidth / box.clientHeight}`: the detail's drawings are unchanged (same positions, checked by the existing skeleton tests and one new equality test on `vehicle`).

**Two passes give a tidy sheet.** Pass 1 deals every non-empty cell with `{aspect: S.CELL_ASPECT}` and gives its height; each **row height** `H_r` is the tallest pass-1 cell of the row. Pass 2 re-deals every cell of row r with `{height: H_r}` (cells fill the row's height and become as narrow as they can); each **column width** is the widest cell of the column. Cell origin = column x + `LANE_PAD` (+ the chip strip on that side, below), row y + `TITLE_H` + `LANE_PAD`. Inside a cell, `skeletonPositions`' rule (columns left to right, `gutter` apart, y from `gridDeal`) places the boxes. Deterministic: same scope and level give the same sheet on every machine and every load (D-040's rule).

**Box.** `boxSize(node, level)` (one function, so M9.5 can add a level without touching the packing): width = max(`MIN_W`, header name width + 2 `PAD_X`, max over drawn rows of name + type widths + 3 `PAD_X`); height = `HEAD_H` + `ROW_H` × drawn rows (+ one note row "+ N columns" at the key level when columns are hidden). Levels: `names` (header only), `keys` (key columns, then the note), `all` (key columns first, then the others in payload order). A table without columns: header only, at every level.

**Edges.** Every relation with both ends in the scope is an edge `{child, parent, cell pair, intra}`; a relation with one end out of the scope is an **out-of-scope stub** (counted on a chip, never drawn as a line). Geometry: child end on the child box's side facing the parent (left or right by centre x), at the FK row's y when that row is drawn, else the box's vertical centre; parent end on the facing side at the first key row's y when drawn, else the header's centre. Same column (x ranges overlap): both ends on the right side, a cubic bow of `GUTTER / 2`. Straight lines otherwise, light (the colour of D-074's straight lines, `#8a8f98` at about half opacity); a **crow's foot** at the FK end (the detail's `arrowtail=crow`, one vocabulary) and a small filled **arrowhead at the PK end** (the brief's direction marker). Crossings are accepted.

**Inter-cell relations: drawn or summarised (D-094).** An edge whose ends are in two different cells is **inter-cell**. The scope is **summarised** when it holds more than `S.LANES_FULL_TABLES` = 300 tables **or** more than `S.LANES_FULL_EDGES` = 150 inter-cell relations (provisional values, confirmed or moved by the measurement of § 10 before the phase closes; the decision records the measured values). Then each inter-cell relation is not drawn but counted on **chips**:

- For each ordered pair (cell c, other cell d) with relations, one chip on c's border facing d: right or left when d's layer column differs (the flow direction wins for diagonal pairs), bottom or top when only the row differs. Text "→ Auction · Raw vault 12" when c holds the FK side, "← … 3" when c holds the PK side ("→ Auction 3" when d is in the same layer column). Chips of one side stack along it in d's (row, column) order; a chip strip of `CHIP_H` + `GAP` is reserved on that side of the cell (the lane padding grows), so chips never cover a box.
- **Out-of-scope stubs** are always chips (summarised or not): "→ Auction (outside this scope) 3", same placement rule by the other table's lane in the whole-project grid order.
- **Expand**: a click (Enter / Space, the chip is a focusable button in the HTML overlay, § 5) toggles the chip: the pair's relations are drawn as full lines in the accent colour, and a popover lists them (`car_link.vehicle_hk → car_hub`, FK column when known), each item a button that frames the other end (disabled with its reason "Outside this scope" for a stub, D-085). Several chips may be expanded; Esc or a second click folds one. Expanded state is page state, never saved.
- Hover or selection of a table draws **all** its relations fully (in-cell and inter-cell, accent), whatever the summarisation: no relation is ever unreachable.
- When not summarised, inter-cell edges are plain light lines like intra-cell ones.

**Lane titles** are part of the sheet (world space, exported and printed): each column's layer name and count at the top of its first row ("Raw vault 828"), each row's domain name and count in the row-head column on its left (`ROW_HEAD_W`), drawn in the domain colour inked to 4.5:1 (`CONTRAST.ink`); lane rectangles a faint tint (the universe's `TINT` alpha, the domain colour for rows) with 1 px separators. The ui-designer settles the look.

**Model object** (returned by the pure `sheetModel(nodes, rels, level)` inside `schema.js`; on the handle as `sheet()` for the tests and for M9.5): `{ W, H, unit: {rowFont, headFont}, columns: [{key, label, x, w, n}], rows: [{key, label, color, y, h, n}], cells: [{row, col, x, y, w, h, n}], boxes: Map(id → {x, y, w, h, rows: [{name, type, key, y}], note}), edges: [{child, parent, x1, y1, x2, y2, bow, intra, drawn}], chips: [{cell, other, dir, n, out, x, y, w, side, rels}], summarised, interCell, ms }`. M9.5's paper size is `W × H` × the print scale; its tiles are rectangles of the same model given to the same emitter.

### 4. The SVG emitter (one for screen, export, print)

`sheetSvg(model, rect, form, marks)` returns an SVG string of everything that intersects `rect` (sheet units): lanes and titles, then edges (`<g class="edge" id="e<i>">`), then boxes (`<g class="node" id="<unique_id>">`, invariant 11), then chips; `form` is `full` (text drawn) or `simple` (§ 5); `marks` the selection, the hovered table and the expanded chips (accent lines, ring, dimming class `dim` as the detail). Every name, type and label goes through `esc` (untrusted, render rules); no `<title>` elements (tooltips are HTML). Classes `node` / `edge` make `common.js svgImage` and `pngImage` work unchanged (they cut what lies off the visible area). M9.5 calls it with the whole sheet or a tile rectangle and `form: 'full'`.

### 5. On screen: virtualised SVG, two forms, overlays

DOM: `#tab-schema` > panel `#s-panel` (side panel with **Scope** and **Show**, `sidePanel`) + stage: toolbar (☰, crumbs `#s-crumbs`, search `#s-q` + datalist `#s-tables`, `?` help `#s-help`, **Fit**, Export image PNG `#s-export-png` / SVG `#s-export-svg`) and `.canvas-box#s-stage` holding `#s-graph` (the zoom box: one `<svg>` with one zoom layer `<g>`), the sticky lane headers `#s-heads` (HTML), the chip buttons layer `#s-chips` (HTML, positioned by the transform), the minimap `#s-mini` (a canvas), the tooltip `.tip`, the live region `#s-live` and the text alternative `#s-summary` (`sr-only`: per cell its domain, layer and table count; the out-of-scope and inter-cell counts).

- **Mount** through `common.js zoomHandle(box, layer, [W, H], onZoom, {scroll: true})` (extended, § 7): one d3 zoom, `fit`, `get`, `set`, `centre`, `destroy`, and `svgImage` / `pngImage` for export as in the detail.
- **Virtualisation**: the DOM holds the boxes and edges that intersect the **render rectangle** = the viewport in sheet units grown by one viewport in each direction (a `d3.quadtree` of box centres with their half sizes, built once per model). On `onZoom`, when the viewport leaves the inner half of the render rectangle, or the form changes, `paintSheet()` re-emits the render rectangle on the next animation frame (one `innerHTML` of the layer); pans in between move only the layer's `transform`. Lanes are always emitted (≤ 100 elements).
- **Two forms**: `full` when row text is at least `S.GREEK_PX` (5 px: `k × ROW_FONT ≥ 5`, so k ≥ 0.45); else `simple`: boxes as their header band and body tint, rows as one `<path>` of grey bars (one element per box), header text kept while `k × HEAD_FONT ≥ 5`, chip text kept likewise. Edges stay in both forms. Exports are "as on screen" (D-021): an image taken in the simple form is the simple form.
- **Opening view** (the document rule): the **Fit** scale when it is at least `S.READ` (0.9, rows ≥ 10 px); else scale 1, with the top-left corner of the first non-empty cell (reading order: rows top to bottom, columns left to right) at the stage's top-left plus `LANE_PAD`. **Fit** (toolbar) always fits the whole sheet (contain, centred).
- **Sticky lane headers** `#s-heads`: when a column's title row has scrolled off the top, its layer name sticks to the top of the stage over that column's x range; when a row's head column has scrolled off the left, its domain name sticks to the left over that row's y range (as the M9.2 band headers, D-090). HTML, so never exported.
- **Minimap** `#s-mini` (bottom-right of the stage, about 180 × 120 px, `aria-hidden`): the lanes (tints) and boxes (kind colour, one pixel minimum) drawn once per model on an offscreen canvas, plus the viewport rectangle redrawn on every zoom event. A click or drag in it centres the view there (`zv.set`, same scale). Hidden when the whole sheet is in view, and below 600 px stage width (the Fit button and the scroll keys remain). Never exported.
- **Tooltip** on hover over a box: `common.js tableTip` + `tableDesc` (the universe's lines), plus the FK column of an edge on hover over an edge ("car_link.vehicle_hk → car_hub").

### 6. Scope, Show level, location, search (D-092)

- **Scope select** `#s-scope` in the panel (filled by `fillSelect`, extended to accept groups `[label, pairs]` rendered as `<optgroup>`): **Whole project**; **Domain** › each domain in panel order (source systems in their own group); **Layer** › each layer in flow order; **Current filters** (the universe's passing tables, fold ignored: `views.universe.passingIds()`, a new handle member returning the ids of the tables that pass the universe's domain, layer and kind filters). "Current filters" is **disabled with its reason** (D-085) when the Universe tab has not been opened or no filter hides a table ("No filter is set in the Universe tab"); its set is read again each time the Schema tab is shown and the sheet is recomputed only when the set changed.
- **Show select** `#s-level`: names / key columns / all columns, the same words as the universe (D-084; the three labels move from the universe's `T` to `common.js L` since two views show them with the same text). Starts at **key columns** (the brief's reading level); not remembered.
- **Breadcrumb** `#s-crumbs` (`common.js crumbs`, the M9.2 component and words): `All domains` (whole project), `All domains › Vehicle` (domain scope), `All layers › Raw vault` (layer scope), `All domains › Current filters` (filter scope), plus `› car_hub` when a table is selected. Ancestors are buttons that change the scope to theirs (the root: whole project); the current segment frames its place (the scope's opening view, or the selected table). One line, never wrapping (the D-089 CSS).
- **Opening from the universe** (`boot.js followUniverse`, generalised to `follow(view)` for the Detail and Schema tabs, one `locationKey` rule): when the Schema tab is shown by its button and the universe location changed since the Schema last followed it, an entered constellation preselects that scope (domain mode → domain scope; layer mode → layer scope) and a selected universe table (level 2) is then framed and selected in the sheet. The viewer's own scope choice stands until the universe location changes again (D-089's rule).
- **Search** `#s-q` with a datalist of the scope's tables (names, ids for duplicates as the detail): Enter or a datalist choice selects the table and frames it at max(current scale, 1), centred; a name not in the scope says "car_hub is not in this scope" in `#s-live` (and in the box's `title`), nothing moves.
- **Selection**: a click (or tap) on a box selects it: ring (accent, 3 u), its relations drawn fully in the accent colour, the rest dimmed (the detail's `dim`), crumbs end with it, `#s-live` announces "car_hub: Hub · Vehicle · Raw vault · 3 key columns · references 2 · referenced by 5". A click on the background clears it. Double-click has no action in M9.4 (D-045's "each view's own action": none here); a hand-off to the Detail or the Universe from the Schema is a roadmap follow-up.

### 7. Navigation: the scroll model (D-093)

The Schema tab is a document: **the wheel scrolls**, **ctrl+wheel and a pinch zoom**, a drag pans. This deviates from D-045 ("the wheel zooms in every view") **for the Schema tab only**; the Universe, Detail and Lineage graph keep D-045 unchanged.

- **One zoom, still d3's.** `common.js zoomOn(sel, zoom, opts)` gains `opts.scroll`: when set, the d3 zoom's `filter` lets a wheel event through only with `ctrlKey` (a trackpad pinch in Chromium, Firefox and Edge arrives as ctrl+wheel; Safari's gesture events are already turned into `zoom.scaleBy` by `zoomOn`), and a `wheel.scroll` listener (non-passive, `preventDefault`) translates through the zoom behaviour: `zoom.translateBy(sel, -dx / k, -dy / k)` with `deltaMode` lines × 16 px and pages × the stage size; `shiftKey` turns a vertical wheel into a horizontal scroll (the mouse's habit). Every transform still goes through d3's zoom (no second gesture library or handler, D-045's intent). `zoomHandle(box, layer, size, onZoom, opts)` passes `opts` on. Without `opts` both functions behave exactly as today.
- **Touch**: one finger pans, two fingers pinch (d3's touch handling, unchanged); a tap selects.
- **Keyboard** (the stage `#s-graph` is focusable, `tabindex=0`, named "Schema sheet"; keys act only while the Schema tab is shown and the focus is not in an input or a select): arrows scroll 40 px; **PgUp / PgDn** scroll one stage height minus 10 % (one screen page; `Shift` → horizontal); **Home / End** the sheet's top-left / bottom-right; **+ / −** zoom by one wheel notch (1.15×) around the stage centre; **0** Fit. The `?` popover lists them (mouse and touch variants as the other tabs).
- **Esc** (one level back, D-089's chain, guards first: popovers, an expanded chip's popover, the search box and selects keep their own): selected table → cleared; a domain, layer or filter scope → the whole project; whole project → nothing.
- **Scroll limits**: the translation is clamped so the sheet cannot leave the stage entirely (`zoom.translateExtent` = the sheet grown by one stage on each side).

### 8. Persistence (none, D-092)

Nothing of the Schema tab is saved: no layout section, no localStorage key, no URL, no export of its state (D-013). The sheet is computed and deterministic, so a saved arrangement would only record drags of a document (dragging is off in this tab); the scope and level are read in a second. The **Layout** menu (Reset / Export / Import) keeps acting on the universe and detail arrangements; the Schema never reads them. The `view` config key (`universe` | `detail`) is not extended: the page never opens on the Schema tab in M9.4 (a later config decision may add `schema`).

### 9. Wiring

- `page.html`: the tab button `data-tab="schema"` after Detail (label `L.schema`, `title` `L.tabSchema`), the `#tab-schema` section (§ 5). `page.py`: a `SCHEMA_JS` placeholder; scripts inlined `common.js`, `detail.js`, `universe.js`, `schema.js`, `flow.js`, `boot.js`.
- `boot.js showTab('schema')`: `views.schema = startSchema(PAGE.universe, DETAIL_INDEX, EXPORT, universeAccess)` on first show, where `universeAccess` = `{ location: () => views.universe?.location() ?? null, passingIds: () => views.universe?.passingIds() ?? null }` (the universe may not be started). Then `follow(views.schema)`.

## Rejected options

- **Graphviz per cell** (option A, § 1): misses the 3 s opening budget on the whole project, risks Viz.js's heap abort on a raw vault cell, and still needs a second drawing system for inter-cell edges and chips.
- **One Graphviz drawing of the whole scope** (dot or neato): 1,419 tables are five times the size that already aborted (D-074).
- **Canvas on screen + SVG for print** (option B): two renderers of one model (invariant 2) and a raster image export of a document.
- **Full SVG of the sheet in the DOM** (no virtualisation): at all columns the whole project is ~25k text elements; panning stays fluid but every re-render (selection, form change) re-lays out all of them.
- **Estimated text widths** (as `sizeOf`): good enough for the screen, but a printed name leaving its box is a defect of the document; measuring costs tens of milliseconds.
- **Orthogonal or routed edges**: routing 978 relations around 1,419 boxes is the work Viz.js could not do at 277 (D-074); straight light lines are the brief's "accept crossings".
- **Summarising by adjacency** (draw inter-cell edges only between neighbouring cells): a second rule to explain; kept as a refinement if the measure (§ 10) shows long edges in small scopes.
- **Kind tint recomputed in JavaScript** or **read from the detail's kinds**: a second implementation of `background`, or missing tints for kinds outside the detail scope.
- **Grouping columns by the universe's Organise-by**: the brief fixes layers × domains for the document; the grouping only chooses which scope a followed location preselects.
- **Folding descriptive tables into their table** (as the universe and the detail skeleton): the Schema is the exhaustive document; the Detail keeps the skeleton.
- **Saving a Schema arrangement or remembering scope and level**: a new layout section or localStorage key (D-013) for a deterministic, computed document.
- **`view: schema` in the config**: not asked; a config value is a format change of its own.
- **PgUp / PgDn by paper page**: paper exists only in M9.5's print dialog; on screen a page is the stage.
- **Wheel zooms here too, scroll with a modifier** (D-045 everywhere): the brief asks for the document gesture; the deviation is scoped and recorded.

## UI design (ui-designer, 2026-11-17)

Task and decision. A viewer who needs the whole shape of the warehouse as a document ("how do these tables hang together, in which domain and layer, can I print it?") picks a **scope**, a **level** (Show), then reads by scrolling, jumps to a table by name, and follows or summarises relations. Everything below is the architect's decided scope (brief § 8, D-092 to D-094). NEEDS USER APPROVAL: none. No conflict with the note. Clarifications and four small deviations, none changes behaviour or the payload:

1. **No PK / FK letters in boxes.** The payload's `cols` carry one flag (`is_key`), which does not tell a primary from a foreign key (the FK column is known only for detail tables). A key row is **bold** (as the detail's cards: the bold survives black-and-white printing); direction is carried by the edge (crow's foot at the FK end, arrowhead at the PK end), as the brief asks. At the all level a 1 u rule separates key rows from the others.
2. **Layout menu on this tab.** Export / Import layout stay (they act on the other tabs' arrangement); **Reset this tab's layout** is disabled with the visible reason (D-085) "Nothing to reset: this sheet is computed" (`L.schemaNoReset`).
3. **No minimap toggle** (remove before adding): the minimap shows only when the sheet is larger than the stage and the stage is at least 600 px wide.
4. **Boxes are not Tab stops** (as the universe's discs). Keyboard ways to a table: the search box, chips' popover items, and Esc / Home / End / PgUp / PgDn to move. A box is reached by pointer or touch.

### Keyboard, focus, aria

- **Tab order**: tab bar (Layout menu) → panel (☰ is in the toolbar: Scope, Show) → toolbar (☰, crumb segments, Find a table, ?, Fit, Export PNG, Export SVG) → `#s-graph` ("Schema sheet") → chip buttons in reading order (rows top to bottom, columns left to right; a chip off the viewport scrolls into view when focused, never hidden from Tab; the popover's items follow their chip in DOM order).
- Keys act only while `#s-graph` has the focus (so typing in the search or a select never scrolls): arrows 40 px; PgUp / PgDn one stage height minus 10 % (`Shift`: horizontal); Home / End top-left / bottom-right of the sheet; `+` `-` zoom 1.15× at the centre; `0` Fit; Esc as the note (popover → table → scope → nothing). The keys are listed in `?`. Browser default page scroll on these keys is prevented only while the stage is focused.
- `#s-graph`: `role="group"`, `aria-label` "Schema sheet", `aria-describedby="s-summary"`; the inner `<svg>` is `aria-hidden`. `#s-summary` (`sr-only`): "Raw vault · Vehicle: 412 tables" per cell, then the inter-cell and out-of-scope counts; rebuilt per model. Chip button `aria-label`: "Relations from Vehicle to Auction, 12; show them" / `aria-expanded`. Live region messages (polite, one sentence each, no repetition on re-render): scope change "Vehicle: 412 tables, 3 layers", selection (Strings), search miss, chip expanded "12 relations drawn".
- **Contrast**: text `--fg` / `--muted` / `--accent` as elsewhere; on colours `CONTRAST.textOn` and `ink` (D-037); marks (box border, bars, dots) `CONTRAST.edge` (D-042). Chip text on `--surface` and `--accent-soft` (accent 4.5:1 on soft: verified `#2f6fb5` on `#e8f0fa` = 4.6:1). Edges are decoration of the table lines, with the table names and chips giving the same information in text (tooltip, popover, live message).
- **Targets**: toolbar and panel controls 44 px under coarse pointer (existing rules); chips 44 × 44 hit area; popover items 44 px high coarse, 28 px fine.
- **Reduced motion**: nothing animates in this tab (scrolling and zoom are direct).

### 360 px

The sheet scrolls inside the stage (drag, one finger; pinch zooms); the page and `body` never scroll sideways (`.canvas-box` clips). Panel closed at start; open it stacks above, ≤ 35vh. Minimap hidden; chips' popover is a bottom sheet (≤ 50 % of the stage); sticky row-head pills ellipsise at 40 %. Opening view is the note's (scale 1 at the first cell when Fit would be under 0.9: at 360 px that is nearly always, so the first screen shows one cell at reading size and the crumb and Fit are the way out).

Any rule that changes how the sheet looks goes into `common.js INLINE` (exported SVG). No new colour, no new font size (11 / 13 are already the scale in use), no icon.

### Notes for the developer

- The sheet's look constants beyond `S` (rule widths, opacities, glyph sizes above) live next to `S` in one object `LOOK`, so M9.5 prints with the same values.
- M9.5 reads this look as is: it prints with `form: 'full'`, kind colours turn to grey on a monochrome printer and the header text keeps `textOn`, so only the colour changes, never the information; the kind is read in a legend and the index page (M9.5 adds them).
