# M8.1 — Roles, complete presets, the large test project (design note)

Status: APPROVED FOR AUTONOMOUS MODE

Every change below is foreseen by `docs/briefs/2026-11-12-m8-synthesis.md` § 4–5 (optional `dbt-erd.yml` key, payload keys, preset content, supersession of the "same size" line of `docs/brief-universe-view.md` § 3, negation). No released format changes beyond what § 4 allows; the layout format is untouched. Two choices go slightly past the brief's letter and are recorded with their reason (§ 3.3 `view` kind, § 3.4 seeds and snapshots in Staging); neither needs the user.

## Context

Request: give every kind a **role** that drives star size, name priority and the Types order; complete the `data_vault` and `star_schema` presets (staging, dimension, fact kinds, roles, default `layers` grouping folders by pattern); add selector negation; add a generated large Data Vault project to the tests. Roadmap M8.1; brief § 5 is the spec, §§ 6–9 use its vocabulary (role, technical, core).

Current state:

- `domain/config.Rule` serves `kinds`, `domains` and `layers` alike (`key`, `label`, `color`, `match`). Lists set in `dbt-erd.yml` replace the preset's whole list (`merge_config`); no per-key override exists.
- `domain/universe.universe_data` gives each node `first_rule(kinds)` or a built-in kind (`TYPE_KINDS` source / seed / snapshot, else `OTHER`). Layers: the `layers` rules (unmatched → `other`), or without rules one layer per first folder ordered by `flow_rank` (`FLOW_PREFIXES`).
- `UniverseKind` is `{key, label, color}`.
- `universe.js`: `DEG` = relations + lineage per table; `starR = min(14, 3 + 1.6·√DEG)`; `labelScore` = degree weighted by the kind's position in `DATA.kinds`; `drawNames` drops ordinary names that would cover a star or leave the circle, so at Fit one arbitrary name shows per domain (finding 1). `roleOf` there means the trajectory's start / up / down.
- `selectors._part_matches`: one part, `field:pattern` or a name glob; an unknown field is a `SelectorError`, raised at match time and prefixed with the config by `cli._views`.
- Presets: `data_vault` has 9 kinds, no staging / dim / fact, no layers; `star_schema` 3 kinds, no layers.
- Large inputs in tests: `test_performance.big_manifest` (parser stress: 3,000 `not_null` tests, analyses, FK constraints; no Data Vault shape) and `browser/test_trajectory_perf.universe_payload` (a synthetic payload, no manifest).

## Chosen design

### 1. Roles in the config (`domain/config.py`)

- `Role = Literal["core", "connector", "descriptive", "technical", "none"]` and `ROLES = get_args(Role)`, declared here only (as `Links`, `Constellations`), reused by `payload` and `classify`.
- New `KindRule(Rule)` with `role: Role | None = None`; `Config.kinds: tuple[KindRule, ...]`. `PresetKindRule(KindRule)` with `PRESET_SETTINGS`; `Preset.kinds` uses it. `domains` and `layers` keep `Rule` / `PresetRule`: a `role` on a domain or layer rule is ignored in `dbt-erd.yml` (lenient, invariant 9) and is an `unknown key` error in a preset (D-030). M8.4 adds `system` to domain rules the same way (a `DomainRule`).
- `None` means "not set"; `"none"` means "explicitly no role". YAML `role: null` and an empty value are "not set" (as an empty `color`, D-041).
- Validation: a `field_validator("role", mode="before")` with the D-041 wording. Anything that is not one of `ROLES` (including another case, a number, a list):
  `config <path>: kinds[2].role: invalid role 'hubb' (core, connector, descriptive, technical or none); fix the file`
  (`in_words(ROLES)`; in a preset `preset <name or path>: kinds[2].role: …`). Exit 1, as every config error.
- **Inheritance by key.** In `merge_config`, before validation, a new private `_inherited_roles(preset, file_config)` (one responsibility: a file kind rule takes its preset kind's role by key): when both the preset and the file have a `kinds` list of mappings, each file mapping whose `key` equals a preset kind's `key` and whose `role` is absent or null gets the preset kind's `role` (when it has one). Nothing else is inherited (label, colour and match stay "lists replace", unchanged). A preset kind absent from the file's list stays dropped, as today. Any other shape is passed through for validation to report. `--preset` / `--preset-file` go through the same path (the preset dict reaches `merge_config` as today).
- The config docstring's example gains `role: core` on the hub rule.

### 2. Roles in the payload

- `UniverseKind` gains `role: Role = "none"`, its **last** key: `{key, label, color, role}`. Configured kinds take `rule.role or "none"`.
- `classify.BuiltinKind` gains `role: Role = "none"`; `universe.TYPE_KINDS` source, seed and snapshot are `technical`; `OTHER` stays `none`.
- `_kinds` keeps its order (configured kinds in config order, then built-ins): the payload order does not change, so a page without roles differs only by the new key (brief § 5 criterion 3). Ordering by role is the page's job (§ 4).
- `DetailKind` is unchanged in M8.1: nothing in the detail uses a role before M8.5, which adds it there with the skeleton (one payload change where it is used).
- Payload of a project with no preset and no `role` key: every configured kind `"role":"none"`, built-in `source` / `seed` / `snapshot` `"role":"technical"`, `other` `"role":"none"`; nothing else changes.

Done-when 1 asks for no "Other" table on the large project, and the brief puts `vw_*` views in its vault folder. For `dim`, `fact`, `stg`, `view` (data_vault) and `stg` (star_schema, same value): each reaches **3:1 on `#f5f6f8`** (D-042, so no outline is needed) and takes an AA ink through `CONTRAST.textOn` (D-037, automatic); each is **at least 12 CIEDE2000** from every other kind colour of both presets and from the built-in kind colours (`#94a3b8`, `#c62a36`, `#64748b`, `#777777`), and at least 8 from `PALETTE`, the trajectory colours (`#6d28d9`, `#c2410c`) and the example's domain colours (M5.7 measured the seed the same way). Check with `tests/colours.py ciede2000`. The technical `stg` colour should read quiet (it marks the plumbing); existing colours are not changed (pairs like hub / ref hub are close on purpose).

#### 3.5 Default `layers` of both presets

Rules use folder globs on `path:` (fnmatch's `*` crosses `/`) and a few name globs. A project's own `layers` replace them (lists replace, as today); `layers: []` in `dbt-erd.yml` restores the folder default (one layer per first folder), the documented way back for a project that preferred it.

`data_vault`:

```yaml
layers:
  - {key: sources, label: Sources, match: ["type:source"]}
  - key: staging
    label: Staging
    match: ["stg_*", "type:seed", "type:snapshot", "path:models/raw*,!path:models/raw*vault*",
            "path:models/stg*", "path:models/staging*", "path:models/base*", "path:models/bronze*"]
  - key: vault
    label: Raw vault
    match: ["path:models/int*", "path:models/vault*", "path:models/raw*vault*", "path:models/ref*",
            "path:models/silver*", "*_hub", "*_link", "*_nhlink", "*_sal", "*_sat", "*_nhsat", "*_masat",
            "*_effsat", "*_refhub", "*_refsat", "*_pit", "*_bridge"]
  - {key: products, label: Data products, match: ["dim_*", "fct_*", "path:models/dp*", "path:models/mart*", "path:models/product*", "path:models/gold*"]}
  - {key: reports, label: Reports, match: ["path:models/report*", "path:models/expo*"]}
```

`star_schema`: the same `sources`, `staging` (without the `raw*vault*` negation, which is Data Vault's) and `reports`; `intermediate` "Intermediate" (`path:models/int*`, `vault*`, `ref*`, `silver*`); `marts` "Marts" (`fct_*`, `fact_*`, `dim_*`, `bridge_*`, `brg_*`, `path:models/mart*`, `dp*`, `product*`, `gold*`).

Choices:

- `stg_*` by name sits in Staging, before the folder rules, so Openlane's stage models inside `int_dwh/` land in Staging (brief § 5).
- **Seeds and snapshots go to Staging** (as the example's Bronze, D-047): loaded or captured as is, before the model. Without it they would be "Other".
- `raw*` folders are staging, except `raw*vault*` (`raw_vault/` is the usual Data Vault folder name): the one place a preset uses negation, which is why negation is built in this phase (§ 5).
- The vault layer also matches the Data Vault kind globs, so hubs in a folder the preset cannot guess (`dwh/`) still land in Raw vault. Rules are tried in flow order and the first match wins, so a hub in `models/int_x/` is Raw vault by folder, a `dim_x` in `models/int_x/` too (accepted: the folder says so).
- Layer labels are English, as the presets' kind labels (config labels are data, D-039).

**One implementation of the folder vocabulary (invariant 2).** `FLOW_PREFIXES` stays the one list of "which folder-name prefix is which step of the flow" and keeps ordering default layers when there are no rules; its values are **not** changed (adding `bronze` / `silver` / `gold` ranks would change the page of every project without rules, which the brief forbids). The presets are config data built on that vocabulary, and a unit test ties them: for each built-in preset and each prefix of `FLOW_PREFIXES` that is not a resource type (`source`, `seed`, `snapshot` are covered by `type:`), a model named `x` in `models/<prefix>/` and in `models/<prefix>_y/` gets a layer from a folder rule, and the layers found follow the prefixes' `flow_rank` order (never a lower-ranked prefix in a later layer). A prefix added to `FLOW_PREFIXES` without a preset rule fails that test. Medallion folders (`bronze*`, `silver*`, `gold*`) are covered by the presets only.

### 4. The page (`render/assets/universe.js`, `common.js`)

- **Tiers.** One map `TIER` (role → `large` | `medium` | `small`): core large; connector and none medium; descriptive and technical small. One map `ROLE_ORDER` (core, connector, descriptive, technical, none) for lists. `KIND[k].role` read from the payload, never guessed from names (brief § 4).
- **Star size (D-058).** `starR(n) = min(cap, base + slope·√DEG)`, degree as today (relations + lineage), per tier: large `6 + 1.6·√d ≤ 16`; medium `3 + 1.6·√d ≤ 14` (today's rule, so a page without roles keeps its stars but for the built-in technical kinds); small `2 + 0.8·√d ≤ 6`. Degree still varies the size inside a tier (proposal; the ui-designer finalises the numbers, the shape stays). Precomputed once per node (`R[]`), since `box`, `drawStar` and `drawNames` call it in loops. `drawNames`' `rMax` takes the largest cap.
- **Name priority.** `orderLabels` sorts by tier first (large, medium, small), then by today's `labelScore`. Trajectory and hovered names keep their precedence. A page without roles changes only in that sources, seeds and snapshots compete after the models.
- **Names at Fit.** From afar (`k < 0.6`, the threshold already used for routes and band separators) and when the drawn tables include at least one core table, the ordinary names offered are, per constellation (domain, or layer in layer mode), the `FIT_NAMES` core tables with the most relations (`DATA.relations` only; ties by `DEG`, then name, then id). Proposal `FIT_NAMES = 3`; the ui-designer sets it. The existing collision rules still apply. Trajectory and hovered names are always offered. With no core table drawn, behaviour is unchanged. This takes the roadmap "Later" item on overview labels.
- **Types list.** The universe Types rows are sorted by `ROLE_ORDER`, stably (so payload order inside a role, as today). The detail Types list keeps its order until M8.5 gives the detail its roles.
- **Glossary rename.** The trajectory's `roleOf` / `role` (start, up, down) become `sideOf` / `side` in `universe.js` (and `flow.js` where the word appears), so "role" has one meaning (D-027). ARIA `role` attributes are untouched. No behaviour change.
- **Test hook.** The universe handle gains `drawnNames()` (ids of the names drawn in the last frame), for the browser tests only, as `geometry()`.
- Layout shapes change where star sizes change (`box` reserves the star): the D-040 fill acceptance is re-measured on acme and on the 1,500-table payload (unchanged there: its kinds have no role).

### 5. Selector negation (`domain/selectors.py`) — built

Small and in one place, and the `data_vault` preset needs it (§ 3.5). In `_part_matches`: a part whose stripped text starts with `!` matches when the rest does not (`not _part_matches(table, rest)`). The rest is a whole part, field included (`!path:models/raw*vault*`, `!vw_*`, `!tag:legacy`). A bare `!` (nothing after it, spaces ignored) raises `SelectorError("empty negation in '<selector part>' (write the selector after '!', such as '!vw_*')")`, which `cli._views` turns into the usual one line naming the config. `!!x` is `x` (recursion; not documented). A selector made only of negations matches every table that none of them excludes. It applies wherever selectors do (`select`, `exclude`, `universe.select` / `exclude`, every rule's `match`); `group_by: tag:<glob>` is not a selector and does not take it. Like an unknown field today, the error shows when the selector is evaluated. Docs: a selector that **starts** with `!` must be quoted in YAML (`"!vw_*"`), else YAML reads a tag and the file fails to load; `path:models/int_dwh/*,!vw_*` needs no quotes.

### 8. Layers, responsibilities, errors

- `domain/`: `config` (Role, ROLES, KindRule, PresetKindRule, `_inherited_roles`), `classify.BuiltinKind.role`, `universe` (`TYPE_KINDS` roles, `_kinds` sets `role`), `payload.UniverseKind.role`, `selectors` (negation). Pure, no I/O.
- `storage/`, `cli.py`: no code change (presets are read as today; the selector error path exists).
- `render/assets/universe.js` (+ `flow.js` rename only): tiers, sizes, name priority, Fit names, Types order, test hook.
- Errors: an invalid role, a bare `!`: one line, exit 1, nothing written (the page is written after the views are built).
- Reused: `selectors.matches` (one selector implementation), `first_rule`, `merge_config`, `errors.in_words`, `validation_message`, `CONTRAST`, `tests/colours.py`, `conftest` builders, `reference_pages.py`.
- Responsibility map, new or changed rows: "Role of a kind; a file kind rule inherits its preset kind's role by key" → `domain/config.KindRule`, `Role`, `ROLES`, `merge_config` (`_inherited_roles`); "Match a table against selectors" gains "(a part starting with `!` negates)"; "Star radius and name priority by role (page)" → `universe.js starR`, `TIER`, `orderLabels`, `FIT_NAMES`; "Order of the Types list by role (page)" → `universe.js ROLE_ORDER`; "Build the large Data Vault test project (tests)" → `tests/large_project.large_manifest`, `LARGE_CONFIG`, `SPECIAL`, `write_large_project`; browser `large_page`.
- Glossary: **role** (`role`, `Role`, `KindRule.role`, `UniverseKind.role`): how much a kind matters in the structure: `core`, `connector`, `descriptive`, `technical`, or none. Not "weight", "class", "category". French UI wording, for when a later phase shows it: rôle; principal, liaison, descriptif, technique, aucun. The trajectory's start / upstream / downstream is its **side** (`sideOf`), not a role.

### 9. Format compatibility

- `dbt-erd.yml`: one optional key (`role` on kind rules). A file without it is valid and gives the same config, except where it lists a kind key the preset gives a role to (it inherits it). Preset files: `role` allowed on kind rules only.
- Pages of projects using a built-in preset change (new kinds, roles, layers by rule instead of by folder when they set no `layers`). Foreseen by the brief; `layers: []` gives the folder default back.
- `dbt-erd-layout.json` and the localStorage keys: unchanged. Layer keys of preset pages change (`sources`, `staging`, `vault`…), so a stored layer-mode arrangement (`layers:*` scopes, keyed by layer key) of such a page no longer finds its layers: its layer pins are ignored and the computed placement is used (no error, nothing lost from the file). Domain-mode arrangements are unaffected.

## Rejected options

- **`role` on `Rule` for every rule type**: a meaningless key on domains and layers, accepted silently in presets.
- **Inheriting the whole preset kind (label, colour, match) by key**: changes the meaning of every existing `kinds` list ("lists replace"); only the role is new, so only the role is inherited.
- **Payload `role: null` for no role**: the page would need `?? 'none'` everywhere; one vocabulary in config, payload and page.
- **Sorting `kinds` by role in Python**: changes the payload order of every page without roles (brief criterion 3) and `labelScore`'s kind rank.
- **Role in `DetailKind` now**: unused before M8.5.
- **Generating the presets' layers from `FLOW_PREFIXES` in code**, or a `layers: flow` key: presets stop being plain, copyable config files (D-015, D-030), and the labels ("Raw vault", "Marts") are the convention's, not the tool's.
- **Adding `bronze` / `silver` / `gold` ranks to `FLOW_PREFIXES`**: changes the pages of projects without rules (brief § 5).
- **Same size inside a role** (fixed radius per role): loses the "pivot tables stand out" that users read today; the tiers already separate roles.
- **One order for both names and the Types list**: with the list order (technical before none), source names would win over model names on every page without roles.
- **Deferring negation**: the `data_vault` staging rule would need a list of every `raw_*` spelling except the vault's; the change is one branch in one function.
- **A committed large manifest**: several MB, and a second source of truth next to its generator (D-033's reasoning).
- **Folding the large project into `big_manifest`**: two responsibilities in one builder; the parser test would depend on Data Vault naming.

## UI design

Task: find where a table lives in a 1,400-table estate. At Fit the user must see which tables are the business entities (hubs, facts, dimensions) and read a few real names per domain; the plumbing (staging, sources, satellites) must recede. Decision served: which domain or layer to zoom into. No new control, no new string, no new interaction (click, hover, drag, search, trajectory, filters unchanged). Layout at 360 and 1280 px is unchanged: only star radii, which names are drawn, and the order of the Types rows change.

### Star radius (finalised, D-058 numbers kept)

`starR = min(cap, base + slope * sqrt(DEG))`, DEG = relations + lineage as today.

| Tier | Roles | base | slope | cap | Radius at DEG 1 / 4 / 16 / 36 |
|---|---|---|---|---|---|
| large | core | 6 | 1.6 | 16 | 7.6 / 9.2 / 12.4 / 15.6 |
| medium | connector, none | 3 | 1.6 | 14 | 4.6 / 6.2 / 9.4 / 12.6 |
| small | descriptive, technical | 2 | 0.8 | 6 | 2.8 / 3.6 / 5.2 / 6 (cap from DEG 25) |

Degree still varies the size inside a tier, so a pivot hub stands out among hubs. At equal degree the tiers are ordered (core > connector > descriptive); across tiers they may overlap (a link of degree 60 is 14 px, a hub of degree 1 is 7.6 px): degree is information, accepted. The smallest star (2.8 px) is above the 2.5 px drawing floor, so the cap and floor logic of `drawNames` / `drawStar` is unchanged; `rMax` in `drawNames` = 16 (the largest cap). Compute once per node.

### Name priority and names at Fit

- `orderLabels`: sort by tier (large, medium, small), then by `labelScore` as today. The `strong` (bold) test, `labelScore >= 10`, is unchanged. Trajectory then hovered names first, as today.
- `FIT_NAMES = 3`. Rule as the note § 4: at k < 0.6 and with at least one core table drawn, per constellation the 3 core tables with most relations, ties by DEG, name, id; the collision, cover-a-star and in-circle rules still apply, so fewer than 3 may show. A constellation with no core table (in layer mode: Sources, Staging) offers no ordinary name from afar: never an arbitrary table. At k >= 0.6 every table competes by tier, as before.
- Why 3: five domains give at most 15 names at Fit on the large project, about one per 90 tables, readable at 11 px next to 2.8 to 16 px stars; 5 would crowd the small discs of the 89- and 96-table domains. Acme (about 8 core Hub / Dimension / Fact names per domain at most) gets 3 per domain.

### Types list

Rows sorted stably by `ROLE_ORDER` (core, connector, descriptive, technical, none). No role heading, no role text or badge: the order and the colours carry it, and a heading per role adds rows to a panel that already scrolls at 360 px. Acme_retail reads: Hub, Dimension, Fact, Link, Satellite, Staging, Source, Seed, Snapshot (Other and View absent when 0 or unused; payload order hub...dim, fact within core). A page without roles: configured kinds first in config order, then Source, Seed, Snapshot (technical), then Other (none): the only change is that Other, which was last anyway, stays last, and sources move before it if they were after. Detail Types list unchanged.
