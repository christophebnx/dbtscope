# M5.10 — One zoom: d3.zoom on the drawing area of every view (design note)

Status: DONE (built, tested and reviewed on 2026-11-05). ACCEPTED by the user on 2026-11-05, with D-045 — D-045 supersedes the library-list clauses of D-014, D-021 and D-034 (svg-pan-zoom leaves the page, the offline page and the shipped licences). The behaviour itself (wheel anywhere, pinch) is the user's own request of 2026-11-05. User answers: svg-pan-zoom removed from the CDN and offline pages and from the shipped licences; the detail wheel step becomes d3's (~1.15×) and its maximum zoom 12×, as in the universe. The user uses Safari on macOS: Safari's trackpad pinch (`gesture*` events) is handled by the one shared zoom helper, in all three views (§ Safari trackpad pinch).

## Context

User report of 2026-11-05: in the **Detail** view the mouse wheel zooms only when the pointer is over a table, not anywhere in the drawing area; the universe zooms anywhere. The user is on macOS (Safari, or Chrome with a trackpad). The user also wants two-finger pinch zoom on a tablet in every view.

Current code:

- `common.js panZoom(box, svg, isCurrent)` mounts **svg-pan-zoom 3.6.1** on the Graphviz `<svg>` (listeners on the svg itself), with `panZoomFit` and `panZoomDestroy`; `detail.js` and `flow.js` use them, and `svgImage` / `pngImage` read svg-pan-zoom's `g.svg-pan-zoom_viewport` and strip its classes and controls.
- svg-pan-zoom listens on the `<svg>`: in some engines the empty parts of an SVG are not a hit target for wheel events, so only painted shapes (the tables) receive them. Headless Chromium does not reproduce it (wheel over the empty svg zooms there), which points to an engine difference rather than a logic bug.
- svg-pan-zoom has no touch support without hammer.js; the universe uses **d3.zoom** (d3 7.9.0, already vendored and loaded), which handles wheel, ctrl+wheel (trackpad pinch in Chrome, Edge, Firefox), drag and two-finger touch pinch.
- `docs/ui-spec.md` already promises "Wheel / pinch zoom, drag to pan" for the flow view.

## Chosen design

Replace svg-pan-zoom by d3.zoom in the detail and flow views, attached to the **drawing box** (`#d-graph`, `#f-graph`: `position:absolute; inset:0` inside `.canvas-box`), not to the svg. An HTML block is a hit target over its whole area in every engine, so wheel, drag and pinch work anywhere in the area, over a table or not. Then remove svg-pan-zoom from the page entirely.

No `domain/` change; payloads byte-identical; layout file and localStorage format unchanged (pinned positions stay in Graphviz points).

### `render/assets/common.js` (one responsibility, replaces `panZoom` / `panZoomFit` / `panZoomDestroy`)

- `zoomOn(sel, zoom) -> sel`: the one way to attach a d3 zoom, used by `graphZoom` (detail, flow) and by `universe.js` (its canvas): `sel.call(zoom).on('dblclick.zoom', null)`, plus Safari's trackpad pinch (§ Safari trackpad pinch).
- `ZOOM_EXTENT = [0.01, 12]`: the one scale range of the page. `universe.js` uses it instead of its literal (same values: no universe behaviour change), and the Graphviz views use it too, so wheel steps and limits feel the same in all three views (d3's default wheel delta everywhere; svg-pan-zoom's `zoomScaleSensitivity: 0.3` disappears).
- `graphZoom(box, svg, isCurrent, onZoom) -> Promise<zv | null>` (replaces `panZoom`):
  1. Reads the drawing size `w`, `h` (points) from the Graphviz `viewBox` (or `width` / `height`), removes the `viewBox`, sets `width` / `height` to `100%`, and moves the svg's children into one bare `<g>` (the **zoom layer**, `zv.layer`). One svg unit is then one CSS pixel at scale 1, so the zoom scale is the real scale (the flow's `realZoom` becomes `k`).
  2. `box.replaceChildren(svg)`, then waits (`requestAnimationFrame`, as today) until `box.clientWidth`, `box.clientHeight` and the layer's `getBBox()` are non-zero; resolves `null` as soon as `isCurrent()` is false.
  3. Builds `d3.zoom().scaleExtent([min(ZOOM_EXTENT[0], fit scale), ZOOM_EXTENT[1]]).clickDistance(3).on('zoom', ev => { layer.setAttribute('transform', ev.transform); onZoom && onZoom(ev.transform); })`, attaches it to `d3.select(box)` through `zoomOn` (no `dblclick.zoom`: double-click keeps its meaning, focus in the detail; Safari gestures), and fits.
  4. Returns the handle `zv = { layer, fit(), get() -> {x, y, k}, set({x, y, k}), centre(rect, k), destroy() }` (review: `size` and `panBy` dropped, unused):
     - `fit()`: contain and centre, no padding (as svg-pan-zoom's `fit` + `center`): `k = min(W / w, H / h)`, `x = (W - w k) / 2`, `y = (H - h k) / 2`; does nothing while the box has no size (hidden tab).
     - `get` / `set`: the current transform, set through `zoom.transform` (synchronous: no animation-frame wait as with svg-pan-zoom).
     - `centre(rect, k)`: puts the centre of a screen rectangle (a node's `getBoundingClientRect()`) at the centre of the box, at scale `k` (current scale when omitted), through `t.invert` of the box-relative point.
     - `destroy()`: `d3.select(box).on('.zoom .gesture', null)` (the zoom and `zoomOn`'s gesture listeners); safe on any state; the caller sets its `zv` to `null`.
- `svgImage(box, zv, scale)`, `svgFile(box, zv)`, `pngImage(box, zv, EXPORT)`: same contract, `zv` replaces `pz`. The visible area is computed from `zv.layer.getScreenCTM().inverse()` and the box rectangle (the svg fills the box). In the clone, the layer's `transform` is removed (the `viewBox` frames the visible area, as today); the svg-pan-zoom class stripping and `#svg-pan-zoom-controls` removal go. Exports still equal the screen.
- `page.css`: `touch-action:none` on `#d-graph`, `#f-graph` and the universe canvas (`#u-stage canvas`), so a pinch zooms the drawing, never the page (iPad Safari). Not a look property: not in `INLINE`.

### Safari trackpad pinch (user answer of 2026-11-05)

Chromium, Edge and Firefox report a trackpad pinch as `wheel` events with `ctrlKey`, which d3.zoom already reads. Safari on macOS does not: it fires its own `gesturestart` / `gesturechange` / `gestureend` events (`GestureEvent`: `scale`, relative to the start of the gesture, and `clientX` / `clientY`), and, if they are not cancelled, zooms the whole page. `zoomOn` listens to them on the drawing area (namespace `.gesture`; `destroy()` removes `.zoom .gesture`):

- every one is cancelled (`preventDefault`): the page never zooms;
- `gesturestart` records `last = event.scale` (1);
- `gesturechange` calls `zoom.scaleBy(sel, event.scale / last, d3.pointer(event, box))` and sets `last = event.scale`: the zoom changes by the ratio between two events, around the pointer, through the d3 zoom behaviour, so the transform, the scale extent and the `zoom` listeners (`onZoom`, the universe's redraw) stay those of d3;
- `gestureend` resets `last`.
- In the universe, d3.drag is mouse-only (`touchable(false)`, review): browsers deliver the two fingers of a pinch as two `touchstart` events, and a touch drag that took the first finger (on a table or a domain name) stops its events, so the zoom could never pinch; a finger cannot be handed over from d3.drag to d3.zoom. On touch a one-finger drag therefore pans, as in the detail, and a pinch zooms wherever it starts.
- iPad Safari fires gesture events alongside the touch events of a two-finger pinch, which d3 already zooms: `zoomOn` counts the fingers down (`touchstart` / `touchmove` / `touchend` in the capture phase, so the universe's d3.drag or the d3.zoom, which stop propagation, cannot hide a touch from it; `touchcancel` resets the count) and, while any is down, a `gesturechange` is only cancelled, so a touch pinch is never applied twice.

The handler reads only `scale`, `clientX` and `clientY`, so the browser tests (Chromium has no `GestureEvent`) dispatch plain `Event`s carrying those fields. Safari itself is not run here; to confirm on the user's Mac.

### `render/assets/detail.js`

- `pz` becomes `zv`; `refit = () => zv && zv.fit()` (Fit, window resize and panel toggle refit, as today).
- `render(keepView)`: `view = keepView && zv ? zv.get() : null`; `zv.destroy()`; after mount `if (view) zv.set(view)` (same semantics as `pz.zoom` + `pz.pan`).
- Node drag: unchanged. `startDrag` still stops propagation of `mousedown` on a table, so d3.zoom (listening on the box) never sees it and does not pan; the screen-to-graph conversion uses `g.parentNode.getScreenCTM()`, which now includes the zoom layer's transform: no change. Saved pinned positions stay in Graphviz points (`LAYOUT.set('detail', viewKey(), …)`, format unchanged). On touch a table drag pans the view (mouse-only drag, as before). Under `pointer: coarse` the hint is a touch one ("Pinch: zoom · drag: pan · tap a table: highlight its links" / "Pincement : zoom · glisser : déplacer la vue · toucher une table : surligner ses liens"), without "drag a table to move it" (review).
- `svg.addEventListener('click', reset)`: unchanged; a pan no longer ends with a reset, since d3.zoom swallows the click that ends a drag beyond 3 px.
- Hint strings (en / fr): "Wheel or pinch: zoom · …" / "Molette ou pincement : zoom · …" (ui-designer confirms the wording).

### `render/assets/flow.js`

- `pz` becomes `zv`; mount with `onZoom = hideTip` (replaces `setOnPan` / `setOnZoom`).
- `initialView`: after the fit, `if (zv.get().k < FLOW_MIN_SCALE) zv.centre(startNode(svg).getBoundingClientRect(), FLOW_MIN_SCALE)`, then `done()` — synchronous, the two `requestAnimationFrame` waits go (D-036 rule unchanged).
- `centreOn(g)` → `zv.centre(g.getBoundingClientRect())` (keyboard focus on an off-screen table).
- The `pointerdown` / `down` guard ("a pan that ends on a table is not a click") goes: `clickDistance(3)` in `graphZoom` owns it now (one implementation).
- Resize keeps the user's zoom and pan (D-036): with d3 the transform is relative to the box's top-left corner, so nothing is needed; the `resize` listener, the handle's `shown` and boot.js's `flow.shown()` call are removed.

### `render/page.py`, `vendor/`

- Remove the svg-pan-zoom `Library` from `LIBRARIES`; `git rm` `vendor/svg-pan-zoom.min.js` and `vendor/LICENSE-svg-pan-zoom.txt` (the tool never deletes files); regenerate `vendor/README.md` with `tools/vendor_libraries.py` (no download needed for the README if the tool supports it, else a run with network; `--check` must pass).
- The default page loses one `<script src>`; the offline page loses the inlined library and its banner.

### Responsibility map (`docs/architecture.md`)

- "Mount, fit and unmount a Graphviz SVG with pan and zoom (page)" → `common.js graphZoom` (handle `fit`, `get`, `set`, `centre`, `destroy`).
- New: "Scale range of every zoom of the page" → `common.js ZOOM_EXTENT`.
- New: "Attach a d3 zoom to a view's drawing area, Safari trackpad pinch included" → `common.js zoomOn`.
- `svgImage` row: "zoom layer transform removed" instead of "svg-pan-zoom markup removed".

Error handling: a failed render shows the existing error message; `destroy()` never throws (the old `try` around `pz.destroy()` goes).

## Rejected options

- **Keep svg-pan-zoom, add hammer.js for pinch and a wheel listener on the box**: a second library for what d3 already does, two zoom engines with different feel, and svg-pan-zoom's async rendering kept the flow's frame waits.
- **Keep svg-pan-zoom and only make the svg hit-testable** (a transparent background `rect`, `pointer-events: all`): may fix the wheel in Safari but not pinch; we cannot test Safari here.
- **d3.zoom on the `<svg>`** (as svg-pan-zoom): the very hit-testing question this change removes.
- **Keep svg-pan-zoom vendored but unused**: dead bytes in every offline page and a licence for code that does not run.
- **Universe settings changed to svg-pan-zoom's feel** (sensitivity 0.3, max 40): would change the view that works.
- (Withdrawn after the user's answer: "not handling Safari's macOS trackpad `gesture*` events". The user uses Safari on macOS, so they are handled, § Safari trackpad pinch.)

### D-045 (text for `docs/decisions.md`)

**D-045 — One zoom for every view: d3.zoom on the drawing area; svg-pan-zoom leaves the page.**
Asked by the user on 2026-11-05 (M5.10, design note `docs/architecture/2026-11-05-m5.10-one-zoom.md`): the detail view zoomed only with the pointer over a table on macOS, and pinch zoom on a tablet did not work in the Graphviz views. The detail and flow views zoom and pan with d3.zoom (d3 is already loaded for the universe), attached to the drawing box that fills the stage, not to the `<svg>`, so wheel, trackpad ctrl+wheel, two-finger touch pinch and drag work anywhere in the area. One helper, `common.js graphZoom`, mounts, fits and unmounts it for both views; one scale range, `ZOOM_EXTENT`, serves all three views. Double-click does not zoom; a drag of more than 3 px is not a click. Fit, the flow's initial view and its resize rule (D-036), the detail's refit on resize, node drag and saved positions, and exports equal to the screen are unchanged. svg-pan-zoom 3.6.1 is removed from `render/page.LIBRARIES`, from `vendor/` (script and BSD-2-Clause licence) and therefore from the default page's CDN scripts and the offline page. Supersedes the svg-pan-zoom part of the library lists of D-014 (now d3 and Viz.js from CDNs), D-021 (now d3 and Viz.js embedded) and D-034 (the licences shipped no longer include svg-pan-zoom's). Rejected: svg-pan-zoom with hammer.js (a second library for what d3 does), making the svg hit-testable only (no pinch), keeping the unused library vendored, handling Safari's non-standard trackpad gesture events.

## Test plan

Default suite (no browser):

- `tests/unit/test_page.py`: the CDN script list is d3 and Viz.js only; the offline page holds no `svg-pan-zoom` banner and the remaining banners keep their order; no `svgPanZoom` anywhere in the page.
- `tests/unit/test_vendor.py`: new `test_vendor_folder_holds_only_vendored_files` (the files of `vendor/` are exactly `vendored_files()` plus `README.md`), so a removed library cannot leave files behind; drop the BSD-2-Clause licence words if nothing else uses them.
- `uv run python tools/vendor_libraries.py --check` passes; `test_vendor_tool.py` unchanged.
- Payloads byte-identical: `tests/fixtures/m3-reference-pages/` expected pages regenerated once, payload blocks unchanged (`test_reference_pages.py`).

Browser suite (headless Chromium), new or adapted:

- **Wheel over empty space zooms** in the detail and the flow: wheel at a point of the box with no `g.node` under it (checked with `elementFromPoint`) changes `d3.zoomTransform(box).k`; the universe test of the same stays green.
- **Wheel when the svg receives no events**: with `svg.style.pointerEvents = 'none'` (a stand-in for engines that do not hit-test empty SVG), wheel over the box still zooms, in detail and flow. This is the regression guard of the user's report.
- **Wheel over a table zooms** (detail, flow), and the zoom is centred on the pointer (the point under it stays within 2 px).
- **Pinch**: a browser context with `has_touch=True`, CDP `Input.dispatchTouchEvent` (`touchStart` with two points, several `touchMove` steps spreading them, `touchEnd`) zooms in the universe (`universe.camera().k`), the detail and the flow (`d3.zoomTransform(box).k`); the page itself is not zoomed (`visualViewport.scale == 1`).
- **Drag on empty space pans** (x / y of the transform change, k unchanged) in detail and flow; a pan that ends on a flow table does not recentre the flow; a pan in the detail does not reset the highlight.
- **Node drag in the detail** still moves the table, saves its pinned position (`LAYOUT` entry in Graphviz points, same as before for the same screen drag at scale 1), redraws with neato and keeps the camera (`keepView`).
- **Fit** restores the contained, centred view after zoom and pan (detail, flow); detail refits on window resize; the flow keeps zoom and pan on resize.
- **Flow initial view**: `REAL_ZOOM` becomes `d3.zoomTransform(document.getElementById('f-graph')).k`; the existing 0.75-on-the-start tests at 360 px and 1280 px pass; a small flow opens fitted.
- **Safari gesture events**: synthetic `gesturestart` / `gesturechange` (scale 1.25, 1.6, 2) / `gestureend` events with `clientX` / `clientY` on `#d-graph`, `#f-graph` and `#u-canvas` are cancelled (`defaultPrevented`), double the scale and keep the point under the pointer within 1 px; a closing pinch (0.8, 0.5) brings the scale back; while two fingers are down (CDP `touchStart`), gesture events change nothing.
- **Keyboard**: focusing an off-screen flow table with Tab centres it (existing test).
- **Exports** (`test_export.py`): the group after the background `rect` is the bare zoom layer (no `transform`, no attributes), then `#graph0`; no `svg-pan-zoom` text; SVG and PNG equal the visible area after a zoom and a pan (existing cut tests); same in the flow.
- **Offline** (`test_offline.py`): every request blocked, the page draws the detail and the flow; `typeof svgPanZoom === 'undefined'`, d3 and Viz present.
- Full browser suite green, en / fr, 360 px.
