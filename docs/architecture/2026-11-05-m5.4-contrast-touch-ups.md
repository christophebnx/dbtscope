# M5.4 — Contrast and page touch-ups (design note)

Status: DONE (built, tested and reviewed on 2026-11-05). The user asked for this scope on 2026-11-05 (roadmap M5.4). Built-in colours, the payload and the layout format stay as they are. The visible changes are those the user listed: text colour on kind colours, darker greys where they fail AA, French spacing, locale numbers, and the detail panel cap. Decisions D-037 to D-039 are recorded in `docs/decisions.md`.

## Context

The request: make every text drawn on or in a colour reach WCAG AA, whatever colours a config chooses; cap the open detail panel at about 35vh on small screens; use French spacing before `:` `?` `!` and none in English; format counts for the page language everywhere; and close the two M5.3 review leftovers. Roadmap M5.4 lists these items; "Later" holds the same items plus the print stylesheet.

Current state (`src/dbtscope/render/assets/`):

- **White text on kind colours, in three places.**
  - Universe card header: `universe.js drawCard`, `ctx.fillStyle = '#fff'`.
  - Detail node header: `detail.js nodeDot`, `<font color="white">` on `k.color`.
  - Flow node header: `flow.js nodeDot`, the same `<font color="white">`.
  - Kind colours come from `domain/universe.TYPE_KINDS`, from the presets, from `Config.kinds` (any string, `DEFAULT_KIND_COLOR` `#777777`) and from `dbt-erd.yml`. Several fail 4.5:1, and the table below lists them.
- **Text drawn in a domain colour.** `universe.js paint` writes each domain name in `dd.color` on the page background `#f5f6f8`. 8 of the 12 `PALETTE` colours fail, `NO_DOMAIN_COLOR` gives 2.8:1, and acme's `#4da3ff` gives 2.4:1.
- **Greys.**
  - `--muted` / `C.muted` `#6b7280` gives 4.83:1 on white but 4.47:1 on `#f5f6f8`. It fails for the universe canvas captions, the dimmer table names and `#d-graph .msg` / `#f-graph .msg`.
  - The universe card column types are `#9aa3af` on white: 2.55:1.
  - In the detail, the types are `#888888` and the "+ N columns" row is `#999999`, both on the kind tint (`classify.background`, 88 % white). They give at most 3.5:1 and 2.85:1.
- **French spacing.**
  - The French strings write a plain space before `:` and `?` (`'Image créée : '`, `'… cet onglet ?'`).
  - Composed strings use `': '` in both languages: the trajectory live text, the per-domain counts and their tooltips, the owner title.
  - The English domain tooltip writes `owner : x` (`universe.js`, mousemove).
- **Numbers.** Only `trajectoryCounts` formats them, through its local `num`. `plural`, filter counts, the detail meta, the flow cap messages and the flow domain list print raw numbers.
- **M5.3 leftovers.**
  - The `pz.resize()` guard is written twice in `flow.js` (the window `resize` listener and `shown`).
  - The table description line of the tooltip is built twice: `<div style="margin-top:6px">` in the universe, `<div class="m" style="margin-top:6px">` (muted) in the flow.

## Chosen design

Only the page changes. `domain/`, `storage/`, `render/page.py` and the CLI stay as they are, and the payload JSON is byte-identical (§ 7).

### 1. Text on colour: one helper in `common.js`, the page picks the ink (D-037)

A new global, `CONTRAST`, declared in `common.js` after `esc` / `plural` as a closure object like `GRAPHVIZ`. It is pure (no DOM) and caches each result in a `Map` by its arguments, because the universe calls it for every card in every frame.

| Member | Owns |
|---|---|
| `CONTRAST.AA` | `4.5`, the one threshold. It is used for every text, large or not: bold names at 16 pt in the detail could pass at 3:1, but one threshold keeps one rule and one test. |
| `CONTRAST.ratio(a, b)` | The WCAG 2.x contrast ratio of two colours: `(L1 + 0.05) / (L2 + 0.05)` from the relative luminance (sRGB channels linearised: `c ≤ 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ^ 2.4`; `L = 0.2126 R + 0.7152 G + 0.0722 B`). It accepts `#rgb`, `#rrggbb` and `#rrggbbaa`; alpha is ignored, so the colour counts as opaque. Anything else gives `NaN`. |
| `CONTRAST.textOn(bg)` | The text colour for a fill: `'#ffffff'` when `ratio('#ffffff', bg) ≥ AA`, else `'#000000'`. An unparsable `bg` gives `'#ffffff'`, as today. |
| `CONTRAST.ink(color, bg)` | A colour used *as text* on a light `bg`. It returns `color` itself when `ratio(color, bg) ≥ AA`. Otherwise it returns `color` mixed toward black in sRGB, by the smallest step `t = j / 32` that reaches AA, as `#rrggbb`. It returns `#000000` if none does, and `color` unchanged if `color` is unparsable. The hue stays, so the name still matches its halo and its legend dot. |

**Why white or pure black, and not white or `#1f2933`.** Over every possible background, the better of white and `#000000` is never below 4.58:1. The crossover is at L = 0.179. The better of white and `#1f2933` (L = 0.021) falls to 3.84:1 for mid tones (L ≈ 0.22, for example `#c9a227`, `#5b7fa6` or `#777777`). Only pure black meets AA for *any* colour a config can hold. On a coloured header, black and `#1f2933` look almost the same.

**Why white first.** White is kept whenever it reaches 4.5:1, even where black would contrast more. Every built-in colour that passes today (hub, dimension, snapshot, same-as link, DV bridge) therefore looks exactly as before, and only failing colours change.

**Call sites:**

| Where | Before | After |
|---|---|---|
| `universe.js drawCard`, card name | `'#fff'` | `CONTRAST.textOn(col)` |
| `detail.js nodeDot`, header `<font color>` | `white` | `${esc(CONTRAST.textOn(k.color))}` |
| `flow.js nodeDot`, header `<font color>` | `white` | `${esc(CONTRAST.textOn(KIND[n.kind].color))}` |
| `universe.js paint`, domain name | `dd.color` | `CONTRAST.ink(dd.color, THEME.bg)` |
| `detail.js nodeDot`, column type and "+ N columns" | `#888888`, `#999999` | `CONTRAST.ink(THEME.muted, k.bg)`: the theme grey, darkened only on the tints where it falls short (the darkest tint, from a black kind, has L = 0.745) |

The exported images follow automatically: the detail and flow SVG carry the `<font color>` from the DOT text, and the universe PNG is painted by the same `draw`.

### 2. Theme greys: one `THEME` in `common.js`, `--muted` darkened (D-037)

- `common.js` declares `const THEME = { bg: '#f5f6f8', fg: '#1f2933', muted: '#5f6774' }`. It is the JavaScript copy of the `page.css :root` variables `--bg`, `--fg` and `--muted`. A browser test checks that the two copies agree.
  - `universe.js C` takes `bg`, `text` and `muted` from it.
  - `flow.js nodeDot` writes its depth with `THEME.fg` and its layer with `THEME.muted`, instead of the literals `#1f2933` and `#6b7280`.
- `--muted` changes from `#6b7280` to `#5f6774`. It gives 5.71:1 on white and 5.28:1 on `#f5f6f8`, and stays above 4.5:1 under the universe name backdrop (`rgba(245,246,248,.85)` over a 15 % halo). That leaves margin for the canvas, and the grey still reads as secondary next to `--fg` (16:1).
- The universe card column types change from `#9aa3af` to `C.muted`, the same as the non-key column names, which keep their own colour.

**Checked and left unchanged** (ratios on the actual background):

| Spot | Ratio |
|---|---|
| `--accent` `#2f6fb5` as text on white (tabs, `.tip .a`, `.tj-back`, `.focus-info`, links on hover) | 5.2 |
| white on `--accent` (`button.on`) | 5.2 |
| `--accent` on `#f5f6f8` | 4.8 |
| `--fg` on white / `#f5f6f8` | 15 / 14 |
| trajectory violet `#6d28d9` and orange `#c2410c` | 7.9 / 4.9 on `--bg` |

The trajectory colours are lines and borders, never text; graphics need 3:1. Kind and domain dots, halos, composition bars, domain bands and edges are graphics too, and each is always named in text next to it or in the tooltip. Tables dimmed by the trajectory mode (alpha 0.2 / 0.45) and disabled buttons are de-emphasised on purpose and exempt (WCAG 1.4.3, inactive components and incidental text). This is unchanged.

### 4. French spacing (D-039)

- **Rule.** In French page strings, a no-break space U+00A0 comes before `:`, and a narrow no-break space U+202F before `?`, `!` and `;`, following the Imprimerie nationale rule. English strings have no space before them.
  - In the source, these characters are written as the escapes ` ` / ` `, never as invisible literal characters: `'Ciblé : '`, `'… de cet onglet ?'`.
- **Composed strings.** `STRINGS` gains `colon`: `': '` in English, `' : '` in French. Every place that joins a label and a value uses `${a}${L.colon}${b}`:
  - `universe.js`: the trajectory live text (`trajOf name: summary`), the per-domain rows and the counts title of the trajectory bar, the domain checkbox title (`owner: x`), and the domain tooltip. The English tooltip becomes "owner: x", fixing the M5.2 finding.
  - `flow.js`: the live text (`flowOf name: counts`) and the `#f-dom-sum` title (`label: count`).
- **Literal strings to change** (fr):
  - `STRINGS`: `resetAsk`, `imageSaved`, `error`.
  - universe `T`: `openDetail`, `zoomIn`, `frame`, `clickTraj`, `hint`.
  - detail `T`: `focused`, `foreign`, `hint`.
  - flow `T`: `clickFlow`, `capDepth`.
  - The developer greps the four scripts for `' :'`, `' ?'`, `' !'`, `' ;'` and `': '` and fixes every hit that is page text.
- Names, descriptions and config labels are data, and stay as written.

### 5. Numbers formatted for the page language (D-039)

- `common.js` declares `const num = n => n.toLocaleString(PAGE.lang);` before `plural`. It gives `1,234` in English, and `1 234` in French with the U+202F group separator that Chromium's ICU writes.
- `trajectoryCounts` drops its local `num` and uses this one.
- **Every number shown as text goes through it:**
  - `plural` returns `` `${num(n)} ${forms[…]}` ``; the singular / plural choice still reads the raw `n`.
  - `filterRow` writes `num(count)` in its `<small>`.
  - The detail meta: `${num(ids.size)} / ${plural(…)}`.
  - The universe card's `+ ${num(b.more)}`; the card width computed by `box` does not depend on that text.
  - `trajectoryLevels`: `L.tipUp(num(d))` / `L.tipDown(num(d))`.
  - The flow:
    - `capDepth` / `capCut`: `num(shown)`, `num(FLOW_MAX)`; `total` already goes through `plural`.
    - The domain list `<small>`: `num(r.c)`.
    - The `#f-dom-sum` title.
    - `depthLabel`: `−${num(d)}`, `+${num(d)}`. Viz.js reads UTF-8, as table names already require.
- Dates, ids and sizes in pixels are not shown, so nothing else is concerned.

### 6. M5.3 review leftovers

- **`flow.js`, one resize helper:** `const resize = () => { if (isOpen && pz && box.clientWidth) pz.resize(); };`.
  - `window.addEventListener('resize', resize)` uses it, and so does the handle (`shown: resize`).
  - `boot.js` calls `shown` only while the flow is open, so the added `isOpen` check changes nothing.
- **One description line for both tooltips:**
  - `common.js` declares `const tableDesc = n => (n.desc ? `<div class="desc">${esc(n.desc)}</div>` : '');` next to `tableTip`, with the same comment block.
  - `universe.js` and `flow.js` call it in place of their own markup.
  - `page.css` gains `.tip .desc { margin-top:6px; color:var(--fg); }`.
  - The description is content, not meta, so it takes the universe look. The flow's description turns from muted to `--fg`. The inline `style` attributes go.

### 7. Payload and reference pages

- No change to `domain/`, `storage/`, `render/page.py` or `embedded_json`. Built-in colours are unchanged.
- In the final asset commit, `uv run python tests/reference_pages.py` is run once. `git diff --exit-code tests/fixtures/m3-reference-pages/payloads/` must be empty; only the page hashes and sizes in `expected.json` change. A payload change is a bug: stop.

### 8. Print stylesheet: not in scope

It is not trivial:

## Rejected options

- **Changing the built-in and preset colours to pass with white.** It changes the payload, the reference pages and colours existing users know, and it does nothing for colours users configure. The page-side ink covers every colour.
- **Darkening the header band** (drawing the kind colour darker under the name). The kind colour would no longer match the dots, legends and stars where it is used, and very light colours would need large shifts.
- **White or `#1f2933` as the dark ink.** It falls to 3.84:1 for mid-tone colours (§ 1); only pure black guarantees AA for any colour.
- **The higher-contrast ink always** (black as soon as it beats white). It turns colours that pass today with white to black for no accessibility gain. "White when it passes" changes only failing colours.
- **Choosing the ink in Python and adding it to the payload.** It is a payload change for a presentation choice, and the page already holds every colour.
- **3:1 for large or bold text.** It needs per-site size rules, and the universe card names (10 px) and flow names would still need 4.5. One threshold keeps it simple.
- **Normalising any CSS colour through a canvas `fillStyle`.** It does DOM work in `common.js`, and every colour the page receives is hex: `classify.background` and the universe halos (`color + '26'`) already require it.
- **A backdrop behind domain names instead of `ink`.** It adds a box to every domain label and hides routes. Darkening keeps the hue.
- **35vh for both panels.** The universe toolbar is a single row, so its panel does not hide the canvas the same way. The user asked about the detail tab.
- **U+202F before `:` as well.** The French rule is a full no-break space before the colon. Either character prevents a line break; the typographic rule was chosen.
- **`Intl.NumberFormat` with options.** `toLocaleString(PAGE.lang)` is what the trajectory already uses, and it gives the same output.
- **Print stylesheet now** (§ 8).
