# M5.3 — Flow view: the trajectory as a left-to-right lineage diagram (design note)

Status: DONE (built, tested and reviewed on 2026-11-04). The user asked for this feature on 2026-11-04 and gave its behaviour. This note adds it to `docs/roadmap.md` (M5.3). D-036 refines D-018 and D-021 and supersedes neither: the trajectory mode keeps its in-place highlight, and a separate, on-demand view is added next to it. Nothing changes in the payload, the layout file or the localStorage key, and no Python domain logic changes.

## Context

**Request.** From the trajectory bar, open a dedicated diagram of the current trajectory: same start, same direction, same depth. It is drawn left to right by Graphviz, with upstream on the left, the start emphasised and downstream on the right. Each table carries its depth. A click recentres the diagram on that table, and the user can go back to the universe without any change to it.

**Why.** In the trajectory mode (M1, D-018) tables stay where the universe layout put them, and that layout is not ordered by lineage. The arrows of a large chain cross in every direction. For example, `fct_orders` in `examples/acme_retail` has 22 upstream tables and 1 downstream table.

**Current code.**

- `universe.js`:
  - `trajectory(lineage, start, direction, depth)` is a pure page global.
  - `enterTrajectory` builds the trajectory edges inline (the `tedges` loop).
  - The bar is `#u-trajbar`, overlaid inside `#u-stage`.
  - The trajectory colours are in `C.up` / `C.down`. They are mirrored to `--traj-up` / `--traj-down` on `#u-stage`.
  - The strings for direction, depth, levels and counts are in the universe `T`.
  - `options(el, values, current)` fills a select from `T`.
  - The tooltip HTML is built inline in the `mousemove` handler.
- `detail.js`:
  - Graphviz rendering goes through its own `Viz` instance. The instance is recreated after an error, and `renderSeq` drops stale renders.
  - The svg-pan-zoom set-up waits until the SVG has a real size.
  - `dotStr` escapes DOT strings.
  - `svgImage(scale)` and `pngImage()` export the visible diagram, with `INLINE` styles. They depend on the closure variables `pz` and `box`.
- `boot.js`:
  - `EXPORT.save(view, ext, make, button)` saves the images.
  - `views` holds the tab views. Layout import relayouts every view in it.
- **Payload.** `universe.nodes[i]` has `id`, `name`, `domain`, `layer`, `kind`, `desc`, `cols`. `universe.lineage` holds sorted `[child, parent]` pairs. `universe.layers` is in flow order: configured order, or `flow_rank` order. `universe.domains` and `universe.kinds` carry the labels and colours.

## Chosen design

### 1. Where the flow lives: an overlay over the whole Universe tab

The flow view is a sub-view of the Universe tab. `#f-view` is the last child of `#tab-universe`, with `position:absolute; inset:0`, and it is hidden by default. It has its own toolbar and its own `.canvas-box` (`#f-graph`). While it is open, it covers the universe side panel and the stage, and both get the `inert` attribute: they cannot be focused or clicked, and screen readers skip them.

- **The universe state stays untouched, by construction.** Nothing in `startUniverse` runs on open or close. The covered stage keeps its size, so its `ResizeObserver` neither fits nor relayouts. Filters, camera, `traj`, `trajOpts` and the manual layout stay as they are. Closing removes `inert`, hides `#f-view` and puts the focus back on `#u-tj-flow`.
- **Tabs.** Switching to Detail and back keeps the flow open, because it belongs to the Universe tab's DOM. Reset layout, Export layout and Import layout keep acting on `current` (the universe or the detail). The flow is not in `boot.js views`, so an import relayouts the universe under the overlay and leaves the flow as it is.
- **Layout store.** The flow saves nothing. Graphviz lays it out from the trajectory alone, tables cannot be dragged, and nothing is written to `LAYOUT`, `dbt-erd-layout.json` or localStorage (D-013, invariant 9).
- **Small screens (D-035).** The overlay is exactly the tab's width. Its toolbar wraps like the others, and the SVG is 100 % of `#f-graph`, so there is no horizontal scroll at 360 px. The flow has no side panel: it has no filters to show (D-018: filters never cut the chain).
- **Export.** The toolbar has its own PNG / SVG group, outside `.canvas-box` (render/CLAUDE.md rule). It runs through the shared SVG export helpers (§ 6).

### 2. Script structure (`render/assets/`)

There is a new script, `flow.js`. It is inlined after `universe.js` and before `boot.js`, as a new `{{FLOW_JS}}` placeholder in `page.html` and a new entry in `render/page.py`.

```js
// flow.js
function flowRanks(members, edges, layerOf) { ... }        // pure page global (§ 4), tested directly
function startFlow(DATA, EXPORT, close) { ... return { open, close, shown, state, svgImage }; }
```

`boot.js`:

- Declares `let flow = null`.
- Defines `openFlow(id, direction, depth)`, which creates the flow on first use (`flow = startFlow(PAGE.universe, EXPORT, closeFlow)`) and calls `flow.open(...)`.
- Defines `closeFlow()`, which hides the overlay, removes `inert` and focuses `#u-tj-flow`.
- Passes `openFlow` to `startUniverse` as a new last parameter. This follows the render/CLAUDE.md rule: stateful services are built by boot and passed in.
- The browser tests reach the handle as the top-level `flow`.

**Moved to `common.js`.** These are page-wide and must not be duplicated (invariant 2, D-006). Each move removes the view's own copy.

render/CLAUDE.md, "a view never declares a global, except the pure, tested `trajectory`", becomes: "…except the pure, tested `flowRanks` (`flow.js`)". `trajectory` now lives in `common.js`.

### 3. Data: no payload change

Everything the flow needs is already in `PAGE.universe`:

- the lineage pairs;
- per table: `domain`, `layer`, `kind`, `name`, `desc`, `cols.length`;
- the layer order (the index in `layers`);
- domain and kind labels and colours.

The flow uses the universe payload, not the detail one. Every table in the universe scope has a lineage there, while the detail payload holds only the selected tables and no lineage.

- Kind colours are the universe colours: the header fill, as on universe cards. The body is white, so no detail `bg` tint is needed.
- `domain/`, `storage/`, `cli.py` and the payload models do not change.
- The M3 reference payloads (`tests/fixtures/m3-reference-pages/payloads/*.json`) stay byte-identical. Only `expected.json` (page hashes and sizes) is regenerated once, in the commit that changes the assets.
- The flow inherits M1's scope limit: a chain stops at tables excluded by `universe.select` / `exclude`.

### 4. Ranks: lineage first, layers as a floor (`flowRanks`)

Rejected first: dot's own ranking alone, and one `rank=same` per layer (see Rejected options). The column of each table is computed in the page and imposed on Graphviz.

```js
// members: table indices; edges: [[parent, child]] among members (data flows left to right);
// layerOf: index -> position of its layer in DATA.layers.
// -> { rank: Map(index -> column), back: Set of "parent,child" edges left out of the ranking (cycles) }
function flowRanks(members, edges, layerOf) { ... }
```

1. **Span per layer.** `span[L]` is 1 + the longest chain of edges whose two ends are both in layer `L`. A layer with no table in the flow gets a span of 0.
2. **Floor per layer.** `floor[L] = Σ span[l]` over the layers `l` before `L` in flow order.
3. **Rank.** In topological order (Kahn), `rank(n) = max(floor[layer(n)], max over parents p of rank(p) + 1)`.
4. **Cycles.** A malformed manifest can have cycles. Tables left over by Kahn are ranked over their already-ranked parents only. Their remaining in-edges go into `back` and are drawn with `constraint=false`. `flowRanks` never loops and never throws.

What the ranks guarantee:

- **Every edge goes left to right**, whatever the layers: `rank(child) ≥ rank(parent) + 1` for every edge not in `back`. So upstream tables sit left of the start and downstream tables right of it.
- **Layers become disjoint column bands** when the lineage follows the layer order: sources, then staging, vault, marts. A parent in an earlier layer ends at most at `floor[L] − 1`. A parent in the same layer stays within the band by the span.
- **Lineage wins on conflict.** When a lineage edge goes against the layer order (a staging model reading a mart), the child is pushed right of its parent and breaks its layer's band locally. The layer is a floor, never a ceiling.
- **Cost.** It is O(V + E), deterministic and pure.

**DOT.**

- Graph settings: `digraph { rankdir=LR; newrank=true; nodesep=0.25; ranksep=0.9; ... }`.
- Ranks: one `{rank=same; "id"; ...}` per column. `newrank=true` keeps the ranks global and stable.
- Edges: `parent -> child`, with the arrowhead at the child.
- **Depth vs. column.** The depth label is the BFS distance: the shortest path, as in the universe tooltip. The column is the longest path plus the layer floor. A level −1 table can therefore sit two columns left of the start, which says that it also feeds the start through a longer path. The label always reads "how many hops to the start", and the column always reads "where it sits in the flow".

### 5. Drawing (DOT built by `startFlow`)

**Node.** `shape=plain`, an HTML-like label with Arial (Viz.js metrics, as in the detail). All text goes through `esc`, and every id and string through `dotStr`.

```
| ▌ | <name>                    |   header: name in white, bold, on the kind colour
| ▌ | −2 · Staging              |   body: depth label and layer label, muted, on white
```

- **Left cell.** A narrow cell (about 6 pt) filled with the **domain colour**, spanning both rows. This is the domain band.
- **Depth label.** `−n` upstream and `+n` downstream, with the U+2212 minus sign. A table in both maps (a cycle) shows `−a / +b`.
- **The start.** It is emphasised with a thicker dark border (`border="3" color="#1f2933"`) and the word **start** in place of the depth. The ui-designer may refine this. It must stay recognisable without colour, as M1 requires.
- **Ids.** Node `id` is the dbt `unique_id` (invariant 11), as in the detail.
- **No native tooltips.** No Graphviz `tooltip` is set. The `<title>` elements Graphviz writes are removed after rendering, so the browser does not show the raw id.

**Edges.** Colour `TRAJ_COLORS.up` / `.down`, by the tag from `trajectoryEdges`. Upstream edges are dashed (`style=dashed`) and downstream edges solid: the same non-colour cue as the universe. `penwidth=1.4`, `arrowsize=0.8`.

**Domains: colour bands, not clusters.**

- Each table's domain is its left band.
- A **Domains** `<details>` in the toolbar lists the domains present, each with a colour disc, its label and its table count. It reuses the `#u-tj-list` pattern.
- The domain also appears in the tooltip.
- Clusters were rejected (§ Rejected options).

### 6. Behaviour and controls (`startFlow`)

**State.** `{ start, direction, depth, shown: { up, down }, capped, edges, ranks }`. It is initialised by `open(id, direction, depth)` from the universe trajectory: `traj.start` and `trajOpts`. The flow keeps its own direction and depth after that. Changing them in the flow never touches the universe selects (the universe state stays untouched).

**Toolbar `#f-bar`.** In DOM and focus order:

1. `#f-back`: "← Universe" / "← Univers", with title "Back to the universe (Esc)".
2. The title: "Flow of" + kind dot + name.
3. `#f-dir` and `#f-depth` selects (`fillSelect`, the shared strings).
4. `#f-counts`: "22 upstream · 1 downstream".
5. `#f-cap`: the cap message (§ 7).
6. The legend: start, upstream, downstream marks (reusing `.mk`).
7. `#f-domains`: the domain breakdown `<details>`.
8. `.grow`.
9. `#f-fit`.
10. The export group: `#f-export-h`, `#f-export-png`, `#f-export-svg`.

`#f-live` is a polite live region outside the bar.

**Opening.**

- The new button `#u-tj-flow` ("Flow" / "Flux", title "Show this trajectory as a left-to-right flow") sits in `#u-trajbar`, before **Leave**.
- It is disabled when the trajectory is empty (`noLineage`).
- Click → `openFlow(N[traj.start].id, trajOpts.direction, trajOpts.depth)` → focus `#f-back`.

**Recentre.**

- A click on a `g.node` calls `open(thatId, state.direction, state.depth)`, which re-renders.
- The universe trajectory does not move.
- A pan of svg-pan-zoom that ends on a node must not recentre. Ignore the click when the pointer moved more than 3 px since `pointerdown`.
- `renderSeq` drops stale renders when the user clicks quickly.

**Tooltip `#f-tip`.** An absolutely positioned div inside `#f-graph`'s box, with the universe's look (`#u-tip` rules shared by class `.tip`). Its content:

- `tableTip(DATA, n)`;
- the trajectory line (`L.tipStart`, `L.tipUp(d)`, `L.tipDown(d)`, the same `.tj` classes);
- the description;
- the action line "Click: show its flow" ("Clic : afficher son flux"), omitted on the start.

It is shown on `mouseover` of a node and hidden on `mouseout` and on pan.

**Closing.**

- `#f-back` or `Esc` calls `close`.
- `Esc` uses a `keydown` listener on `document` in the **capture** phase, active only while the flow is open. It closes the domain `<details>` first if that is open. It does nothing when the target is a `select`, as M1 does. Otherwise it closes the flow, then calls `preventDefault()` and `stopPropagation()`.
- The universe `Esc` handler gains `if (ev.defaultPrevented) return;`, so one `Esc` never also leaves the trajectory.

**Fit, resize.** `#f-fit` and `window` resize call `pz.resize(); pz.fit(); pz.center()`, as `refit` does in the detail.

**Empty and error states.**

- "Laying out…" while Graphviz runs. One `requestAnimationFrame` before rendering lets the message paint.
- "Render error: …" plus a new `GRAPHVIZ` instance if Graphviz fails.
- Export stays disabled until `panZoom` resolves.

**Strings.** The flow's own strings live in the `T` of `startFlow`, in `en` and `fr`, with the same key set. Counts use `plural`.

### 7. Performance: a cap with automatic depth reduction

`FLOW_MAX = 150` tables, start included. It is one constant at the top of `flow.js`.

1. Run one traversal with `depth = Infinity` in the chosen direction (`trajectory`). Count the tables per distance.
2. **Effective depth** `e` = the largest `d ≤ requested depth` such that the tables with distance `≤ d`, plus the start, number `≤ FLOW_MAX`. The flow draws depth `e`. `#f-depth` shows `e` (`d1`, `d2`, `d3`, or `dall` when not capped). `#f-cap` says `T.capDepth(e, total)`. The user can pick another depth, and it is capped again.
3. If level 1 alone is over the cap (a hub with hundreds of direct parents or children), the flow draws the start plus the first `FLOW_MAX − 1` level-1 tables. They are sorted upstream first, then by domain label, then by name. `#f-cap` says `T.capCut(...)`. Level 2 is not offered.
4. **Budgets**, checked on the 1,500-table synthetic payload of `test_trajectory_perf.py`:
   - The preparation (traversal, cap, `flowRanks`, the DOT string) takes **under 100 ms**. It is measured in the page with `performance.now()` and exposed as `state().prepareMs`.
   - The Graphviz render of a capped flow (150 tables) takes **under 5 s** in headless Chromium.
   - If 5 s is not met, the tester lowers `FLOW_MAX`. It is the only knob. The final value goes into `docs/progress.md`, `docs/ui-spec.md` and D-036.
5. **Why 150.** Graphviz in Viz.js runs on the main thread. 150 HTML-label nodes is the order of the largest detail group drawn today. Beyond that, a left-to-right diagram is not readable without zooming anyway.

### 8. Hooks for the tests (read-only)

`flow.state()` returns a fresh plain object:

```js
{ open, start, direction, depth, effectiveDepth, capped, prepareMs,
  up: { id: distance }, down: { id: distance },
  edges: [[parentId, childId, 'up' | 'down']], ranks: { id: column } }
```

All ids are `unique_id`s.

`flow.svgImage(scale)` wraps the shared `svgImage(box, pz, scale)`.

`views.universe.trajectoryState()` gains a `camera: { x, y, k }` field (the d3 zoom transform). With it, tests can assert that closing the flow leaves the universe camera untouched. This adds no UI.

### Errors

- A Graphviz failure shows "Render error: …" in `#f-graph` and the toolbar stays usable.
- A cycle cannot hang the page: there is the `seen` set of `trajectory` and the Kahn leftovers of `flowRanks`.
- Nothing is written to disk or storage.

## Rejected options

**Placement**

- **A third tab, "Flow".** It needs a new tab name, visible at all times, with an empty state when no trajectory is on. It would add a third kind of view to `boot.js views` and its `relayout` / layout-reset logic (meaningless for the flow). It would also make "back to the universe" a tab switch, which hides that the flow belongs to the trajectory.
- **An overlay over the universe canvas only (inside `#u-stage`).** The universe filter panel would stay visible beside the flow, yet it has no effect on the flow. The universe toolbar's PNG export would also sit above a diagram it does not export.
- **A mode of the Detail tab.** The detail draws the `entities` of the detail selection, with columns, groups and relations. Most trajectory tables (sources, staging) are not in it. Mixing two diagrams in one tab muddles its group, focus, drag and saved-layout logic (the detail saves layouts per drawing, the flow must not).

**Ranks and grouping**

- **dot's own ranks only (no imposed ranks).** Every edge already goes left to right, but sources at different distances land in different columns, and layers are scattered.
- **`rank=same` per layer.** An edge inside a layer (staging → staging, vault → vault) becomes vertical, and an edge against the layer order points left. Both break "every edge goes left to right", which the user asked for and the tests check.
- **Ranks by BFS distance (column = depth).** An edge between two tables at the same distance would be vertical. The depth is shown as a label instead.
- **Domain cluster subgraphs.** One domain spans many layers, so its cluster must stretch across columns. Clusters that interleave are what dot lays out worst. At about 150 tables, with seven or more domains and many cross-domain edges, they overlap or bloat the diagram, and they make dot markedly slower. They also conflict with imposed ranks. Clusters only for small flows were rejected too: two looks for one view, and two code paths.

**Data and behaviour**

- **A payload change** (precomputed flow ranks, or per-table depth): it is not needed, since the page has every input, and it would change the M3 reference payloads.
- **Moving the universe trajectory when the flow recentres:** it breaks "the universe state stays untouched", and the user opened the flow from a specific trajectory.
- **Native Graphviz tooltips** (the `tooltip` attribute, as in the detail): no tooltip on touch, a slow and plain look, unlike the universe.
- **Dragging tables in the flow:** it would need a saved layout per flow (a new layout scope, D-013) for a diagram that is regenerated from lineage each time.
- **No cap, or a hard refusal over the cap:** the first freezes the page on a hub; the second leaves the user with nothing. Automatic depth reduction always shows the closest levels and says what was left out.

## Impacts

### Decision D-036 (appended to `docs/decisions.md`)

> **D-036 — The flow view: a trajectory drawn left to right by Graphviz, in an overlay of the Universe tab.**
> Asked by the user on 2026-11-04 (M5.3, design note `docs/architecture/2026-11-04-m5.3-flow-view.md`). A **Flow** button in the trajectory bar opens the current trajectory as a left-to-right Graphviz diagram (Viz.js, as the detail view), with the same start, direction and depth. Upstream tables are on the left, the start is emphasised, and downstream tables are on the right. Each table shows its depth (`−n` upstream, `+n` downstream), its kind colour (as in the universe) and its domain as a colour band, listed in a legend. It shows every table of the trajectory: the universe filters do not apply (D-018).
> Columns are computed in the page by `flowRanks`: lineage first, so every edge goes left to right, with the configured layer order as a floor. Layers become column bands wherever the lineage follows them.
> A click on a table recentres the flow. **Back** or `Esc` returns to the universe exactly as it was: the flow is an overlay over the whole Universe tab (panel and stage made `inert`), not a tab, and it saves nothing (no layout, D-013).
> It exports PNG and SVG through the detail view's export helpers, moved to `common.js`, as `<title>-flow.png|svg`. This extends the file names of D-021.
> A flow holds at most `FLOW_MAX` = 150 tables. Above that, the depth is reduced to the largest level that fits, or level 1 is cut, and a message says so.
> No payload change: the universe payload already holds the lineage, layers, domains and kinds.
> This refines D-018: the trajectory mode itself keeps the universe layout. The rejected option "showing the trajectory alone with a new layout" remains rejected *for the mode*. The flow is a separate view, opened on demand.
> Rejected: a third tab (a new, always-visible tab with an empty state), a mode of the Detail tab (other tables, a saved layout), domain clusters (unreadable and slow at about 150 tables, and they conflict with imposed ranks), `rank=same` per layer (vertical and backward edges), and no cap (Graphviz blocks the page on a hub).

## As built

- **`FLOW_MAX` = 150, unchanged.** Measured in headless Chromium on the 1,500-table payload of `test_trajectory_perf.py`: the capped hub flow (146 tables, depth reduced to 5 levels) is drawn in about 0.45 s (budget 5 s); the preparation takes about 2 ms (budget 100 ms). D-036's value stands.
- **`newrank` + `rank=same` worked in Viz.js 2.1.2.** Each edge also carries `minlen = rank(child) − rank(parent)`, so dot's ranks equal `flowRanks`' columns even where a column has no edge from the one before it (risk 2's fallback is kept as part of the main path).
- **`#f-view` is the first child of `#tab-universe`, not the last.** `tests/unit/test_page.py` checks that no export control follows a `.canvas-box` in the markup before its section ends; placed last, the flow's toolbar would follow the universe canvas. Absolute positioning and `z-index` make the order invisible, and the covered universe is `inert`.
- **The universe camera is its own test hook, `views.universe.camera()`,** not a field of `trajectoryState()`: an existing test compares the whole `trajectoryState()` across a relayout, which refits the camera.
- **More shared helpers than listed in § 2**, to keep one implementation each: `trajectoryCounts` / `noTrajectory` (the counts and empty texts of the bar and the flow header), `trajectoryTip` (the tooltip line), `svgFile` (the SVG export as a Blob). `fillSelect` also fills the detail's group and depth selects.
- **The flow handle** also has `isOpen()` (boot shows the flow again when the Universe tab is shown) and `state().max` (the cap, read by the tests). The unused `region` string was not added: the region is named by its title (`aria-labelledby`).
- **When the window is resized**, the flow keeps the user's zoom and pan (`pz.resize()` only); **Fit** shows the whole flow again.
- **Initial 0.75 scale:** svg-pan-zoom applies a zoom on its next animation frame, so the start is centred one frame after the zoom, and the drawing counts as ready (export enabled) one frame later. Browser tests check the start is within 3 px of the centre at 360 px (acme `fct_orders`) and 1280 px (a 201-table fan).
- **Graphviz label escapes (review loop 1):** Graphviz reads `\\`, `\N`, `\G`, `\E`, `\T`, `\H`, `\L` inside HTML-like label text as escapes, and character entities are decoded before that. The one label-text escaper `common.js dotText` (`esc`, then every backslash doubled, checked with the vendored Viz.js) is used by both the flow and the detail view (names, column names and types), which fixes the same bug in the detail view.
- **Review loop 1, also shared:** `panZoomFit` / `panZoomDestroy` (Fit and unmount), `trajectoryLevels` (the level words of the node names and the tooltip lines), `countByDomain` (the trajectory list and the Domains list). ## Risks

1. **Graphviz time at 150 tables.** If it is over 5 s, lower `FLOW_MAX`; the ranks and the DOT do not change.
2. **`newrank=true` with many `rank=same` groups in Viz.js 2.1.2 (Graphviz 2.40).** `newrank` is supported there. If a render fails, fall back to `minlen = rank(child) − rank(parent)` on each edge, without `rank=same`: this keeps left to right and approximates the bands. Test 2 detects the failure.
3. **The click at the end of an svg-pan-zoom pan.** Handled by the 3 px threshold (test 6).
4. **`inert` support.** It is supported by Chromium and all current browsers. Without it, focus could reach the covered controls, but nothing breaks.
5. **Moving helpers out of `detail.js`.** A regression in the detail export. Its existing browser tests must pass unchanged before step 2.

## UI design

Written by the ui-designer. Where this section differs from § 5 and § 6 (toolbar order, inline legend, strings), this section wins. Prototype: the example page built offline, the DOT of acme `fct_orders` (24 tables) and of a synthetic 150-table fan rendered by the vendored Viz.js in node, then screenshotted at 1280 and 360 px. Viz.js lays out 150 tables in about 0.7 s in node.

### Task and decision

- **Task.** "Where does this table's data come from, and where does it go, step by step?" The trajectory mode answers *which* tables. The flow answers *in what order*, without crossing arrows.
- **Decision the user makes.** Which upstream table to inspect next, or whether a change to the start table reaches a given mart. Then: recentre on that table, export the picture for a ticket, or go back.
- **Information needed.** Per table: its name, its kind (header colour), its domain (band), how many hops from the start (`−2`, `+1`) and its layer. Globally: the start, the counts, what was left out by the cap.

### Opening: the Flow button

- `#u-tj-flow` sits in `#u-trajbar` after `.grow`, just before **Leave**: `… legend ⟷ [Flow] [Leave]`. Tab order: … counts, **Flow**, **Leave**.
- Label **Flow** / **Flux**. Title "Show this trajectory as a left-to-right flow" / "Afficher cette trajectoire en flux, de gauche à droite". A plain button, like Leave (no accent fill: it is not a commit action).
- **Disabled** when the trajectory is empty for the current direction (the bar already shows "No upstream table" etc., so the reason is visible next to it; no extra string). Enabled again as soon as the direction or depth gives a table. Never disabled by the cap: the flow handles it.

### Header (`#f-bar`), in DOM and focus order

1. `#f-back` — `<span aria-hidden="true">← </span>Universe` / `Univers`; title "Back to the universe (Esc)" / "Revenir à l'univers (Échap)". First, so it is where focus lands on open.
2. `<h2 id="f-title" class="f-title">` — "Flow of" / "Flux de" + kind dot (`<i>`, the kind colour) + `<b>` name (ellipsis at 40ch, full name in `title`). Styled 13 px, weight 400 for "Flow of", 600 for the name: it is a heading for screen readers, not a large title.
3. `#f-dir`, `#f-depth` — labelled selects "Direction" / "Sens" and "Depth" / "Profondeur", filled by `fillSelect` with the shared strings (both, upstream, downstream; all levels, 1, 2, 3 levels). They remind the trajectory's settings on open and change only the flow.
4. `#f-counts` — plain text, tabular figures: `plural(total, L.tables)` + " · " + `L.countUp(u)` + " · " + `L.countDown(d)`; a direction that is off is omitted (as in the universe). Example: "24 tables · 22 upstream · 1 downstream". When the direction has no table, the counts read the shared empty text alone ("No downstream table").
5. `#f-domains` — `<details>` whose `<summary>` shows up to 6 domain colour dots (`aria-hidden`) then `plural(n, L.domainsN)` ("5 domains", "1 domaine"); `summary.title` lists "Label: n" per domain, as the universe counts do on hover. Its list (`#f-dom-list`, the `#u-tj-list` look, shared class `.tj-pop`):
   - three legend rows: a 14×10 box with a 2 px dark border + "start"; an 18 px dashed violet line + "upstream"; an 18 px solid orange line + "downstream" (`L.lgStart`, `L.up`, `L.down`);
   - a 1 px `--border` separator;
   - one row per domain present: colour disc, label (ellipsis), table count right-aligned in tabular figures, sorted by count descending then label.
6. `#f-cap` — the cap message, only when capped (`hidden` otherwise). Text colour `--fg` (not muted: something was left out), no icon. It sits after the domains so it wraps onto its own row at 360 px.
7. `.grow`.
8. `#f-fit` — "Fit" / "Recadrer", title "Show the whole flow" / "Afficher tout le flux".
9. Export group `.export` (`#f-export-h` "Export image", `#f-export-png` "PNG", `#f-export-svg` "SVG"), the existing group rules (one piece, `margin-left:auto`).

`#f-live` (polite, `.sr-only`) follows the bar.

### Node look (DOT, checked in the prototype)

```
┃▌│ fct_orders␣␣␣         │   row 1: kind colour fill, name white bold 14 pt (+ 3 &#160; so bold names fit, as in the detail)
┃▌│ −2␣␣·␣␣Staging         │   row 2: white; depth #1f2933 bold 12 pt, then "  ·  " and the layer label #6b7280 12 pt
```

- `<table border="1" color="#c3c9d2" cellborder="0" cellspacing="0" cellpadding="4" bgcolor="white">`; first cell `rowspan="2" width="6" bgcolor="<domain colour>"`, empty: the **domain band** on the left edge.

- **Depth label** at the start of row 2, before the layer, bold and dark, so the eye scans one column of `−3 −2 −1`; U+2212 for minus, `+n` downstream, `−a / +b` for a table in both maps. Followed by `&#160;&#160;·&#160;&#160;` (Viz.js under-measures bold).

### Edges

- `color` = `TRAJ_COLORS.up` (`#6d28d9`, dashed) / `.down` (`#c2410c`, solid), `penwidth=1.4`, `arrowsize=0.8`, arrowhead at the child: the trajectory's colours and dash, the non-colour cue of M1. `back` (cycle) edges: same colour, `constraint=false`, `style=dotted`.
- Contrast on `--bg`: violet 7.9:1, orange 4.9:1 (both ≥ 3:1 for graphics).

### Initial view, recentre and how the header reflects it

- **Initial view** after each render: `fit`; if the fitted scale is below `FLOW_MIN_SCALE = 0.75` (names under about 10 px), zoom to 0.75 instead and centre on the start node. At 1280 px acme `fct_orders` fits whole at about 1.0; the 150-table fan (fit ≈ 0.15, unreadable) opens at 0.75 on the start; the user pans or presses **Fit** for the whole shape. **Fit** always fits the whole flow.
- **Recentre**: click (or Enter / Space on a focused node) → re-render on that table with the flow's own direction and depth. The header follows: title name and kind dot, counts, domain summary and list, cap message, the selects (effective depth). `#f-live` says "Flow of stg_erp__orders: 4 tables · 3 upstream · 1 downstream." (+ the cap message when capped). After the render, focus moves to the new start node if focus was on a node (keyboard path); a mouse click leaves focus where it was.
- No "back to the first table" control: **← Universe** then **Flow** returns to the trajectory's start in two clicks, because the universe trajectory never moves. Remove before adding.
- A focused node outside the visible area is panned into view (`pz.pan`), so keyboard users never tab to an invisible node.

### Tooltip (`#f-tip`, shared `.tip` look)

`tableTip` (name; "domain · layer · kind · N columns"), then the trajectory line (`.tj` / `.tj.up` / `.tj.start`), the description (muted, at most the payload's 400 characters), then the action line "Click: show its flow" / "Clic : afficher son flux" in accent, omitted on the start.
