# M8.2 — Entities: descriptive tables folded into their parent (design note)

Status: APPROVED FOR AUTONOMOUS MODE (the user asked for the whole of M8 to be built without stopping; every point the brief leaves open is settled below and recorded in D-061 and D-062).

## Context

Request: give each table of role `descriptive` at most one **parent** (a `core` or `connector` table), computed in `domain/` from declared relations, else from names; in the universe, fold such tables into their parent (an **entity**), so that a large vault draws its hubs and links rather than its satellites, without ever reducing a count or making a table unreachable. Roadmap M8.2, brief `docs/briefs/2026-11-12-m8-synthesis.md` § 6 (constraints § 4). Later phases read it: M8.3 cards count entities, M8.4 routes carry the folded tables' links, M8.5 builds the detail skeleton from the same parent and the same fold / show choice.

Current state of the code (after M8.1):

- `domain/universe.universe_data` builds one `UniverseNode` per table in scope (named keys `id, name, domain, layer, kind, desc, cols`; `cols` positional), `relations` / `lineage` as `[child, parent]` index pairs, kinds with their `role` (D-058), `defaults` ending with `constellations` (D-048). The kind of a node is `first_rule(table, config.kinds)` or a built-in (`TYPE_KINDS`, `OTHER`; never `core`, `connector` or `descriptive`).
- `domain/model.Relation` has `child` (the table carrying the test or the constraint) and `parent` (the table referred to); `origin` is `relationships_test` or `foreign_key`.
- `render/assets/universe.js layout()`: `visible` = tables passing the domain, layer and kind filters; it is also what is drawn, what `P` places, what the quadtree holds and what the meta line counts. `edges` = visible relations / lineage, used for drawing, routes (`agg`, `flow`), band order and the meta line. `layoutCache` key = grouping, constellation, detail level, links, member indices. `reveal` treats "no `P[i]`" as "filtered out".
- `cli._summary` derives every row from the payloads; `LABEL_WIDTH = 10`.
- `tests/large_project.py`: 175 hubs, 191 links, 422 satellites (of which 38 effectivity satellites of links), 20 PITs (role descriptive), 32 dimensions and 30 facts (core); `NO_RELATION_SAT = vehicle_e001_s5_sat` (no relation), `TWO_PARENT_SAT = vehicle_e002_s5_sat` (relations to `vehicle_e002_hub` and `vehicle_e003_hub`), `OTHER_DOMAIN_SAT = vehicle_e004_s5_sat` (schema `claim`, relation to `vehicle_e004_hub`). Raw vault layer: 808 tables.

## Chosen design

### 1. The parent rule (`domain/`)

New module **`domain/fold.py`** (no existing module owns it: `classify` holds rules shared by both views on one table at a time, `universe` assembles a payload; the parent rule needs every table, kind and relation at once and M8.5 reuses it for the detail). It imports `config` (`KindRule`), `model`, `selectors`. Public:

```python
def parents(
    tables: Mapping[str, Table],          # the tables in scope, by unique_id
    kinds: Mapping[str, KindRule | None], # the kind rule of each table; None for a built-in kind
    domains: Mapping[str, str],           # the domain key of each table (universe.domain_of)
    relations: Iterable[Relation],
) -> dict[str, str]:                      # folded table's unique_id -> its parent's unique_id
```

and `stem(table: Table, rule: KindRule | None) -> str`. One helper is added to `selectors.py`, which owns the selector syntax: `name_glob(selector: str) -> str | None` (the pattern of the selector's single name part — a bare part or `name:` — or `None` when it has none or several).

Definitions:

- **Role of a table**: `kinds[uid].role` (`None` for built-ins). **Descriptive** tables are those with role `descriptive`; **candidates** those with role `core` or `connector`.
- **Stem** (`stem`): lower-cased. Take the first selector of the rule's `match` that matches the table (`selectors.matches`; the same first-match order that classified it). If that selector has a name glob holding exactly one `*` and no `?` or `[`, the stem is the table name without the glob's fixed prefix and suffix (`*_hub` → `vehicle_order_hub` → `vehicle_order`; `dim_*` → `dim_vehicle_01` → `vehicle_01`; `*_effsat` → the link stem). Otherwise (no name part, as `tag:hub` or `schema:x`; several wildcards; a built-in kind) the stem is the whole name. With several globs in a kind, the first matching one decides. An empty stem (a table named exactly as the fixed part) gives no stem: such a candidate is never found by name.
- **Boundary**: a stem `s` is a *prefix* of a descriptive table's own stem `d` when `d == s`, or `d` starts with `s` and the character of `d` right after it is not alphanumeric (`_`, `.`, `-`…). So `vehicle_e001` is a prefix of `vehicle_e001_s5` but not of `vehicle_e0012_s1`. The descriptive table is compared through **its own stem** (same rule, its own kind), so suffix (`*_sat`) and prefix (`sat_*`) conventions both work, and `customer_sat` finds `customer_hub` (equal stems).

Steps, for each descriptive table `t`:

1. **By relation.** `R` = the distinct `parent`s of relations whose `child` is `t` (either origin), that are in `tables` and are candidates. **Direction matters**: only relations *from* `t` count (a descriptive table carries the test pointing at what it describes; a test pointing *at* a satellite says nothing about whom it describes). Lineage is never used. `|R| == 1` → that table.
2. **By name**, when `|R| != 1`. The pool is `R` when `|R| >= 2`, else every candidate of `t`'s domain. Among the pool, the stems that are prefixes of `t`'s stem; the **longest** wins. **Tie** (two or more pool tables with that same longest stem, e.g. `customer_hub` and `customer_refhub`): **no parent** (ambiguous, never arbitrary). No prefix: no parent.
3. Otherwise, no parent.

**Same domain only.** A parent found in another domain does **not** fold the table: `t` stays a star in its own domain, and `parents` omits it (brief proposal adopted: a constellation never loses a table to another, and a domain's stars and counts stay its own). Step 1 is not retried in `t`'s own domain when its one related parent is elsewhere: the relation says who the parent is.

**No opt-out key** for step 2. A project that disagrees with a name fold declares a relationship test (step 1 wins), removes `descriptive` from the kind's role, or sets `universe.fold: false`. A wrong fold is visible (the entity's tooltip and card list its folded tables; the CLI counts them). Revisit with a new decision if a project reports wrong name folds.

**Determinism and cost.** Tables are visited in sorted `unique_id` order; `R` is a set; step 2 uses a dict per domain (and one built for `R` when `|R| >= 2`) from stem to the list of pool tables, and looks up the boundary prefixes of `t`'s stem longest first; the first prefix found decides (one table: parent; several: tie, none). No result depends on dict or set iteration order. Cost: stems O(N · G) (G = globs per kind), step 1 O(R), step 2 O(D · L) (D descriptive tables, L the length of a stem): linear, no pairwise comparison. On the large project (1,374 tables, 442 descriptive) it is well under 50 ms; the existing `test_large_project` page-build budget (< 5 s) covers it.

Expected result on the large project: every satellite, effectivity satellite and PIT with one relation folds into it (step 1); `NO_RELATION_SAT` folds into `vehicle_e001_hub` (step 2, same domain); `TWO_PARENT_SAT` folds into `vehicle_e002_hub` (step 2 within `R`); `OTHER_DOMAIN_SAT` is **not folded** (parent in `vehicle`, table in `claim`). So 441 of the 442 descriptive tables fold, and the raw vault draws 808 − 441 = **367 stars** (Done-when 1: ≤ 400).

### 2. Payload

- **`UniverseNode.parent: str | None = None`**, the **last key** of a node: the parent's `unique_id` (invariant 11), `null` when the table is not folded. Filled by `universe_data` from `fold.parents(tables, kinds, domains, project.relations)`, with `kinds` and `domains` already computed per table for the nodes (no second `first_rule` / `domain_of` pass). Absence is JSON `null` (rejected: omitting the key, a top-level map `{child: parent}` — see Rejected).
- **`UniverseDefaults.fold: bool = True`**, the **last key** of the universe defaults (after `constellations`). It is `config.universe.fold`; the page folds only when some node has a parent (the effective state is decided by the page, as `constellations` below two layers).
- **Config.** `UniverseSettings.fold: StrictBool = True` (`universe.fold` in `dbt-erd.yml`, also allowed in presets through `PresetUniverse`; a non-bool is the usual one-line config error). No preset sets it.
- **Detail payload: unchanged in M8.2.** `DetailEntity` gains its parent in **M8.5**, which regenerates the reference pages anyway and must settle how the parent applies to the detail's groups and selection; `fold.parents` is the one implementation it calls. So each phase regenerates the reference pages once.

**Expected diff of `tests/fixtures/m3-reference-pages/payloads/*.json`** (checked once by the developer with a script before regenerating; written in `docs/progress.md`): in **every** case (`none`, `fr`, `edge`, `layers_domains`, `kinds`, `star_schema`, `data_vault` and the offline twins), each universe node gains `,"parent":null` as its last key and the universe `defaults` gain `,"fold":true` as their last key. Nothing else: no reference project has a descriptive kind with a parent (the `shop` project has no satellite; `kinds` has no role). Removing those two keys from the new payloads gives the old payloads byte for byte. Every `expected.json` hash and size changes (assets change too).

### 3. CLI summary

`cli._summary` gains one row, **`fold:`**, after `universe:`, derived from the universe payload only (descriptive kinds = `universe.kinds` with role `descriptive`; folded = nodes with a `parent`; entities holding them = distinct parents):

```
  fold:     441 tables folded into 213 entities; 1 descriptive table not folded
```

(The number of entities is illustrative: the developer writes the generator's exact number into `tests/fixtures/large-data-vault/expected.json`.)

- `not folded` covers both "no parent" and "parent in another domain" (the payload does not tell them apart, and the user's action is the same: declare a relation in the right domain). The clause is omitted at 0.
- When `config.universe.fold` is false: `…; the page opens with them shown` appended.
- When no table folds but descriptive tables exist: `0 tables folded; 12 descriptive tables not folded`.
- **The row is omitted when the page has no descriptive kind**, so pages without roles (and the star schema example) keep their summary.
- `_count` for plurals; numbers with `,`; lower case, no final period (D-029). `LABEL_WIDTH` unchanged (`fold:` is shorter than `universe:`). The user guide's summary excerpts that show a Data Vault run gain the row (`tests/unit/test_docs.py`).

### 4. Page (`render/assets/universe.js`)

Python decides the parent; the page decides only what is drawn. Words: an **entity** is a `core` or `connector` table with the tables folded into it (possibly none).

**State and memory.**
- `PARENT[i]`: the node index of `N[i].parent` (`null` when none), built once from an id → index map. `FOLDABLE = PARENT.some(p => p != null)`.
- `state.fold`: `FOLDABLE ? foldMemory.get() ?? DATA.defaults.fold : false`. `foldMemory` mirrors `byMemory` (D-048): localStorage key **`dbtscope-fold:<title>`**, values `"folded"` / `"shown"`, written only when it differs from the page default, removed otherwise; never in the layout object, never exported; without storage the choice lasts for the session.
- The panel control (fold / show the descriptive tables; label built from the labels of the descriptive kinds present, details by the ui-designer) is **hidden when `!FOLDABLE`**. Changing it calls `relayout()`.

**Who is drawn.** In `layout()`:
- `visible` keeps its meaning: tables passing the filters. It feeds every count (meta line, constellation tooltips, `n` of a constellation, trajectory counts) — counts are never reduced.
- A visible table `i` is **folded** when `state.fold`, `PARENT[i] != null`, the parent is visible, and the parent is in the same constellation (`G.of`). In domain mode the last condition always holds (Python folds within a domain); **in layer mode a table whose layer differs from its parent's is not folded**: it stays a star in its own layer (a constellation never loses a table to another, the D-061 rule applied to layers).
- **A parent filtered out** (its kind, layer or domain unticked) leaves its folded tables **drawn as ordinary stars** in their constellation (D-062: a filter never makes a ticked table disappear; ticking only "Satellite" shows satellites). Rejected: drawing a ghost of the filtered-out entity (shows a table the viewer filtered out), hiding its folded tables (they would vanish while ticked).
- `drawn` = visible minus folded. `B`, `P`, the packing, bands, `MAIN`, names and the quadtree hold `drawn` only (plus the tables shown temporarily, below). `FOLDED`: `Map<parent index, [visible folded indices]>`, sorted by name then id.
- **Marks.** An entity with folded tables carries a mark of how many (ui-designer: badge, ring or segments), in both groupings. Unticking a kind or layer of folded tables only lowers the mark and the counts.

**Entity count and meta line.** Entities = visible tables of role `core` or `connector` (every core / connector table is an entity, whether or not it holds folded tables; unfolded descriptive tables, technical tables and tables without a role are not entities). When `state.fold` is effective (FOLDABLE and on) the meta line reads `1,374 tables · 428 entities · 2,285 links · 12 domains` (en) / `1 374 tables · 428 entités · …` (fr); otherwise as today. On the large project that is 175 hubs + 191 links + 32 dimensions + 30 facts = **428** (the brief's 366 predates M8.1's core dimensions and facts). The links count stays `edges.length` (visible links, folded ends included).

**Links.**
- `edges` keeps every visible link (counts, `agg` routes, `flow` direction): a folded table's links reach other constellations through its constellation, which is its entity's, so routes and domain-level counts carry them unchanged (M8.4 builds on this).
- Drawing skips any edge with an end that is not placed (`!P[a] || !P[b]`): links between an entity and its own folded tables, between two folded tables, and between a folded table and any drawn table are **not drawn inside the constellation while folded**.
- `bandsOf` neighbours already restrict to members, so folded tables do not affect band order.

**Layout and cache.** Folding reduces what is packed: reserved boxes and band packing hold drawn tables only (D-040 rules unchanged). The cache key gains `state.fold` and, per member entity, its visible folded indices (they change the entity's box at keys / all levels and its mark): `[by, key, detail, links, fold, members, foldedOfMembers]`. Folded and shown layouts are therefore cached side by side; toggling back is a cache hit.

**Box of an entity.**
- Names level: the star and label as today; the mark's footprint, if it extends past the star, is added to `w` / `h` (ui-designer gives the size; it must not depend on the digit count so a filter does not change it more than the rows do).
- Keys / all levels: the card lists its visible folded tables, name and kind, under its columns: one 11 px row each plus a heading row, at most `FOLD_ROWS` (ui-designer, proposal 12) then `+ N more`; `box()` counts them, so the reserved box holds the card (D-040).
- Tooltip of an entity: its folded tables by name with their kinds (same cap, `+ N`).

**Reachability: temporary unfolding without relayout.** D-018 says the universe keeps its layout; a re-pack of the constellation on every search or click would move tables the viewer knows. So a folded table that must be seen is **shown on an orbit around its entity**, not packed:
- `shown`: the set of folded tables shown now = the folded members of the trajectory (start included) ∪ every folded table of the entity of the last table found by search.
- `placeShown()` runs after `layout()` and whenever `shown` changes (search, trajectory enter / move / leave). For each entity with shown tables: positions on a circle centred on the entity's `P`, radius `starR(entity) + gap`, grown so neighbours do not touch, evenly spaced from the top, in `FOLDED` order (radius, gap and label rule: ui-designer). They are drawn above the constellation, may cover neighbours, are not reserved boxes, do not change `B` of anyone else and are **not draggable** (only shown tables at rest — fold off — are dragged and saved). The quadtree is rebuilt over `drawn ∪ shown`. Cost O(shown); budget below.
- **Search** of a folded table: `reveal` (filters), `shown` gets its entity's folded tables, `found` is the table, the camera goes to its orbit position as today. Cleared by the next search, `relayout()` (as `found`), the fold control, or a click on the empty background.
- **Trajectory**: every folded table of the trajectory is shown on its entity's orbit, the start included; leaving the trajectory removes them (unless the search holds them). Trajectory edges are drawn to the orbit positions. `renderBar`'s hidden count and `reveal` must test **filter visibility** (a `vis` set), not `P[i]`, since a folded table has no `P` before `placeShown`.
- **Double-click on an entity**: today's behaviour, which already opens the detail focused on it when it is in the detail's scope (`openInDetail` → `views.detail.focus`), else zooms. Same on a shown folded table. The detail itself is unchanged in M8.2 (it already holds every satellite of the `data_vault` preset's `select`).

**Saved arrangements** (D-013, D-040): format, file, localStorage key and scopes unchanged; no new scope. Folded and shown states use the same scopes (`names`, `keys`, `all`, `layers:*`). A stored offset of a folded table stays in the layout (the store is never pruned) and applies again when the table is drawn at rest (fold off, or its parent filtered out). Dragging works on drawn tables in both states; pins stay absolute.

**Image export**: the view as on screen (marks, orbits). **Flow view**: unchanged (it draws every table of the trajectory, D-036).

### 5. Performance budgets (large project, `large_page`)

- Page open ≤ 3 s, folded (default) and with `dbtscope-fold:<title> = shown`.
- A filter change ≤ 1 s, folded and shown.
- Fold toggle (folded → shown, cold cache) ≤ 1 s; back to folded (cache hit) ≤ 1 s.
- `geometry().layoutMs` reported for both states in `docs/progress.md`.
- Search of a folded table to the frame with its orbit: no `layout()` run (`layoutRuns` unchanged) and `placeShown` ≤ 50 ms.

### 6. Test hooks

- `geometry()`: `tables` lists **drawn** tables (stars at rest, then shown ones), each gaining `parent` (id or null), `held` (visible folded tables it marks, 0 for none) and `shown` (true for a temporary orbit table); new top-level `fold` (`{ available: FOLDABLE, on: state.fold }`) and `folded` (ids of visible tables not drawn because folded, shown ones excluded).
- `trajectoryState().layoutRuns` already exists and proves no relayout.
- The handle is unchanged otherwise; the control is driven by clicking it.

### Error handling

One new possible config error: `universe.fold` that is not a bool (`config <path>: universe.fold: …; fix the file`, exit 1, nothing written). The parent rule never fails: anything ambiguous gives no parent.

## Rejected options

- **Folding across domains** (parent in another domain): a constellation would lose a table and its counts to another; the cross-domain relation still shows as a route.
- **First candidate on a tie** in step 2 (by name, by id, core before connector): an arbitrary fold is worse than none, and the CLI counts the leftovers.
- **An opt-out key** for step 2 (`fold_by_name: false`, per kind or global): three existing switches already exist (declare the relation, the role, `universe.fold`); a key is only worth adding when a real project needs it.
- **Comparing the parent's stem with the raw descriptive name**: fails for prefix conventions (`sat_*`) and for `customer_sat` → `customer_hub`.
- **Prefix without a boundary**: `vehicle_e001` would claim `vehicle_e0012_s1_sat`.
- **Relations in both directions / lineage in step 1**: a hub's test pointing at a satellite, or a PIT's lineage from several satellites, does not say whom a table describes.
- **Parent on `DetailEntity` now**: M8.5 settles the detail's rule and regenerates the reference pages anyway; adding it now costs a second regeneration in M8.5 if the shape changes.
- **A top-level `parents` map** (`{child_id: parent_id}`, one key on pages without roles): the brief asks for the parent on each folded table, and a node keeps carrying its own classifications (`domain`, `layer`, `kind`) as the page reads them; one more `null` per node is about 14 bytes.
- **Omitting `parent` when null** (logic in `payload.py`, as D-048 and D-058 rejected).
- **`universe.fold` defaulting to "auto"** (a third value): `true` with the page's `FOLDABLE` check gives the same behaviour with a bool.
- **Re-packing the constellation to show a searched or trajectory table**: moves known tables on every click (D-018) and costs a layout per click on the large project.
- **New layout scopes for the folded state** (`fold:names`…): the viewer would arrange the map twice; offsets of drawn tables apply in both states.
- **Folding a table into a parent of another layer in layer mode**: the table would vanish from its layer constellation.
- **Keeping the fold choice in the exported layout**: a viewer preference, as the grouping (D-048).

## UI design

Task: a data engineer or analyst opens a large Data Vault page and must (1) see the hubs and links of a domain without 400 satellites in the way, (2) know at a glance which hubs carry satellites and how many, (3) still reach any satellite by search or trajectory, without the map moving. Decisions: fold or show (panel), read what is folded (mark, tooltip, card), reach a folded table (search, trajectory). Everything below is `universe.js` / `page.html` / `page.css`; no new dependency, no new colour (inks `C.text`, `C.muted`, white; kind colours through `CONTRAST.edge`).

### 1. Constants (paste into `universe.js`, after `OVERVIEW_NAMES`)

```js
const BADGE_H = 15, BADGE_MAX = 26;   // entity badge, screen px: height; widest (3 characters "99+")
const BADGE_ARC = 2.5;                // below OVERVIEW_K the badge is a dark arc of this screen width on the star's north-east rim, no digits
const ORBIT_GAP = 18;                 // world px between an entity's star and its first orbit
const ORBIT_RING = 16, ORBIT_STEP = 16;  // most shown tables per orbit; world px between two orbits
const ORBIT_ROOM = 10;                // world px added to a shown star's radius when spacing neighbours (room for ring + search mark)
const FOLD_ROWS = 12, FOLD_HEAD = 15, TIP_FOLDED = 8;  // folded rows on a card; heading row height; folded names in a tooltip
const KIND_LIST = 3;                  // kind labels written under the panel control before "+ N"
```

### 2. The mark of an entity: a count badge

Chosen: a **badge**, a pill holding the number, at the upper right of the star. Rejected: **ring** (one ring carries "has folded tables", not "how many"; thickness needs colour or width discrimination that fails at a 2.5 px star and is confused with the trajectory and search rings, which are rings too); **segments** (an arc split in N is unreadable past 4 or at small radii, N up to 10 means 10 arcs of 2 px). The badge is the only form that states the number at 1 to 99, uses shape and digits (not colour), and does not collide with the ring vocabulary.

- **Near (scale ≥ `OVERVIEW_K`, 0.6)**: pill, height `BADGE_H` = 15 screen px, width `max(15, 8 + 6 × digits)` (1–2 digits 15–20 px, "99+" 26 px = `BADGE_MAX`), radius 7.5, fill `C.text` (`#1f2933`, 14:1 on the page, so D-042 3:1 holds for the mark and D-037 4.5:1 for its digits), digits white 10 px bold `FONT`, centred, 1 px white outline (so it reads on any star colour and on the dark double ring of a start). Count above 99 is written `99+`. Numbers through `num`.
- **Far (scale < 0.6)**: a short arc of `BADGE_ARC` (2.5 screen px) wide, round caps, in `C.text`, centred on the star's north-east rim (angles −1.4 to −0.2 rad), no digits. It covers about a tenth of a 2.5 px star, so the star's kind colour stays readable from afar (hub vs link); its outer half is on the page (`C.text` is 14:1, D-042 3:1 holds). The tooltip and the card give the number. (A 3.5 px dot, the first design, hid the colour of every small star.)
- **Anchor** (screen space, so it does not shrink with the star): its lower-left corner sits on the star's north-east rim point, `(p.x + 0.71·r, p.y − 0.71·r)` in world px (`r` the drawn radius), pill extending right and up by its own screen size (`/ k` in world units). For the far arc, its centre line is the rim. Drawn after the star and its rings, before names; its pill is an obstacle in the names competition, so no name covers a count. It never rotates and is the same at 2.5 to 18.9 px radii.
- **Drawn only** when the entity holds ≥ 1 visible folded table in a folded state (`held > 0`), in both groupings. A kind or layer filter that hides some folded tables lowers the number; at 0 the badge disappears. Not drawn while fold is off, on cards (the card has its list heading, § 5), on shown (orbit) tables, nor on an entity whose own table is filtered out.
- **Footprint** (names level only; the reserved box of D-040 grows so the badge never covers a neighbour's box). In `box(n)` when `held > 0`, with `r = starR(n)`:
  `w = max(w, 2·(0.71·r + BADGE_MAX))`; `e = max(0, ceil(0.71·r + BADGE_H − (r + 2)))`; `h += e`; `oy −= e / 2`. The width term uses `BADGE_MAX`, not the digit count, so a filter changing 12 to 9 does not move the box. (At k = 1; at lower scales the badge is bigger in world units and may overlap a neighbour's box by a few px, accepted: a name that would cover a badge is skipped.)
- **Export PNG**: drawn by the same canvas helper, same sizes (screen px × scale): identical to the screen.
- Hover/search/trajectory rings of the star are unchanged and sit under the badge.

### 3. Shown on demand: an orbit

Folded tables found by search, or in a trajectory (start included), are drawn **on a dashed orbit circle around their entity's star**, above everything, not packed (as § 4 of the architect's note).

- **Geometry** (`placeShown`, world px). For an entity with `n` shown tables: ring `j = floor(index / ORBIT_RING)` holds `m = min(ORBIT_RING, n − j·ORBIT_RING)` tables; radius `R_j = max(starR(entity) + ORBIT_GAP + j·ORBIT_STEP, (maxShownR + ORBIT_ROOM) / sin(π / max(m, 2)))`. Tables evenly spaced, first at the top (−90°), clockwise, in `FOLDED` order (name, id); the table found by search is not moved to the front (positions are stable).
- **Star size**: `starR` as at rest (descriptive 0.75 factor, 2.5 px floor, so about 2.5 to 7 px), kind colour, same white / `CONTRAST.edge` outline as `drawStar`; start-of-trajectory rings, up/down rings and the search ring are `drawStar`'s, unchanged (they need `ORBIT_ROOM`).
- **Told from tables at rest**: (a) the **orbit circle**, 1 px, `C.muted` at 60 %, dashed `[3/k, 3/k]` (a line, so shape not colour), drawn under the shown stars and above the constellation; (b) a 2 px white halo behind each shown star (they float above neighbours); (c) their names are always drawn (below). The orbit exists only while some table of the entity is shown.
- **Names**: every shown table's name is drawn (they are few), 11 px, `600` for the found table, `C.text`, placed outside the orbit along the radial direction: right half left-aligned at `r + 4` px from the star, left half right-aligned, within 20° of the vertical centred above / below. Names of shown tables enter `drawNames` with the priority of hovered names (never skipped for collision with ordinary names; the ordinary ones yield). A white 3 px stroke under the text keeps it readable over neighbours.
- **Search mark**: the table found gets the existing `mark` ring (2 px `C.text` at `r + 4/k`), as any found table; the other shown tables of the entity have none.
- **Trajectory**: rings per side as `drawStar` (start double, up dashed violet, down solid orange); trajectory edges end at the orbit positions (`P`-like lookup through `shownP`); dimming rules as today (shown trajectory tables are members, so full alpha; the entity itself keeps the alpha it has).
- **Hit-testing**: `pickAt` tests the shown list first (hit radius `max(8, 8/k)` like stars, nearest first), then the quadtree; so an orbit table over a neighbour wins. At `k < FAR` (0.5) nothing is picked, as today. Click: trajectory (as any table). Double-click: detail focused on it, else zoom (as any table). Not draggable (cursor stays default, `drag.subject` ignores shown tables).
- **Tooltip of a shown table**: the usual `tableTip` + trajectory lines + description, plus one line `Entity: <parent name>` (§ 7), action line as for any table.
- **Cleared** by: next search, fold control, `relayout()`, background click, leaving the trajectory (unless search holds it). Nothing animates (no motion to reduce).

### 4. Tooltip of an entity

After the usual `tableTip` lines (name, meta), before the description, only when `held > 0`:

```
<b>3 folded tables</b>            (m line, plural(held, T.foldedN))
name_a_sat · Satellite            (m line each, name esc, kind labelOf(KIND[k]))
name_b_sat · Satellite
name_c_pit · PIT
```

Order: `FOLDED` order (name, then id) = the order of the card. At most `TIP_FOLDED` (8) lines, then `+ N` (`+ ${num(N)}`, a last m line, no noun). Counts are visible folded tables only (filters apply). Strings: `foldedN` en `['folded table', 'folded tables']`, fr `['table repliée', 'tables repliées']`. Action line unchanged. When fold is off the entity shows no folded list (nothing is folded).

### 5. Cards (keys, all fields levels)

Under the columns (and under the "+ N" columns row when present), when `held > 0`:

- **Separator**: 1 px line across the card at the list top, `rgba(100,116,139,.22)` (`C.edge`; decorative).
- **Heading row** (`FOLD_HEAD` = 15 px high): `plural(held, T.foldedN)` ("3 folded tables"), 9 px `600`, `C.text`, left at `x + 5`.
- **Rows** (11 px pitch like columns, 9 px `FONT`): a kind dot (radius 2.5, kind colour, 1 px outline in `CONTRAST.edge(col, C.bg)` when it falls short, D-042) at `x + 8`; the table name at `x + 14`, `C.text`; the kind label right-aligned at `x + w − 5`, `C.muted` (as column types). All ink is on the card's white: D-037 holds (5.3:1 muted, 14:1 text); no text on a kind colour.
- **Cap**: `FOLD_ROWS` = 12 rows, then one muted row `+ N`. At scale ≤ 0.6 the text is not drawn (existing `k > 0.6` rule); the card keeps its height.
- **Box**: `box()` adds `FOLD_HEAD + 11 × min(held, FOLD_ROWS) + (held > FOLD_ROWS ? 11 : 0)` to `h` and includes the folded names and kind labels in the width estimate (`name.length + 1 + kind.length × 0.8`, `chars` formula of the columns), so the card holds them (D-040: no overlap).
- Hover/start/up/down borders and the hit box are the card's, unchanged.

### 6. Panel control

- **Control**: one native checkbox in `fieldset#u-fold` (no legend), a `.panel label` row like the filter rows: `<input type="checkbox" id="u-fold-on">`, text block, count `<small>` at the right. Checked = folded. Position: right after the Constellations radios (or first in the panel when those are hidden), before **Links**. It is the third kind of "what do I draw" switch after grouping, so it sits with it.
- **Label** (`T.fold`): en "Fold descriptive tables into their entity", fr "Replier les tables descriptives dans leur entité". Under it, a muted 12 px second line `#u-fold-kinds` naming what that means in this project: **the labels (`labelOf`) of the kinds of role `descriptive` that have at least one table with a parent, in payload order, the first `KIND_LIST` (3) joined with `, `, then ` + N`** ("Satellite, Ref sat, PIT"); written as in the config, so no plural agreement is needed and it works for any preset or config (the sentence's "descriptive" is the fixed role word, `T.roles.descriptive`). A kind with `label: null` shows its key (`labelOf`). The same text is the checkbox's `aria-describedby`.
- **Count** (`<small>`, tabular figures, right-aligned like other rows): the number of tables that have a parent (`PARENT.filter(p => p != null).length`), whatever the filters or the state: "441". It does not change with the toggle (counts never change).
- **Title** (`T.foldTitle`): en "Draw each descriptive table inside its entity. Search or a trajectory shows it around its entity." fr "Dessiner chaque table descriptive dans son entité. La recherche ou une trajectoire l'affiche autour de son entité."
- **Hidden** (`fieldset.hidden = true`) when `!FOLDABLE`; the page then has no fold at all (no badge, meta unchanged).
- **Behaviour**: `onchange` sets `state.fold`, `foldMemory.set(...)` (§ architect), clears `shown`, calls `relayout()`; no fit change beyond what `relayout()` does. Live announcement (§ 9).
- **Keyboard**: Tab reaches it after the radios (or ☰ when they are hidden); Space toggles; focus stays on the checkbox after the relayout. Native focus ring.
- **Coarse pointer**: `.panel label { min-height: 44px }` already applies; the row wraps its second line inside the label so the 44 px target is the whole row.
- **CSS** (`page.css`, near `.panel label small`): `.panel label .sub { display:block; color:var(--muted); font-size:12px; line-height:1.4; }`; `.panel label.fold { align-items:flex-start; }` with the checkbox `margin-top:3px`; the text block `flex:1; min-width:0; overflow-wrap:anywhere` so it wraps at 360 px; `.panel label small { font-variant-numeric: tabular-nums; }` (check whether already set). `.panel fieldset[hidden] + h3` rule already handles the first-child margin; the new fieldset adds `margin-bottom:12px`.
- `page.html`: after `fieldset#u-by`:
  ```html
  <fieldset id="u-fold" hidden><label class="fold"><input type="checkbox" id="u-fold-on" aria-describedby="u-fold-kinds"><span><span id="u-fold-t"></span><span class="sub" id="u-fold-kinds"></span></span><small id="u-fold-n"></small></label></fieldset>
  ```
  and the `.panel h3:first-child` margin rule extended to `fieldset[hidden] + fieldset[hidden] + h3`.

### 7. Meta line and the entity cues

- **Meta line**, fold effective (`FOLDABLE && state.fold`): `tables · entities · links · groups`: en "1,374 tables · 428 entities · 2,285 links · 12 domains", fr "1 374 tables · 428 entités · 2 285 liens · 12 domaines". `entities` counts visible tables of role core or connector (architect), via `plural(count, T.entitiesN)`; `entitiesN` en `['entity', 'entities']`, fr `['entité', 'entités']` (French: 0 and 1 singular). Fold off or not foldable: today's line.
- **Entity whose own table is filtered out**: its folded tables are ordinary stars; **no mark on the canvas** (a ghost would show a table the viewer filtered out, as the architect decided). The cue is in the table's tooltip: a line `Entity: <parent> (filtered out)`. Same line for a table left at rest in layer mode: `Entity: <parent> (other layer)`. A shown (orbit) table and a table at rest with fold off: `Entity: <parent>`. Strings: `entity` en `Entity`, fr `Entité` (joined with `L.colon`); suffixes `T.entityHidden` en ` (filtered out)`, fr ` (masquée par les filtres)`; `T.entityLayer` en ` (other layer)`, fr ` (autre couche)`. The parent name is `esc`aped. Shown only when the table has a parent.

### 8. Hint

`T.hint` gains, when `FOLDABLE && state.fold`, a trailing clause (kept out of the base string so pages without folding are unchanged byte for byte of text): en ` · a number on a star: tables folded into it, shown around it by search or trajectory`; fr ` · un nombre sur une étoile : tables repliées dans celle-ci, affichées autour d'elle par la recherche ou la trajectoire`. The hint is rewritten when the control changes (`$u('hint').textContent`).

### 9. Screen readers, 360 px, export

- Canvas stays silent; the polite live region of the universe (`#u-tj-live`) announces:

  - the control: en `Descriptive tables folded into 428 entities` / `Descriptive tables shown`; fr `Tables descriptives repliées dans 428 entités` / `Tables descriptives affichées` (`T.foldOn(n)`, `T.foldOff`);
  - a trajectory that shows folded tables appends to its existing message: en ` Shown around their entity: 3.`, fr ` Affichées autour de leur entité : 3.` (`T.shownAround` + `L.colon` + `num(n)`), only when n > 0.
- The search box and datalist remain the keyboard route to a folded table (orbit tables are not focusable, like every table of the canvas).
- **360 px**: no horizontal scroll: the control's text wraps; the tooltip is not shown on touch. Badge is screen-sized (15 px), never clipped by the stage.
