# M8.2 — Entities: descriptive tables folded into their parent (design note)

Status: APPROVED FOR AUTONOMOUS MODE

Every change below is foreseen by `docs/briefs/2026-11-12-m8-synthesis.md` § 4 and § 6, and by `docs/roadmap.md` M8.2: an optional `dbt-erd.yml` key (`universe.fold`), new payload keys at their defaults, new optional layout scopes added the way D-048 added the layer scopes (brief § 4 allows exactly this), a new per-viewer localStorage key as D-048. No decision is superseded: D-013, D-040, D-048 and D-018 are refined (§ Impacts). No released format changes: `dbt-erd-layout` version 1, the file name and the localStorage key `dbt-erd-layout:<title>` are unchanged, and pages and files from before M8.2 load as they are. The open points the brief leaves to the architect (cross-domain parents, ties, opt-out key, an entity whose own table is filtered out) are decided below with their reason; none is a choice between options with no documented preference that only the user can make.

## Context

Request: on a project whose kinds have roles (M8.1), draw each `descriptive` table (satellite, ref sat, PIT) inside the `core` or `connector` table it describes, so that a 1,400-table Data Vault reads as its entities; the parent is computed in Python and every folded table stays reachable and counted. Roadmap M8.2; brief § 6 is the spec (findings 1 and 2).

Current state:

- `domain/universe.universe_data` gives each node its kind (`first_rule(kinds)` or a built-in kind), domain (`domain_of`) and layer (`_layer_of`); relations and lineage are `[child, parent]` index pairs. `UniverseNode` is `{id, name, domain, layer, kind, desc, cols}`; `UniverseDefaults` ends with `constellations` (D-048).
- `domain/config.UniverseSettings`: `select`, `exclude`, `links`, `detail`, `hidden_kinds`, `constellations`. `KindRule.role` exists (D-059); `data_vault` gives `sat` / `refsat` / `pit` the role `descriptive`, `hub` / `refhub` / `dim` / `fact` `core`, links and bridge `connector` (D-060).
- `universe.js` draws every table that passes the three filters (`visible`); `edges` are the drawn links; `constellations[].n` and `mix` count the drawn tables; routes (`agg`) and the flow direction count drawn links between constellations; the meta line counts drawn tables and links; `reveal` uses `P[i]` (drawn) to tell a filtered-out table; layout scopes are `names|keys|all` and `layers:names|keys|all` (`BY[*].scope`); the viewer's grouping is kept in `dbtscope-constellations:<title>` (`byMemory`).
- `tests/large_project.py`: 1,419 tables; Raw vault layer 828 tables (175 hubs, 191 links, 422 satellites including effectivity satellites, 20 PITs, 20 views); `SPECIAL` holds `no_relation_by_name` (`car_unlinked_sat`), `no_parent` (`orphan_ledger_sat`), `two_parents` (`van_shared_sat`), `other_domain` (`auction_vehicle_sat`, in `vehicle`, related to `auction_hub`) and `effectivity_on_link`.
- The detail view is not touched by M8.2 (M8.5 builds its skeleton on the parents computed here).

## Chosen design

### 1. The parent rule (`domain/fold.py`, new module)

A new module, because the rule is one responsibility shared by the universe now and by the detail skeleton in M8.5 (`domain/detail.py` will call it): it would not belong in `universe.py`.

Vocabulary: a table's **place** is its pair (domain, layer) in the universe payload. **Candidates** are tables of the universe payload whose kind has role `core` or `connector`.

**Stem.** `stem(table, rule) -> str`: the table's name, lower-cased, without the fixed part of the name glob that classified it.

- The glob is taken from the first selector of the kind rule's `match` that selects the table (`selectors.matches`), and inside it the first **positive name part** (a part with no field or with `name:`, not starting with `!`) that holds a wildcard (`*`, `?`, `[`). The parts are read by a new `selectors.name_patterns(selector) -> tuple[str, ...]` (positive name patterns of one selector, in order): the selector syntax keeps one implementation (invariant 2).
- The fixed part is the literal text before the first wildcard (prefix) and after the last one (suffix): `*_hub` gives suffix `_hub`, `dim_*` prefix `dim_`, `sat_*_v` both. The stem is the name with that prefix and suffix removed.
- No such glob (the kind is matched by `path:`, `tag:`… only, or by an exact name, or the table has a built-in kind): the stem is the whole name, lower-cased. An empty stem is never a candidate's stem (a candidate with an empty stem is skipped in step 2).
- Examples: `vehicle_order_hub` → `vehicle_order`; `vehicle_order_status_sat` → `vehicle_order_status`; `sat_vehicle_status` (glob `sat_*`) → `vehicle_status`; `car_pit` → `car`; `belt_camera_registration_effsat` → `belt_camera_registration`.

**Parent.** `parents(members, relations) -> dict[str, str]` (descriptive table id → parent id; tables without a parent are absent). `members` is a sequence of `Member` (frozen, `model.DOMAIN` config, built by `universe_data`): `id`, `role`, `stem`, `domain`, `layer`. `relations` are the project's `Relation`s. For each member of role `descriptive`:

1. **By relation.** The distinct candidates the table points to: relations whose `child` is the table and whose `parent` is a candidate, other than itself (`relationships` tests and `foreign_key` constraints alike, D-012). Exactly one: that table is the **found** parent. Relations from a candidate to the descriptive table (the other direction), and relations to descriptive, technical or unclassified tables, are not read.
2. **By name**, when step 1 finds none or several. The pool is the candidates of step 1 when several, else every candidate **in the same place**. A candidate matches when the table's stem equals its stem, or starts with it followed by a character that is not a letter or a digit (`car` matches `car_status`, never `carpet_status`). The found parent is the matching candidate with the **longest** stem. **Tie** (several matching candidates share that longest stem): no parent.
3. **Otherwise** no parent.

Then **the found parent holds only in the same place**: when it is in another domain or another layer, the table has no parent. A declared relation outranks a name: when step 1 finds exactly one candidate elsewhere, step 2 is not tried.

Choices, with their reason:

- **Other domain: not folded** (the brief's proposal). A table is counted, coloured, filtered and placed in its own domain; folding it into another domain's star would move a table out of the constellation that counts it and break "a count is never reduced by a fold" per constellation. Its relation still shows as a link and in the route between the two domains. Large project: `auction_vehicle_sat` stays a star in Vehicle.
- **Other layer: not folded either** (same reason in layer mode, D-048: a folded table must stay in its layer constellation and its domain band). It also keeps the name step inside the vault: without it, `dim_car` (stem `car`, Data products) would tie with `car_hub` (stem `car`, Raw vault) for every `car_*_sat`. In practice a satellite sits in its hub's folder; a project whose layers split them sees them unfolded, which the CLI row (§ 3) makes visible.
- **Ties: no parent.** Any pick (first by name, core before connector) would be a guess the user cannot see in the config; the rule must be explainable in one sentence. A tie needs two candidates with the same stem in one place (`customer_hub` and `customer_refhub`), where a `relationships` test decides (step 1). Ties are counted in the CLI row with the other unfolded tables.
- **Stems on both sides.** The brief compares a candidate's stem with the table's name; comparing it with the table's **stem** gives the same result for suffix conventions (`*_sat`) and also works for prefix conventions (`sat_*`, `hub_*`), which the brief's version cannot.
- **Word boundary.** Without it, `car_hub` would claim `carpet_colour_sat` whenever no `carpet_hub` exists.
- **No opt-out key for the name step.** The name step only runs for descriptive tables, only inside one place, only on a word boundary, and only when relations do not decide; a wrong fold shows in the entity's tooltip and card, and is corrected by declaring the `relationships` test (step 1 wins), by giving the kind another role, or for the whole page by `universe.fold: false`. A key would be a new permanent `dbt-erd.yml` surface (invariant 9) for a case none of the test projects has.
- **Lineage is not read.** In a Data Vault a satellite is built from stage models, not from its hub, so lineage would point the wrong way; the brief's rule is relations then names.
- Deterministic: candidates are scanned in `unique_id` order; the result does not depend on manifest order.

Performance: candidates are indexed once per place, each list sorted by stem length (longest first); step 2 stops at the first length that matches and checks for a tie at that length. On the large project (442 descriptive tables, at most about 130 candidates per place) this is far below the payload-build bound (§ 7).

### 2. The payload (`domain/payload.py`, `domain/universe.py`, `domain/config.py`)

- `UniverseNode.parent: str = ""`, **last key** of a node: the parent's `unique_id` (invariant 11), `""` when the table has no parent. Every node carries it, as `domain` carries `""` for no domain; D-048 rejected omitting a key at its default (logic in `payload.py`). Cost on the large project: 12 bytes per unfolded node, about 16 kB on an 857 kB page.
- `UniverseSettings.fold: StrictBool = True` (config `universe.fold`, also allowed in presets through `PresetUniverse`; a non-boolean is the usual one-line config error, `config <path>: universe.fold: …`, exit 1).
- `UniverseDefaults.fold: bool = True`, **last key** of the universe defaults (after `constellations`): `universe.fold` copied as is. Python does not decide whether the control is shown (D-048's reasoning: the rule would exist twice); the page shows it when at least one node has a parent.
- `universe_data` builds one `fold.Member` per node from what it already computes (kind rule → role and `fold.stem`; `domain_of`; `_layer_of`), calls `fold.parents(members, project.relations)` once, and sets `parent` on each node. Built-in kinds give role `technical` or `none` and are never parents nor folded.
- **Pages without descriptive tables** (no preset, no `role`, or `star_schema`): every node has `"parent":""` and the defaults end with `"fold":true`; nothing else changes (brief § 4). The page then hides the control and draws exactly as today (§ 4.1).

### 3. CLI summary (`cli._summary`)

A new row, `folded:`, after `universe:`, only when the universe holds at least one table whose kind has role `descriptive` (read from the payload: `UniverseKind.role` and `UniverseNode.parent`; no new domain call):

```
folded:   440 descriptive tables into their parent, 2 without a parent
folded:   440 descriptive tables into their parent, 2 without a parent; shown when the page opens (universe.fold: false)
```

`_count` gives the plural (`1 descriptive table`); the `without a parent` part is always present, `0 without a parent` included, so a test or a CI log can grep it. "Without a parent" covers the three cases of § 1 (no relation and no name, a tie, a parent in another domain or layer); the user guide's troubleshooting lists them. The label `folded: ` fits `LABEL_WIDTH` (10). A page without descriptive tables prints the summary exactly as today.

### 4. The page (`render/assets/universe.js`, `page.html`, `common.js`)

#### 4.1 State and the three sets

- `PARENT[i]`: index of node i's parent, or -1 (from `n.parent` through an id → index map; the parent is always a node of the payload). `FOLDED[p]`: the indices whose parent is p.
- `CAN_FOLD = PARENT.some(p => p >= 0)`. When false: no control, no entity, no meta entry, no new scope; every code path below reduces to today's.
- `state.fold`: `foldMemory.get()` when stored, else `DATA.defaults.fold`; forced false when `!CAN_FOLD`.
- `opened`: entities opened by the last search (§ 4.5), at most one; `traj` (existing) holds the trajectory.
- Three sets replace the one `visible`, each computed once per layout:
  - **passing**: tables whose domain, layer and kind are ticked (today's `visible`);
  - **folded now**: passing tables with a parent, when `state.fold`, whose parent passes, whose parent is not in `opened`, and that are not trajectory members;
  - **drawn** (`visible`, kept as the name so the drawing code is unchanged): passing minus folded now.
- `held(p)`: the folded-now tables of p, in name order; an **entity** is a drawn table of role `core` or `connector` (holding tables or not, brief § 6: 1,374 tables · 366 entities).
- **An entity whose own table is filtered out** (the brief's open point): its folded tables are not folded now, so they are drawn as their own stars, in their own place. Reason: a ticked kind keeps meaning "these tables are drawn"; hiding satellites because Hub is unticked would make a ticked box show nothing, and a ghost entity would be a new mark with no table behind it. Unticking Hub on the large project therefore shows the 440 satellites and PITs, as the user asked.

#### 4.2 What is counted (never reduced by a fold, brief § 4)

- Meta line: `plural(passing, tables)` · entities (only when `CAN_FOLD && state.fold`: drawn core and connector tables, `[entity, entities]` / `[entité, entités]`) · links · constellations. The links count is the links between **passing** tables, as without folding (a fold changes what is drawn, not what is counted). Example: "1,419 tables · 428 entities · 2,621 links · 12 domains".
- Constellation count line, composition bar (`mix`), domain tooltip, layer tooltip and band counts (`bands[].n`): over passing tables, folded included.
- Filter row counts (`COUNT`, static), trajectory counts and the flow: unchanged.

#### 4.3 Links and routes

- **Table-level links** (`edges`): between drawn tables only. A link of a folded-now table is not drawn, inside or across constellations (brief § 6: "not drawn inside the domain while folded"; across, the route says it).
- **Routes** (`agg`) and the flow direction of a route (`flow`): computed over the links of **passing** tables. Since a parent shares its table's place (§ 1), the route between two constellations is the same, folded or shown: an entity carries its folded tables' links in the routes, and d3-force gets the same link strengths in both states.
- Hover dimming (`near`) uses drawn links, as today.

#### 4.4 Drawing an entity (ui-designer finalises the look, these are the constraints)

- **Mark** on the star of every entity holding at least one table, in both groupings and at every zoom: the ui-designer chooses badge, ring or segments (brief § 6). Constraints: it says how many tables the entity holds (a number, or a shape whose size is readable at Fit); kind colours drawn as marks reach 3:1 (D-042) and any text 4.5:1 (D-037); it does not change the star's radius (D-058: degree already grows with the satellites' relations); `box(n)` reserves its room at names level so the packing never overlaps it (D-040); trajectory rings, the search mark and the start's double ring stay readable around it; image export draws it as on screen.
- **Tooltip** of an entity holding tables: after today's lines, its folded tables by name with their kind label (`labelOf(KIND[k])`), first 12 then "+ N" (as `TIP_DOMAINS`); new strings in both languages.
- **Cards** (keys, all fields): under the columns, the folded tables, one row each: name, and the kind label where the type is shown for a column (muted), at most 12 rows then "+ N"; `box(n)` counts these rows. A card that holds nothing is drawn as today.
- `box(n)` therefore depends on `held(n)`: the layout cache key (`layoutCache`) gains, per member, its held ids (cards) or held count (names), so a cached constellation is reused only when its boxes are the same.

#### 4.5 Reachability (brief § 6, done-when 3)

- **Search.** The datalist keeps every name. A folded-now table found by the search box: `opened` becomes its parent (replacing any earlier one), `reveal` ticks back filtered-out boxes as today, one relayout, then the camera goes to the table and marks it (`found`). Searching a table that is not folded clears `opened` (relayout only if it was set). `opened` is also cleared by the fold control and by Reset layout.
- **Trajectory.** Its members (start included) are never folded now: entering, moving or changing the direction or depth of a trajectory relayouts when the set of members that would be folded changes; leaving relayouts when it unfolded any. These relayouts never refit: the camera keeps its scale and stays anchored on the clicked table (the start), so it stays under the pointer; an explicit Fit still frames the trajectory. `layoutCache` makes leaving give back the exact folded placement (same members, same boxes, same seeded force). This is the same behaviour as `reveal` today (bringing back filtered-out tables already relayouts the universe). "N hidden by the filters" and "brought back" keep their meaning (filters only); unfolded members are not counted there.
- **Double-click** on an entity: opens the detail focused on it when it is in the detail (today's action); the detail is unchanged by M8.2, so its focus at "direct links" shows the satellites related to it, and its own focus box reaches every table of its scope.
- `reveal` tests the filters (`passing`), no longer `P[i]`, so a folded table is never "brought back" by mistake.

#### 4.6 The fold control (ui-designer: wording, place, widget)

- One native control in the universe panel, after **Constellations**, hidden when `!CAN_FOLD`. Proposal: a checkbox row "Fold descriptive tables" ("Replier les tables descriptives") with the labels of the descriptive kinds that have at least one parent, in Types order (`Satellite · PIT`), and the number of tables with a parent. The label is built from the payload's roles and kind labels (D-059: never from names).
- Changing it: `state.fold` flips, `opened` is cleared, `foldMemory.set`, relayout and Fit (as the Constellations switch, D-048).
- **Per-viewer memory** (as D-048): localStorage `dbtscope-fold:<title>`, values `folded` / `shown`, written only when it differs from `DATA.defaults.fold` (choosing the default again removes it), never in the layout object, never exported; without storage the choice lasts for the session. Reset layout does not clear it (as `byMemory`).

#### 4.7 Saved arrangements (D-013 unchanged, scopes extended as D-048)

- The folded drawing gets its own scopes: `folded:names`, `folded:keys`, `folded:all`, `layers:folded:names`, `layers:folded:keys`, `layers:folded:all`, each with the shape of its unfolded twin (`{domains|layers, nodes}`). `BY[*].scope()` returns `[layers?, folded?, detail]` joined by `:`; "folded" is `CAN_FOLD && state.fold` (search and trajectory unfolding do not change the scope).
- Why a scope and not the shared one: a drag pins every constellation (`constellations.forEach(d => saved[G.pins][d.k] = …)`); folded discs are about half the area of shown ones on the large project, so pins saved while folded would make every disc overlap once shown, and pins saved while shown would leave wide gaps once folded. D-048 added scopes for the same reason (different discs).
- **A stored offset of a folded table is kept and applies again when shown** (brief): it lives in the unfolded scope, which folded drags never touch; `savedLayout()` already keeps every `nodes` entry when it writes. A table opened by search or a trajectory member drawn while folded takes its folded-scope offset, if any.
- Pre-M8.2 files and stored arrangements are arrangements of the shown drawing: they load into the unfolded scopes, unchanged, and apply when the viewer shows the descriptive tables. A page that folds by default opens on the computed placement until the viewer arranges it. Pages without parents use only today's scopes. Older pages ignore the new scopes and keep them on export (D-048). `domain/layout.check_layout` accepts any scope: no change. Reset layout clears every scope (`LAYOUT.clear`).

#### 4.8 Hooks for the browser tests

`geometry()` gains `fold` (the effective state) and, per drawn table, `held` (ids folded into it); the universe handle gains nothing else. `drawnNames()`, `place(id)` and `camera()` unchanged.

### 5. Layers, responsibilities, errors

- `domain/`: `fold.py` (new: `Member`, `stem`, `parents`), `selectors.name_patterns`, `config.UniverseSettings.fold`, `payload.UniverseNode.parent`, `payload.UniverseDefaults.fold`, `universe.universe_data` (builds members, sets `parent`). Pure, no I/O.
- `cli.py`: `_summary` (`folded:` row). `storage/`: no change.
- `render/assets/universe.js` (state, sets, counts, links, routes, mark, tooltip, cards, control, memory, scopes, reachability, hooks), `page.html` (the control's markup), `page.css` if the control needs it; `common.js` only if a string is shared (none expected).
- Errors: `universe.fold` not a boolean is a config error (one line, exit 1, nothing written). The rule itself never fails: a table that cannot be placed has no parent.
- Reused: `selectors.matches`, `classify.first_rule`, `universe.domain_of`, `_layer_of`, `errors.validation_message`, `common.js labelOf`, `plural`, `num`, `CONTRAST`, `paintDot`, `filterRow` (if a checkbox row), `byMemory`'s pattern (a second instance, `foldMemory`; the developer may share a small `memory(key, values)` helper inside `universe.js` rather than copy it), `reveal`, `layoutCache`.
- Responsibility map, new rows: "Parent of a descriptive table (relation, then stem; same domain and layer; D-062)" → `domain/fold.parents`, `Member`; "Stem of a table's name from its kind's name glob" → `domain/fold.stem`; "Positive name patterns of a selector" → `domain/selectors.name_patterns`; "Which tables are folded now, held by an entity, drawn (page)" → `universe.js PARENT`, `FOLDED`, `held`, the passing / folded-now / drawn sets; "The viewer's fold choice, kept out of the layout (page)" → `universe.js foldMemory`; "Folded-drawing layout scopes (page)" → `universe.js BY[*].scope`.
- Glossary (D-027), new rows:
  - **entity**: a drawn `core` or `connector` table with the descriptive tables folded into it (M8.2). Not group, family, cluster. French UI: entité. The detail payload's protected `entities` key and `DetailEntity` keep their name (any table of the detail view); in prose and in new code "entity" means only this. Update the "table" row's "Not" column accordingly.
  - **fold** (`fold`, `universe.fold`, `defaults.fold`, folded, folded now): drawing a descriptive table inside its parent's star instead of as its own star; the opposite is **show**. Not collapse, hide, nest. French UI: replier / afficher.
  - **parent** (of a descriptive table; `UniverseNode.parent`, `fold.parents`): the core or connector table it folds into. Same word as the referenced end of a relation (`Relation.parent`), which it is when step 1 decides; say "the parent of a relation" for the other sense when both appear in one sentence.
  - **stem**: a table name without the fixed part of its kind's name glob.

### 7. Performance budgets

On the large project (browser, `large_page`), folded and shown:

- page open to first frame ≤ 3 s (brief § 4; M8.1 measured 0.44 s);
- a filter change ≤ 1 s, folded and shown;
- the fold control ≤ 1 s (a relayout);
- a search that opens an entity ≤ 1 s, and a trajectory that unfolds tables (enter and leave) ≤ 1 s;
- the existing trajectory and flow budgets unchanged;
- Python: `parse_manifest` + `universe_data` + `detail_data` keeps the 1.5 s CI-safe bound of `test_large_project.py` (M8.1: 0.22 s), and `fold.parents` alone on the large project stays under 0.1 s (unit bound, measured value in `docs/progress.md`).

The 1,500-table synthetic payload (no roles) keeps its M5.5 / M8.1 budgets and must show no change.

## Rejected options

- **Folding into a parent in another domain** (or layer): moves a table out of the constellation that counts and filters it; folded counts would differ per constellation.
- **Restricting step 1 to same-place relations, then trying names**: a declared relation is the project's own statement (D-012); overriding it by a name guess hides that the satellite describes another domain's hub.
- **Breaking ties by role, kind order or name**: an invisible guess; a relation decides instead.
- **An opt-out key for the name step** (`fold_by_name: false`): see § 1; `universe.fold: false` and roles already cover it.
- **Lineage as a step**: points from satellites to stage models in a Data Vault.
- **Comparing a candidate's stem with the table's full name** (the brief's letter): fails prefix conventions (`sat_*`).
- **Parents as `[child, parent]` index pairs** (like `relations`): smaller, but the brief asks for the parent's `unique_id` on each folded table and the page would need a second lookup; 16 kB on the largest page is acceptable.
- **Omitting `parent` when empty**: logic in `payload.py`, rejected by D-048 for the same reason.
- **Python deciding whether the control shows**: the rule would exist twice (D-048).
- **Hiding folded tables whose entity is filtered out**, or drawing a ghost entity: a ticked kind would show nothing, or a mark would stand for no table.
- **Drawing a folded table's links from its entity's star inside the domain**: clutter the fold removes; the brief says routes only.
- **Unfolded trajectory members drawn on an orbit around the entity without a relayout**: overlaps neighbours and labels, and needs a second placement rule next to D-040.
- **One layout scope for both fold states**: pins saved in one state overlap or leave gaps in the other (§ 4.7).
- **A new top-level layout section or format version**: brief § 4 and D-013; scopes are enough.
- **The fold state inside the exported layout**: it is the viewer's preference (D-048).
- **Keeping the bare word "entity" out of the glossary** (another word such as "anchor"): the brief and the roadmap name the concept "entity", and the meta line shows it.

## Impacts

Refines D-018 (a trajectory may relayout to show its folded members, as it already does to bring back filtered tables), D-048 (one more config key, payload key and viewer key, same rules) and D-058 (the star radius is unchanged by folding).

## UI design

Task: at Fit, read a 1,400-table Data Vault as its entities, then find a given satellite without knowing where it went. Decisions served: which domain or layer to zoom into; "is this satellite drawn, and under which entity?". The mark answers "this star holds tables"; the tooltip and the card answer "which"; search answers "where is table X". Nothing else is added to the page.

### The mark: a badge (chosen)

A small dark disc on the upper right of the star (centre on the rim at -45°, so the star's radius is unchanged, D-058), on every entity that holds at least one table. Badge, not ring (rings already mean trajectory, search / hover and start, and a ring would also be lost under them) and not segments (a 2.8 to 16 px star cannot carry a readable segment split, and segments would compete with the kind colour).

| | Fit (k < 0.6) | Zoomed (k >= 0.6) |
|---|---|---|
| Radius on screen | a ring, 1.5 px off the star, 1.25 px wide (a dot of 4 px hid the kind colour at Fit; cards keep the dot) | 7 px |
| Content | none (the dot says "holds tables") | the count, white, 9 px bold, tabular figures; "99+" above 99 |
| World radius | 4 / k and 7 / k (screen-constant, as names; the star keeps `max(starR, 2.5 / k)`) | |

- Colours: fill `#1f2933` (the page text colour, `C.text`), 1.5 px white outline (`#ffffff`) so it stays apart from any kind colour, number `#ffffff`. Measured with `tests/colours.py`: fill on the page `#f5f6f8` 13.6:1 (D-042 needs 3:1), on white 14.8:1; white number on the fill 14.8:1 (D-037 needs 4.5:1). A fixed colour, so no `CONTRAST.edge` is needed and no config colour can make it fail; it does not use a kind or domain colour, so it is never confused with one. The same dark ink is the "search / hover" ring, but a filled disc on the rim cannot be mistaken for a ring around the star.
- Drawn after the star and its rings, so trajectory rings, the start's double ring and the search / hover ring pass behind it and stay readable around it. Same in domain and layer grouping, at every zoom, in image export (it is drawn by the same `draw`, so the pixel test needs no special case).
- Cards (keys, all fields): the same badge, centred on the card's top-right corner, at every zoom. The card's folded rows say which tables; the badge says it from afar.
- Room, D-040: `box(n)` adds 6 px on the top and on the right for an entity holding tables (names level: `w = max(w, 2r + 16)`, `h += 6`, `oy` follows the taller top; cards: `w += 6`, `h += 6`). Nothing else changes in the packing.
- A drawn table that has a parent but is shown (opened by search, trajectory member, entity filtered out) carries no badge and no other mark: it is an ordinary star.

### Tooltip

Over an entity holding tables, after today's lines (name, kind, domain, layer, description, links, click and double-click hints), one block:

```
3 folded tables
vehicle_status_sat · Satellite
vehicle_pit · PIT
vehicle_price_sat · Satellite
```

- Heading "3 folded tables" / "3 tables repliées" (`foldedN`, plural by `plural`). One line per table, name then the kind label (`labelOf(KIND[k])`) in muted grey, in name order; first 12 (`TIP_FOLDED = 12`, as `TIP_DOMAINS`), then "+ N". All text through `esc`.
- Over a drawn table that has a parent (shown by search, by a trajectory, or because the entity or the fold is off): one line "Folds into: car_hub" / "Se replie dans\u00a0: car_hub" (`foldsInto`), so the user knows where it goes back to. Not shown on tables with no parent.
- No tooltip change for a table with neither.

### Cards (keys and all fields)

Under the columns, a 1 px separator (`C.muted` at 40 %), then one row per folded table, same 9 px type and row height (11 px) as columns: the name left in `C.text`, the kind label right in `C.muted` (the place of a column's type), at most 12 rows then "+ N" in muted (as the columns' "+ N"). The columns keep their own cap (30). `box(n).h` = existing + (held ? 6 + 11 × (min(12, held) + (held > 12 ? 1 : 0)) : 0), width counts the longer of name + kind. Drawn only at k >= 0.6 like the columns; from afar the card is its rectangle and the badge. A card that holds nothing is drawn as today.

### The fold control

- **Place**: universe panel, a fieldset right after **Constellations** and before **Links**, so the two "how is the universe drawn" choices sit together at the top (the first thing the user meets). Hidden (`hidden`) when `!CAN_FOLD`.
- **Widget**: one native checkbox in a `label` row, the same row component as the filters (`filterRow` is not reused: it has no legend; the row's markup mirrors it, so the height, left edge and 44 px coarse rule `.panel label` apply as they are, no new CSS). Fieldset legend (the panel's small-caps heading): "Entities" / "Entités". Row: checkbox, then the label, then the count right-aligned in `<small>` (tabular, as filter counts): the number of tables that have a parent.
- **Label** from roles, never from names (D-059): "Fold" + the labels of the descriptive kinds with at least one parent, in Types order, joined by " · ": "Fold Satellite · PIT" / "Replier Satellite · PIT". More than 3 kinds: the first 3 then "+ N" ("Fold Satellite · PIT · Ref sat + 2"); long labels wrap inside the 260 px panel. Row `title`: "Draw these tables inside the table they describe" / "Dessiner ces tables à l'intérieur de la table qu'elles décrivent".
- **Checked** = folded. Default and memory as § 4.6 (D-048 pattern). Choosing it: `state.fold` flips, `opened` cleared, relayout and Fit, as the Constellations switch; hover and search mark cleared. Focus stays on the checkbox. A live region announces the result (see States).
- **Keyboard**: one Tab stop in panel order (Constellations radio group, then this checkbox, then Links); Space toggles; visible focus (the page's default). No new shortcut.
- **Coarse pointer**: row 44 px high (`.panel label`), checkbox hit area the row.
- **Narrow screens**: the panel is already scrolling at 360 px (45 % of the height, D-038); the control is one fieldset of one row (about 70 px) between two existing ones. Nothing new at 360 px; checked there for no horizontal scroll.

### Filters

- Unticking a kind or layer of folded tables: the entity's badge count and tooltip list drop those tables; the meta line "tables" count is the passing count, so it drops with them (that is today's meaning of a filter); nothing else moves.
- Unticking the entity's own kind (Hub): its folded tables are drawn as stars (§ 4.1), the entity count drops; no ghost mark.
- Domain filter: as today; an entity and its tables share a domain (§ 1).
- Types counts (static), constellation counts and composition bars: unchanged by the fold.

### States

- **Nothing has a parent**: no control, no badge, no meta entry, no tooltip block: the page is today's (done-when 5).
- **Folded (default)**: badges, entity count, tooltip block, card rows.
- **Shown**: no badge, no entity entry, no control change but unchecked; tooltip "Folds into" on tables with a parent.
- **Loading / error**: none (a relayout is synchronous and within 1 s, § 7). Config error: CLI, not the page.
- **Empty**: every folded table of an entity filtered out: the entity has no badge (it holds nothing).
- **Storage unavailable**: the choice lasts for the session.
