## 2. Duplicated responsibilities

Judged with the reviewer's rule: would the two places always change together?

**TO FIX — The display name of a domain, layer or kind exists in three places with different rules.**
- `render/assets/common.js:149` `labelOf` (`label ?? key`) is documented as the one rule (M5.13, `render/CLAUDE.md`).
- `domain/universe.py:88` `_domains` resolves `label: null` to the key itself (`rule.label if rule and rule.label else key`), so for domains the page never sees `null` and `labelOf` is never needed. `_layers` and `_kinds` pass `rule.label` through, so for them the rule lives in the page.
- `cli.py:482` `_summary` prints `k.label` of each detail kind: a kind with `label: null` is summarised as `1 None` (reproduced: `detail:   1 table (1 None), 0 relations`). The CLI has no display-name rule at all.
- Because of the Python fallback, `flow.js:95` `domainLabel`, `flow.js:162`–`170` `domainList` and `universe.js:914` `renderBar` read `DOM[k].label` directly instead of `labelOf`: correct today only by accident.
Fix: one rule. Either (a) `domain/` resolves it for every rule (`_layers`, `_kinds` and the summary through one `display_name(rule)` in `domain/classify`, `_domains` kept; the page's `labelOf` stays for old pages), or (b) `domain/` passes `rule.label` through everywhere, the summary uses `label or key`, and the four page sites use `labelOf`. Either way the universe payload of a config with `label: null` on a domain changes (not the reference pages, which have none) and (b) changes the page bytes (asset edit, D-028). Recommendation: (b), one rule in Python for the CLI and one in the page, each named in the map.

**TO FIX — The layout file is validated twice, with different rules.**
- `domain/layout.py:24` `_problem` / `check_layout`: `format`, `version` (must be 1), `universe` and `detail` must be mappings.
- `render/assets/boot.js:119` import: `format` only, then `LAYOUT.load(d)`; `boot.js:23` `dump` writes `version: 1` as a literal, apart from `LAYOUT_VERSION`.
A file with `version: 2` or `"universe": []` is refused by the CLI with a one-line message but accepted by **Import layout** and then breaks `savedLayout` silently. Both change together whenever the format moves (invariant 9). Fix: the page import applies the same three checks (`LAYOUT_VERSION` written once in boot.js next to `LAYOUT_FORMAT`), with the existing `L.bad` alert; a browser test imports a `version: 2` file. Page bytes change (asset edit).

**TO FIX — "A path the system refused" is worded in three places.**
`cli.py:253` `_kind`, `storage/project_files.py:130` `read_preset_file` and `storage/project_files.py:219` `read_layout` each catch the `OSError` of `path_kind`, then build `cannot use <what>: <os_reason>; <refused_hint>`. The map lists `path_kind` and `refused_hint` but the sentence is assembled three times (and the "not a file" wording, `not found` / `is a folder` / `is not a regular file`, twice more at `project_files.py:135` and `:225`). Fix: `storage/files.refused_message(error, source, setting)` (or `checked_kind(path, source, setting, error_class)`) used by the three; the per-option sentences of `cli._project` / `_config` / `_manifest` / `_output` stay, they are option-specific wording (D-029).
