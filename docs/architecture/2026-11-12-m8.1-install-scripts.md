# M8.1 — One-step install scripts (design note)

Status: approved. The user answered the two approval points on 2026-11-12: (1) no `install.cmd` is shipped, only `install/install.ps1` and `install/install.sh`; (2) the PowerShell profile PATH block is added by default, opt-out `-SkipProfile`, only when the execution policy lets profiles run. No documented decision is superseded; D-058 refines D-055. No project file name or format changes (invariant 9). No CI change (invariant 12, D-053).

Proposed milestone: **M8.1**, under a new roadmap heading "M8 — One-step install".

## Context

Request in one sentence: ship `install.ps1` (Windows PowerShell 5.1 and PowerShell 7) and `install.sh` (macOS, Linux) that take a non-developer from "nothing" to a working `dbtscope --version` in one step, installing uv if missing, then dbtscope from a wheel file (D-055) or from GitHub.

What the user hit on Windows, following user guide § Install by hand:
1. uv missing.
2. git not on `PATH` (uv needs it for `git+https://…`).
3. `dbtscope` not found after `uv tool update-shell`: new terminals opened from an already running app (Windows Terminal, VS Code) inherit that app's old environment, so the user `Path` written in the registry is not seen until the app restarts. A line in the PowerShell profile fixed it.
4. PowerShell 5.1 printing uv's progress on stderr as red `NativeCommandError` records (it does so whenever a native command's stderr is redirected, `2>&1`, or under `$ErrorActionPreference = 'Stop'` with redirection).
5. The execution policy refusing to run a downloaded script.

Current state: no install script exists. `.gitattributes` already declares `*.ps1 text eol=crlf`. `tools/doc_consistency.py` already accepts `.ps1` and `.sh` files in map references. User guide § Install has options A (GitHub), C (wheel, D-055) and B (clone). The GitHub URL is `https://github.com/christophebnx/dbtscope` (private).

## Chosen design

### 1. Where the scripts live and how users get them

- New top-level folder **`install/`**: `install/install.ps1` and `install/install.sh`. Not `tools/` (developer tooling in Python, run with `uv run`), not `scripts/` (too vague), not the repo root (crowded, and the maintainer copies a folder). The folder is project-owned (not in `.claude/template.json`).
- The scripts are **not** in the wheel: the wheel needs uv already, and the scripts exist to get uv.
- **Distribution: next to the wheel.** The maintainer, after `uv build --wheel` from a release tag (D-055), copies `dist/dbtscope-<version>-py3-none-any.whl` and the files of `install/` into the shared folder (network drive, SharePoint, chat). The user runs the script from that folder; it finds the wheel beside it. The scripts are generic (no version inside), so any script works with any wheel.
- **No web one-liner.** The repository is private: `https://raw.githubusercontent.com/…/install.ps1` needs a token, so `irm … | iex` and `curl … | sh` cannot work without auth, and putting a token in such a line would leak it into shell history. The user guide says so. Users who can read the repository can fetch the script with the GitHub CLI (`gh api repos/christophebnx/dbtscope/contents/install/install.sh -H "Accept: application/vnd.github.raw" > install.sh`) or a clone, but they can also simply use option A; the guide mentions this in one sentence.

### 2. How users run them

Windows, in a PowerShell window opened in the shared folder (no admin; the policy change lasts only for this window):

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\install.ps1
```

Run this way, the script runs **inside** the user's session, so its `$env:Path` update makes `dbtscope` work in that same window. The guide also lists `powershell -ExecutionPolicy Bypass -File .\install.ps1` (a child process: a new terminal is then needed). `-Scope Process` and `-ExecutionPolicy Bypass` never need admin and also bypass the "downloaded file" block (Mark of the Web), so no `Unblock-File` step.

macOS and Linux, in a terminal in the shared folder: `sh install.sh` (no exec bit needed after a download).

### 3. Parameters

| `install.ps1` | `install.sh` | Meaning |
|---|---|---|
| `-Wheel <path>` (also the first positional argument) | `--wheel <path>` (also a lone positional argument) | Install this wheel. |
| (none) | (none) | Install the single `dbtscope-*.whl` found next to the script. |
| `-FromGitHub` | `--from-github` | Install `git+https://github.com/christophebnx/dbtscope`. |
| `-Ref <tag or commit>` | `--ref <tag or commit>` | With `-FromGitHub` only: append `@<ref>`. |
| `-SkipProfile` | (none) | Windows: do not add the PATH line to the PowerShell profile (§ 5). |
| `-Help` | `--help`, `-h` | Usage, then exit 0. |

Rules: `-Wheel` and `-FromGitHub` together, `-Ref` without `-FromGitHub`, a wheel path that does not exist or does not end in `.whl`, an unknown option: usage error, exit 2. No wheel given, none next to the script, and no `-FromGitHub`: exit 2 with `no wheel found next to the script (<dir>); pass a wheel path, or --from-github if you can read the GitHub repository`. Two or more wheels next to the script: exit 2, listing them (no version sorting: BSD `sort` on macOS lacks a reliable `-V`, and guessing the wrong one is worse than asking).

No `-Yes`/`--yes`: the script never prompts. Nothing it does is destructive (installing uv, reinstalling the tool, an idempotent profile block), and a prompt would block CI and unattended runs. No `-Force`: every run uses `uv tool install --reinstall`, which also implies `--refresh` (D-055: covers upgrades and a rebuilt wheel of the same version, and refetches the latest commit for GitHub).

### 4. Steps (both scripts, same order, same messages)

1. **Find uv.** `uv` on `PATH`, else the default install locations (`$UV_INSTALL_DIR`, `$XDG_BIN_HOME`, `~/.local/bin`; on Windows also `%USERPROFILE%\.local\bin` and `%LOCALAPPDATA%\Microsoft\WinGet\Links`).
2. **Install uv if missing**, with the official per-user installer (no admin):
   - Windows: in a **child** process of the same PowerShell (`(Get-Process -Id $PID).Path -NoProfile -ExecutionPolicy Bypass -Command "<TLS 1.2>; irm https://astral.sh/uv/install.ps1 | iex"`), so an `exit` or error inside the installer cannot end our script, and so PowerShell 5.1 negotiates TLS 1.2 (`[Net.ServicePointManager]::SecurityProtocol -bor Tls12`). If that fails and `winget` exists, `winget install --id=astral-sh.uv -e --scope user --accept-source-agreements --accept-package-agreements`. Then reload `$env:Path` from the registry (User then Machine values, read with `[Environment]::GetEnvironmentVariable(…, 'User'|'Machine')`) and look again (step 1).
   - macOS / Linux: `curl -LsSf https://astral.sh/uv/install.sh | sh`, or `wget -qO- … | sh` when curl is absent; neither: exit 1 with `neither curl nor wget found; install uv by hand (docs/user-guide.md § Install uv) and run this script again`. No Homebrew path: one installer, one location, as on Linux.
   - Still no uv: exit 1 (`uv could not be installed; …`, pointing to user guide § Install uv, and to a company proxy as the usual cause).
3. **Choose the source** (§ 3). For GitHub: `git` must be on `PATH`, else exit 1 with `git not found; install it (Windows: winget install --id Git.Git -e) or install from a wheel file instead`. Then check access with `git ls-remote <url>` under `GIT_TERMINAL_PROMPT=0` (no hang on a password prompt; also set for the `uv tool install git+…` call, and restored when the PowerShell script ends); git's own message stays visible, and a failure exits 1 with `cannot read the repository https://github.com/christophebnx/dbtscope (git's message is above: private repository without access, or network); set up access (docs/user-guide.md § Access to the private repository) or install from a wheel file`. The scripts never read, ask for or pass a token: git uses whatever access the user configured (`gh auth setup-git`, the `GIT_CONFIG_*` variables of the guide).
4. **Install:** `uv tool install --reinstall <wheel path | git+https://…[@ref]>`. Non-zero exit: exit 1 with `uv tool install failed (see uv's messages above)`.
5. **Make `dbtscope` reachable** (§ 5).
6. **Final check:** run `<uv tool dir --bin>/dbtscope --version` by full path. Failure: exit 1. Then resolve `dbtscope` through `PATH` (`Get-Command` / `command -v`) to choose the closing message (§ 5).
7. **dbt, informational only** (D-056, D-012): look for `dbt` on `PATH` without running it (dbtscope's only dbt command is `dbt parse`, and the script is not where it runs). Found: `dbt found: <path>; live mode will run dbt parse with it`. Not found: `dbt not found on PATH: dbtscope can still map an existing manifest (--no-parse, --manifest); for live mode, install dbt with your project's adapter the way your team does`. Never installs dbt or an adapter, never reads `profiles.yml` or `~/.dbt`. Exit code unaffected.

### 5. PATH

- Always `uv tool update-shell` (Windows: the user `Path` in the registry; macOS/Linux: the shell rc files). Idempotent in uv itself.
- **Windows, current session:** prepend `uv tool dir --bin` to `$env:Path` if absent. Effective in the user's window when the script runs in-process (§ 2).
- **Windows, profile (approval point 2):** unless `-SkipProfile`, add one marked block to `-ProfilePath`, which defaults to `$PROFILE.CurrentUserCurrentHost` (PS 5.1 and 7 have separate profile folders, so the block goes to the profile of the edition and host running the script, and the guide says so). `-ProfilePath` exists for the tests: a path given explicitly is written as is, without the platform and execution policy checks:

  ```powershell
  # >>> dbtscope install >>>
  $dbtscopeBin = '<bin dir>'
  if ((Test-Path $dbtscopeBin) -and -not (($env:Path -split ';') -contains $dbtscopeBin)) { $env:Path = "$dbtscopeBin;$env:Path" }
  # <<< dbtscope install <<<
  ```

  - Idempotent: an existing block between the markers is replaced, never duplicated. A begin marker without its end marker (or the reverse) stops the script with a message naming the profile; nothing is changed.
  - The block stays ASCII: a bin folder under `$HOME` is written `Join-Path $HOME '<relative>'`; a folder elsewhere with non-ASCII characters is written as UTF-8 (with a BOM in a new file).
  - Only when the policy that new windows will get lets local scripts run (`RemoteSigned`, `Unrestricted`, `Bypass`). That policy is read **without** the `Process` scope (which § 2 set to `Bypass` for this window only): the first defined of `Get-ExecutionPolicy -Scope MachinePolicy`, `UserPolicy`, `CurrentUser`, `LocalMachine`, and `Restricted` when none is defined. Under `Restricted` (the Windows client default) or `AllSigned`, a profile would print a red error in every new window: skip it and say `a new terminal is needed; if dbtscope is still not found, close and reopen Windows Terminal or VS Code`.
  - Atomic, in the spirit of invariant 3 (`storage/files.atomic_write` is Python and not available here): read the profile as **bytes**, append or replace the ASCII block, write to `<profile>.dbtscope.tmp` in the same folder, then `[IO.File]::Replace(…, [NullString]::Value)` (or `Move-Item` when the profile does not exist yet); the temporary file is removed on failure. Bytes keep the user's encoding (UTF-8 with or without BOM, ANSI). A profile starting with a UTF-16 BOM is not touched: the script prints the block for the user to paste.
- **macOS / Linux:** a child `sh` cannot change the calling shell's `PATH`. If `command -v dbtscope` fails in the script after the install, the last line is `open a new terminal (or run: export PATH="<bin dir>:$PATH") to use dbtscope`.
- **Closing message**: `dbtscope <version> is installed and ready in this terminal` when `PATH` resolves it, else `dbtscope <version> is installed; open a new terminal to use it` (plus the Windows Terminal / VS Code hint on Windows). Both exit 0: the install succeeded.

### 6. Messages, streams, exit codes, PowerShell 5.1 hygiene

- **English**, like the CLI (D-004). The scripts are tooling around the CLI; their lines sit between uv's and git's English output; the page language (D-016) comes from `dbt-erd.yml`, which does not exist at install time; and an English message is searchable in the user guide's troubleshooting. Text is **ASCII only**: PowerShell 5.1 reads a BOM-less script as the ANSI code page, so any non-ASCII byte would be mangled.
- Form, after D-029: progress lines `dbtscope install: <step>` on stdout; failures one line `dbtscope install: error: <what happened>; <what to do>` on stderr (`[Console]::Error.WriteLine`, never `Write-Error`, which prints a red error record on 5.1).
- **Exit codes** (D-004): 0 installed and `--version` runs (even if a new terminal is needed); 1 an install step failed (uv, git, access, `uv tool install`, final check); 2 usage (§ 3). Ctrl-C keeps the shell's own code.
- **PowerShell native calls** go through one helper, `Invoke-Native`, which: sets `$ErrorActionPreference = 'Continue'` for the call and `$PSNativeCommandUseErrorActionPreference = $false` (PS 7.3+), **never redirects stderr** (so 5.1 does not wrap uv's progress into `NativeCommandError`), captures stdout only when a value is needed (`uv tool dir --bin`), and returns `$LASTEXITCODE`. Everything else runs under `Set-StrictMode -Version 2` and `$ErrorActionPreference = 'Stop'` inside one `try` that turns an unexpected exception into the one-line error, exit 1.
- **POSIX sh**, not bash: `#!/bin/sh`, `set -eu`, no bashisms (macOS ships bash 3.2; Debian's `sh` is dash). One `fail()` and one `usage_error()` function own the message form.

### 7. Approval points (answered 2026-11-12)

1. **`install.cmd`**: declined. Only `install.ps1` and `install.sh` ship; the guide shows the two PowerShell lines of § 2.
2. **Profile block on by default**, opt-out `-SkipProfile`: accepted, only when the execution policy lets profiles run (§ 5).

### 8. Responsibility map (`docs/architecture.md`)

New rows, nothing reused from Python (the scripts run before dbtscope exists on the machine):
- "Install uv and dbtscope for a user, make `dbtscope` reachable, report dbt's presence (D-058)" → `install/install.ps1`, `install/install.sh`.
- "Check the install scripts (static rules, fake-uv runs)" → `tests/unit/test_install_scripts.py`.
- § Where facts live: the "Install, upgrade, uninstall" row stays the user guide; add `install/` to "Other files link to it".

Error handling and what is left on disk: a failure leaves at most uv installed (wanted anyway) and a previous dbtscope install (uv replaces a tool atomically). The profile write is temp + replace; the temporary file is removed even on failure.

## Rejected options

- **Scripts at the repository root** or under `tools/`: clutter, or mixed with developer-only Python tooling.
- **Scripts inside the wheel**, run through `uvx` or `python -m`: needs uv first, the very thing missing.
- **A web one-liner** (`irm …/install.ps1 | iex`): impossible without auth on a private repository; a token in the line would leak into history.
- **Installing git or dbt from the script**: git is only for `-FromGitHub` (the wheel path avoids it); dbt and its adapter are the project's choice (D-056).
- **Running `dbt --version`** as the dbt check: slow, noisy, and dbtscope runs no dbt command but `dbt parse` (D-012); presence on `PATH` is enough.
- **Prompts / `-Yes`**: nothing is destructive; prompts break unattended runs and CI.
- **Skipping the install when the same version is present**: cannot see a rebuilt wheel; `--reinstall` every time is simpler and idempotent in effect.
- **`--force`** instead of `--reinstall`: keeps the cached build (D-055).
- **Homebrew on macOS**: a second installer and location; uv's own installer is the same on macOS and Linux.
- **Picking the newest of several wheels**: version sorting is not portable in POSIX sh; asking is safer.
- **Broadcasting `WM_SETTINGCHANGE`**: running apps such as Windows Terminal and VS Code ignore it for their children; it does not fix problem 3.
- **French messages**: no config at install time (D-016), and uv/git around them are English.
- **bash instead of POSIX sh**: `sh install.sh` must work on dash and on macOS bash 3.2.
- **Adding `shellcheck-py` or PSScriptAnalyzer as dependencies**: new dependencies for two scripts; tests use them only when already installed.

> **D-058 — One-step install scripts in `install/`, shipped next to the wheel.**
> Asked by the user on 2026-11-12 (M8.1, design note `docs/architecture/2026-11-12-m8.1-install-scripts.md`), after a manual install on Windows failed on a missing uv, a missing git, a stale `PATH` and PowerShell 5.1 error noise. `install/install.ps1` (Windows PowerShell 5.1 and PowerShell 7) and `install/install.sh` (POSIX sh, macOS and Linux) install uv with its official per-user installer when missing (Windows: winget as fallback), then dbtscope with `uv tool install --reinstall` from a wheel (given, or the single one next to the script, D-055) or, with `--from-github [--ref]`, from the private repository (git and access checked first, no token handled). ## Test plan

New `tests/unit/test_install_scripts.py`, in the default suite: no network, no real uv (fakes only), so it respects invariant 5 without a `live` marker. It runs locally and in the manual CI unchanged (D-053).

**Static checks (every OS):**
1. The two files exist under `install/`; each is ASCII only; `install.sh` starts with `#!/bin/sh`.
2. Invariant 4 guard: no script mentions `.env`, `config.toml`, `profiles.yml`, `.dbt`, `credentials`, `TOKEN`.
3. No admin: no `sudo`, `RunAs`, `-Scope AllUsers`, `LocalMachine`, `'Machine'` writes (`SetEnvironmentVariable(…, 'Machine')`); the only `Set-ExecutionPolicy` is in docs, not in the scripts.
4. D-056: no `dbt-`, `pip install`, `uv tool install dbt`, `winget install … dbt` in the scripts.
5. The GitHub URL in both scripts equals the one in the user guide; the profile markers are the same in the script and the user guide (so § Uninstall stays true).
6. `install.ps1` never redirects a native command's stderr (`2>&1`, `2>$null` on a native call) and never uses `Write-Error`.
7. `sh -n install/install.sh` passes (skip when `sh` is absent, i.e. Windows); `shellcheck --shell=sh` passes when `shellcheck` is on `PATH` (skip otherwise).

**Behaviour of `install.sh`** (POSIX only; skip on Windows), each run: `sh <tmp>/install.sh` copied into a temp folder, `HOME=<tmp>/home`, `PATH=<tmp>/fakebin:/usr/bin:/bin` (skip if `/usr/bin` or `/bin` holds a real `uv`, `git` or `dbt`). The fake `uv` (a sh script) appends its arguments to a log, implements `tool install` (writes an executable fake `dbtscope` that prints `dbtscope 0.0.0` into `<tmp>/home/.local/bin`), `tool dir --bin` (prints that folder) and `tool update-shell` (logs only); fakes can be told to fail through an env variable.
8. Wheel next to the script: exit 0; log holds `tool install --reinstall <abs wheel>` then `tool update-shell`; stdout ends with the "open a new terminal" or "ready" line; the `--version` output is shown.
9. `--wheel <path>` and a positional path: same; missing file or not `.whl`: exit 2.
10. Two wheels next to the script: exit 2 listing both. No wheel, no flag: exit 2 with the "no wheel found" line.
11. `--ref` without `--from-github`, `--wheel` with `--from-github`, unknown option: exit 2.
12. `--from-github` without git: exit 1, "git not found". With a fake git whose `ls-remote` exits 128: exit 1, the private-repository line, and `uv` is never called with `tool install`. With a passing fake git and `--ref v0.3.0`: log holds `tool install --reinstall git+https://github.com/christophebnx/dbtscope@v0.3.0`; the fake git saw `GIT_TERMINAL_PROMPT=0`.
13. uv missing, fake `curl` that prints a tiny "installer" writing the fake uv into `$HOME/.local/bin`: exit 0, uv found there. uv missing, no curl and no wget: exit 1 with the curl/wget line. Fake installer that installs nothing: exit 1, "uv could not be installed".
14. `uv tool install` failing: exit 1, "see uv's messages above"; the fake uv's stderr line is on stderr, above ours.
15. Final check: fake uv that installs no `dbtscope`: exit 1.
16. dbt: with a fake `dbt` on `PATH`, stdout names its path and the fake dbt was **never run** (it writes a marker file if run); without, the "not found … existing manifest" line; exit 0 in both.
17. Idempotence: two runs in a row give exit 0 twice and the same log lines per run.
18. No file outside `<tmp>` is written: the names in the real home, `~/.local/bin` and `~/.config` are the same before and after.

**Behaviour of `install.ps1`** (skip unless `pwsh` is on `PATH`; on Windows also `powershell.exe` for 5.1 when present): cases 8 to 12, 14, 15 and 17 with the same fakes (`uv` as a sh script on POSIX, `uv.cmd` on Windows, as `conftest.fake_dbt_executable` already does for dbt: extract a shared `fake_executable(folder, name, body)` helper from it instead of writing a second one, invariant 2), with `-SkipProfile` where the profile is not the subject. The profile block is tested through `-ProfilePath` (a file in the temporary folder, any OS): written once after two runs, replaced with the rest of the profile kept, untouched with `-SkipProfile`, an orphaned marker refused. A first argument starting with `-` is `--help` (exit 0) or a usage error. The `Restricted` policy branch is checked manually: no test-only override goes into the script. uv bootstrap on Windows is manual only (it needs the network).

**Manual checks** (recorded in `docs/progress.md`), on a Windows machine without uv and git, with PowerShell 5.1 then 7: shared folder with wheel + scripts; `Set-ExecutionPolicy -Scope Process Bypass; .\install.ps1` gives a working `dbtscope --version` in the same window and in a new Windows Terminal tab; no red text from uv; a second run succeeds; `-FromGitHub` without git gives the git line. On macOS (bash 3.2, zsh default shell) and on Linux: `sh install.sh` without uv.

Definition of done: local CI green (`uv run python tools/ci.py`), `ruff format` clean, no new duplicate-code finding, `tools/doc_consistency.py` passes with the new map rows, `tests/unit/test_docs.py` passes with the new sections and anchors. Browser tests not needed (no page change).
