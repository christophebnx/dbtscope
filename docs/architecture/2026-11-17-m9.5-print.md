# M9.5 — Print: paper model, one sheet, tiled sheets (design note)

Status: APPROVED FOR AUTONOMOUS MODE. Everything here is the brief's decided scope (`docs/briefs/2026-11-17-visualization-optimization.md` § 3 row 6, § 9): a paged print document written with `@page` CSS and printed by the browser (`window.print()`, print-to-PDF), no new Python dependency, no new library, the page stays self-contained. One payload key is added (`PagePayload.generatedAt`, the manifest's own `metadata.generated_at`, extension, backwards compatible); no config key, no layout format, layout scope or localStorage key; nothing of the print dialog is saved. Decisions **D-095** (paper model and print technique) and **D-096** (tiling format).

## Context

Request: in the Schema tab, a **Print** dialog that takes a paper (A4, A3, A2, A1, A0 or custom mm), an orientation and a **minimum font size** (default 7 pt), tells before printing the physical size the scope needs ("this scope at key columns needs 1.42 m × 3.30 m at 7 pt"), and prints either **one sheet** (the wall poster: one vector page at the computed size) or **tiles** (A4 / A3 sheets with 10 mm overlap, crop marks, coordinates A1…G9 and an index page: table → tile, legend, title, dates); all columns of a large scope only per domain (roadmap M9.5).

Current state (after M9.4, see its "As built"):

- `schema.js` declares at top level `S` (sheet units: 1 u = 1 CSS px at scale 1; row text `S.ROW_FONT` = 11 u, the smallest text of a full-form sheet: rows, types, notes, chips and counts are 11 u, titles and headers 13 u), `LOOK` (colours read from `THEME`, rules, relation ends), `textW` (measured widths), `boxRows` / `boxSize(n, level)`, `scopeTables`, `sheetModel(universe, nodes, level, {rels, relColumns, summarise})` → `{W, H, unit, columns, rows, cells, boxes, edges, chips, kinds, adj, summarised, …}` and `sheetSvg(model, rect, form, marks)` → the **inner** markup (no `<svg>` wrapper) of everything meeting `rect`, with selection, hover and expansion as `marks` (dimming written into the markup, `class="dim" opacity=…`). Boxes are `<g class="node" id="<unique_id>">`.
- The handle `startSchema(…)` returns `{shown, relayout, follow, sheet, view, svgImage, perf, nodes, zoom}`; `view()` gives `{scope, level, …}`.
- Measured whole-project sheets of the large fixture (1,419 tables): names 4,511 × 9,455 u, keys 6,318 × 14,679 u, all columns 6,899 × 16,543 u; at 7 pt (7 / 11 pt per unit = 0.2245 mm per unit) that is 1.01 × 2.12 m, **1.42 × 3.30 m (4.7 m²)** and 1.55 × 3.71 m. The brief's "raw vault ≈ 4–6 m²" is confirmed in order of magnitude by the whole project.
- No print rule exists anywhere in the page (`@media print`, `@page`, `window.print` absent); the roadmap's "Later" item "Print stylesheet: the current view on one page" covers all views.
- The page carries no date: `PagePayload` is `title, lang, view, detail, universe, layout`. The manifest's `metadata` is read only for `project_name` (`manifest_schema.Metadata`).

## Chosen design

Layers touched: `domain/manifest_schema.py`, `domain/model.py`, `domain/manifest.py`, `domain/payload.py` (the date, § 7); `render/page.py` (one parameter, one script placeholder); `cli.py` (passes the date); `render/assets/`: `schema.js` (three small extensions: kind tags, id attribute, the Print button wiring), new `print.js`, `page.html`, `page.css`, `common.js` (strings only). `storage/`, `detail.js`, `universe.js`, `flow.js`, `boot.js` (but the script order in `page.html`): unchanged.

### 1. One drawing, printed: the print document (D-095)

The print is the M9.4 sheet model drawn by the M9.4 emitter, nothing else (D-092: "one emitter for screen, export and print"):

- The dialog computes a **print model**: `sheetModel(DATA, scopeTables(...), level, {rels, relColumns, tags: kindTags(DATA.kinds)})` (the tab's scope; the dialog's level; kind tags, § 5). It is a second model only because the tags widen box headers; on screen nothing changes. No selection, hover or expansion is printed: the print is the clean document (`marks = {k: 1, ids: false}`).
- `print.js printPlan(model, options)` (pure) turns the model and the dialog's choices into a **plan**: the print scale, the paper, every page and its rectangle in sheet units, the tiles, the index entries and the sizes to announce (§ 2–4).
- `print.js printDocument(model, plan, meta)` (pure, returns an HTML string) writes the pages: each page a `<section class="pp">` of the paper's exact size in mm, holding inline `<svg>`s whose `viewBox` is a rectangle of the sheet and whose content is `sheetSvg(model, rect, 'full', {k: 1, ids: false})`. Vector throughout: Chromium prints inline SVG as PDF vector paths and text.
- **Container**: `<div id="print-doc" hidden>` as the last child of `<body>`, filled on demand, emptied on `afterprint`. While a print is running `<html>` carries the class `printing`, and only then the print rules apply: `@media print { html.printing body > :not(#print-doc) { display: none } html.printing #print-doc { display: block } }`, `.pp { break-after: page; overflow: hidden; position: relative }`, `#print-doc { print-color-adjust: exact; -webkit-print-color-adjust: exact }` (kind colours and tints print without the "background graphics" option). Without `html.printing` a Ctrl+P prints the page as today (the Universe / Detail print rules stay "Later").
- **`@page` rule**: one `<style id="print-page">` element rewritten per print with `@page { size: <w>mm <h>mm; margin: 0 }` (numbers only, from the plan; no untrusted text). Every page of one print has the same size (the index pages use the tile paper), so one unnamed `@page` suffices; named pages are not needed (rejected below).
- **Printing**: the dialog's Print button builds the plan and the document, sets `html.printing`, waits two animation frames (layout of the container), calls `window.print()`; `afterprint` (and a fallback after `window.print()` returns, since Chromium blocks there) clears the container and the class, and gives the focus back to the toolbar's Print button. The live region says "Print document ready: 24 pages" before the browser's print window opens.
- **Invariants.** 7: nothing but the embedded payload is read. 8: names, types, key flags, kinds, lanes, relations and counts, the same structure the sheet shows. 9: no file name, format or storage key. 10: no library, no fetch, the document is built in the page; every name goes through `esc` inside `sheetSvg` and `printDocument`. 11: boxes keep their `unique_id`, as `data-id` (§ 5) since tiles repeat boxes and ids must stay unique in the DOM.

### 2. The paper model (D-095)

Units: the plan works in **millimetres** of paper; `mmPerU = floor / S.ROW_FONT × 25.4 / 72` (the print scale at which the smallest sheet text, 11 u, is exactly `floor` pt; 7 pt → 0.2245 mm/u). `floor` is the dialog's minimum font size, 5 to 14 pt in steps of 0.5, default 7 (`PRINT.FLOOR`).

**The size the scope needs** (always shown, the brief's "honest answer"): drawing `W × mmPerU` by `H × mmPerU`, written in metres with two decimals from 1,000 mm, else in centimetres ("Vehicle at key columns needs 0.62 m × 1.10 m at 7 pt (0.68 m²)"), through `num`.

**Papers** (`PRINT.PAPERS`, portrait mm): A4 210 × 297, A3 297 × 420, A2 420 × 594, A1 594 × 841, A0 841 × 1189; **Custom** w × h mm, each side 100 to `PRINT.MAX_SIDE` mm (§ 3); **Fitted** (one sheet only: the paper is the drawing plus its margins). Orientation portrait | landscape swaps the sides of a named or custom paper; for Fitted it is disabled with its reason ("The fitted paper follows the drawing", D-085).

**Margins** (`PRINT.MARGIN` = 10 mm on every side of every page, the band office printers cannot print in, where crop marks and labels go) and, on a one-sheet page, a **title band** of `PRINT.BAND` = 24 mm above the drawing (§ 3).

**Two outputs**:

| Output | Paper | Scale | Verdict shown |
|---|---|---|---|
| **One sheet** | Fitted (default when it applies, see below), or a named / custom paper | Fitted: exactly `mmPerU`. Named / custom: the drawing scaled up to fill the printable area (`min(areaW / W, areaH / H)` mm per unit), so text is at least the floor and as large as the paper allows | Fitted: "One sheet of 1.44 m × 3.34 m (margins and title included)". Named: "Fits on one A0 sheet at 9.4 pt" or, when the scale would put text under the floor, the option is **disabled with its reason**: "On one A0 sheet the text would be 4.1 pt, under 7 pt: choose Tiles or the fitted paper" |
| **Tiles** | A named or custom paper (Fitted disabled with its reason "Tiles need a paper size") | exactly `mmPerU` (text at the floor) | "8 × 13 tiles of A4: 92 sheets to print (12 blank positions skipped), plus 2 index pages" |

**Recommendation** (one line, under the verdict): the smallest named paper, in either orientation, on which one sheet holds the scope at the floor ("Smallest single sheet at 7 pt: A1 landscape"), or "No A-size sheet holds it at 7 pt: a print shop roll of 1.44 m width, or tiles". **Default choice** when the dialog opens: one sheet on that smallest named paper and orientation if any; else one sheet on Fitted when it is within `PRINT.MAX_SIDE`; else tiles on A4 portrait. The viewer's choices are kept while the page is open (dialog reopened), never saved (D-013).

**All columns** (brief: "offered per domain only"): the dialog's Show select offers all columns when the scope is a **domain** or holds at most `PRINT.ALL_MAX` = 300 tables (acme_retail's whole project, a layer of a small project); otherwise the option is disabled with its reason "All columns print one domain at a time: choose a domain as the scope". The screen keeps offering all columns everywhere (M9.4).

### 3. One sheet: the poster, and the page-size limit (D-095)

The page: paper `w × h` mm, margin 10 mm, the title band (title in 18 pt bold, then one line of 9 pt: scope · level · "minimum 7 pt" · "Schema of <date>" · "Printed <date>", § 7; then the **legend strip**, § 5) then the drawing, centred horizontally in the area, top-aligned, as one `<svg width="…mm" height="…mm" viewBox="0 0 W H">`. Four crop marks at the paper's trimmed edge are not drawn (a poster is not assembled; the print shop trims to the paper).

**Page-size limit.** A PDF page side is limited to 14,400 user units = 200 in = **5,080 mm** (PDF 1.x without `UserUnit`; Acrobat refuses larger pages, and Chromium's PDF writer is expected to clamp or emit pages that viewers reject). `PRINT.MAX_SIDE` = 5,080 mm, **to be confirmed by measure** (test plan 6: a page of 5,000 × 1,000 mm must print with that MediaBox; one of 5,200 mm is checked for what Chromium does; if Chromium clamps lower, the constant follows the measure and D-095 records it as a refinement). Handling: a one-sheet page with a side over `MAX_SIDE` is not offered (Fitted disabled with its reason "This sheet would be 6.20 m long; a PDF page stops at 5.08 m: choose Tiles, a smaller font or a domain"), and Custom sides are bounded by it. The large fixture's heaviest whole-project sheet (all columns, 3.71 m + margins at 7 pt) is within it; at 9.5 pt it is not (5.04 m drawing + 54 mm), which the dialog then says. A custom paper is also checked against nothing else: the print shop knows its rolls.

### 4. Tiles (D-096)

Paper `w × h` (named or custom, oriented), margin `m` = 10 mm, overlap `o` = `PRINT.OVERLAP` = 10 mm.

- **Grid.** Content area per tile `cw = w − 2m`, `ch = h − 2m` (mm). Step `sx = cw − o`, `sy = ch − o`. Drawing in mm `Dw = W·mmPerU`, `Dh = H·mmPerU`. Columns `nc = max(1, ceil((Dw − o) / sx))`, rows `nr = max(1, ceil((Dh − o) / sy))`. Tile (i, j) shows the sheet rectangle `x = i·sx/mmPerU`, `y = j·sy/mmPerU`, `w = cw/mmPerU`, `h = ch/mmPerU` (sheet units); adjacent tiles share exactly `o` mm. The grid is anchored at the sheet's top-left (deterministic, D-040's rule); the last column and row may run past the drawing (blank paper).
- **Coordinates.** Columns are letters A, B, … Z, AA, AB…, rows numbers 1, 2, …: tile "B3" is the second column, third row (map convention: letter across, number down). Pages are printed row by row (A1, B1, … then A2…), after the index pages.
- **Blank tiles** (`plan.tiles[].blank`): a tile whose own step rectangle meets no box, relation, chip or lane title (only lane tint or nothing) is **not printed** and is shown hatched on the assembly map, so a sparse whole-project sheet does not waste paper. The count line says how many were skipped.
- **Each tile page** (`printDocument`): the content `<svg>` placed at (m, m), `cw × ch` mm, `viewBox` = the tile rectangle, `overflow: hidden`; in the margin band, drawn as one SVG over the whole page:
  - **Crop marks**: at the four corners of the content area, two 5 mm hairlines (0.25 pt black) outside it, in the margin, offset 1 mm from the corner (they do not touch the drawing).
  - **Overlap ticks**: on each side that has a neighbour, two 3 mm ticks in the margin at the inner edge of the overlap band (`o` mm in from the content edge), so the assembler knows where the next tile's content starts: trim one tile at its content edge and lay it on the neighbour, the ticks matching its edge.
  - **Coordinates**: the tile name in 14 pt bold in the bottom-right margin corner ("B3"), and in the bottom-left margin, 7 pt or the floor if larger: "<title> · <scope> · B3 (column 2 of 8, row 3 of 13) · page 5 of 94". Neighbour names in 7 pt at the middle of each side that has one ("↑ B2", "→ C3", "↓ B4", "← A3").
- **A box cut by a tile edge** appears on both tiles (the overlap carries 10 mm of it: a row of 18 u = 4 mm at 7 pt, a header 5.4 mm, so a row cut at one edge is whole on the other tile when the cut falls within the overlap). Boxes are never moved to avoid edges: the tiles are cut from the one sheet so they assemble into it.
- **Index pages** (first in the print; same paper and orientation as the tiles; `PRINT.INDEX_FONT` = max(8 pt, floor)):
  1. **Title block**: the project title (18 pt bold), the scope and level ("Vehicle · key columns"), "Minimum text 7 pt · drawing 0.62 × 1.10 m · 8 × 13 tiles of A4 portrait, 10 mm overlap", "Schema of <date> · Printed <date>" (§ 7).
  2. **Assembly map**: the whole sheet as a thumbnail (`sheetSvg(model, whole, 'simple', {k: thumbK, ids: false})`, the M9.4 simple form, vector), at most half the content height, with the tile grid over it (0.5 pt lines, tile names centred in each tile at 8 pt on a white halo, blank tiles hatched and named in grey "not printed").
  3. **Legend** (§ 5).
  4. **Tables → tile**: every table of the scope, sorted by name (ties by `unique_id`; a duplicated name shows its id in grey, as the search list), "car_hub ……… B3". Its tile is the tile whose **step** rectangle (`[i·sx, (i+1)·sx) × [j·sy, (j+1)·sy)` mm) holds the box's top-left corner + half a header (where its name reads), so each table has exactly one tile even inside the overlap. In columns (as many as fit at `max(48 mm, longest entry)` width), one line per entry at 1.4 × the font, names cut with `common.js ellipsis` at the column width (measured, the sheet's font). **The pagination is done in JavaScript**, not by the browser: the plan knows how many lines each page holds (the first page has less room), so `plan.pages` is exact and the PDF's page count is checkable; overflow is never left to CSS fragmentation.
- **Order of magnitude** (to be measured, test plan 7): the large fixture's whole project at keys, 7 pt, A4 portrait: 8 × 13 = 104 positions, of which the empty corners of short rows are blank; Vehicle (299 tables) is expected around 3 × 5 A4.

### 5. Black and white: kind tags and the legend (D-095)

The M9.4 UI review found Hub and Link headers near-identical in grayscale. Colour stays (a colour printer or plotter prints it), and a **kind tag** is added to every printed box header so the kind reads without colour:

- `schema.js kindTags(kinds)` (pure, deterministic): for each payload kind in order, the shortest unique tag of its label (`labelOf`): the first letter upper-cased; on a clash the initials of its words ("Point in time" → "PIT"), then its first two, then three letters; still clashing, the kind's 1-based position ("K7"). Tags are at most three characters plus digits. Example: Hub H, Link L, Satellite S, PIT P… (whatever the config's labels give).
- `sheetModel(…, {tags})` passes each node's tag to `boxSize(n, level, tag)`: the header width reserves `textW(tag, S.ROW_FONT, 600) + PAD_X` more (so a name still never meets its tag); the model carries `tags` and `sheetSvg` draws the tag right-aligned in the header, 11 u (the floor) 600 weight, in the header's `textOn` colour. Without `tags` (the screen) both functions are unchanged, output-identical (checked).
- **Legend** (index page, and the poster's legend strip): per kind present in the scope, a small sample header (its colour, its tag in `textOn`) then its label and its count ("**H** Hub 42"); then the reading keys, each drawn with the real marks: a bold row "key column"; an italic "+ 5 columns" "columns not shown at this level"; a relation with its crow's foot "the referencing table (foreign key side)" and its arrowhead "the referenced table (key side)"; a chip "→ Auction · Raw vault 12: relations to another lane, counted, not drawn"; a dashed chip "relations to tables outside this scope"; the lane heads "columns: layers in data-flow order · rows: domains". Domain row heads already carry their names in text; no colour carries meaning alone.

### 6. The dialog (D-095)

A native `<dialog id="s-print">` opened with `showModal()` (focus inside, `Esc` and the browser's own focus trap, inert background), from a **Print…** button `#s-print-btn` in the Schema toolbar right after the export group (outside `.canvas-box`, never in an image). The button is disabled with its reason while the sheet is computing or the scope is empty (D-085). Contents (`<form method="dialog">`), top to bottom:

1. Heading "Print the schema" and the scope line ("Vehicle · 299 tables"; to change it, the tab's Scope select: the dialog does not duplicate it).
2. **Show** select (names / key columns / all columns, `common.js LEVELS`; starts at the tab's level; all columns disabled with its reason per § 2).
3. **Minimum text size** number input (pt, 5–14, step 0.5, default 7) with its unit.
4. **Output** radio pair: One sheet | Tiles.
5. **Paper** select: Fitted to the drawing (one sheet only) | A4 | A3 | A2 | A1 | A0 | Custom; **Custom** shows two number inputs w × h mm (100 to 5,080); **Orientation** radio pair Portrait | Landscape.
6. **Needs** block `#s-print-needs` (`role=status`, polite, updated on every change, debounced 150 ms; the model is recomputed only when the level changes): the size line, the verdict line, the recommendation line (§ 2), all text.
7. Help line: "In the print window choose Save as PDF or your printer, margins None (or Default), scale 100 %." (`.hint`)
8. Buttons: **Print** (primary; disabled with its reason when the verdict says no) and **Cancel**.

At 360 px the dialog is full width and scrolls inside (max-height 90vh). 44 px targets under coarse pointers (D-035). Every string in en and fr (§ Strings proposal below; the ui-designer settles them).

### 7. Dates: from the manifest and from the viewer's clock (D-095)

The index page and the poster band carry **two dates**, each with its meaning:

- **"Schema of 17 November 2026"**: the structure's date, the manifest's own `metadata.generated_at` (written by `dbt parse`). It travels as a new payload key **`PagePayload.generatedAt`** (`str | None`, last key): `manifest_schema.Metadata.generated_at: str | None`, `model.Project.generated_at: str | None = None` set by `manifest.parse_manifest` verbatim (no parsing, no clock), `render_page(…, generated_at=None)` and `cli.py` passing `project.generated_at`. The page shows its date part (`YYYY-MM-DD` read from the string, formatted with `Intl.DateTimeFormat(PAGE.lang, {dateStyle: 'long', timeZone: 'UTC'})`); an absent or unreadable value omits the phrase.
- **"Printed 18 November 2026"**: the viewer's clock (`new Date()`) at the moment Print is pressed, formatted the same way in the viewer's time zone.

Why: a poster on a wall is read weeks later; what matters is how old the **structure** is, which only the manifest knows (invariant 7: the manifest is the only source), and the manifest's own date is deterministic for a given input (the reference pages stay reproducible). Taking the date from the page build instead would need `domain/` to be given `now` (invariant 1 allows it when passed in) but would change every page's bytes on every build, break the byte identity of the M3 reference pages, and date the page, not the schema; with the fallback of `cli._parse` (an older manifest when `dbt parse` fails) it would even lie. The print date is a fact of the print run, not of the structure: it is read in the browser, where invariant 1 does not apply (it constrains `domain/`), and only when the viewer prints; `printDocument(model, plan, meta)` takes it as `meta.printed` so the tests pass a fixed date.

### Formats and compatibility

- **Payload**: `PagePayload.generatedAt` (string or `null`), new last key; the M3 reference pages are regenerated once (their manifests may carry no `generated_at`: then `null`); a diff assertion checks nothing else changed. `Project.generated_at` defaults to `None`, so hand-built projects and tests are unchanged.
- **Config, layout format, layout scopes, localStorage keys, export file names**: unchanged; no migration. No file is written by dbtscope for printing (the PDF is the browser's).
- **Existing users**: a Print… button and dialog in the Schema tab; the screen sheet is unchanged (tags are print-only).

### Error handling

No new Python failure path (`generated_at` absent or not a string → `None`, the field is optional and read leniently, `INPUT` config). Page: the plan never throws on a valid model (empty scope: the Print button is disabled); a document build that throws shows `L.error` with the message in the dialog's needs block and leaves `html.printing` unset (a `try`/`finally` clears the container); a browser without `<dialog>` support (none of the supported ones) is not handled; `afterprint` missing (some browsers) is covered by the cleanup after `window.print()` returns and by the next open.

## Rejected options

- **A PDF written in Python or a JS PDF library**: a new dependency (Python) or a new vendored library and a second renderer of the sheet (brief § 3 row 6 decided the browser's print-to-PDF).
- **Printing the screen's SVG with a print stylesheet** (the Schema stage scaled into `@page`): the screen holds only the virtualised part, the simple form when far, selection marks and HTML overlays; and no tiling.
- **Raster tiles (PNG per page)**: not vector, enormous at poster size, blurred text.
- **Named pages (`@page index`, `@page tile`, `@page poster`)**: every page of one print has the same paper; one rewritten unnamed `@page` is simpler and works in more browsers.
- **Letting the browser paginate the index**: the page count would only be known after printing, so the dialog could not announce it and the tests could not check it.
- **Repacking boxes per tile so none is cut by an edge**: the tiles would no longer assemble into the poster; the overlap carries cut rows instead.
- **The page build date** (`now` passed into `domain/`): changes every page's bytes, breaks the reference pages' byte identity, dates the page instead of the schema, and is wrong under the parse fallback. **The manifest file's mtime**: read by `storage`, changed by a copy or checkout, not the parse moment. **The viewer's clock only**: tells nothing of the structure's age.
- **Colour only in print, grayscale by luminance**: the review's finding stands (Hub and Link near-identical); **patterns per kind** (hatching headers): unreadable at 7 pt, at most a handful of distinguishable patterns; **the full kind label in each header**: widens every box by ~60 u.
- **Kind tags on screen too**: not asked, clutters the screen where colour and the tooltip already tell the kind.
- **Scaling one sheet below the floor to fit a paper**: the floor is the reader's requirement; the dialog says what fits instead.
- **All columns for any scope** in print: a whole-project all-columns poster is 1.55 × 3.71 m of mostly unread rows; the brief offers it per domain.
- **A CLI `--print`**: out of scope (brief § 9).
- **Remembering the dialog's choices** (localStorage): a new key (D-013) for a choice made in seconds.

## UI design (ui-designer, 2026-11-17)

Task and decision. A viewer who has a scope on screen asks "can I put this on paper, and on what?" The decision: **one sheet or tiles**, on **which paper**, at **what text size**. The dialog's job is to answer before printing, in one block that is always in view, then to print in one press. Everything is the architect's decided scope (brief § 9, D-095, D-096). NEEDS USER APPROVAL: none. No conflict with the note; six small clarifications, none changes the payload, a decision or a format:

1. **The needs block is first, and sticky** (the note lists it after Paper). It is the answer, and at 360 px a block placed after five fields scrolls out of sight while the user edits them. Single column at both widths; the block sticks to the top of the dialog's scroll area.
2. **Units of the size line.** The note's rule (metres from 1,000 mm, else centimetres, per side) would write "62 cm × 3.30 m" for a narrow, tall sheet and contradicts its own example "0.62 m × 1.10 m". Rule: **one unit for both sides, chosen by the longer side**: longer side at least 1 m: metres, two decimals, plus the area ("4.69 m²"); else centimetres, whole numbers ("42 cm × 30 cm"), no area. `num` gains an optional `decimals` argument (`n.toLocaleString(PAGE.lang, {minimumFractionDigits: d, maximumFractionDigits: d})`), so French reads "1,42 m × 3,30 m".
3. **Print closes the dialog** (the note's focus return to the toolbar button implies it). Choices stay in memory while the page is open (D-013: nothing saved), so reopening after a cancelled print window costs one click.
4. **One-sheet band height is computed.** The 24 mm band holds title and info line; the **legend strip** below it wraps, so on A4 it takes two or three lines. `plan.band` = 24 mm + legend lines × 7 mm (an extra plan field; the drawing area is `h − 2·margin − band`). The page-limit and fitting maths use `plan.band`, not the constant.
5. **Edge opacity on paper.** The screen edge (`#8a8f98` at .5) prints at about 1.7:1 on white, and fainter on a laser. Print passes `marks.edge = .8` (one optional mark; absent = .5, screen output identical). Prove on a test print or the PDF render; no other look change.
6. **Running head on index pages** (range of names on the page), added because a 1,400-name index with no landmark is slow to scan; no letter headings (they cost lines and add nothing).

### The needs block (`#p-needs`, `role=status`, `aria-live=polite`, `aria-atomic=true`)

Three text lines, re-written 150 ms after the last change (the model recomputed only on a level change):

1. **Size** (always): "Vehicle at key columns needs 1.42 m × 3.30 m at 7 pt (4.69 m²)."
2. **Verdict**: one of: fits ("Fits on one A1 sheet at 9.4 pt." / "One sheet of 1.44 m × 3.34 m (margins and title included)."); no ("On one A0 sheet the text would be 4.1 pt, under 7 pt: choose Tiles or the fitted paper."; "This sheet would be 6.20 m long…"); tiles ("8 × 13 tiles of A4: 92 sheets (12 blank skipped), plus 2 index pages"). A "no" verdict is plain text with a leading "Not possible:" word in the same ink (not a colour); a fits verdict has no prefix. No red, no green, no icon.
3. **Recommendation**: "Smallest single sheet at 7 pt: A1 landscape" / "No A-size sheet holds it at 7 pt: a print shop roll of 1.44 m width, or tiles".

All three lines are one polite, atomic region; the 150 ms debounce keeps typing in the size field from chattering, and the text is rewritten only when it changed. While the model is recomputed (level change on a large scope, up to a second): the block shows "Calculating…" (`T.calculating`) `aria-busy=true`, Print disabled.

## As built (M9.5, 2026-11-17)

Built as designed (D-095, D-096, the six UI clarifications). Deviations and measures; none changes a format or a decision, one refines D-095.

**Chromium's page limit (the measure).** `page.pdf(prefer_css_page_size=True)` writes a page of any size it is given: 5,000 mm (MediaBox 14,173 pt), 5,080 mm (exactly 14,400 pt), 5,200 mm, 6,000 mm, 10 m, 20 m, 50 m and 200 m (566,929 pt) all print one page per `.pp` with the true MediaBox, on either side (`tests/browser/test_print.py::test_the_page_sizes_chromium_writes_are_not_clamped`, 5,000 and 5,200 mm). Chromium does not clamp. So `PRINT.MAX_SIDE` stays **5,080 mm**, now with its reason stated as the PDF viewers' limit (Acrobat and most viewers stop at 14,400 pt = 200 in), not Chromium's: a poster longer than that would print but not open everywhere. Recorded in D-095.

**Sizes with the kind tags.** The print model is a second sheet because tags widen headers, so the announced size is the tagged one and slightly larger than the screen sheet's (the note's 1.42 × 3.30 m): whole project at 7 pt, names 0.99 × 2.31 m, keys **1.46 × 3.38 m** (4.9 m²), all columns 1.52 × 4.07 m; Raw vault layer at keys 1.02 × 2.51 m; Vehicle at keys 1.14 × 0.61 m (7 × 3 A4 tiles: 18 printed, 3 blank, 3 index pages, 21 pages), at all columns 1.14 × 0.71 m. At 7 pt the whole project fits one fitted sheet within the 5.08 m page limit; at 14 pt it does not (the dialog says so and moves to A4 tiles).

**Measured** (large project, 1280 × 800, headless Chromium, median of 5, in the page around the pure functions; `tests/browser/test_print_perf.py`): model with tags 31 to 52 ms for the whole project (2 to 15 ms for a domain), `printPlan` 4 ms for a sheet and 18 to 22 ms for the whole project in tiles (budget 100), `printDocument` 11 ms (sheet) and 48 ms (whole project at keys in tiles), DOM insertion and layout 165 ms (sheet) and 423 ms (tiles, 88 pages, 3.8 MB of markup): **the whole project at keys in A4 tiles is ready in about 0.5 s** (budget 3,000 ms). PDFs written by Chromium: Vehicle at keys, A4 tiles, 21 pages, 1.3 MB, `page.pdf` 0.5 s (guard 30 s); whole project fitted sheet, 1 page, 0.2 MB, 0.4 s; whole project in A4 tiles, 88 pages, 5.2 MB, 2.8 s. The page-count of every PDF checked equals `plan.pages`. The optional `<symbol>` / `<use>` sharing of the plan was not needed.

**Deviations.**

- **Edge opacity (clarification 5)**: not changed. `LOOK.edgeAlpha` is already 1 (raised by the M9.4 review: `LOOK.edge` is `#767c86`, 3:1), so the `marks.edge = .8` of the note would have made the print fainter than the screen. No `marks.edge` option was added.
- **`marks.bare`** (new, optional): the assembly map draws the sheet's simple form with no chips and no text (a badge would be 14 px, about 10 pt, on a map). Absent, output is identical.
- **Needs sentence**: "Vehicle with key columns needs 1.14 m × 0.61 m at 7 pt (0.70 m²)." (the note's "at key columns" does not read for "names"; French "avec colonnes clés demande"). Sizes of 1 m or more are metres with two decimals and the area, else whole centimetres, both sides in one unit.
- **Page band is exact**: `plan.band` = the title and info block (at least 24 mm, wrapped lines counted) + the legend's measured height + 3 mm (the note's "24 mm + 7 mm per legend line", computed). The legend and the title block are sheet-unit / mm markup measured with `textW`, never CSS-wrapped. A fitted paper's drawing area is at least 120 mm wide (`PRINT.MIN_FIT`) so a one-box scope still has room for the title.
- **Index columns** are at most 56 mm wide (the note: the longest entry), so an A4 portrait index has three columns; longer names are cut with an ellipsis. Entries are drawn as SVG text with a dotted SVG leader, not CSS flex.
- **Index entry of a duplicated name** shows its id in grey after the name when it fits, else the name is cut and the id dropped.
- **Overlap ticks** are drawn on every side that has a neighbour in the grid; the neighbour hint (arrow and name) only where that neighbour is printed.
- **Model recomputation** keyed by the tab's `nodes` array and the dialog's level; the defaults (best paper) are recomputed when the scope changes, the viewer's own choices kept otherwise. Opening the dialog shows "Calculating…" first and fills it on the next task.
- **Reference pages** regenerated twice: with `generatedAt` (domain commit, only that key changed) and with the page assets (print commit, sizes and sha256 only; every payload equals the one of the domain commit).
- **Handle**: `print` on `startSchema`'s handle is `{open, close, plan(opts), build(opts, now), clear, choices, model(level)}`; `build` also sets `html.printing` (the test prints it with `page.pdf`), `clear` undoes it. `afterprint` empties the document (also after the test's `page.pdf`, so the DOM is checked before the PDF).
- **Schema toolbar at 360 px**: Print… is a third button group after Fit and the export buttons; to keep the toolbar at two rows in French (M9.4 review test), the search box is `border-box` and the Fit, PNG, SVG and Print… buttons take 4 px side padding at 600 px or narrower.
- The example page grows from 455 to 516 kB (`print.js` 52 kB, the dialog and CSS); the user guide's quoted sizes follow.
