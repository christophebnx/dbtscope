# M5.13 — Constellations by domain or by layer (design note)

Status: Implemented. The user approved the feature on 2026-11-05 and, the same day, chose the per-viewer memory of § 7 (a localStorage key `dbtscope-constellations:<title>`, written only when the choice differs from the config default, never exported, every access wrapped so the page works without storage). D-048 is Accepted with that choice. **Implemented** on 2026-11-05 (default suite 606, browser suite 304 tests green).

## Implementation and review fixes

What the build changed from this note, or settled where it left a choice:
- **Names.** `bands(members)` is `bandsOf`; `BY[state.by]` is read through `grouping()`. Layer-mode drawing helpers: `bandSpans`, `rimAngle`, `rimHalf`, `drawDomainBands` (tints from `TINT`, cached in `TINTS`), `drawBandNames`, `layerTip` (`TIP_DOMAINS` = 12).
- **Force strength.** Layer mode uses `flowX` 0.3 (§ 1, recorded below); domain mode keeps 0.06.
- **Name lift.** In layer mode the constellation name, count line and composition bar are raised `NAME_LIFT` = 8 px, so the bar ends 4 px above the rim arcs instead of touching them.
- **Radio rows.** `.panel input[type=radio]` takes the checkbox's default margin, so on a desktop the radio rows align with the checkbox rows (same height, same left edge).
- **One display-name rule.** `common.js labelOf(item)` = `label ?? key`, used by the panels, tooltips, canvas and flow view. Small visible change: a layer whose rule sets `label: null` now shows its key; before, the panel showed nothing and the tooltip and the flow "null". `detail.js` keeps a local `labelOf` for an entity's name (a different responsibility).

## Context

**Request.** The universe view gets a switch, **Constellations: Domains | Layers** ("Constellations : Domaines | Couches").
- **Domains** (the default): today's map, one constellation per domain with layer bands inside (D-040).
- **Layers**: one constellation per layer, in flow order. Inside each one, the tables sit in bands by domain (the mirror of today), and domain colours are kept.
- The switch is hidden when the project has fewer than two layers.
- The default comes from `dbt-erd.yml`.
- Nothing is specific to medallion projects. It must work for star schemas, flat projects and odd tables.

**Current state.**
- `domain/universe.py` gives every `UniverseNode` a `domain` (`domain_of`, D-015) and a `layer` (`_layer_of`). `UniversePayload.layers` is already in flow order (configured rules, then `other`; or folders sorted by `flow_rank`).
- `render/assets/universe.js` groups the visible tables by `n.domain` in `layout()`.
  - `layoutDomain` packs a domain's tables into layer bands (`layerBands`, `flowRanks`, `packRow`).
  - d3-force (seed 42) places the domains, with `forceX` by the domains' mean layer rank. Routes are counted between pairs of domains.
  - Saved positions are read and written through `LAYOUT.get/set('universe', state.detail)`, as `{domains: {key: [x, y]}, nodes: {unique_id: [dx, dy]}}`.

**The browser can regroup from `node.domain` and `node.layer` alone.** The payload already holds both, the layer order and the domain order and colours. Python only has to embed the configured default (§ 4).

## Chosen design

### 1. One grouping descriptor, every layout step generic (universe.js)

A constant `BY` in `startUniverse` describes what a constellation stands for. `state.by` is `'domains'` or `'layers'`.

| | `domains` | `layers` |
|---|---|---|
| `of(n)`: the constellation key | `n.domain` | `n.layer` |
| `band(n)`: the band position, or `null` for "no band" | `layerPos(n)`: the layer position, `null` for the catch-all `other` (D-040) | the position of `n.domain` in `DATA.domains`; never `null` |
| `bandKey(pos)` | `DATA.layers[pos].key` | `DATA.domains[pos].key` |
| `rank(key, members)`: x target of the force | mean layer rank of the members (today) | `LAYER[key].rank` |
| `info(key)`: label, colour, owner | `DOM[key]` | `LAYER[key]` label, a neutral colour (§ 5), no owner |
| `pins`: key of the pinned centres in a saved arrangement | `domains` | `layers` |
| `scope`: layout scope | `state.detail` (today) | `'layers:' + state.detail` |

Changes:
- **`layerBands`** becomes **`bands(members)`**. It reads `BY[state.by].band`, and its code is otherwise unchanged:
  - in-band lineage is kept for `flowRanks`;
  - tables with a `null` band are placed by rank range;
  - tables are ordered by barycentre, then name, then id.
  
  In layer mode no table has a `null` band, so the catch-all rule simply never applies. `bands` returns `[{key, tables}]`, where `key` was `layer`.
- **`layoutDomain`** becomes **`layoutConstellation`**. Same packing, `rank` from `BY`.
- **`layout()`** groups by `BY.of`.
  - The cache key gets `state.by` first. A layer key may equal a domain key.
  - Routes count pairs of constellations, and their `flow` direction uses lineage between constellations, as before.
  - Saved pins are read from `saved[BY.pins]`.
- **Drag** pins `saved[BY.pins]` and moves the tables with `BY.of(n) === s.d.k`. `savedLayout()` uses `BY.scope`.
- **Drawing** uses `BY.of` wherever it now reads `.domain` to mean "the constellation":
  - `cross` links;
  - the trajectory's context alpha (`tdom`);
  - the constellation the drag end looks up.
  
  `countByDomain` (trajectory breakdown, flow legend) stays per domain in both modes (D-018, D-036).
- **Renaming.** The internal array `domains` becomes `constellations` (entries `{k, rank, n, bands: [{key, x0, x1}], r, mix}`). The test hook `geometry()` returns `{by, constellations: [{key, x, y, r, bands: [{key, x0, x1}]}], tables}`, and the 4 uses in `tests/browser/` are updated.

Domain bands are ordered as `DATA.domains`: largest first, "No domain" last, the order of the Domains panel. So a domain keeps the same relative position in every layer constellation. Layer constellations get `forceX` by layer rank (strength 0.06, as today), so they read left to right along the flow. The acceptance test in § Test plan checks that order. If the force cannot guarantee it on the example and on the 1,500-table payload, the developer may raise the `forceX` strength **in layer mode only**, and records the value in this note.

**Recorded (developer, 2026-11-05).** At 0.06 the layer constellations of the 1,500-table payload are out of order (`marts` right of `reports`'s left neighbour). Layer mode uses **0.3** (`BY.layers.flowX`); domain mode keeps 0.06, so its geometry is unchanged. At 0.3 both acme_retail and the 1,500-table payload read strictly left to right, with a clear margin (0.15 passed only narrowly).

### 2. What does not change

- **Filters.** The Layers, Types and Domains panels, their counts, **all / none** (domains) and `visible` (domain ∧ layer ∧ kind) behave the same in both modes. Unticking a layer removes a constellation in layer mode and a band in domain mode. Unticking a domain does the opposite.
- **Search and `reveal`** are unchanged.
- **Trajectory mode** (D-018) is unchanged.
  - Switching keeps the trajectory: `relayout()` already re-renders the bar and `fit` frames it.
  - The breakdown stays per domain.
- **Flow view** (D-036) is unchanged: its columns are lineage and layers, and its domain bands do not depend on the universe grouping.
- **Detail tab opening** (double-click) is unchanged.
- **Semantic zoom thresholds** (0.35, 0.5, 0.6) and the name competition are unchanged.
- **Image export** draws what is shown, with the same file name.

### 3. Switch: visibility and default (universe.js, page.html)

- **Control.** First in the universe panel, above Links, with the heading "Constellations". The ui-designer chose a native radio pair (`fieldset#u-by`, legend `#u-h-by`) over a `select`: see § UI design.
- **Hidden** (`hidden` on the fieldset) when `DATA.layers.length < 2`, that is, when the Layers panel has fewer than two rows. "Other" counts: it is a row of the panel.
  - Example: a flat project with sources gets `sources` and `models`, two layers.
  - When the switch is hidden, `state.by` is forced to `domains` whatever the config or the memory says, and the page is unchanged.
  - One rule, in the browser only: Python embeds the configured value as is.
- **Initial `state.by`**, in this order:
  1. the per-viewer memory (§ 7), if valid;
  2. `DATA.defaults.constellations`;
  3. `domains`.
- **On change:** `state.by` is set, the memory is written (§ 7), then `relayout()` (layout, bar, `fit(false)`, draw), as Links and Tables do.

### 4. Config and payload (domain/config.py, payload.py, universe.py)

- **Config.** `config.Constellations = Literal["domains", "layers"]`, declared once in `config.py` like `Links`, and reused by `payload`. A new key `UniverseSettings.constellations: Constellations = "domains"`.
  - `PresetUniverse` inherits it, so presets may set it (D-030).
  - Any other value is the existing one-line validation error (`config <path>: universe.constellations: …; fix the file`, exit 1).
  - The `config.py` docstring gets the line `constellations: domains     # domains | layers`.
- **Key name.** The key is `constellations`, not `group`: "group" is already the `group_by` value and the dbt group (glossary, D-027).
- **Payload.** `UniverseDefaults.constellations: Constellations`, declared **last**, so the JSON change is a tail addition: `"defaults":{…,"hiddenKinds":[…],"constellations":"domains"}`. `universe_data` passes `universe.constellations`.
- **Reference pages.** The page bytes change anyway, because `universe.js` is inlined (D-028), so the M3 reference `expected.json` is regenerated in the asset commit. Every `payloads/*.json` gains exactly this one key and nothing else. The diff is reviewed as such: no other byte of any payload changes.
- **No CLI option.**

### 5. Drawing in layer mode (universe.js; details for the ui-designer)

- **Constellation disc and name.**
  - A layer has no colour in the payload, so the disc, its halo and its name use a neutral ink, `THEME.muted` (5.3:1 on the page: passes 3:1 for the mark and 4.5:1 for the text, D-037 / D-042).
  - The count line and the composition-by-kind bar are as today.
- **Domain bands carry the domain colour at every zoom.** In domain mode, layer bands only get faint separators at scale ≥ 0.6. In layer mode, each band is the only domain cue, so:
  - each band is filled with a light tint of its domain colour, clipped to the disc;
  - a mark in `CONTRAST.edge(domain colour)` (a bar of 6 px or less, D-042) sits at the top of the band's chord;
  - the separators stay as in domain mode.
  
  The ui-designer sets the alphas and the bar size, and decides whether band names are drawn at constellation zoom.
- **Colour is not the only cue (WCAG 1.4.1): the tooltip.** Over a layer disc, the tooltip shows:
  - the layer label and its table count;
  - the line "Domains: Sales · Finance · …" ("Domaines : …", joined with `L.colon`, then " · ", since domains have no flow order);
  - when the pointer is over a band, the line "Domain: <label>" ("Domaine : …");
  - the action line "Double-click: zoom on this constellation".
  
  The domain-mode tooltip is unchanged, including "Layers: A → B".
- **Meta line.** "N tables · N links · N layers" ("couches") in layer mode, through a new `T.layersN`, `['layer', 'layers']` / `['couche', 'couches']`.
- **Hint.** "drag a table, or a domain by its name" becomes "… or a constellation by its name" ("… ou une constellation par son nom"), in both modes.
- **Strings**, in the universe's own `T`, en and fr:
  - `by` "Constellations" / "Constellations";
  - `layersN`;
  - `domainsLine` "Domains" / "Domaines" (reuse `T.domains`);
  - `domainOne` "Domain" / "Domaine";
  - `frameC` "Double-click: zoom on this constellation" / "Double-clic : cadrer cette constellation";
  - the hint.
  
  French spacing follows D-039.
- **Narrow screens.** The radio pair sits in the panel, which starts closed at 600 px or narrower (D-035), stacks at most 45vh, and gets 44 px rows on coarse pointers like the checkbox rows. The toolbar is untouched, so there is still no horizontal scroll at 360 px.

### 6. Shared manual layout: backward-compatible scopes (D-013 extended, not superseded)

- **Scopes.** The `universe` section of the layout (in memory, in localStorage `dbt-erd-layout:<title>` and in `dbt-erd-layout.json`) is a mapping of scopes. Today its scopes are `names`, `keys` and `all`. Layer mode adds three optional scopes, `layers:names`, `layers:keys` and `layers:all`, each `{layers: {<layer key>: [x, y]}, nodes: {<unique_id>: [dx, dy]}}`. A table offset is relative to its **layer** constellation's centre.
- **Format unchanged:** format `dbt-erd-layout`, version 1, the localStorage key, the file name, and the existing scopes and their shape.
- **Compatibility.**
  - An old file or stored arrangement loads unchanged: no `layers:*` scope, so layer mode is computed.
  - A page from before M5.13 reads only its own scopes. It ignores the new ones and keeps them on export, since `dump` spreads `data` and `LAYOUT.set` replaces one scope only.
  - Dragging in one grouping never moves the other.
- **No change in Python.** `domain/layout.check_layout` already accepts any scope inside a mapping `universe` section, so `layout.py` and `LAYOUT_SECTIONS` are unchanged. A comment in `layout.py` and the `render/CLAUDE.md` rule name the scopes.
- **Reset layout** on the Universe tab still runs `LAYOUT.clear('universe')`, so it clears both groupings, as it already clears every detail level. The confirmation already says "this tab".

### 7. Per-viewer memory of the grouping (user decision, 2026-11-05)

- **Storage.** A new localStorage key `dbtscope-constellations:<title>` holds `domains` or `layers`.
  - It is written only when the choice differs from `DATA.defaults.constellations`. Choosing the default again removes it, so a later change of the team's default reaches every viewer who never deviated.
  - It is read at start, and any other value is ignored. Every read, write and removal is wrapped (`try` / `catch`), as in `LAYOUT`: without storage (private mode, blocked, quota) the switch works for the session and nothing is shown.
- **Kept out of the layout object.** It is not exported, so one viewer's preference never becomes the team's default through `dbt-erd-layout.json`. It also does not fall under the `savedAt` "newest wins" rule, which would drop it whenever a newer layout file is embedded.
- **One helper:** `universe.js byMemory` (`get()`, `set(value, fallback)`).
- **Rejected by the user:** session-only memory (the choice lost on reload, the config default each time).

### 8. Error handling

- An invalid `universe.constellations` stops the run with the one config line, exit 1. Nothing is written.
- A `layers` default on a project with fewer than two layers is silently domains: the page shows no switch. No CLI warning: the CLI does not know the layer count, and the page stays correct.
- Corrupt memory or layout scopes are ignored by the page and the computed placement is used, as today.

## Rejected options

- **A layer constellation's colour from the `layers` rule `color`.** `UniverseLayer` would gain a field, so every payload changes. Default folder layers have no colour, so a palette rule would be needed. And the user asked to keep domain colours. This could come later.
- **Domain bands stacked as rows** (domains top to bottom, flow left to right across discs, a matrix reading). It needs a second packing, and table boxes are wide, so rows waste room. `packRow` is reused instead (invariant 2).
- **Python computing the effective grouping** (forcing `domains` below two layers). The rule would exist twice, since the browser must hide the switch anyway. The browser owns presentation (invariant 10).
- **Omitting `constellations` from the payload when it equals `domains`**, to keep the payloads byte-identical. It needs a custom serializer, which is logic in `payload.py`, or pydantic 2.11's `exclude_if`, which raises the floor (D-025). The page bytes change anyway with the assets.
- **A new top-level layout section** (`universe_layers`). It would need `LAYOUT_SECTIONS`, `check_layout` and Reset to change, for nothing scopes do not already give.
- **Reusing the `domains` pin key for layer pins.** A layer pin would be stored under a key named for domains (D-027).
- **Storing the viewer's choice in the layout object.** It would be exported to the shared file and lost on newer embedded layouts (§ 7).
- **The config key `group`.** It clashes with the glossary's group (D-027).
- **A toolbar segmented switch.** The toolbar already wraps at 360 px. The panel holds the other view settings (Links, Tables).
- **Fixed positions for layer constellations in a row.** Long routes such as Sources → Gold would cross the discs between them. d3-force is reused, with its order checked by a test.

## UI design

### Task and decision

- **Task.** An analyst or a manager wants the estate read by tier, not by domain: "what sits in Gold, and for which domains?", "which domains have no Silver yet?". A data engineer wants to check that a layer only reads the layer before it (the routes between layer constellations).
- **Decision.** Which grouping answers the question at hand; then, in layer mode, which domain band of which layer to zoom into or open.
- **Information needed.** Both choices visible at once with how many constellations each gives; in layer mode, each band's domain at a glance (colour, then its name close up, then the tooltip), and the Domains panel as the colour legend.

### Control: a native radio pair in the panel, not a select

The architect's `select` is replaced by two native radio buttons (`fieldset` + `legend`), first in the universe panel, above Links.
- **Why radios.** Two exclusive options: both are visible without opening anything, so a first-time viewer discovers that a layer view exists, and switching is one click or one arrow key instead of two. The rows look and behave like the panel's existing checkbox rows (same `label` row, same 44 px on coarse pointers), so no custom segmented widget is added. Links and Tables keep their selects: three options each, and they are read less often.
- **Counts.** Each row shows, right-aligned in the muted `small` of the filter rows, how many constellations that choice gives over the whole project (`DATA.domains.length`, `DATA.layers.length`, through `num`). They do not follow the filters.
- **Markup** (page.html), replacing `#u-h-by` / `#u-by`:
  ```
  <fieldset id="u-by" hidden><legend id="u-h-by"></legend>
    <label><input type="radio" name="u-by" value="domains"><span id="u-by-domains"></span><small id="u-by-domains-n"></small></label>
    <label><input type="radio" name="u-by" value="layers"><span id="u-by-layers"></span><small id="u-by-layers-n"></small></label>
  </fieldset>
  ```
  The group is named by its legend, each radio by its row; no ARIA attribute is needed. `hidden` is removed when `DATA.layers.length >= 2`.
- **Change.** The radios' `change` event (fired by click, tap, arrow keys or Space) runs § 3's on-change: `state.by`, `byMemory.set`, `relayout()`. The checked radio is set from the initial `state.by` before the first draw.
- **Existing gap, fixed in passing.** The Links and Tables selects are not tied to their headings. `aria-labelledby="u-h-links"` / `"u-h-detail"` on `#u-links` / `#u-detail` (and `d-h-group`, `d-h-depth` in the detail panel) gives them a name; nothing visible changes. Developer: two attributes per select in page.html.

### Drawing in layer mode

Domain mode is drawn exactly as today. In layer mode:
- **Constellation disc.** No radial fill (the bands tint it). Outline as a domain disc's, in `THEME.muted`: `muted + '66'`, 1.5 px screen width, `ctxAlpha` as today.
- **Constellation name.** The layer label, 600 weight, same size rule as a domain name, in `C.text` (`THEME.fg`, 14:1); the count line in `C.muted` and the composition-by-kind bar unchanged. Same name competition and `labelHits` (drag by the name, double-click frames).
- **Band tint.** Each domain band is a vertical strip of the disc, from the midpoint with the previous band (the disc's left edge for the first) to the midpoint with the next (the right edge for the last), clipped to the disc, filled with an **opaque** colour: the page background mixed with `CONTRAST.edge(domain colour)` at **6 %**, computed once per domain. Why 6 %: it is lighter than today's domain disc centre (15 %), so table stars, cards and names keep at least the contrast they have in domain mode; muted text on it stays at 4.6:1 even for a black domain colour (4.5:1 needed, D-037).
- **Band mark.** The upper arc of the disc over the band's span, stroked 4 px (screen) in `CONTRAST.edge(domain colour)` at full opacity (3:1 against the page, D-042; a line of 6 px or less, so the edge colour), butt caps, 1 px gap between neighbouring arcs. Drawn at every zoom: from afar the outline of each layer reads as a ring of domain colours, so "which domains have a Silver" shows before any table.
- **Separators.** As in domain mode: the faint 1 px `C.cross` line between bands, at scale 0.6 or more.
- **Band names.** At scale 0.6 or more, each band's domain label, 11 px, 600 weight, in `CONTRAST.ink(domain colour, tint)` (4.5:1 on the band's own tint), centred on the band, 14 px below its arc. They enter the name competition after the constellation names and before table names, and a band name wider than the band on screen is not drawn. In domain mode no layer names are drawn, as today (D-040): there, the band order is the flow order the viewer knows; in layer mode the domain order is arbitrary, so the bands need their names.
- **Trajectory dimming** and `tdom` read `BY.of`: a layer constellation without a trajectory table is drawn at 45 %, its tints and arcs included.
- **Routes** between layer constellations: as today (width by count, arrow along the flow). Cross links are links between two layers.

### Panels in each mode

Unchanged in both modes (§ 2): Layers, Types and Domains keep their order, counts and all / none. In layer mode the Domains panel's colour dots are the legend of the bands; nothing is added to it. Unticking a layer removes a constellation, unticking a domain removes its band from every disc.

### Switching

- **Instant, then Fit.** `relayout()` as for Links and Tables: the new grouping is drawn at once and framed (`fit(false)`; in trajectory mode Fit frames the trajectory). No animation: no constellation exists in both groupings, so a tween would suggest a continuity that is not there, and moving 1,500 tables per frame costs more than it tells.
- **Lost on switch, as on any relayout:** the hover and the search mark (`found`). The search box keeps its text; Trajectory stays enabled.
- **Focus** stays on the radio. Nothing is announced: the radio's checked state is announced by the browser, and the meta line updates.
- **Saved arrangements.** Each grouping has its own (§ 6): switching shows the other grouping's saved or computed placement, and switching back restores the first exactly. A drag in one never moves the other. **Reset layout** clears both.

### States

- **Fewer than two layers:** the fieldset is `hidden`; the page is domain mode and its panel starts with Links, as today.
- **Nothing visible** (every layer, domain or type unticked): the existing empty text `L.empty`; the radios stay usable.
- **One visible layer** in layer mode: one constellation, framed.
- **A layer holding one domain:** one band; the whole disc is tinted, one arc all round the top.
- **Storage unavailable** (private mode, quota, blocked): the switch works for the session; nothing is shown.

### Keyboard and focus order

Panel order: the radio group (one Tab stop; ←/→ or ↑/↓ move and apply at once, native), Links, Tables, Layers rows, Types rows, Domains all / none and rows. The canvas and the toolbar are unchanged.
