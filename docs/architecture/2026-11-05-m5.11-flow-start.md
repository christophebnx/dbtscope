# M5.11 — The flow's start table stands out at every zoom (design note)

Status: DONE (approved for autonomous mode, asked by the user on 2026-11-05; a presentation refinement of "start emphasised" in D-036, no behaviour, payload or format change)

## Context

User feedback of 2026-11-05: "the flow view is great but in a detailed (large) flow it is hard to see which table is the focus (the start table)".

Current state (`render/assets/flow.js nodeDot`, `docs/ui-spec.md` § flow view): the start table has a 3 px dark frame (`border="3" color="#1f2933"`) and reads "start" / "départ" instead of a depth. Both are drawn in diagram units, so they shrink with the zoom. At **Fit**, a 24-table flow (`fct_orders` of acme) is drawn at scale ≈ 1.0 at 1280 px but ≈ 0.30 at 360 px, and a capped 146-table flow (`t1000` of the 1,500-table perf payload) at ≈ 0.21 at 1280 px and ≈ 0.06 at 360 px: the frame is then under 1 px and the start is one small box among 146. The header names the start ("Flow of ● fct_orders") but gives no way to get back to it after panning.

Screenshots (scratchpad of the design session, not committed): `before-*` = today, `after-*` = the prototype below, for `fct_orders`, `order_hub` and `t1000`, at 1280 and 360 px, at the initial view (0.75 centred on the start when Fit is smaller) and at Fit.

## Chosen design

Two small additions, both in `flow.js` and the flow's markup and CSS; nothing in `domain/`, the payload or Python.

1. **A start ring of constant screen size** around the start table, drawn in the SVG (so the export shows it), resized on every zoom.
2. **The header's start name becomes a button** ("locate the start"): it centres the view on the start table.

The flow's Domains legend mark for "start" becomes a double frame, the same symbol as the universe's start mark (`.mk.start`, double ring).

### `render/assets/flow.js`

- `START_RING = { gap: 6, width: 3, glow: 10 }` (screen pixels), next to `FLOW_MIN_SCALE`.
- `tidy(svg)` also inserts the ring: one `<g class="f-halo" aria-hidden="true">` holding two `<rect>`s, inserted in Graphviz's graph group before its first `g.node` / `g.edge`, so every table and arrow is drawn over it:
  - glow: `fill=THEME.fg fill-opacity=0.14`, no stroke;
  - ring: `fill="white" stroke=THEME.fg`.
- `ringStart(k)` (new, one responsibility: size the ring for scale `k`): reads the start node's `getBBox()` (cached for the render) and sets, with `u = 1 / k`, the ring to the node box grown by `(gap + width / 2) · u` with `stroke-width = width · u` and `rx = (gap + width / 2) · u`, and the glow to the node box grown by `(gap + width + glow) · u` with `rx` the same growth. On screen: a 3 px dark ring 6 px outside the table's frame, then a 10 px soft grey glow, whatever the zoom. Presentation attributes only, no CSS: `common.js INLINE` does not change, `svgImage` / `pngImage` export it as shown (checked with the prototype: the SVG of the Fit view holds the ring at its screen size).
- `graphZoom(box, svg, current, onZoom)` gets `t => { hideTip(); ringStart(t.k); }` instead of `hideTip` (graphZoom calls it on its first `fit()`, after the svg is mounted, so `getBBox` works).
- `nodeDot`: the start's frame is written with `THEME.fg` instead of the literal `#1f2933` (same value); otherwise unchanged (the name, the "start" label and the 3 px frame stay: they are what reads at a readable zoom; the ring makes it findable at any zoom).
- `locateStart()` (new): when a flow is drawn, `zv.centre(startNode(svg).getBoundingClientRect(), Math.max(zv.get().k, FLOW_MIN_SCALE))`: the start in the middle of the area, at the current scale or 0.75 if smaller (the initial view's scale, the smallest at which names read). Does nothing while "Laying out…" or after a render error. The focus stays on the button (repeatable). No announcement: the view moves, nothing changes in the content.
- `T` gains `startTitle` (below). `header()` is unchanged (`#f-dot`, `#f-name` keep their ids and their filling).

### `render/assets/page.html`

`#f-title` becomes:

```html
<h2 class="f-title" id="f-title"><span id="f-of"></span> <button id="f-start" type="button"><i id="f-dot"></i><b id="f-name"></b></button></h2>
```

### `render/assets/page.css`

- `.f-title i` / `.f-title b` rules move to `#f-start i` / `#f-start b` (same values); the 600 px rule `.f-title b { max-width:none }` becomes `#f-start b`.
- `#f-start { display:inline-flex; align-items:center; gap:6px; min-width:0; padding:3px 8px; border:2px solid var(--fg); }`: a button whose dark 2 px frame echoes the start table's frame. Name in `font-weight:600` as today. Focus: the existing `#f-view :focus-visible` accent outline. Coarse pointer: already a 44 px target through the `button` rule (D-035).
- `.fmk.start { width:16px; height:12px; border:3px double var(--fg); border-radius:2px; }` (was a 2 px single frame).

### Responsibility map (`docs/architecture.md`)

`flow.js`: add "the start ring (constant screen size, resized on zoom) and **locate start** (header button)". No new global; no change to `common.js`.

## Rejected options

- **A larger start node or a larger name (DOT `fontsize`).** Changes Graphviz's layout and still shrinks with the zoom: at Fit on 146 tables a 1.3× box is as lost as a 1×.
- **A "START" text badge above the node, at constant screen size.** Readable at any zoom, but at scale < 1 it covers the tables above (rank separation is 18 pt) and repeats the "start" label already in the box; the ring is enough to find the table, the box says what it is once zoomed.
- **Highlighting the start's column.** Columns are not drawn; a band would add a shape with no other meaning, and at Fit the column holds dozens of tables.
- **Stronger edges touching the start.** In a hub flow most edges touch the start: thickening them darkens half the drawing instead of pointing at one table. The arrows converging on the ring already lead the eye.
- **A colour of its own for the start (accent blue, yellow highlighter).** The accent blue is the focus outline (a focused start would be ambiguous); a new hue breaks "one accent colour". Dark `--fg` is the start's colour in the universe (double dark ring) and in both legends.
- **`vector-effect: non-scaling-stroke` alone.** Keeps the stroke width, not the gap: at Fit the ring would sit on the table's frame and vanish into it.
- **A single-key shortcut to locate the start.** WCAG 2.1.4 forbids an unmodified character shortcut that cannot be turned off; the button is second in the Tab order, one Tab from the focus on open.

## Test plan

Browser tests (`tests/browser/test_flow.py`, acme and the `test_trajectory_perf` payload; en and fr):

1. **One ring, under everything.** After open: exactly one `#f-graph .f-halo`; it precedes every `g.node` and `g.edge` in document order; it has `aria-hidden="true"`; the start `g.node` keeps `aria-current`.
2. **Constant screen size.** On the `t1000` flow, at Fit (k ≈ 0.21), at 0.75 and after `zv.set` to k = 3: the ring rect's screen rectangle equals the start node's grown by 7.5 ± 1 px on each side, its stroke-width × k = 3 ± 0.1, the glow's grown by 19 ± 1 px. Same at 360 px (k ≈ 0.06).
3. **Follows a recentre.** Click a table: still one ring, now around the new start (its centre within 1 px of the new start node's centre).
4. **Contrast.** `CONTRAST.ratio(ring stroke, THEME.bg) ≥ 3` and `≥ 3` against the glow over the page (the blend `#d7d9dc`); the computed `border-color` of `#f-start` and of `.fmk.start` is `--fg`; `.fmk.start` `border-style` is `double`.
5. **Locate start.** Big flow, Fit (k < 0.75), pan by 300 px, click `#f-start`: the start node's centre is at the box centre ± 2 px and k = 0.75. At k = 2, click: k stays 2 and the start is centred. Keyboard: on open focus is on `#f-back`; one Tab reaches `#f-start`; Enter centres. During "Laying out…" a click throws nothing (no page error).
6. **Header strings.** `#f-start` `title` is "Centre the view on the start table" (en) / "Centrer la vue sur la table de départ" (fr); `#f-name` text and `title` unchanged (hostile name test still passes: the name is still set with `textContent`).
7. **Small screens.** At 360 px: no horizontal scroll with the long hostile name; under `pointer: coarse`, `#f-start` is at least 44 px high (extend the existing touch-target test).
8. **Export.** At Fit on the big flow: `flow.svgImage(1)` holds one `.f-halo` whose ring `stroke-width` × the screen scale is 3 ± 0.1 (same as screen); the PNG export at the start's position has dark ring pixels (`--fg` ± 8 per channel) on the ring's left edge.
9. **Unchanged.** Existing flow tests (left to right, depth labels incl. "start", recentre, Esc, cap, perf < 5 s) pass; reference pages regenerated with byte-identical payloads.

## UI design

### Task and decision

The user opens a flow to see what feeds a table and what it feeds. In a flow of 25 to 150 tables, at Fit or after panning, they must answer "where is my table?" at a glance, then read its neighbours. Information needed: the start's position, visible at any zoom; and a one-step way back to it.

### Visuals (exact)

| Element | Value |

| Ring | `rect`, `fill="white"`, `stroke=THEME.fg`, 3 px on screen, 6 px between the table's frame and the ring's inner edge, rounded (`rx` = gap + width / 2) |
| Glow | `rect`, `fill=THEME.fg`, `fill-opacity=0.14`, 10 px beyond the ring's outer edge, rounded |

### Behaviour and states

- **Open, recentre, direction / depth change:** the ring is drawn with the flow, around the start; it never animates (no motion to reduce).
- **Zoom / pan / Fit:** the ring and glow keep their screen size; at high zoom they stay a thin frame 6 px out.
- **Locate start (`#f-start`):** click, Enter or Space: the start in the middle of the area, at max(current scale, 0.75). Hover title explains it. Nothing happens while "Laying out…" or on a render error (the button stays enabled: no state to explain).
- **Export:** PNG and SVG show the ring as on screen (it is part of the SVG, presentation attributes only).
- **Tooltip, Esc, live region, cap message:** unchanged.

### Keyboard and focus order

**← Universe** (focus on open) → **● start name** (locate) → Direction → Depth → Domains → Fit → PNG → SVG → tables left to right. Enter / Space on the start name centres the start. No single-key shortcut (WCAG 2.1.4).

### Strings (`flow.js T`)

| Key | en | fr |
|---|---|---|
| `startTitle` (title of `#f-start`) | Centre the view on the start table | Centrer la vue sur la table de départ |

The button's accessible name is its text (the table name); `title` gives the description. Existing strings (`flowOf`, `L.lgStart` "start" / "départ") unchanged.
