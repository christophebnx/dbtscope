# M5.2 — Page polish: plurals, script tidy-up, small screens (design note)

Status: DONE (built, tested and reviewed on 2026-11-04). The user decided the scope on 2026-11-04 (plurals with the French rule "0 and 1 are singular", the tidy-up of the M4.1 note § 6, the small-screen opening state recorded as D-035, the payload byte-identical). Nothing below goes beyond those decisions.

## Context

Request: one milestone that changes the page, so the M3 reference pages are regenerated once. It makes every count the page shows agree in number (en, fr), tidies the page scripts (M4.1 note § 6 and equivalent findings), and fixes small screens: the side panel starts closed at 600 px or narrower, and every control is a 44 px target on touch screens. Roadmap "Later" items 2–4 (`docs/roadmap.md`).

Current state (`src/dbtscope/render/assets/`):

- The scripts are inlined in this order: `detail.js`, `universe.js`, `boot.js`. `boot.js` parses `PAGE`, holds `L`, and starts the views at its end. The views only declare functions (plus the pure `trajectory` global).
- There are two `esc` functions. `detail.js` escapes `& < > "`. `universe.js` escapes `& <` only, so a table name holding `"` breaks `<option value="…">` in the universe datalist.
- There are three string tables: `L` (boot), and `T` in each view. `startUniverse` receives `lang`, while `startDetail` reads `DATA.lang`. `exportImage`, `png`, `filters`, the empty message and `Types` are written twice.
- Counts use a fixed plural: "1 tables", "1 colonnes", "+ 1 columns". `brought` and `hiddenN` hand-code `n === 1`, and in French they give "0 tables …".
- The ☰ toggle code is written twice, and so are the checkbox rows of the filter panels (one built by string, one by a delegated listener).
- `'dbt-erd-layout'` is written twice in `boot.js`. The bodies of `startDetail` and `startUniverse` are not indented, and helpers mix `function` declarations and arrow constants.
- `page.css` gives 44 px targets on coarse pointers to the trajectory bar, `#u-traj` and the export buttons only. The layout buttons are 12 px text with 4 px padding.

## Chosen design

### 1. How the scripts share code: a new first script, `assets/common.js`

- The new asset `render/assets/common.js` is inlined **first**, in its own `<script>` block. `page.html` gains `<script>\n{{COMMON_JS}}\n</script>` right after `{{SCRIPTS}}`, and `render/page.render_page` gains `"COMMON_JS": _asset("common.js")` (Python, `render/` only). The order becomes `common.js`, `detail.js`, `universe.js`, `boot.js`.
- Top-level `const` and `function` of classic scripts share the page's global scope across `<script>` blocks, so the later scripts can use what `common.js` declares. `common.js` only declares (no DOM work at load), apart from `document.documentElement.lang`.
- **Rule**, written in `render/CLAUDE.md`: page-wide constants and pure helpers are globals declared in `common.js` (`PAGE`, `STRINGS`, `L`, `esc`, `plural`, `sidePanel`, `filterRow`). Stateful services built by `boot.js` (`LAYOUT`, `EXPORT`, `openInDetail`) are still passed to `startDetail` / `startUniverse` as parameters. A view never declares a global, except the pure, tested `trajectory`.
- Rejected alternatives are listed under "Rejected options".

`common.js` holds:

| Name | Owns |
|---|---|
| `PAGE` | `JSON.parse` of `#data`, moved from `boot.js`. Tests already read `PAGE` as a global. |
| `STRINGS`, `L` | `STRINGS = { en: {…}, fr: {…} }` is the page-wide string table: the strings that `boot.js` uses, and every string shown with the same text by both views. `L = STRINGS[PAGE.lang]`. `STRINGS` stays global so a browser test can compare the en / fr keys. |
| `esc(s)` | The one HTML escaper: `& < > " '` → `&amp; &lt; &gt; &quot; &#39;` (`&` first). It is safe in text and in single- or double-quoted attributes. It is also used inside Graphviz HTML-like labels, which accept the same character references. |
| `plural(n, forms)` | `forms` is `[singular, plural]`. Returns `` `${n} ${forms[k]}` `` with `k = 0` when `n === 1`, or when `n === 0` and `PAGE.lang === 'fr'`, else `k = 1`. Numbers are written as today: no locale formatting (the trajectory's own `num` stays as it is). |
| `sidePanel(view, onToggle)` | Wires the ☰ button `#<view>-toggle` and the panel `#<view>-panel`: sets `title` / `aria-label` to `L.filters`, and keeps `aria-expanded` in sync with `.closed`. When the view starts at a width of 600 px or less (`matchMedia('(max-width: 600px)')`, the breakpoint `page.css` already uses), it starts closed (D-035). `onToggle` runs after each click (the universe: `resize(); fit(false)`, the detail: `refit`). It replaces the two copies of the toggle code. |
| `filterRow({label, color, count, checked, title}, onChange)` | One `<label>` of a filter panel, built with DOM calls: `input[type=checkbox]`, `<i>` with its background (only when there is a `color`), `<span>` label (`textContent`), `<small>` count. Same structure and CSS as today, minus the unused class `chk`. The universe's `checkboxes` and the detail's `refreshControls` use it, so no untrusted label goes through `innerHTML` and the detail's delegated `change` listener with `data-kind` goes. |

### 2. Plural agreement (every count the page shows)

String tables hold `[singular, plural]` pairs. "0 and 1 are singular" applies to French only; English is singular for 1 only.

| Where | Before | After (en / fr) |
|---|---|---|
| Universe meta `#u-meta` | `N tables · N links · N domains` | `plural(n, L.tables)` · `plural(n, T.links)` · `plural(n, T.domains)`; `T.links = ['link','links'] / ['lien','liens']`, `T.domains = ['domain','domains'] / ['domaine','domaines']` |
| Universe domain caption (canvas) and domain tooltip | `${d.n} ${T.tables}` | `plural(d.n, L.tables)`; "Shared" of `acme_retail` reads "1 table" |
| Universe table tooltip | `N columns` | `plural(n.cols.length, L.columns)`, `L.columns = ['column','columns'] / ['colonne','colonnes']` |
| Trajectory bar `brought` | hand-coded `n === 1` | `plural(n, T.brought)`, `['table brought back by the trajectory', 'tables …']` / `['table ramenée par la trajectoire', 'tables ramenées par la trajectoire']` (also in the live region) |
| Trajectory bar `hiddenN` | hand-coded | `plural(n, T.hidden)`, `['hidden by the filters','hidden by the filters']` / `['masquée par les filtres','masquées par les filtres']` |
| Detail meta `#d-meta` | `X / Y tables · N relations` | `` `${X} / ${plural(Y, L.tables)} · ${plural(N, T.relations)}` ``: the noun agrees with the total `Y`; `T.relations = ['relation','relations']` (both languages) |
| Detail "+ N columns" row | `T.more(n)` | `'+ ' + plural(n, L.columns)` ("+ 1 column", "+ 1 colonne") |

These stay as they are, because no noun follows the number or the text is fixed: the counts in the checkbox `<small>`, "5 upstream" / "5 en amont" (invariant adjective), "Upstream, level n", the fixed option labels "1 level" / "2 levels", and the universe card's "+ N" (it has no noun, and adding one would change the card width computed by `box`).

### 3. Script tidy-up (M4.1 note § 6 and equivalents found)

1. **One escaper**: `common.js esc` (§ 1). Both local `esc` functions are deleted. Equivalent fixes found while reading the scripts:
   - Universe: `<option value="${esc(n.name)}">` was not safe for `"`; the shared `esc` fixes it.
   - Universe checkbox colours and detail `data-kind="${k.key}"` / `background:${k.color}` were not escaped. They are now built by `filterRow`.
   - Detail DOT: the table ids in `"${e.id}" [id="${e.id}"` and `"${r.parent}" -> "${r.child}"` go through `dotStr`, and `color="${k.color}" bgcolor="${k.bg}"` of the HTML-like label go through `esc`. For any real dbt id and hex colour, the DOT text is the same.
2. **String tables, one convention**: each table is written `{ en: {…}, fr: {…} }[PAGE.lang]`. `L` holds the page-wide strings (`common.js`); `T` holds one view's own strings, declared at the top of its start function. Both views read `PAGE.lang`, so `startUniverse` loses its `lang` parameter and `startDetail` stops reading `DATA.lang`. The `lang` fields of the detail and universe payloads stay in the JSON, unread, because the payload is byte-identical (invariant 9 spirit; dropping them is a payload change for later). A string moves to `L` when both views show it with the same text in both languages: `exportImage`, `png`, `filters`, `empty` (the universe `empty` and the detail `none`), `kinds` ("Types"), `tables`, `columns`, plus the strings of `boot.js`.
3. **Repeated strings**: § 3.2. `fit` stays per view because the French texts differ ("Recadrer" in the universe, "Recentrer" in the detail), and unifying them would change visible text. The depth labels stay per view too: "1 level" and "direct links" are different options.
4. **Layout format**: `boot.js` declares `const LAYOUT_FORMAT = 'dbt-erd-layout'` once. `dump` and the import check use it. A unit test (`test_page.py`) asserts that the asset holds `LAYOUT_FORMAT = '<domain/layout.LAYOUT_FORMAT>'`. The localStorage key `'dbt-erd-layout:' + PAGE.title` is unchanged (invariant 9).
5. **Style**: the bodies of `startDetail` and `startUniverse` are indented by two spaces. A helper with a block body is a `function` declaration; a one-expression helper or lambda is an arrow `const`. In `universe.js`, locals that would shadow the new globals are renamed: the `L` of the `for (const [, L] of local)` loop becomes `dl`, and `count` in `reveal` becomes `hidden`. The detail's `$d('fit').onclick` reuses `refit`. The stray space in `}[DATA.lang] ;` goes. Reviewers read this diff with `git diff -w`.

These were found but are **left unchanged**, because each would change visible text or numbers on desktop (to be listed in roadmap "Later"):
- The domain tooltip writes "owner : x" with the French spacing in English as well, while the checkbox title writes "owner: x".
- Counts are not locale-formatted ("1500 tables"), but trajectory counts are ("1,500 upstream").
- The `fit` wording differs between the two views in French.

### 4. Small screens

- **Opening state (D-035)**: each view runs `sidePanel` when it starts (on its first showing). At 600 px or narrower, its panel gets `.closed` and `aria-expanded="false"` before the first layout, so the canvas and the diagram are sized and fitted with the panel closed. Above 600 px nothing changes. There is no automatic change on later resize or rotation: the user's toggle wins. Nothing is saved (no new localStorage key, invariant 9).
- **Touch targets**: the existing `@media (pointer:coarse)` block of `page.css` becomes:
  ```css
  @media (pointer:coarse) {
    button, select, input:not([type=checkbox]):not([type=file]), #u-tj-counts summary,
    .panel label, .panel h3 a { min-height:44px; }
    button { min-width:44px; }
    .panel h3 a { display:inline-flex; align-items:center; padding:0 8px; }
  }
  ```
  This covers the tabs, Reset / Export / Import layout, ☰, Fit, Trajectory, Show all (detail), Columns, the export buttons, the search and focus inputs, the panel selects, the checkbox rows and the all / none links. The trajectory bar rule it replaces is a subset of it. With a fine pointer (desktop) no rule applies, so the desktop rendering is unchanged.
- **360 px**: the rule against horizontal scrolling stays. It is checked with the panels closed by default and under the coarse pointer, where the taller layout buttons wrap inside `#tabs` (they already wrap at 600 px or narrower).

### 5. Payload and reference pages

- No change to `domain/` or `storage/`, and none to the `cli.py` output. `render/page.py` only gains the `COMMON_JS` part. `embedded_json` is untouched.
- In the final page commit, the developer:
  1. runs `uv run python tests/reference_pages.py`;
  2. checks that `git diff --exit-code tests/fixtures/m3-reference-pages/payloads/` is empty (only `expected.json` hashes and sizes change);
  3. commits the regenerated `expected.json` with the asset changes, and says so in the message.
- If any `payloads/*.json` changes, stop: that is a bug.

## Rejected options

- **Shared helpers at the top of `boot.js`.** They would work only because the views are started after `boot.js` ran (temporal dead zone otherwise): order-dependent and easy to break by moving a call.
- **`boot.js` first, starting the views on `DOMContentLoaded`.** It changes the start timing for no gain.
- **Passing `esc` / `plural` as parameters.** It makes the signatures longer, and these are pure, page-wide helpers like `d3`.
- **`Intl.PluralRules`.** In current engines (CLDR ≥ 38), French has a `many` category (for example 1,000,000), which would need a third form or a fallback. The user's rule is two lines and gives the same result on every engine.
- **Plural forms as functions `n => …`.** These are the `brought` / `hiddenN` of today, written once per string; pairs keep one rule in one place.
- **Closing the panel with CSS only (`@media (max-width:600px) .panel {display:none}`).** `aria-expanded` and `.closed` would no longer say the truth, and the toggle would need to override the media query.
- **Remembering the panel state.** That is a new stored state, which invariant 9 and D-013 protect; it was not asked.
- **44 px everywhere (fine pointers too).** It changes the desktop rendering, which the user excluded.
- **Unifying `fit` / the owner colon / number formatting now.** These are visible text changes outside the listed ones (§ 3, last list).
- **Dropping the payload `lang` fields.** The payload must stay byte-identical.

## UI design

Checked on the current page generated from `examples/acme_retail` (en and fr), in Chromium at 360 × 800 (touch emulation, `pointer: coarse`) and 1280 × 800, with the CSS below injected. Everything here stays inside the user's decisions of 2026-11-04 and D-035.

### Tasks served

- **Read a count at a glance** (everyone, every visit): "1 table", "0 lien" must read as language, not as a template, so the reader trusts the number. Decision supported: is this domain / filter / trajectory worth a look.
- **Use the map on a phone** (managers and analysts away from the desk): the drawing must be visible at opening, every control hittable with a finger, the filters one tap away and nothing scrolling sideways.

Key names keep today's keys where they exist, so they never collide with the panel headings (`T.links` = "Links" and `T.domains` = "Domains" stay headings; the note's § 2 names `T.links` / `T.domains` / `T.relations` / `T.hidden` are these keys):

| `L.columns` (`STRINGS`) | `['column', 'columns']` | `['colonne', 'colonnes']` | universe table tooltip; detail "+ N" row, written `'+ ' + plural(n, L.columns)` |
| universe `T.linksN` | `['link', 'links']` | `['lien', 'liens']` | universe meta |
| universe `T.domainsN` | `['domain', 'domains']` | `['domaine', 'domaines']` | universe meta |

### 2. Side panel on narrow screens

**Opening state** (D-035, `sidePanel`): at 600 px or narrower, the view starts with `.panel.closed` and the ☰ button `aria-expanded="false"`; above 600 px, `aria-expanded="true"` as today. The ☰ button looks the same in both states (no `.on` fill: desktop unchanged); its name stays "Filters" / "Filtres" (`title` and `aria-label`), so a screen reader says "Filters, collapsed, button" / "Filtres, réduit, bouton". Focus is not moved at opening (nothing is focused, as today); the closed panel is `display:none`, so its controls are out of the tab order.

**Reopening on a phone**: the ☰ button is the first control of each toolbar, at the top left under the tabs (12 px from the edge, 44 × 44 under a coarse pointer), the same place as on desktop. One tap opens the panel; focus stays on ☰; a second tap closes it. The `title` "Filters" is the only text label: the hamburger glyph plus its position is the convention users know, and adding a visible word would change the desktop toolbar.

**Open panel at 600 px or narrower: stacked, not side by side.** Today an open panel at 360 px leaves 71 px for the stage and the page scrolls sideways (measured: scroll width 438 px en, 457 px fr). In the existing `@media (max-width:600px)` block (width only, so a narrow desktop window gets it too; wider windows are unchanged):

```css
@media (max-width:600px) {
  .tab.on { flex-direction:column; }
  .panel { width:auto; max-height:45vh; border-right:none; border-bottom:1px solid var(--border); }
}
```

The panel spans the full width above the toolbar and scrolls inside itself; the ☰ button stays visible right below it to close it, and the canvas / diagram takes the rest of the height (`onToggle` already resizes and refits). Measured: scroll width 360 px with the panel open, en and fr, both tabs. The DOM order (panel, then toolbar) is unchanged, so the visual order and the tab order agree.

### 3. 44 px targets (coarse pointer only)

```css
@media (pointer:coarse) {
  button, select, input:not([type=checkbox]):not([type=file]), #u-tj-counts summary,
```
