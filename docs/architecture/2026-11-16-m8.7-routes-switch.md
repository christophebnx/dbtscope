# M8.7 — Routes are optional, on by default (design note)

Status: BUILT (APPROVED FOR AUTONOMOUS MODE; user request of 2026-11-16, recorded as D-083; the default keeps today's page, no documented decision is superseded, see § Impacts)

## Context

Request (user, French, 2026-11-16): "in the universe view, the arrows that show the flows between the groups of tables should be optional". The arrows are the **routes** between constellations (glossary, D-071). The viewer must be able to hide or show them; the page opens as today (routes drawn).

Current state (`render/assets/universe.js`): whether routes are drawn at a frame is decided in two places by the same expression, `routesOn = k < 0.6 || cardsOn` in `paint` (line ~1094) and `t.k < 0.6 || a >= 0.02` in `geometry()` (line ~2100). Everything route-related reads it: `routeView(a, routesOn)` (no spotlight `sp` when false; `kept` = the strong set without finding paths when false), `drawRoutes` (called only when true; fills `routeHits`, hence route tooltips), the meta line's "N of M routes" entry (`hidden` requires `routesOn`), `syncRoutesRow` (the **Show all routes** row, shown while `view.hides`). The precedent is the **Summary cards** switch (M8.6, D-081): native checkbox, config default, `common.js viewerMemory`, live-region announcement, redraw without layout or camera move.

## Chosen design

### 1. Config and payload (domain)

- `config.UniverseSettings.routes: StrictBool = True`, after `cards`; docstring line `routes: true  # draw the routes between constellations (D-071, D-083)`. Allowed in presets unchanged (`PresetUniverse` subclasses it); no built-in preset sets it. A non-boolean gives the existing one-line error (`config <path>: universe.routes: …; fix the file`, exit 1).
- `payload.UniverseDefaults.routes: bool = True`, **new last key** (after `cards`); `universe.universe_data` passes `routes=universe.routes`. No logic in Python, no CLI change.
- **Payload diff**: every page's universe defaults end `…,"cards":false,"routes":true}` (+14 bytes). Reference pages (`tests/fixtures/m3-reference-pages/`) regenerated once in the asset commit, after checking old and new payloads are equal once `,"routes":true` is removed (said in the commit message and `notes.md`).
- `dbt-erd.yml` gains one optional key whose default is today's behaviour: no migration, no user-visible change for existing projects. `dbt-erd-layout.json` (format `dbt-erd-layout` v1), its localStorage key and every scope are untouched.

### 2. The page: one switch point

- `const routesMemory = viewerMemory('dbtscope-routes', ['on', 'off'])` beside `cardsMemory`; `state.routes = routesMemory.get() ? routesMemory.get() === 'on' : DATA.defaults.routes`. Key `dbtscope-routes:<title>`, written only when it differs from the default (else removed by `viewerMemory.set`), never in the layout object, never exported, kept by **Reset layout**.
- **New helper `routesDrawn(k, a) = state.routes && (k < 0.6 || a >= 0.02)`**, the one place that combines the switch with the zoom rule to answer "are routes drawn at this frame" (`syncRoutesRow` and the `routesOn` / `drawn` test hooks also read `state.routes`); `paint` and `geometry()` both call it instead of their two copies of the expression (a small de-duplication). With the switch off it is false at every zoom, which is exactly today's "close zoom" state of the route machinery:

| Dependent | Routes off |
|---|---|
| `drawRoutes` (individual and bundled sets) | not called: no route, no arrowhead, at any zoom, cards on or off |
| `routeHits`, `routeAt`, `routeTip` | empty: no route tooltip, no route cursor |
| Spotlight (`spot`, `routeView` → `sp = null`, `near = null`) | off: hovering or focusing a constellation or its panel row dims nothing (the dimming exists to read the routes it draws). Table hover inside a constellation (`near` of tables, its links) unchanged |
| Path finding (`pathOf`, `routeCache`) | not run (`kept` takes the strong set without paths, as at close zoom); `perf.routes` ≈ 0. Toggling back finds paths on the next frame, as when zooming out today |
| Meta line | no "N of M routes" entry; "N links" stays. `setMeta` keeps its two-form min-height, so the toolbar height does not change on toggle (D-082) |
| **Show all routes** row | hidden while routes are off (`syncRoutesRow` hides when `!state.routes`); `showAll` keeps its session value and applies again when routes come back |
| Table-level links (Links select) | unchanged: hidden below 0.35, cross-domain hidden below 0.6, as today. The **Links** select stays: it still drives table links, the counts and the domain placement |
| Placement (D-070 flow columns, `routePairs`) | unchanged: the domains' x targets come from route counts, not from their drawing; no relayout, so the map does not move |
| Trajectory | unchanged: its own edges and, with cards on, its aggregated arrows between cards are trajectory marks, drawn whatever the switch (they use `pathOf`, found on demand) |
| Group card of source systems | unchanged (it is a card; only the bundled routes through it disappear) |
| `#u-summary` (text summary) | unchanged: each constellation's "Routes" list stays for screen readers (the text alternative describes the map's structure, not what is painted, D-066) |
| Export | as on screen: no routes when off |
| `geometry()` | `routes` keeps the current set with every `drawn: false`; new key `routesOn` (`state.routes`) |

- **Toggling** runs no layout and never moves the camera: `state.routes` changes, `routesMemory.set(state.routes ? 'on' : 'off', DATA.defaults.routes ? 'on' : 'off')`, `spot`-driven hover cleared (`hoverRoute` / tooltip hidden), live-region announcement, `draw()`.
- **Ticked = today exactly**: every frame, hit and hook equals the M8.6 page with the same camera.

### 3. Control, strings, accessibility

## Rejected options

- Hiding routes through the **Links** select (a fourth value "none"): Links chooses what is counted (relations, lineage, both) and drives counts, table links and placement; "none" would mix counting and drawing and move the map.
- Merging with **Show all routes** into one three-state select (none / strongest / all): changes a shipped control and its session semantics; two checkboxes, the second a sub-option shown only when relevant, keep both as they are.
- Keeping the hover spotlight (dimming and drawing a constellation's routes on hover) while routes are off: the viewer asked for the arrows to go; arrows popping up on every hover would contradict the switch. The dimming without arrows has no visible cause.
- Dropping the routes from `#u-summary` when off: screen-reader users would lose structure the sighted viewer can switch back on; the summary is the text alternative of the whole map (D-066).
- Making placement ignore routes when off: the constellations would move on toggle.
- Default off: the user asked for optional, not removed by default; today's pages stay as they are.
- The choice in the exported layout, or omitting the key when true: D-048, D-063, D-081.

## UI design

**Task and decision.** Reading the constellations' contents, the viewer finds the arrows between groups in the way and wants a clean map, or wants them back to see how domains feed each other. One checkbox, one click, no layout change: the decision is "arrows or no arrows", reversible, so no confirmation.

**Placement.** In `#u-panel`, in the Links block, in this order: `Links` heading, `#u-links` select, **Routes between constellations** (`#u-routes-on-row`), **Show all routes** (`#u-routes-row`, sub-option, same row style, no indent, no new CSS), then the Detail heading. Markup and ids as in section 3. No toolbar control (the toolbar holds export and the meta line only). Row shown when the current grouping has at least one route pair.

```
1280 px: panel (left)            360 px: panel under ☰, max 45vh, scrolls
 Links                            Links
 [Relations and lineage v]        [Relations and lineage v]
 [x] Routes between constellations [x] Routes between
 [ ] Show all routes  18 hidden        constellations   (label wraps)
 Detail ...                       [ ] Show all routes
```

**Strings** (T, section 3): label `routesSwitch`, row `title` `routesSwitchTitle`, live `routesLiveOn` / `routesLiveOff`. French ` ` before `:`. Nothing else added; no hint text, no new heading.

**States.** Ticked: today's page. Unticked: see the table of section 2; **Show all routes** row hidden (its session value kept); meta line "N links" only. No route on the page (row hidden, `state.routes` ignored). Storage unavailable: session only, no message (as Summary cards). No loading or error state: the change is synchronous and local.

**Keyboard and focus.** Native checkbox in the panel's Tab order: Links select, Routes switch, Show all routes (only when shown), Detail select. Space toggles. Focus stays on the box after toggling, also when the row below appears or vanishes (no focus move, no scroll). Visible focus from the existing `.panel` rule. Announcement in `#u-live` (polite, replaces the previous text), same mechanism as `cardsLive*`; it also fires for keyboard and pointer alike, not at page load.

**Pointer and phone.** Under `pointer: coarse` the label is a 44 px target through `.panel label` (D-035); the `title` is a mouse and keyboard aid only: the label says everything needed, the live region confirms the result. At 360 px the panel is closed behind the existing ☰ button; the label wraps, nothing overflows horizontally. Toggling needs no panel close and no camera move, so the map change is visible behind a closed-on-select panel only when the user closes it, which the live text covers.

**Interactions.** **Show all routes**: only meaningful while routes are on; hiding it avoids a dead control. Meta line: "N of M routes" entry absent when off, "N links" shown, min-height kept so the toolbar does not jump. **Links** select, Detail, folds, Summary cards: independent and unchanged; cards on + routes off draws cards without bundled arrows.

**Style.** None: no CSS, colour or icon change. `docs/ui-spec.md` updated (Routes switch bullet in the source systems and routes section), covered by D-083; no further approval needed.
