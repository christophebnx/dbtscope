# M9.4 — Print the current view on one page (design note)

Status: APPROVED FOR AUTONOMOUS MODE. The user approved this item of `docs/roadmap.md` § Later on 2026-11-12 ("Print stylesheet: the current view on one page, without panels and toolbars"). D-061 is new; D-021 listed print as "not in M2" and is not superseded. No payload, layout, localStorage or CLI change. The ui-designer designs the points marked **[UI]**. Order of M8: see `2026-11-12-m9.2-table-link.md` (this is the last of three: it prints the final state of every view, the M9.2 trajectory bar and the M9.3 paths mode included).

## Context

**Request.** Printing the page (browser Print, Ctrl+P / Cmd+P, or Save as PDF) gives the view on screen, on one sheet, without panels, toolbars or tooltips.

**Why it was left out of M5.4** (roadmap): the universe is a canvas sized to the screen, so it prints blurred and cut; the Graphviz views sit in a zoom layer sized to the stage, so they print at the wrong scale or overflow; the trajectory bar and the flow overlay need their own rules.

**Current code.** Image export (D-021) already produces "exactly what is on screen": `universe.js draw(target, scale)` paints the view onto any canvas (`image()` uses it at `EXPORT.scale`), and `common.js svgImage(box, zv, scale)` returns the visible part of a Graphviz diagram as a standalone SVG (synchronously). `boot.js` knows the current tab (`current`) and whether the flow is open (`flow.isOpen()`). `page.css` has no `@media print` rule.

## Chosen design

### 1. Principle: print = the exported image, on paper

The printed figure is what **Export image** would save for the same view, so print reuses the export code and there is one definition of "the view as shown" (D-021):

- **Universe:** the canvas drawn again by `draw(ctx, s)` at `s = EXPORT.scale(W, H)` (2 × the screen resolution, capped): sharp on paper (about 230 dpi across A4 landscape from a 1,280 px stage), with filters, zoom, detail level, search mark, trajectory rings and dimming; hover left out, as in the export.
- **Detail and flow:** the visible area as vector SVG, `svgImage(box, zv, 1)`, so it stays sharp at any print scale.
- **Which view:** the flow when it is open (it covers the Universe tab), else the current tab.

### 2. How: a print-only figure built on `beforeprint`

- `page.html` gains `<div id="print" aria-hidden="true"><p id="print-caption"></p><div id="print-figure"></div></div>` after the tabs, hidden on screen (`display:none`).
- **`beforeprint`** (boot.js, synchronous, still in screen layout, so sizes are the screen's): ask the shown view for `printFigure()` → `{ figure: Element | null, caption: string }`, put the figure and the caption in `#print`, and write the page orientation (§ 3). **`afterprint`**: empty `#print` and remove the orientation rule. The live views are never resized, re-laid out or re-drawn: their camera, trajectory, flow state and layout are untouched (no `ResizeObserver` fires, since `#print` replaces them only under print media).
  - Universe `printFigure()`: a new `<canvas>` of `W × s` by `H × s` device pixels drawn by `draw(canvas.getContext('2d'), s)` (the body of `image()` without the PNG step, factored as one helper `snapshot(s)` used by both `image()` and print: one implementation).
  - Detail and flow `printFigure()`: `svgImage(box, zv, 1)` parsed with `DOMParser` and imported; every `id` attribute of the copy removed (the live diagram keeps the dbt `unique_id`s, invariant 11; the copy must not duplicate them in the document). `null` while laying out or after a render error.
  - No figure (nothing drawn, laying out, render error): the caption is followed by the view's own message text ("No table for these filters.", "Laying out…", the render error).
- **`@media print`** (`page.css`): every child of `body` but `#print` is `display:none`; `#print` is a column flex box of height `100vh` (the page box), `break-inside:avoid`; the caption one line, 10 pt, `--fg`; `#print-figure` takes the rest (`flex:1; min-height:0`), and its canvas or svg is `width:100%; height:100%; object-fit:contain` (svg: `preserveAspectRatio="xMidYMid meet"`, already set by `svgImage`), so the figure keeps its aspect ratio and fits the page box. `print-color-adjust: exact` on `#print`, so kind colours and the figure's background print as on screen.
- **Fallback** (a browser that fires no `beforeprint`): `#print:empty` stays hidden and the live tab prints with every `.panel`, `.toolbar`, `#tabs`, `#u-trajbar`, `.tip` and `#u-notfound` hidden. It may be cut or blurred, but never shows controls.

### 3. Page box **[UI]**

- **Orientation follows the figure:** on `beforeprint`, a `<style id="print-page">@page { size: landscape; margin: 10mm }</style>` (or `portrait`) is added, landscape when the figure is wider than tall; removed on `afterprint`. `size: landscape | portrait` keeps the paper size the user chose (A4, Letter…). Without it, a wide universe would print small on a portrait sheet.
- **One sheet:** the `100vh` box, `overflow:hidden` and `break-inside:avoid` keep everything on the first page; the figure shrinks to fit, never splits.
- **Background:** the figure keeps the page background `#f5f6f8`, as the exported image (D-021: never transparent); the sheet margins stay white. The ui-designer may choose white for print instead (one switch: the background passed to `draw` and `svgImage`); contrast marks are already checked against white (D-042).

### 4. Caption **[UI]**

One line above the figure, so a sheet on a desk says what it shows (the export has no caption, D-021; paper has no window title). Proposal: `<page title> · <view>` + the view's own state, reusing existing strings:

- Universe: `· Universe` (`L.universe`), plus `· Trajectory of <start>: <counts>` in trajectory mode (the bar's text), and the brought-back count when not zero.
- Detail: `· Detail` (`L.detail`) and the drawn group or focus (the toolbar's meta and focus text).
- Flow: `· Flow of <start>: <counts>` (the flow's live text, cap message included); in paths mode (M9.3) `· Paths from A to B: …`.

Names are set with `textContent`. The ui-designer decides the exact form and whether the trajectory and flow legends (start, upstream, downstream marks) are printed under the caption; a legend is HTML only, never drawn into the figure (exports unchanged).

Responsibility map, new rows: "Print the current view: the figure, its caption, the page orientation (page)" → `boot.js PRINT`; "Visible Graphviz diagram as a print copy (page)" → `common.js printSvg`; update "Draw the universe (screen or image)" → `universe.js draw`, `snapshot`. `render/CLAUDE.md`: the `boot.js`, `universe.js`, `detail.js`, `flow.js`, `common.js` and `page.css` rows, and a rule: "print shows the export's figure: a change to what the export shows changes print too". Glossary: nothing new ("print" is the browser's word).

### 6. Strings (D-016)

No new string in the proposal: the caption reuses `L.universe`, `L.detail`, the trajectory and flow texts and `L.colon`. If the ui-designer adds a word (for example "Printed from dbtscope"), it goes into `STRINGS` in en and fr.

## Rejected options

- **Printing the live canvas with print CSS only:** the backing store is the screen's (blurred), and resizing it for print fires the `ResizeObserver`, which refits the camera: the print would not be the view as shown, and the screen would change.
- **Re-laying out the Graphviz views at the page size:** a new render per print (seconds on 150 tables) inside a synchronous `beforeprint`; and it would print the whole diagram, not the view as shown (the option D-021 rejected for export).
- **An `<img>` of the exported PNG or SVG:** decoding is asynchronous, so the print snapshot can be taken before the image is ready.
- **A Print button in the toolbars:** the browser's Print menu and Ctrl+P / Cmd+P exist everywhere; another control on toolbars that already wrap at 360 px.
- **Several pages (tiling a large view):** the request is one page; the user zooms before printing, as before exporting.
- **A fixed `@page { size: landscape }`:** wrong for a tall detail diagram or a narrow window.

## UI design (ui-designer, 2026-11-12)

Resolves every **[UI]** point of §§ 3, 4 and 6. No `NEEDS USER APPROVAL`: the choices are inside the approved request. The note's "no new string" becomes four (legends); all in en and fr.

### Task and decision

Someone prints or saves as PDF a view to put on a desk or in a document. Decision: "what does this sheet show, and how do I read its marks?" A sheet has no window title, no panels and no colours it can rely on (greyscale printers), so it needs one line saying what it is and, for a trajectory or flow, one line saying what the marks mean.

### Layout of the sheet (landscape or portrait by the figure)

```
+------------------------------------------------------------+  10 mm margin (white)
| acme_retail · Flow of fct_orders: 24 tables · 22 upstream   |  caption, 10 pt, --fg, may wrap to 2 lines
|   · 1 downstream                                            |
| Start: dark frame · Upstream: dashed violet arrow (−n) ·    |  legend, 9 pt, --muted, only when marks exist
|   Downstream: solid orange arrow (+n)                       |
| +--------------------------------------------------------+ |
| |                                                        | |  figure: page background #f5f6f8,
| |            the view as exported (contain)              | |  fits the rest of the sheet, aspect kept
| |                                                        | |
| +--------------------------------------------------------+ |
+------------------------------------------------------------+
```

No header or footer of our own: the browser prints date, URL and page number if the user keeps them on. Nothing is printed beyond the caption, the legend and the figure (no panels, toolbars, bar, tooltips, messages).

### Resolutions

1. **Sheet background (§ 3):** keep the page background `#f5f6f8` behind the figure, as the exported image (D-021). Reasons: print stays "the export on paper" with one definition and the pixel-equality tests of the note hold; the pale grey gives the figure a visible edge on white paper; it costs almost no ink and prints near-white on most printers. White is not adopted: it would add a background parameter to `draw` and `svgImage` and change the export path. The margins stay white. Colour marks were checked against both (D-042).
2. **Orientation (§ 3):** as the note (landscape when the figure is wider than tall), margin 10 mm.
3. **Caption (§ 4), exact form:** `<page title> · <view text>`, parts separated by ` · ` (space, middle dot, space), the view text being the shown view's own live text, so wording is already translated and agrees in number:
   - Universe, no trajectory: `acme_retail · Universe` / `acme_retail · Univers`. Add the active grouping only if it is Layers: `· Layers` / `· Couches` (existing `L` strings). Filters are not described: the figure shows what they leave.
   - Universe, trajectory: `acme_retail · Trajectory of fct_orders: 5 upstream · 1 downstream` (the bar's text, brought-back count appended when not zero, "1 table brought back by the trajectory").
   - Detail: `acme_retail · Detail` + the toolbar's meta text (group or focus, counts) as it is on screen.
   - Flow: `acme_retail · Flow of fct_orders: 24 tables · 22 upstream · 1 downstream` + the cap message when capped. Paths mode: `acme_retail · Paths from A to B: 9 tables · paths of 4 to 6 steps`.
   - French colons keep the no-break space already in those texts. The caption wraps to two lines at most (`overflow-wrap:anywhere`), never truncated: a cap message must stay readable.
4. **Legend (§ 4):** printed, HTML only, one line of text under the caption, only where the figure has marks that need it. Marks are described by their shape first, so it reads on a greyscale printer. Never drawn into the figure (exports unchanged).
   - Universe trajectory: `Start: double ring · Upstream: dashed violet ring · Downstream: solid orange ring`.
   - Flow: `Start: dark frame · Upstream: dashed violet arrows (−n) · Downstream: solid orange arrows (+n)`; paths mode appends ` · Target: dashed frame` (M9.3) and drops the Upstream / Downstream words that do not apply (the direction is read from the arrows: `Arrows: dashed = upstream of the start, solid = downstream`; the note's tests only require the caption).
   - Universe without trajectory, detail: no legend (kind and domain names are in the figure; the detail's own marks are self-explanatory and absent from the export).
5. **Nothing drawn:** caption, then the view's message in `--fg` 11 pt in place of the figure ("No table for these filters.", "Laying out…", the render error); no legend.
6. **Text colours:** caption `--fg` (14:1 on white), legend `--muted` `#5f6774` (5.9:1 on white); both ≥ 4.5:1.

### Components

`#print` with `#print-caption`, a new `#print-legend` (one `p`, between caption and figure) and `#print-figure`. All texts set with `textContent`; the existing `PRINT` listeners in `boot.js` fill all three, the views' `printFigure()` returning `{ figure, caption, legend }`. The `@media print` rules of § 2 apply; `#print-legend:empty` is `display:none`. `aria-hidden` stays (print only, no screen reader use).

### States

| State | Sheet |
|---|---|
| Figure drawn | caption, legend if any, figure |
| Nothing drawn / laying out / error | caption + message, no figure, no legend |
| Browser without `beforeprint` | live tab, every control hidden (fallback of § 2) |
| After printing | `#print` emptied; screen unchanged |

There is no control, so no focus or keyboard design: Ctrl+P / Cmd+P and the browser's menu are the entry points. The 44 px and 360 px rules do not apply to the sheet; the screen layout is unchanged at 360 and 1280 px.
