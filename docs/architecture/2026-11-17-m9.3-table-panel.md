# M9.3 — Table panel (design note)

Status: APPROVED FOR AUTONOMOUS MODE. Everything here is the brief's decided scope (`docs/briefs/2026-11-17-visualization-optimization.md` § 3 row 3, § 7: "single click on a table inside a domain opens a table panel; the trajectory stops being the single-click default"). The one supersession (the single click of the lineage mode, D-018 as built in M1 and `docs/ui-spec.md` § Universe view — lineage mode "Entering") is the one § 7 asks for, recorded as D-091. No payload, config, layout or localStorage change.

## Context

Request: in the universe, a single click on a table (inside an entered constellation, and at star zoom generally) opens a **table panel**: name, kind, domain, layer, description, columns at the chosen level, its relations and direct lineage neighbours as a clickable list (click = go to that table), and two buttons, **Open in Detail** and **Lineage**; `Esc` or a background click closes it, one `Esc` level before leaving the domain; screen readers announce it; the **Lineage** button next to the search box stays (roadmap M9.3).

Current state (after M9.2):

- `universe.js` canvas `click`: a ghost enters it; a table (`aim() && pick(ev)`) calls `enterTrajectory(i)` (D-018, start or move the lineage); a card row frames its band; a disc / label enters; the empty background leaves the lineage. `dblclick` on a table hands off to the Detail tab (`openInDetail`) or zooms to it.
- The location `nav = {inside, table}` (D-088): `select(i)` sets the table level (search `mark`, `locate`, `enterTrajectory`), `unselect()` clears it (and leaves the lineage when it is its start), `back()` is the Esc chain (table → entered → map). `found` is the ring. The breadcrumb already has a table segment (`pathItems`, `renderCrumbs`), whose action frames the table.
- `zoomTo(x, y, k)` centres on the stage below the lineage bar (`top()`); `fit` / `fitInside` frame below it too. `stageBox()` (the spread's box) is independent of the framing.
- The payload's `UniverseNode` carries `name`, `domain`, `layer`, `kind`, `desc` (cut to `DESCRIPTION_LIMIT` = 400 characters), `cols` (`[name, type, is_key]`), `parent`; `relations` and `lineage` are `[child, parent]` index pairs. The detail payload (`PAGE.detail`) carries, for the detail tables (`detailIds`, the same `unique_id`s, invariant 11), the full description, column descriptions (`columns[i][3]`) and each relation's column (`DetailRelation.column`).
- Helpers that already answer parts of the question: `common.js tableTip` (domain · layer · kind · columns line), `labelOf`, `paintDot`, `plural`, `num`, `trajectory(lineage, start, direction, depth)` (level-1 upstream / downstream with `'both', 1`); `universe.js` `DOM`, `LAYER`, `KIND`, `ID`, `PARENT`, `HELD` (the entity's folded tables), `mark(n)` (go to a table: tick it back, open its entity, enter its constellation, select, ring, frame), `enterTrajectory`, `openInDetail`, `T.reads`, `L.up` / `L.down`.

## Chosen design

Layers touched: `render/assets/` only (`page.html`, `page.css`, `common.js`, `universe.js`, `boot.js`). `domain/`, `storage/`, `cli.py`, `render/page.py`, `detail.js`, `flow.js`: unchanged.

### 1. The payload already carries what the panel shows (no growth)

| Panel content | Source | Change |
|---|---|---|
| Name, kind, domain, layer | `UniverseNode` + `KIND`, `DOM`, `LAYER`, `labelOf` | none |
| Description | the detail entity's `description` when the table is a detail table (full text), else `UniverseNode.desc` (≤ 400 characters; a cut one ends with "…" when its length is exactly the limit) | none |
| Columns, key flag, type | `UniverseNode.cols` (every universe table) | none |
| Column description | the detail entity's `columns[i][3]`, matched by column name, when the table is a detail table; else none | none |
| Relations (references / referenced by) | `DATA.relations` (`[child, parent]`), deduplicated per neighbour | none |
| Relation column | `DetailRelation.column` when both ends are detail tables; else the neighbour alone | none |
| Lineage neighbours (upstream / downstream, level 1) | `trajectory(DATA.lineage, i, 'both', 1)` (reused, not a second traversal) | none |
| Drawn inside / holds (entities, D-063) | `PARENT[i]`, `HELD.get(i)` | none |

Everything shown is structure (names, types, keys, descriptions, relations): invariant 8 holds. **The payload is byte-identical**; the M3 reference pages are regenerated once for the page bytes (assets), never for the payload (`tests/unit/test_reference_pages.py` asserts the payloads unchanged). Growing the universe payload with column descriptions was rejected (below): it would add the largest field of the page to every table, for the tables the detail already describes.

**Detail lookup, passed not global.** `boot.js` today passes `new Set(detail ids)` as `detailIds`. It passes instead `DETAIL_INDEX = detailIndex(PAGE.detail)`, a new pure `common.js` helper built once: `{ has(id), entity(id), columns(id) → Map(name → description), relationColumns(childId, parentId) → [column, …] }`. `has` keeps the two existing `detailIds.has` call sites unchanged in meaning. One index, one place that reads detail data on behalf of the universe.

### 2. Interaction model (D-091)

The panel is the UI of the table level of D-088: **an open panel ⇔ `nav.table` set by a selection that is not the lineage bar's start alone**. State: `panel = { i, cols: 'keys' | 'all', more: Set(group) } | null` in `universe.js`.

| Action | Today | M9.3 |
|---|---|---|
| Single click on a table (`aim() && pick`) | `enterTrajectory(i)` | `openPanel(i, 'click')`: `select(i)`, ring (`found = i`), panel shown, camera only panned if the table would sit under the panel (`clearOfPanel`), live announcement; **no lineage** |
| Single click on a table while a lineage is shown | moves the lineage | opens the panel on that table **over** the lineage (the lineage stays drawn, its start unchanged); the panel's **Lineage** button moves the lineage there |
| Single click on a ghost | enters it | unchanged (the panel closes, its table being outside) |
| Single click elsewhere with the panel open | card row / disc / background rules | **closes the panel only** (one click, one step back), nothing else |
| Single click elsewhere with no panel | | unchanged (card row frames, disc enters, background leaves the lineage) |
| Double-click on a table | Detail hand-off (or zoom) | unchanged; the first click has opened the panel, which is there again on the way back (`locate`) |
| Search (`#u-q` change) and return from the Detail tab (`mark` / `locate`) | select + ring + frame | the same, **and the panel opens** (focus stays where it is: `#u-q`) |
| **Lineage** button next to the search box | starts the lineage of the table found | unchanged; it closes the panel (the bar takes the table level) |
| Panel **Lineage** button | — | `enterTrajectory(i)`, the panel closes, focus to the bar's Direction select (as the toolbar button) |
| Panel **Open in Detail** | — | `openInDetail(id)` (same hand-off as the double-click, trail included, D-089); disabled with its reason when the table is not a detail table (D-085) |
| A neighbour in a panel list | — | `goTo(j)` = `mark(N[j])` (ticks it back if filtered out, opens its entity if folded, enters its constellation if another, selects, rings, frames in the uncovered area), then the panel shows `j`. Focus moves to the panel heading (the list it was in is rebuilt) |
| Panel **×** (close) | — | `closePanel('button')` |

Lineage is reachable in two interactions from the canvas (click, Lineage) and in two from the search box (type, Lineage), as the brief requires.

**Esc chain** (one handler, `back()` extended, its guards of M9.2 unchanged: popovers, the lineage graph, the counts list, `#u-q`, selects first):

1. panel open → `closePanel('esc')`: the table level goes back to the lineage start when a lineage is shown (`nav.table = traj.start`, ring cleared), else `unselect()` without leaving the constellation;
2. table level of a lineage → leave the lineage (today);
3. entered constellation → leave (today);
4. map → nothing.

So with a panel open inside Vehicle: Esc closes the panel, Esc leaves Vehicle — the brief's "one Esc level before leaving the domain". With a lineage and a panel over it: panel, lineage, domain.

**Breadcrumb** (`pathItems`, unchanged structure): the last segment is the panel's table (`All domains › Vehicle › car_hub`); during a lineage with a panel over it, the panel's table (the lineage start shows in its bar). The current table segment's action frames the table **and moves the focus to the panel heading** (the keyboard way into the panel). Going to the constellation segment closes the panel.

**What closes the panel** (all through `closePanel(how)`, which also clears `nav.table` unless a lineage keeps its start): Esc, ×, background click, the constellation or root crumb, leaving or switching the entered constellation to one that does not hold the table (ghost, panel row, zoom out, Organise by), a filter that hides the table (`settleInside` / `refreshPanel` path: the table is no longer passing), a layout reset or import that leaves the table undrawn, the toolbar Lineage button. A Show change keeps it open (its column level follows, § 3). Switching tabs keeps it (page state, as the location).

**Composition** with M9.2 and the rest:

| Feature | With the panel |
|---|---|
| Entering / leaving / zoom hysteresis (D-088) | `followZoom` unchanged; leaving closes the panel; an anchored zoom enter keeps no panel (zooming never selects) |
| Spread (`stageBox`) | never changed by the panel: opening it never relays out or refits |
| Framing (`zoomTo`, `fit`, `fitInside`, `frame`, `clearOfPanel`) | frame inside the **uncovered area** `visibleArea()` = the stage minus the lineage bar (today's `top()`) minus the panel's rectangle; one function replaces `top()` in these callers |
| Links inside (`linksOf`) | the panel's table is `nav.table`: its links are drawn, as for any selected table |
| Lineage graph (D-036) | opened from the bar as today; the panel stays under the overlay (inert) and is there on Back |
| Image export | the panel is HTML in `#u-stage`, never drawn on the canvas: never exported (D-021); the ring is, as today |
| Inside note `#u-inside-note` | hidden while the panel is open (a table is selected: its links show) |
| Ghosts under the panel | covered and not hit (the panel takes the pointer); the panel rows and the ghosts left of it remain |
| Saved arrangements, drag | unchanged (no drag starts on the panel; dragging a table at the map level does not open the panel: d3-drag swallows the click) |
| `#u-summary` | unchanged |

Nothing about the panel is saved (D-013): no localStorage key, no layout field, no URL.

### 3. Panel content

`<section id="u-tpanel" class="tpanel" role="region" aria-labelledby="u-tp-name" hidden>` inside `#u-stage`, after the canvas, before `#u-summary` (DOM order = Tab order: after the toolbar's Export, as the stage follows the toolbar). Built with DOM calls and `textContent` (names and descriptions are untrusted), by `renderPanel()`:

1. **Header**: kind dot (`paintDot`), name as `<h2 id="u-tp-name" tabindex="-1">` (focus target), × button `#u-tp-close` (named "Close the table panel (Esc)").
2. **Facts** (`<dl>`): Table kind, Domain, Layer (labels through `labelOf`; in layer mode the order is Layer, Domain), and when folded "Drawn inside: <parent>" (a button: goes to the parent), when an entity "Holds N descriptive tables" (its list is a neighbour group, item 5). Owner of the domain when the payload has one (`UniverseDomain.owner`).
3. **Description**: the text, at most 6 lines then a "More" toggle (`<details>`); "No description" in muted text when empty.
4. **Columns**: heading "Columns (N)" with a two-option toggle **Key columns | All columns** (`aria-pressed` buttons), starting from the Show select (`names` and `keys` → key columns, `all` → all columns) and following it when it changes; a viewer's toggle holds until the next Show change or the next table. Rows: name, type (muted, tabular), a key mark (the text "key" / "clé" in a small badge, no icon, so screen readers read it); a column description as the row's second line (muted, 12 px) when known. "No key column" when the key list is empty (with the toggle still offering all columns). Above 200 rows: the first 200, then "Show all N" (no virtualisation needed at that size).
5. **Neighbours**: up to five groups, each a heading with its count and an `<ul>` of buttons, shown only when not empty:
   - **References** (relations where this table is the child: its parents), **Referenced by** (its children) — each item `name` + the relation column(s) when known ("via vehicle_hk"), the neighbour's domain when it differs ("· Auction");
   - **Upstream** and **Downstream** (direct lineage, `L.up` / `L.down`, the lineage legend's words);
   - **Drawn inside it** (an entity's folded tables, `HELD`).
   Items sorted by name, then id; each group shows its first 20 then "Show all N" (`panel.more`, per open). An item hidden by a filter is listed with "(hidden by a filter)" and still goes (`mark` ticks it back, as the search does). A self relation is skipped; a neighbour reached by several relations is one item with its columns joined.
6. **Actions** (sticky at the panel bottom): **Open in Detail** (disabled with the visible reason "Not in the Detail tab's scope" when `!DETAIL_INDEX.has(id)`, D-085), **Lineage**.

### 4. Placement and size

- **Wide stage (> 600 px)**: an overlay on the right of `#u-stage`, `width: min(340px, 40%)`, full height below the lineage bar when it shows (`top` follows the bar, as the framing does), `overflow-y:auto`, `--surface` background, 1 px `--border` left edge, shadow. The stage is **never resized** (D-082: a resize refits), so the canvas, the spread and the ghost ring stay as they are; only the framing area shrinks.
- **Narrow stage (≤ 600 px, so at 360 px)**: a **bottom sheet** in `#u-stage`: full width, `max-height: 50%` of the stage, scrolling inside, rounded top corners, the header and the actions sticky. The left ☰ side panel is stacked above the toolbar at that width (D-035), so the two never sit side by side; at wide widths ☰ is on the left and the table panel on the right, both visible.
- No horizontal scroll at 360 px; long names and column names wrap (`overflow-wrap:anywhere`); 44 px targets on coarse pointers (×, toggle, items, actions).
- `clearOfPanel(i)`: after a click-open, if the table's reserved box is not inside `visibleArea()` with a 16 px margin, pan (never zoom) by the smallest vector that puts it there, 200 ms (instant under `prefers-reduced-motion`); a page transition, so `followZoom` ignores it.

### 5. Accessibility

- **Announce**: on open and on each change of table, `#u-live` (polite) says "car_hub: Hub · Vehicle · Raw vault · 14 columns · 3 relations · 2 lineage links. Table panel open, Esc closes it." (fr equivalent); on close "Table panel closed". The region's accessible name is the table name.
- **Focus**: a pointer click does not move the focus (the viewer is on the canvas); a keyboard path does: the table crumb segment and a neighbour item move it to the heading `#u-tp-name`; search and `locate` keep it in `#u-q` (M9.2 behaviour) and the announcement says how to reach the panel ("Tab to the table panel" is not added: the crumb segment is the documented way). Closing with focus inside the panel moves it to the current crumb segment (the constellation, or the root).
- Not a modal dialog (`role="region"`, no focus trap): the canvas, toolbar and side panel stay usable with the panel open.
- Esc from inside the panel closes it (the panel's own inputs: the toggle buttons and `<details>` do not consume Esc).

### 6. Help and tooltip wording

- Table tooltip action line: `T.clickTraj` ("Click: show its lineage") is replaced by `T.clickPanel` ("Click: open its panel"); the start of a lineage keeps its line.
- Hints: mouse "… click a table to open its panel · double-click a table to open its detail"; touch "… tap a table: its panel · double-tap a table: its detail …".
- `T.needTable` ("Find a table first, or click one on the map") is no longer true (the toolbar Lineage button reads the search box, which a click does not fill): it becomes "Find a table first, or use the Lineage button of a table's panel" (fr equivalent). The ui-designer settles the final en / fr wording of every string of this note.

### Formats and compatibility

- Payload, config, layout format and every storage key: unchanged; no migration. Reference pages: page bytes regenerated once, payloads byte-identical.
- **Behaviour change for existing users** (D-091): a single click on a table opens its panel instead of starting (or moving) the lineage; the lineage is one more click away (the panel's Lineage button) or through the search box as before; a background click with the panel open only closes it; a search and the return from the Detail tab also open the panel.

### Error handling

No new failure path. A neighbour no longer in the universe scope cannot be listed (lists are built from the universe payload); a neighbour folded and filtered out is ticked back and opened by `mark`; a panel whose table becomes undrawn (filter, reset, import, Organise by) closes with "Table panel closed". A detail lookup that misses (not a detail table) falls back to the universe fields.

## Rejected options

- **Grow `UniverseNode` with column descriptions and relation columns.** The descriptions are the largest strings of a manifest; every page would grow for every table, while the detail payload already holds them for the tables it draws. Kept for later if users ask for descriptions of out-of-detail tables (a payload decision of its own).
- **Keep single click = lineage, panel on another gesture** (long press, Shift-click). Decided against by the user (brief § 3 row 3).
- **Panel and lineage mutually exclusive (a click during a lineage leaves it).** Loses the lineage while reading one of its members; the panel over the lineage keeps both and the Esc chain unwinds them in order.
- **A click during a lineage still moves the lineage.** Two meanings for one click by mode; the panel's Lineage button moves it in one more click.
- **Resizing the stage beside the panel (a third column).** A resize refits and recomputes the spread (D-082, D-088); the overlay keeps the view still.
- **Panel on the left, swapping with ☰.** The ☰ panel is the filters the viewer keeps open while browsing tables; left for filters, right for the table is the common split.
- **A modal dialog.** Blocks the canvas while reading; the brief wants the list to navigate the map behind it.
- **Lineage neighbours at every depth.** That is the lineage mode; the panel lists the direct ones (level 1), the Lineage button shows the chain.
- **Opening the panel on hover.** Flicker over dense spreads; hover keeps the tooltip.
- **Moving the focus into the panel on every open.** Steals the focus from the search box after Enter and from the canvas after a click; the crumb segment and neighbour items move it when the viewer asked for the panel.
- **A panel memory (columns toggle, open groups) in localStorage.** A new key for a transient view; the Show select already gives the starting level.

## UI design (ui-designer, 2026-11-17)

Task and decision. A viewer who has found a table on the map (by clicking it, searching it or coming back from the Detail tab) asks "what is this, what is it tied to, where next?". The panel gives the identity (kind, domain, layer, description), the columns, and the neighbours as a list that goes there, then the two next steps: **Open in Detail** and **Lineage**. Everything below is the architect's decided scope (brief § 7, D-091). NEEDS USER APPROVAL: none. No conflict with the note; four clarifications, none changes behaviour:

1. **Panel kept by the pointer, left alone by the keyboard.** The note's focus rules stand (a click leaves the focus on the canvas; crumb segment and neighbour item move it to `#u-tp-name`). Added: the live message says how to reach the panel only through the crumb ("Location line: Enter on the table to read its panel"), see Strings.
2. **Toolbar Lineage button disabled hint** (the flagged `T.needTable`): a title can no longer say "click one on the map" (a click opens the panel). New wording below; it stays a `title`, as every toolbar reason (ui-spec § Panel groups).
3. **Selected table marker on the canvas** is the existing `found` ring (drawn today for search, `locate`, `mark`): no new mark, no new colour. It is shape, not colour only, and it stays as long as the panel is open; Esc / × clear it. The lineage start keeps its own double ring; a panel over a lineage rings the panel's table with the single ring.
4. **Neighbour rows are buttons in `<ul><li>`**, not links, not rows of a table: they act on the page.

- Narrow stage (≤ 600 px): `left:0; right:0; bottom:0; max-height:50%`, `border-top`, `border-radius:12px 12px 0 0`. Same markup; header and actions `position:sticky` (top / bottom, `--surface`), the middle scrolls. Padding 12px 14px, 13 px text; no new font size (12, 13, 14 bold for the name).

- Description: `-webkit-line-clamp:6` and a `<details><summary>More</summary>` holding the full text only when the text is longer (measured once per render: `scrollHeight > clientHeight`); a `<details>` is the native toggle, no JS state.

### Keyboard, focus, aria

- `<section id="u-tpanel" role="region" aria-labelledby="u-tp-name">`, non-modal, no focus trap. The name is `<h2 id="u-tp-name" tabindex="-1">`; the group titles are `<h3>`.
- **Tab order**: toolbar (… crumbs … Find a table, Lineage, ?, Fit, Export) → the panel (×, columns toggle: Key columns, All columns, description More, each neighbour item and "Show all", Open in Detail, Lineage) → the rest of the stage. × is first so that a keyboard viewer can close at once; the sticky footer is last in DOM order and last in Tab order (DOM order = visual reading order, even if stuck at the bottom). `Shift+Tab` from the first control goes back to the toolbar.
- **Open**: a pointer click, a search, `locate` and the Detail return do not move the focus. A keyboard viewer gets in by the crumb's current segment (Enter) or by `Tab` from Export after a search; focus lands on `#u-tp-name`.
- **Enter / Space** on a neighbour item = `goTo(j)`; focus to `#u-tp-name` of the same panel (the rebuilt list had the focus; the heading is the stable target, and it re-reads the new table's name). "Show all N" keeps the focus on its button (rebuilt in place, the button is replaced by the next item: focus the first item revealed, the 21st). Toggle buttons keep the focus.
- **Esc chain** unchanged from the note (panel → lineage → domain → map), also from inside the panel; Esc in `#u-q`, selects, popovers, the counts list and the lineage graph keep their own first (M9.2 guards). Closing with the focus inside the panel moves it to the current crumb segment. **×** is the same as Esc.
- **Lineage** (panel button): the panel closes and focus goes to the bar's Direction select. **Open in Detail**: the Detail tab, as the double-click.
- **Live region** (`#u-live`, polite): on open and on each change of table, one sentence, no repetition on a same-table re-render (a Show change re-renders silently). On close: "Table panel closed".
- Contrast: all text is `--fg` or `--muted` (5.3:1 on `--bg`; on `--surface` white 5.9:1) or `--accent` on `--surface` (4.5:1 or more, as `.tj-back`); the kind dot is a mark at 3:1 (D-042, `paintDot` already handles it) and decoration beside the written kind. Text on a colour: none. Pressed toggle and "key" badge carry text, not only colour.
- Targets: ×, toggle buttons, More, neighbour items, "Show all", Open in Detail, Lineage: `min-height:44px` and `min-width:44px` under `pointer:coarse`; on fine pointers items are 28 px high lines (the list stays compact for 20 rows). Footer buttons share the width at 360 px (each ≥ 44 px wide, "Open in Detail" wraps onto two lines before it overflows).
- No horizontal scroll at 360 or 1280 px: panel width capped, content wraps, no fixed-width child. Checked at both.

### Notes for the developer

- `visibleArea()` must read the panel's rectangle from the DOM only when it shows (`!hidden`), so the 360 px sheet (bottom) and the 1280 px panel (right) both work with one function: the rectangle is subtracted from the side it touches.
- `renderPanel()` replaces the section's children in one pass and restores the focus to `#u-tp-name` only when the focus was inside the panel before the render (a Show change from ☰ leaves focus where it is).
- The panel never carries a tooltip; its text is the reading.

## As built (2026-11-17)

Built as designed (assets only: `page.html`, `page.css`, `common.js detailIndex`, `universe.js`, `boot.js`; `domain/`, `storage/`, `page.py`, `detail.js`, `flow.js` unchanged; payload byte-identical, reference pages regenerated once for the page bytes). Deviations, all small:

- **A neighbour click and `locate`/search go through `mark`**, which now opens the panel (it replaced `select` + `found`); `mark` still enters another constellation and, as before, leaves a lineage whose start is not in it (so a search during a lineage in another domain ends the lineage, then opens the panel).
- **The description's More toggle is a `button[aria-expanded]`** that toggles the 6-line clamp (`Less` after), not a `<details>`: a `<details>` holding the full text would have read the description twice (the clamped paragraph and its copy).
- **`letClickThrough`** (not in the note): after a click-open the panel takes no pointer for 450 ms, so the second click of a double-click on a table that sits where the panel has just appeared still reaches the table (otherwise a double-click on a table in the right 340 px would hit the panel).
- **A Direction or Depth change of a lineage keeps an open panel** (`enterTrajectory(i, true)`); every other `enterTrajectory` (panel Lineage, toolbar Lineage) drops it.
- **French "Show all"** is `Voir tout (N)`: `Tout afficher` is on the list of retired words of `test_the_page_strings_hold_none_of_the_words_d_084_retired`.
- **The "Drawn inside" fact** shows whenever the table has a parent and the fold is on (the table may be drawn on its own while a search keeps its entity open).
- **A layout (`relayout`, `relayoutAnchored`) keeps the panel** (`resumePanel`) when its table still passes the filters and belongs to the entered constellation; `clearFound` (enter, leave, grouping change, anchored zoom) closes it.
- **The export test** compares the PNG with the panel shown and with the section hidden by script (closing the panel clears the ring, so "open == closed" cannot hold for the canvas).
- **Not tested in a browser**: the double-tap hand-off on touch (Chromium's touch emulation does not synthesise `dblclick` reliably); the tap, the 44 px targets and the hint are.
- **Tests adapted, not weakened** (single click used to start the lineage): `test_trajectory.py` (`centre` returns the table's star, `lineage_of` = click + the panel's Lineage), `test_drill_down.py`, `test_entities.py`, `test_constellations.py`, `test_page_polish.py` (a search now frames the table left of the centre, beside its panel), `test_ui_coherence.py` (the new `needTable` title).

Measured (large project, 1280 × 800, headless Chromium, `tests/browser/test_drill_down_perf.py::test_the_table_panel_opens_well_under_100_ms_on_the_tables_with_the_most_links`, the ten most linked tables of Vehicle opened by a click, the page's own `perf().panel`): **median 5.7 ms, worst 14 ms** (budget 50 / 100 ms); a neighbour of another domain (`locate`: enter + panel) enters in 6 ms (budget 1 s). Browser tests: `tests/browser/test_table_panel.py` (30 tests: acme_retail and the large project, en and fr, 1280 and 360 px, mouse, keyboard and touch).
