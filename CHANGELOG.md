# Changelog

All notable changes are listed here, newest first. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versions follow semantic versioning.

## [Unreleased]

### Added

- Example project `examples/acme_retail/` (M5.1, D-033): a fake dbt project (sources, staging, Data Vault, star-schema marts in 6 dbt groups, `relationships` tests, `foreign_key` constraints, seeds, snapshots, typed and untyped columns) valid for dbt-core and dbt Fusion; README § Try it on the example project. Its `dbt parse` manifest is committed compressed (`tests/fixtures/acme_retail/manifest.json.gz`, 104 kB) and regenerated by `tools/example_manifest.py`; the default tests build both views from it without dbt, a browser test draws every detail group in both column modes, and `DBTSCOPE_DBT` turns on a check against a fresh `dbt parse`.
- README: installing from the private repository (GitHub CLI, SSH or a fine-grained token, checked with `git ls-remote`) and a token step in the GitHub Actions example.
- Preset files (M4.2b, D-030): `--preset-file <path>` (relative to the current folder) or `preset: <path>` in `dbt-erd.yml` (relative to the config file's folder, `\` read as `/`; a value holding `/` or `\` or ending with `.yml` / `.yaml`) starts a run from a team's own conventions. `--preset` with `--preset-file`, or an empty `--preset-file`, is a usage error (exit code 2). Every preset, built-in or file, is validated on its own: an unknown key, `output`, `layout_file` or a chained `preset` stops the run with one line, `preset <path>: <key>: <problem>; fix the file` (exit code 1), an unknown key shown first. A wrong `--preset` now suggests `--preset-file`. `dbt-erd.yml` stays lenient. The summary's `config:` line names the preset applied, also when it comes from the file's `preset:` key; an unknown name in that key now suggests giving the path of a preset file. The generated page is unchanged byte for byte.
- Image export (M2, D-021): **Export image** at the end of each toolbar saves exactly the current view (zoom, filters, detail level, highlight, trajectory dimming) on the page background: PNG in the universe, PNG and SVG in the detail. PNGs at twice the screen resolution; the SVG is cut to the visible area and opens on its own. Files are named `<title>-<view>.<ext>`. English and French.
- Offline page (M2, D-021): `--offline` or `offline: true` in `dbt-erd.yml` embeds d3, Viz.js and svg-pan-zoom, so the page works with no network; the CLI summary gives its size. The libraries are vendored in `src/dbtscope/render/vendor/` at the exact CDN bytes, with their licences: d3, Viz.js, svg-pan-zoom, Graphviz (with its source URL), Expat, Emscripten and musl. `tools/vendor_libraries.py` refreshes them (`--check` verifies their hashes).
- Trajectory mode of the universe view (M1, D-018): click a table, or use **Trajectory** after a search, to highlight its upstream and downstream lineage across domains and layers while the rest is dimmed and the layout stays still. Direction and depth selectors, per-domain counts, filtered tables brought back and counted, **Leave** / `Esc` / background click to leave. English and French.
- Browser tests of the page in headless Chromium with Playwright (`tests/browser/`, marker `browser`, dependency group `browser`), excluded from the default run and from CI (D-019); includes a check on a 1,500-table payload.
- `dbtscope` 0.2.0: the `dbt-erd-html` v0.2 tool imported into the template layout. One self-contained HTML page with a universe view (tables grouped by data domain, layers, routes, filters, semantic zoom) and a detail view (Graphviz ERD), built from the dbt manifest; `dbt-erd.yml` config with selectors, kinds, domains and layers; `data_vault` and `star_schema` presets; manual layout exported to and embedded from `dbt-erd-layout.json`.

### Changed

- Licence (D-034): dbtscope is now licensed under the Apache License 2.0 (`LICENSE`, `NOTICE`), instead of MIT.
- CI paused during development (D-031, D-032): no automatic run; started by hand from the Actions tab, with an option to add Windows and macOS to the tests; read-only token; same checks as before.
- README opens with install and use cases (bash and PowerShell); diagrams of the run, the layers and the `/feature` workflow; troubleshooting lists every error message; two tests keep the README options and the documented commands in line with `--help` (M4.3).
- CLI rebuilt with Typer (M4.2, D-026, D-029). `--help` groups the options (Project, dbt, Output, Page), states each default and ends with examples; `--preset` and `--view` are checked choices. Option names, `-h`, `--version` and `python -m dbtscope` are unchanged. Typer is now a runtime dependency (`typer>=0.27.2`, with rich and shellingham).
- CLI output (D-029): stdout holds only the summary, whose first line is the **absolute** path of the page; progress lines (`Running dbt parse in …...`, `Opening the page in the browser...`) and **dbt's own output** now go to stderr (scripts that read dbt's log from dbtscope's stdout must read stderr). dbt runs with `DBT_USE_COLORS=false` when stderr is not a terminal and the variable is unset. The summary always has a `page:` line (view, language, CDN or offline, size) and a `config:` line, counts use thousands separators and the singular for 1, and the `layout:` line gives the file and when it was saved.
- Every failure is one line `dbtscope: error: <what happened>; <what to do>`, never a traceback: files are named `manifest <path>`, `config <path>`, `layout <path>` with their absolute path; usage errors are one line ending `; see dbtscope --help` (no usage block); the page is written atomically. Fixed tracebacks: an output folder that cannot be created or written (permission, read-only, disk full, name too long), a dbt that cannot be run, Ctrl-C (now `interrupted`, exit code 130), a closed stdout (silent, exit code 1). Clearer messages for a missing or misplaced project, config, manifest or dbt, an empty or truncated manifest, invalid YAML (line and column), an unknown selector field, an empty selection.
- Exit code changes (approved, design note § 8): an unknown or empty `--preset` and an empty path option (`-o ""`, `--config ""`, `--manifest ""`, `--dbt ""`, `--project-dir ""`) are usage errors, exit 2; a layout path that is a folder, a layout `version` other than 1 or a non-mapping `universe` / `detail` section, and an output that exists and is not a regular file (`/dev/null`, a FIFO) stop the run with exit 1 instead of being ignored or replaced.
- New warnings, exit code 0: the browser could not be opened (the page's `file://` address is printed), the detail view or the universe view is empty.
- Code review (M4.1, D-027, D-028), no user-visible change: one page encoder (`render/page.embedded_json`) and one list of vendored files (`render/page.vendored_files`) shared by the page, the vendoring tool and the tests; dead fallbacks and unused parameters removed in `domain/`; shared test helpers in `tests/conftest.py` and `tests/browser/conftest.py`; redundant tests removed or merged (default suite 397 → 346 tests, 2.75 s → 1.9 s; browser suite 98 → 84); a glossary of the project's words in `docs/architecture.md`; `from __future__ import annotations` enforced by ruff. The generated page is unchanged byte for byte.
- Typed data model (M3, D-024, D-025): manifest input, tables and relations, configuration and page data are pydantic v2 models. pydantic is now a runtime dependency. The generated page is unchanged byte for byte.
- Stricter inputs, each failure one line with exit code 1: an invalid or unexpected manifest stops with `dbtscope: error: manifest <path>: <location>: <problem>`; `include_packages` and `offline` accept only `true` / `false`; a `universe` that is not a mapping is refused; a manifest, layout, `dbt-erd.yml` or preset that is not UTF-8, not valid JSON / YAML or nested too deeply is reported instead of a traceback. An invalid layout file now says "is not valid JSON".
- Config error messages reworded as `config <path>: <key>: <problem>` (for example `config <path>: view: must be 'universe' or 'detail'; fix the file`).
- A number is accepted as `title` or rule `label` (`title: 2024`).
- French layout buttons now name what they act on: "Réinitialiser la disposition", "Importer une disposition".
- The ☰ panel toggles are named "Filters" ("Filtres") for screen readers and on hover, and expose `aria-expanded`.
- Browser tests need no network: the page's libraries are served from their vendored copies (D-022, supersedes the network part of D-019).
- CI reduced to one Ubuntu job: ruff, the default test suite and a gitleaks secret scan (D-020). Duplicate-code detection stays in pre-commit; Windows and macOS test runs and coverage are gone.
- Command renamed from `dbt-erd` to `dbtscope`; `dbt-erd.yml`, `dbt-erd-layout.json` and the layout format are unchanged (D-013).
- Requires Python ≥ 3.12 (was ≥ 3.10).
- The design brief of the universe view is translated into English (`docs/brief-universe-view.md`).

### Fixed

- Detail view (M4.4): a column without a `data_type` no longer breaks the whole diagram with "Render error: … in label of node …"; its type cell is left empty.
- `--dbt` given as a relative path is run as its absolute path; it was looked up from the project folder, where dbt runs (M4.2).
- A dbt group owner whose email is a list (manifest v12) no longer stops the run; the addresses are joined.
- A `relationships` test without `attached_node` is now drawn (its child is taken from the test's dependencies).
- A dbt description containing `<!--` or `<script>` could stop the page scripts from running; every `<` of the embedded data is now escaped (D-023).
- On screens about 360 px wide, the tab bar and the layout buttons wrap instead of causing a horizontal scroll.

### Template

- Project template: `src/` layout managed with uv, pure `domain/` layer with a layering test, atomic file writer, example CLI.
- Claude Code workflow: project rules (`CLAUDE.md`), six agents (architect, ui-designer, developer, tester, reviewer, documentation), skills `/init-project`, `/feature`, `/build-roadmap`, `/release`, `/add-fixture`, `/add-decision`, hooks guarding secrets and `main` and formatting edited files.
- Quality gates: commit-msg check, pre-commit (ruff, duplicate code, gitleaks), CI on Ubuntu, Windows and macOS.
