# Changelog

All notable changes are listed here, newest first. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versions follow semantic versioning.

## [Unreleased]

### Added

- Constellations by layer (M5.13, D-047): the universe panel opens with **Constellations: Domains | Layers** ("Domaines | Couches"). **Layers** makes one constellation per layer, left to right along the data flow; inside each, the tables of each domain sit in a band tinted in the domain's colour and marked by an arc of the rim, with the domain's name when zoomed in; the tooltip lists the layer's domains. The switch is hidden below two layers. New config key `universe.constellations: domains | layers` (default `domains`, also in presets); the page's data gains `defaults.constellations`, its last universe key, and nothing else. Each grouping keeps its own arrangement: new optional scopes `layers:names`, `layers:keys`, `layers:all` in the `universe` section of `dbt-erd-layout.json` (format and version unchanged; old files load unchanged, **Reset layout** clears both). Each viewer's last choice is kept in the browser (`dbtscope-constellations:<title>`), never exported. Filters, search, trajectory, flow and export behave the same in both modes; domain-mode placement is unchanged. The reference pages are regenerated.
- Flow view, the start stands out (M5.11): a dark ring and a soft grey glow surround the start table and keep the same screen size at every zoom, so the start is found at a glance even at Fit on 150 tables; they lie under every table and arrow and are exported in the PNG and SVG as shown. The header's start name is now a button ("Centre the view on the start table" / "Centrer la vue sur la table de départ"), second in the Tab order: it centres the start at the current scale, or 0.75 if smaller. The Domains list marks the start with a double dark frame, as the universe does. The embedded data, `dbt-erd.yml`, `dbt-erd-layout.json` and the localStorage key are unchanged; the reference pages grow by 2,483 bytes.
- Colour marks (M5.7, D-042): every kind or domain colour drawn as a mark reaches 3:1 against the page (WCAG 1.4.11), whatever colours `dbt-erd.yml` chooses: universe stars, card borders and header bands, domain circles and composition bars, every filter, legend and title dot, detail table borders and headers, flow domain bands and kind headers. A light colour (`#ffffff`, `#ffff00`…) keeps its fill and gets a 1 px outline in the same hue darkened just enough; thin marks (borders, bars, the domain circle) are drawn in that darker colour. Colours that already reach 3:1 look exactly as before; in the shipped presets and the example, the source and no-domain greys, the satellite, reference-satellite and fact colours and the example's Customer and Sales domains get the outline or darker edge. Exported images show the same marks.

- Contrast (M5.4, D-037): text on colours reaches WCAG AA (4.5:1) whatever colours `dbt-erd.yml` chooses. Table names on their kind colour (universe cards, detail and flow headers) stay white where white passes and turn black elsewhere: the built-in source, seed and `other` colours and the preset link, satellite, reference and fact colours now take black. Domain names on the universe are drawn in their colour darkened just enough; the detail's column types and "+ N columns" row use the theme grey, darkened on tints where needed. Exported images show the same inks.

- Flow view (M5.3, D-036): **Flow** in the trajectory bar draws the current trajectory (same start, direction and depth) left to right with Graphviz, in an overlay over the whole Universe tab: upstream tables on the left, the start in a thick dark frame, downstream tables on the right, every arrow pointing right. Each table shows its kind colour, its domain as a colour band (listed with counts under **N domains**), its depth (`−2`, `+1`) and its layer; columns follow the lineage with the configured layers as a floor. Click (or Enter) on a table to recentre; **← Universe** or `Esc` returns to the universe exactly as it was; nothing is saved. PNG and SVG export as `<title>-flow.png|svg`. At most 150 tables: above that the depth is reduced, or level 1 is cut, with a message. English and French, 44 px targets on touch, no horizontal scroll at 360 px. The embedded data and the layout file are unchanged; the reference pages grow by 30,179 bytes.
- Small screens (M5.2, D-035): a view that starts in a window 600 px wide or narrower opens with its side panel closed (☰ reopens it); there an open panel sits above the toolbar, full width, at most 45 % of the screen height, so nothing scrolls sideways at 360 px. On touch screens every control is a 44 px target. Desktop rendering is unchanged.
- Example project `examples/acme_retail/` (M5.1, D-033): a fake dbt project (sources, staging, Data Vault, star-schema marts in 6 dbt groups, `relationships` tests, `foreign_key` constraints, seeds, snapshots, typed and untyped columns) valid for dbt-core and dbt Fusion; README § Try it on the example project. Its `dbt parse` manifest is committed compressed (`tests/fixtures/acme_retail/manifest.json.gz`, 104 kB) and regenerated by `tools/example_manifest.py`; the default tests build both views from it without dbt, a browser test draws every detail group in both column modes, and `DBTSCOPE_DBT` turns on a check against a fresh `dbt parse`.
- README: installing from the private repository (GitHub CLI, SSH or a fine-grained token, checked with `git ls-remote`) and a token step in the GitHub Actions example.
- Preset files (M4.2b, D-030): `--preset-file <path>` (relative to the current folder) or `preset: <path>` in `dbt-erd.yml` (relative to the config file's folder, `\` read as `/`; a value holding `/` or `\` or ending with `.yml` / `.yaml`) starts a run from a team's own conventions. `--preset` with `--preset-file`, or an empty `--preset-file`, is a usage error (exit code 2). Every preset, built-in or file, is validated on its own: an unknown key, `output`, `layout_file` or a chained `preset` stops the run with one line, `preset <path>: <key>: <problem>; fix the file` (exit code 1), an unknown key shown first. A wrong `--preset` now suggests `--preset-file`. `dbt-erd.yml` stays lenient. The summary's `config:` line names the preset applied, also when it comes from the file's `preset:` key; an unknown name in that key now suggests giving the path of a preset file. The generated page is unchanged byte for byte.
- Image export (M2, D-021): **Export image** at the end of each toolbar saves exactly the current view (zoom, filters, detail level, highlight, trajectory dimming) on the page background: PNG in the universe, PNG and SVG in the detail. PNGs at twice the screen resolution; the SVG is cut to the visible area and opens on its own. Files are named `<title>-<view>.<ext>`. English and French.
- Offline page (M2, D-021): `--offline` or `offline: true` in `dbt-erd.yml` embeds d3, Viz.js and svg-pan-zoom, so the page works with no network; the CLI summary gives its size. The libraries are vendored in `src/dbtscope/render/vendor/` at the exact CDN bytes, with their licences: d3, Viz.js, svg-pan-zoom, Graphviz (with its source URL), Expat, Emscripten and musl. `tools/vendor_libraries.py` refreshes them (`--check` verifies their hashes).
- Trajectory mode of the universe view (M1, D-018): click a table, or use **Trajectory** after a search, to highlight its upstream and downstream lineage across domains and layers while the rest is dimmed and the layout stays still. Direction and depth selectors, per-domain counts, filtered tables brought back and counted, **Leave** / `Esc` / background click to leave. English and French.
- Browser tests of the page in headless Chromium with Playwright (`tests/browser/`, marker `browser`, dependency group `browser`), excluded from the default run and from CI (D-019); includes a check on a 1,500-table payload.
- `dbtscope` 0.2.0: the `dbt-erd-html` v0.2 tool imported into the template layout. One self-contained HTML page with a universe view (tables grouped by data domain, layers, routes, filters, semantic zoom) and a detail view (Graphviz ERD), built from the dbt manifest; `dbt-erd.yml` config with selectors, kinds, domains and layers; `data_vault` and `star_schema` presets; manual layout exported to and embedded from `dbt-erd-layout.json`.

### Changed

- Labels (M5.13): a domain, layer or kind whose rule sets `label: null` is shown by its key everywhere in the page; such a layer showed nothing in the panel and "null" in the tooltip and the flow. The hint now says "drag … a constellation by its name" and "double-click a constellation".
- Example project as a medallion (M5.12, D-046): `examples/acme_retail/` moves to `models/bronze_<system>/`, `models/silver/<domain>/` (the Data Vault) and `models/gold/<domain>/` (the marts). Domains come from the schemas by convention (`+schema: <domain>` and a `generate_schema_name` macro that keeps it as is), no longer from dbt groups or `meta.domain`; groups, owners and `access` are removed. The page shows the layers Sources → Bronze → Silver → Gold and the detail groups become the six domain schemas. Every `unique_id` and domain key is unchanged, so saved layouts still apply; dbtscope itself is unchanged.
- Zoom (M5.10, D-045): the detail and flow views zoom like the universe, with d3: the mouse wheel zooms anywhere in the drawing area, over a table or not (it zoomed only over a table on macOS), a two-finger pinch zooms the drawing on touch screens and trackpads, and dragging the background pans. Safari's trackpad pinch (its `gesture*` events) zooms the drawing, never the page, in all three views. On touch screens, universe tables and domains are no longer dragged (a drag pans, a pinch zooms wherever it starts), as in the detail; the detail's hint has a touch variant. One wheel notch is about 1.15× in every view (the detail used 1.3×); the maximum zoom is 12× real size (was 40× the fit). Fit, the flow's initial view, table dragging and saved positions, and exports equal to the screen are unchanged. svg-pan-zoom is no longer loaded, embedded or shipped (`vendor/` loses it and its BSD-2-Clause licence): the default page loads d3 and Viz.js only, and the offline page is 28,844 bytes smaller. The embedded data, `dbt-erd.yml`, `dbt-erd-layout.json` and the localStorage key are unchanged; the CDN reference pages grow by 2,219 bytes.
- CI (M5.9, D-044): Windows and macOS run only the tests that touch the operating system; the secret scan runs in the pre-commit hook only.
- CI (M5.8, D-043): runs again on pull requests and pushes to `main`, on Linux, Windows and macOS; it installs only the new `test` dependency group, with uv from PyPI; ruff and gitleaks run on Linux.
- Seed colour (M5.7, D-042): the built-in seed kind is red `#c62a36` (was violet `#8b5cf6`, next to the dimension and bridge violet `#8e5bb5` of the presets and the example, with the opposite text colour); seed names on it are white. The universe data of a project with seeds changes; config and layout formats do not. The reference pages (no seed) grow by 1,413 bytes, their data unchanged.
- Universe layout (M5.5, D-040): inside each domain, tables are placed in layer bands, left to right along the data flow (sources, staging, …, marts), ordered by lineage inside a band, and laid out side by side in the smallest circle around them; long names wrap on two lines at names level, names and cards never overlap at any level, and the picture is the same at every generation. Circles are smaller than before at names level; at the card levels a domain with a few bands of wide cards forms a wide row (its circle cannot be narrower than its bands). From afar, a name that would cover another star or leave its circle is not drawn. Tables matching no configured layer ("Other") follow their parents. Faint lines separate the bands when zoomed in, and the domain tooltip lists its layers ("Layers: Sources → Staging → Raw vault → Marts"). Saved arrangements load unchanged: pinned domains stay put, dragged tables keep their offset and push computed tables off; **Reset layout** gives the new placement. On a 1,500-table project the page opens in about 0.3 s and a detail change takes about 50 ms. The embedded data and the layout file are unchanged; the reference pages grow by 11,526 bytes.
- Page touch-ups (M5.4, D-038, D-039): the muted grey is darker (`#5f6774`, was `#6b7280`, which fell below 4.5:1 on the page background) and the universe card's column types use it (were `#9aa3af`). At 600 px or narrower the open detail panel takes at most 35 % of the screen height (the universe panel keeps 45 %). Every number follows the page language ("1,234" / "1 234"): counts, filter counts, cap messages, depth labels. French strings put a no-break space before `:` and a narrow one before `?`, `!`, `;`; the English domain tooltip reads "owner: x" (was "owner : x"). The flow tooltip's description is in the text colour, as in the universe (was muted). The embedded data and the layout file are unchanged; the reference pages grow by 3,792 bytes.

- Detail view (M5.3): a table or column name holding a backslash (`a\Nb`, `q\\z`) is now drawn as written; Graphviz read `\N`, `\G`, `\\`… as escapes. The French **Fit** button of the detail reads "Recadrer", as in the universe (was "Recentrer").
- Page scripts (M5.3): the lineage traversal, the trajectory colours and strings, the Graphviz renderer, the pan-zoom mount and the SVG / PNG export of a Graphviz diagram move to `common.js`, shared by the detail and flow views; the detail view's behaviour is unchanged.
- Page polish (M5.2): every count agrees in number in English and French ("1 table", "0 table · 0 lien · 0 domaine", "+ 1 column", "1 relation", "1 table brought back by the trajectory"; French: 0 and 1 are singular). The universe count line now also updates when the filters leave no table (it kept the previous counts). Names and labels holding `"` or `'` no longer break the universe search list or the filter rows (one shared escaper; filter rows built as text). The page scripts share a new first script, `common.js` (strings, escaper, plural, side-panel toggle, filter row). The embedded data and the layout file are unchanged; the reference pages grow by 3,981 bytes.
- Licence (D-034): dbtscope is now licensed under the Apache License 2.0 (`LICENSE`, `NOTICE`), instead of MIT.
- CI paused during development (D-031, D-032): no automatic run; started by hand from the Actions tab, with an option to add Windows and macOS to the tests; read-only token; same checks as before.
- README opens with install and use cases (bash and PowerShell); diagrams of the run, the layers and the `/feature` workflow; troubleshooting lists every error message; two tests keep the README options and the documented commands in line with `--help` (M4.3).
- CLI rebuilt with Typer (M4.2, D-026, D-029). `--help` groups the options (Project, dbt, Output, Page), states each default and ends with examples; `--preset` and `--view` are checked choices. Option names, `-h`, `--version` and `python -m dbtscope` are unchanged. Typer is now a runtime dependency (`typer>=0.27.2`, with rich and shellingham).
- CLI output (D-029): stdout holds only the summary, whose first line is the **absolute** path of the page; progress lines (`Running dbt parse in …...`, `Opening the page in the browser...`) and **dbt's own output** now go to stderr (scripts that read dbt's log from dbtscope's stdout must read stderr). dbt runs with `DBT_USE_COLORS=false` when stderr is not a terminal and the variable is unset. The summary always has a `page:` line (view, language, CDN or offline, size) and a `config:` line, counts use thousands separators and the singular for 1, and the `layout:` line gives the file and when it was saved.
- Every failure is one line `dbtscope: error: <what happened>; <what to do>`, never a traceback: files are named `manifest <path>`, `config <path>`, `layout <path>` with their absolute path; usage errors are one line ending `; see dbtscope --help` (no usage block); the page is written atomically. Fixed tracebacks: an output folder that cannot be created or written (permission, read-only, disk full, name too long), a dbt that cannot be run, Ctrl-C (now `interrupted`, exit code 130), a closed stdout (silent, exit code 1). Clearer messages for a missing or misplaced project, config, manifest or dbt, an empty or truncated manifest, invalid YAML (line and column), an unknown selector field, an empty selection.
- Exit code changes (approved, design note § 8): an unknown or empty `--preset` and an empty path option (`-o ""`, `--config ""`, `--manifest ""`, `--dbt ""`, `--project-dir ""`) are usage errors, exit 2; a layout path that is a folder, a layout `version` other than 1 or a non-mapping `universe` / `detail` section, and an output that exists and is not a regular file (`/dev/null`, a FIFO) stop the run with exit 1 instead of being ignored or replaced.
- New warnings, exit code 0: the browser could not be opened (the page's `file://` address is printed), the detail view or the universe view is empty.
- Code review (M4.1, D-027, D-028), no user-visible change: one page encoder (`render/page.embedded_json`) and one list of vendored files (`render/page.vendored_files`) shared by the page, the vendoring tool and the tests; dead fallbacks and unused parameters removed in `domain/`; shared test helpers in `tests/conftest.py` and `tests/browser/conftest.py`; redundant tests removed or merged (default suite 397 → 346 tests, 2.75 s → 1.9 s; browser suite 98 → 84); a glossary of the project's words in `docs/architecture.md`; `from __future__ import annotations` enforced by ruff. The generated page is unchanged byte for byte.
- Typed data model (M3, D-024, D-025): manifest input, tables and relations, configuration and page data are pydantic v2 models. pydantic is now a runtime dependency. The generated page is unchanged byte for byte.
- Stricter inputs, each failure one line with exit code 1: an invalid or unexpected manifest stops with `dbtscope: error: manifest <path>: <location>: <problem>`; `include_packages` and `offline` accept only `true` / `false`; a `universe` that is not a mapping is refused; a manifest, layout, `dbt-erd.yml` or preset that is not UTF-8, not valid JSON / YAML or nested too deeply is reported instead of a traceback. An invalid layout file now says "is not valid JSON".
- Config error messages reworded as `config <path>: <key>: <problem>` (for example `config <path>: view: must be 'universe' or 'detail'; fix the file`).
- A number is accepted as `title` or rule `label` (`title: 2024`).
- French layout buttons now name what they act on: "Réinitialiser la disposition", "Importer une disposition".
- The ☰ panel toggles are named "Filters" ("Filtres") for screen readers and on hover, and expose `aria-expanded`.
- Browser tests need no network: the page's libraries are served from their vendored copies (D-022, supersedes the network part of D-019).
- CI reduced to one Ubuntu job: ruff, the default test suite and a gitleaks secret scan (D-020). Duplicate-code detection stays in pre-commit; Windows and macOS test runs and coverage are gone.
- Command renamed from `dbt-erd` to `dbtscope`; `dbt-erd.yml`, `dbt-erd-layout.json` and the layout format are unchanged (D-013).
- Requires Python ≥ 3.12 (was ≥ 3.10).
- The design brief of the universe view is translated into English (`docs/brief-universe-view.md`).

### Fixed

- Windows: a path with a name over 255 characters now gives `file name too long; choose a shorter <option>` (was `invalid argument; check <option>`), and system errors use the same words on every OS (`file name too long`, `permission denied`, `no space left on device`…, no longer the OS's own wording). On every OS, Ctrl-C during `dbt parse` still stops dbt before `interrupted` is printed; this is now tested with a dbt that ignores Ctrl-C.
- Config (M5.6, D-041): a rule colour that is not hex (`red`) or a short hex (`#26b`) no longer crashes the run. A short hex is written out; anything else stops the run with one line naming the file and the rule, for example `config …/dbt-erd.yml: kinds[0].color: invalid colour 'red' (a hex colour such as '#2f6fb5'); fix the file`.
- Detail view (M4.4): a column without a `data_type` no longer breaks the whole diagram with "Render error: … in label of node …"; its type cell is left empty.
- `--dbt` given as a relative path is run as its absolute path; it was looked up from the project folder, where dbt runs (M4.2).
- A dbt group owner whose email is a list (manifest v12) no longer stops the run; the addresses are joined.
- A `relationships` test without `attached_node` is now drawn (its child is taken from the test's dependencies).
- A dbt description containing `<!--` or `<script>` could stop the page scripts from running; every `<` of the embedded data is now escaped (D-023).
- On screens about 360 px wide, the tab bar and the layout buttons wrap instead of causing a horizontal scroll.

- Claude Code workflow: project rules (`CLAUDE.md`), six agents (architect, ui-designer, developer, tester, reviewer, documentation), skills `/init-project`, `/feature`, `/build-roadmap`, `/release`, `/add-fixture`, `/add-decision`, hooks guarding secrets and `main` and formatting edited files.
- Quality gates: commit-msg check, pre-commit (ruff, duplicate code, gitleaks), CI on Ubuntu, Windows and macOS.
