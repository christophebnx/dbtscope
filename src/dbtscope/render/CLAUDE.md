# render/ — rules

- Builds the single self-contained HTML page from the view data computed in `domain/`. No business rule here: what is drawn, grouped and coloured is decided in `domain/detail.py` and `domain/universe.py`.
- Imports allowed: the standard library and `domain`. Reads its own assets through `importlib.resources`, never from the working directory.
- **No edit under `assets/` outside a milestone that changes the page** (D-028): the assets are inlined, so any edit, even a comment or whitespace, changes the page bytes checked by `tests/fixtures/m3-reference-pages/`.
- The page lays itself out in the browser (layer bands packed into discs, d3-force for the domains and a canvas for the universe, D-040; Graphviz via Viz.js for the detail and the flow view); Python only embeds the data as JSON.
- The embedded JSON is `domain/payload.PagePayload` serialised by `embedded_json`: `model_dump(by_alias=True)` then the one `json.dumps(ensure_ascii=False, separators=(",", ":"))`, never `model_dump_json` (one encoder, byte identity with `tests/fixtures/m3-reference-pages/`).
- Every `<` in the embedded JSON is escaped as `\u003c` (D-023), so data can never close or disturb a `<script>` block. Every `</script` of an inlined library (and of its licence banner) is escaped as `<\/script`; a vendored file, script or licence, must hold none of `UNSAFE_MARKUP` (`<!--`, `<script`; checked by `tools/vendor_libraries.py` and `tests/unit/test_vendor.py`).
- The JS writes and reads the layout format `dbt-erd-layout` (`domain/layout.LAYOUT_FORMAT`, written once in boot.js as `LAYOUT_FORMAT`) and the localStorage key `dbt-erd-layout:<title>`: change them only with a decision that supersedes D-013.
- Scripts are inlined in this order, each in its own `<script>` block: `common.js`, `detail.js`, `universe.js`, `flow.js`, `boot.js`. Page-wide constants and pure helpers are globals declared in `common.js` (`PAGE`, `STRINGS`, `L`, `esc`, `num`, `plural`, `THEME`, `CONTRAST`, `paintDot`, `dotEdge`, `sidePanel`, `filterRow`, `fillSelect`, `tableTip`, `tableDesc`, `trajectory`, `flowRanks`…, the Graphviz helpers); it only declares (no DOM work at load but `document.documentElement.lang`) and holds no `</script`. Stateful services built by `boot.js` (`LAYOUT`, `EXPORT`, `openInDetail`, `openFlow`, `closeFlow`) are passed to `startDetail` / `startUniverse` / `startFlow` as parameters. A view never declares a global.
- UI strings, in every supported language (`en`, `fr`, D-016), are written `{ en: {…}, fr: {…} }[PAGE.lang]`: page-wide strings (used by `boot.js`, or shown with the same text by both views) in `common.js` `STRINGS` / `L`, a view's own strings in the `T` at the top of its start function. A count's noun is a `[singular, plural]` pair shown through `plural(n, forms)` (French: 0 and 1 are singular).
- Text on a colour takes `CONTRAST.textOn(fill)`, text drawn in a colour `CONTRAST.ink(color, background)`, so it reaches 4.5:1 whatever the config's colours (D-037). A kind or domain colour drawn as a mark reaches 3:1 on `THEME.bg` (D-042): a filled area keeps its colour and gets an outline in `CONTRAST.edge` (canvas stroke, `dotEdge` for a Graphviz cell, `paintDot` for a page dot); a line, a border or a bar of 6 px or less is drawn in `CONTRAST.edge` itself; a colour that passes gets no outline, so its look is unchanged; the scripts draw with `THEME`, the copy of `page.css :root` `--bg` / `--fg` / `--muted` (change both together). Every number shown goes through `num` (D-039). French strings write `\u00a0` before `:` and `\u202f` before `?` `!` `;`, as escapes, never as literal characters; a label and a value are joined with `L.colon` (D-039).
- Style: the bodies of `startDetail` / `startUniverse` / `startFlow` are indented; a helper with a block body is a `function` declaration, a one-expression helper or lambda an arrow `const`.
- Names, descriptions and config labels are untrusted: set them with `textContent` / `title` (filter rows through `filterRow`), or pass them through `common.js esc`, the one HTML escaper (`& < > " '`), before any `innerHTML`; text inside a Graphviz HTML-like label goes through `dotText` (`esc`, then every backslash doubled: Graphviz reads `\\`, `\N`, `\G`… there as escapes); DOT ids and strings go through `dotStr`.
- Page behaviour is tested in headless Chromium under `tests/browser/` (D-019), with the libraries served from `vendor/` and no network (D-022); `tests/unit/test_page.py` only checks the rendered markup.
- A library is added or upgraded in `page.LIBRARIES` only, then `tools/vendor_libraries.py` refreshes `vendor/`.
- Every zoom of the page is a d3 zoom attached with `common.js zoomOn` to an HTML element that fills the stage (`#d-graph`, `#f-graph`, `#u-canvas`, all `touch-action:none`), never to an `<svg>`: no second zoom library, no second gesture handler (D-045).
- Any `#d-graph` or `#f-graph` CSS rule that changes how a diagram looks adds its property to `common.js INLINE`, or the exported SVG will not look like the screen (focus outlines and cursors are never exported).
- Export controls stay in the toolbars, never inside `.canvas-box`: they must not be drawn into the image.

## Modules

| Module | Owns |
|---|---|
| `page.py` | `render_page(detail: DetailPayload, universe: UniversePayload, config: Config, layout, offline=False)`: wraps both views in `PagePayload` and assembles `assets/page.html` with its CSS, scripts (`COMMON_JS` first) and the JSON payload, in one substitution pass. `embedded_json(payload)`: the one page encoder, with the D-023 escape. `vendored_files()`: every file of `vendor/` by name (`VendoredFile`: URL, label, SPDX id, sha256 of a script), once each, library by library (script, licence, notices); read by `tools/vendor_libraries.py` (download, `README.md`) and the tests. `UNSAFE_MARKUP`. `LIBRARIES` (`Library`, `Notice`, whose `source` the banner prints as `Source: <url>` when the licence asks for it, EPL-1.0 § 3): the one list of the page's JavaScript libraries (CDN URL, vendored file, licence, sha256); `_scripts(offline)` writes into `{{SCRIPTS}}` either their `<script src>` tags or, offline, one inline block per library with its licence banner |
| `vendor/` | The libraries of `LIBRARIES` at the exact CDN bytes, their licences (and those of Graphviz, Expat, the Emscripten runtime and its musl libc, compiled into `full.render.js`), `README.md` (provenance). Written only by `tools/vendor_libraries.py`, never edited by hand; `-text` in `.gitattributes` |
| `assets/page.html`, `assets/page.css` | Page shell, tabs, side panels (stacked above the toolbar at 600 px or narrower, D-035; at most 45vh there, 35vh for the detail, D-038), toolbars, the trajectory bar (`#u-trajbar`, an overlay at the top of the universe canvas so the stage never resizes, with **Flow** `#u-tj-flow`), the flow view (`#f-view`, D-036: an overlay; its title holds the start as the button `#f-start`, M5.11; the Domains list marks the start with a double dark frame, `.fmk.start`; over the whole Universe tab, `#tab-universe` is `position:relative`; first child of the tab so its toolbar never follows a `.canvas-box` in the markup), the **Export image** groups (`.export`: `#u-export`, `#d-export-png`, `#d-export-svg`, `#f-export-png`, `#f-export-svg`) at the right end of each toolbar (`margin-left:auto`, also when it wraps), and `#export-live` in the top bar. Shared classes: `.tip` (both tooltips), `.tj-pop` (the trajectory and flow lists). Under `@media (pointer:coarse)` every control is a 44 px target (D-035) |
| `assets/common.js` | Inlined first. `PAGE` (the parsed payload), `STRINGS` / `L` (page-wide strings, including those the universe and the flow show alike, and `colon`, the label–value separator), `esc` (the one HTML escaper), `num(n)` (a number in the page language), `plural(n, [singular, plural])`, `THEME` (`bg`, `fg`, `muted`: the copy of `page.css :root`), `CONTRAST` (`AA`, `ratio(a, b)`, `textOn(fill)`, `ink(color, bg)`: WCAG contrast of text on colours, cached, D-037; `MARK`, `edge(color, bg)`: a colour drawn as a mark, darkened to 3:1 by the same darkening as `ink`, D-042), `paintDot(el, color)` (the one colour dot of the page: fill, plus an inset outline in `edge` when the colour falls short), `dotEdge(color)` (the ` border color` attributes outlining a Graphviz cell filled with a config colour, `''` when it passes), `sidePanel(view, onToggle)` (☰ button, `aria-expanded`, closed at start at 600 px or narrower, D-035), `filterRow({label, color, count, checked, title}, onChange)` (a filter checkbox row built with DOM calls, its dot through `paintDot`), `fillSelect(el, [[value, label]], current)`, `tableTip(DATA, n)` (name and meta lines of a table tooltip), `tableDesc(n)` (its description line, `.desc`). Trajectory: `TRAJ_COLORS`, `trajectory(lineage, start, direction, depth)` (the pure lineage traversal), `trajectoryEdges`, `trajectoryCounts`, `noTrajectory`, `trajectoryLevels` / `trajectoryTip` (a table's levels, as words or tooltip lines), `countByDomain`. `flowRanks(members, edges, layerOf)`: the pure columns along the data flow (lineage first, layers as a floor, a `null` layer gets no floor and counts in no span; cycles go to `back`), used by the flow's columns and the universe's layer bands (D-036, D-040). Graphviz views: `dotStr` (the one DOT-string escaper), `dotText` (the one escaper of label text), `GRAPHVIZ.render(dot, options)` (one lazy Viz instance, recreated after a failed render), `graphZoom(box, svg, isCurrent, onZoom)` (D-045: the svg's children moved into one bare `<g>`, the zoom layer, at one CSS pixel per point at scale 1; waits for a real size; d3.zoom on the box, never on the svg, so the whole area is a target; `clickDistance(3)`: a pan is not a click; resolves the handle `zv` = `layer`, `fit()`, `get()`, `set({x, y, k})`, `centre(rect, k)`, `destroy()`), `INLINE`, `svgImage(box, zv, scale)` (the visible part as a standalone SVG: `INLINE` styles inlined, off-area tables and links and tooltips removed, the zoom layer bare), `svgFile`, `pngImage(box, zv, EXPORT)`. Every view: `ZOOM_EXTENT` (the one scale range) and `zoomOn(sel, zoom)` (the one way to attach a d3 zoom: no double-click zoom, and Safari's trackpad `gesturestart` / `gesturechange` / `gestureend` cancelled and turned into `zoom.scaleBy` around the pointer, except while fingers are down, counted in the capture phase so a d3.drag or d3.zoom touch handler cannot hide a touch from it) |
| `assets/boot.js` | Tabs, shared layout store (browser storage + embedded file), export / import / reset of the layout (`LAYOUT_FORMAT`). `saveFile(name, blob)`: the page's one download implementation. `EXPORT` (`scale`, `png`, `save(view, ext, make, button)`): names (`<title>-<view>.<ext>`, via `fileSlug`), scales and saves the exported images, announces them in `#export-live`; passed to every view. `flow` (started on first use, not in `views`: layout reset and import never touch it), `openFlow(id, direction, depth)` (makes the universe panel and stage `inert`, focus on `#f-back`), `closeFlow()` (uncovers them, focus on `#u-tj-flow`) |
| `assets/universe.js` | Universe view. `startUniverse(DATA, openInDetail, detailIds, LAYOUT, EXPORT, openFlow)`: placement (D-040: `layoutDomain` puts a domain's tables in layer bands, `layerBands` orders them by `flowRanks` rank, barycentre, name and id; `packRow` lays the bands' reserved boxes (`box`: `w`, `h`, `oy`, the box centre's offset from the star; names on one or two lines by `nameLines`, label widths estimated, never measured) out in one row, each band in balanced `columns` under a height cap scanned for the smallest enclosing circle of the box corners (`d3.packEnclose`, deterministic: fixed-seed shuffle); `holds` + `margin()` give the radius that holds a box (layout and `reach`); deterministic, cached per domain; `placeAroundDragged` applies saved offsets and runs `separate`, the one rectangular pass, only around dragged tables, which never move; d3-force with seed 42 places the domains), layer markers between bands at scale ≥ 0.6 and the domain tooltip's layers line, `drawNames` (an ordinary name that would cover another star or leave its circle is skipped), canvas drawing, semantic zoom (attached with `common.js zoomOn`, range `ZOOM_EXTENT`), filters, drag (mouse only, D-045: on touch every finger goes to the zoom, so a pinch can start on a table), search, and the trajectory mode (enter / move / leave, bar, dimming, trajectory arrows, framing); `reveal` is the one way to tick filtered-out tables back on (search and trajectory). `draw(target, scale)` paints the screen, or an exported image, through the same helpers (the closure's `ctx` is swapped until it returns: keep it synchronous); `image()` is the PNG of the view as shown. The **Flow** button calls `openFlow` with the trajectory (never changed by the flow); its `Esc` handler ignores an `Esc` the flow already handled (`defaultPrevented`). It returns `{shown, relayout, trajectoryState, image, camera, place, geometry}`; `trajectoryState()`, `image()`, `camera(to)` (the zoom transform, moved first through the zoom when `to` is given), `place(id)` (a drawn table's reserved screen rectangle) and `geometry()` (`layoutMs`, tables with `P` and reserved box, domains with radius and world band ranges) are hooks for the browser tests, not used through the handle by the page |
| `assets/detail.js` | Detail view: `startDetail` (Graphviz ERD, group / kind filters, focus, drag; its hint has a touch variant under `pointer: coarse`, where a drag on a table pans), rendered and exported through the Graphviz helpers of `common.js`. It returns `{shown, relayout, focus, svgImage}`; `svgImage(scale)` on the handle is for the browser tests |
| `assets/flow.js` | Flow view (M5.3, D-036). `startFlow(DATA, EXPORT, close)`: columns from `common.js flowRanks`; the trajectory of one table at most `FLOW_MAX` tables (depth reduced, or level 1 cut), its DOT (ranks imposed with `rank=same` and `minlen`), render, initial view (`FLOW_MIN_SCALE`, through `zv.centre`), the start ring (M5.11: `addRing` puts a `.f-halo` group, glow and ring, first in Graphviz's graph group, under every table and arrow; `ringStart(k)`, called from graphZoom's `onZoom`, sizes it to `START_RING` screen pixels with SVG attributes only, so exports show it), **locate start** (`locateStart`, the header button `#f-start`: the start centred at max(current scale, `FLOW_MIN_SCALE`), nothing while laying out), recentre on click / Enter, tooltip, toolbar, `Esc`, export as `<title>-flow.<ext>`. Saves nothing. No resize hook: the d3 zoom is relative to the box's top-left corner, so a resized window keeps the zoom and pan (D-036). It returns `{open, close, isOpen, state, svgImage}`; `state()` and `svgImage` are hooks for the browser tests |
