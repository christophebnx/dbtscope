# render/ — rules

- Builds the single self-contained HTML page from the view data computed in `domain/`. No business rule here: what is drawn, grouped and coloured is decided in `domain/detail.py` and `domain/universe.py`.
- Imports allowed: the standard library and `domain`. Reads its own assets through `importlib.resources`, never from the working directory.
- The page lays itself out in the browser (d3-force + canvas for the universe, Graphviz via Viz.js for the detail); Python only embeds the data as JSON.
- The embedded JSON is `domain/payload.PagePayload`, dumped with `model_dump(by_alias=True)` then the one `json.dumps(ensure_ascii=False, separators=(",", ":"))`, never `model_dump_json` (one encoder, byte identity with `tests/fixtures/m3-reference-pages/`).
- Every `<` in the embedded JSON is escaped as `\u003c` (D-023), so data can never close or disturb a `<script>` block. Every `</script` of an inlined library (and of its licence banner) is escaped as `<\/script`; a vendored file, script or licence, must hold neither `<!--` nor `<script` (`tests/unit/test_vendor.py`).
- The JS writes and reads the layout format `dbt-erd-layout` (`domain/layout.LAYOUT_FORMAT`) and the localStorage key `dbt-erd-layout:<title>`: change them only with a decision that supersedes D-013.
- UI strings live in the tables at the top of each script (`L` in boot.js, `T` in universe.js and detail.js), in every supported language (`en`, `fr`).
- Names and descriptions from the manifest are untrusted: set them with `textContent` / `title`, or pass them through `esc` before any `innerHTML`.
- Page behaviour is tested in headless Chromium under `tests/browser/` (D-019), with the libraries served from `vendor/` and no network (D-022); `tests/unit/test_page.py` only checks the rendered markup.
- A library is added or upgraded in `page.LIBRARIES` only, then `tools/vendor_libraries.py` refreshes `vendor/`.
- Any new `#d-graph` CSS rule that changes how the diagram looks adds its property to `INLINE` in detail.js, or the exported SVG will not look like the screen.
- Export controls stay in the toolbars, never inside `.canvas-box`: they must not be drawn into the image.

## Modules

| Module | Owns |
|---|---|
| `page.py` | `render_page(detail: DetailPayload, universe: UniversePayload, config: Config, layout, offline=False)`: wraps both views in `PagePayload` and assembles `assets/page.html` with its CSS, scripts and the JSON payload, in one substitution pass. `LIBRARIES` (`Library`, `Notice`, whose `source` the banner prints as `Source: <url>` when the licence asks for it, EPL-1.0 § 3): the one list of the page's JavaScript libraries (CDN URL, vendored file, licence, sha256); `_scripts(offline)` writes into `{{SCRIPTS}}` either their `<script src>` tags or, offline, one inline block per library with its licence banner |
| `vendor/` | The libraries of `LIBRARIES` at the exact CDN bytes, their licences (and those of Graphviz, Expat, the Emscripten runtime and its musl libc, compiled into `full.render.js`), `README.md` (provenance). Written only by `tools/vendor_libraries.py`, never edited by hand; `-text` in `.gitattributes` |
| `assets/page.html`, `assets/page.css` | Page shell, tabs, side panels, toolbars, the trajectory bar (`#u-trajbar`, an overlay at the top of the universe canvas so the stage never resizes), the **Export image** groups (`.export`: `#u-export`, `#d-export-png`, `#d-export-svg`) at the right end of each toolbar (`margin-left:auto`, also when it wraps), and `#export-live` in the top bar |
| `assets/boot.js` | Tabs, shared layout store (browser storage + embedded file), export / import / reset of the layout. `saveFile(name, blob)`: the page's one download implementation. `EXPORT` (`scale`, `png`, `save(view, ext, make, button)`): names (`<title>-<view>.<ext>`, via `fileSlug`), scales and saves the exported images, announces them in `#export-live`; passed to both views |
| `assets/universe.js` | Universe view. Top level: `trajectory(lineage, start, direction, depth)`, the pure lineage traversal (no DOM, no state). `startUniverse`: d3-force layout, canvas drawing, semantic zoom, filters, drag, search, and the trajectory mode (enter / move / leave, bar, dimming, trajectory arrows, framing); `reveal` is the one way to tick filtered-out tables back on (search and trajectory). `draw(target, scale)` paints the screen, or an exported image, through the same helpers (the closure's `ctx` is swapped until it returns: keep it synchronous); `image()` is the PNG of the view as shown. It returns `{shown, relayout, trajectoryState, image}`; `trajectoryState()` and `image()` are hooks for the browser tests, not used through the handle by the page |
| `assets/detail.js` | Detail view: `startDetail` (Graphviz ERD, group / kind filters, focus, drag). `svgImage(scale)`: the visible part of the diagram as a standalone SVG (styles of `INLINE` inlined, off-area tables and links, tooltips and svg-pan-zoom markup removed); `pngImage` rasterises it. It returns `{shown, relayout, focus, svgImage}`; `svgImage` on the handle is for the browser tests |
