# domain/ — rules

- Pure business logic. No file system, no network, no database, no model calls, no environment variables, no current time read implicitly (pass `now` as an argument). Ids and random tokens come from callers.
- Imports allowed: the standard library, declared pure libraries (`pydantic` v2, D-025), and other `domain` modules. Nothing else from `dbtscope` (`tests/unit/test_layering.py`).
- Every public function has unit tests in `tests/unit/test_<module>.py`.
- Before adding a function, check the responsibility map in `docs/architecture.md`. If the responsibility exists, reuse or extend it. If you add a cross-cutting responsibility, add it to the map.
- Errors derive from `errors.DomainError`; the CLI turns them into exit code 1. A pydantic `ValidationError` becomes a message only through `errors.validation_message`.
- Tables are `model.Table` (built in one place, `manifest._table`); the input models of `manifest_schema` are read only by `manifest.py`. Three model configs only (D-028, D-030): `model.DOMAIN` (frozen, `extra="forbid"`) for everything dbtscope builds, reused by `payload` and `classify.BuiltinKind`; frozen with `extra="ignore"` for what users and dbt write (`config.SETTINGS`: `Config` / `Rule` / `KindRule` / `DomainRule` / `UniverseSettings`; `manifest_schema.INPUT`); frozen with `extra="forbid"` for presets (`config.PRESET_SETTINGS`: `Preset` / `PresetRule` / `PresetKindRule` / `PresetDomainRule` / `PresetUniverse`, subclasses of the config models, validators only). Sequences are tuples; `meta` is never mutated.
- Selector field names map to `Table` attributes only through `selectors.ATTRIBUTES` (`field_value`).
- The page JSON is byte-identical to `tests/fixtures/m3-reference-pages/`: a change of a payload field, its order or its type changes the page; regenerate the reference only for an intended page change, in the same commit.
- User-visible labels produced here (`Other`, `No domain`…) exist in every page language (`en`, `fr`).

## Modules

| Module | Owns |
|---|---|
| `errors.py` | `DomainError(ValueError)`, base of every module's error class; `in_words(values)`: `a, b or c`, the one way messages and the CLI help list choices; `lower_first(text)`: a reason or problem quoted inside a message; `validation_message(error, prefix, first)`: the one-line `<location>: <problem>` of a pydantic `ValidationError` (`nodes['model.x'].columns: must be a mapping`, `+ (and N more problems)`; an extra key is `unknown key`; `first`, an error type shown first when present); `PROBLEMS` (pydantic error type → its words) |
| `selectors.py` | Selector syntax (`name`, `tag`, `path`, `schema`, `database`, `package`, `type`; `,` = and, list = or) on a `Table`: `matches`, `matches_any`, `ATTRIBUTES` (field → attribute), `FIELDS` (the attributes and `tag`), `field_value`, `glob` (case-insensitive fnmatch), `name_patterns(selector)` (the positive name patterns of one selector, in order, read by `fold.stem`), `SelectorError` (an unknown field lists the fields in words; a bare `!` is `empty negation`); a part starting with `!` matches when the rest does not (D-061) |
| `manifest_schema.py` | Input models of the manifest fields read (`ManifestFile`, `NodeHeader`, `TableNode`, `SourceNode`, `RelationshipTest`…; `TableType`, the drawn `nodes` types; unknown fields ignored, optional fields nullable). No logic |
| `model.py` | Frozen domain models: `Column`, `Table`, `Relation` (with `origin`), `LineageEdge`, `Group`, `Project`; `DOMAIN`, the config of every model dbtscope builds |
| `manifest.py` | `parse_manifest(dict) -> Project`: tables, relations (`relationships` tests, FK constraints), lineage (`depends_on`), dbt groups (owner: name, else email or emails joined), root project; errors are `<location>: <problem>` without the file (storage prefixes `manifest <path>: `); a relationships test without `attached_node` takes its child from its two `depends_on` tables; entries of `nodes` dispatched on `NodeHeader` (others skipped unchecked); `ManifestError`, `NODE_TYPES` (= `TableType`), `RELATIONSHIP_TESTS`, `REF_RE` / `SOURCE_RE` (the `ref(...)` / `source(...)` of a relationships test's `to`) |
| `config.py` | `Config` (field defaults are the defaults; `kinds` are `KindRule`s: a `Rule` plus `role`, D-059; every kind rule gets a colour, `DEFAULT_KIND_COLOR` when unset; `offline`, a bool: embed the libraries in the page), `Rule`, `DomainRule` (a `Rule` plus `system: true | false`, `None` when not set, a strict bool; `Config.domains` are `DomainRule`s, D-068), `UniverseSettings` (`constellations`, default `domains`, D-048; `fold`, a strict bool, default true, D-063), `CONFIG_FILE`, `DEFAULT_KIND_COLOR`, `GROUP_BY_RE`, `GROUP_BY_CHOICES` (the `group_by` values in words, for its error), `HEX_COLOR_RE` (a rule `color` is `#rrggbb` or `#rgb`, written out; D-041), the literals `Role` (`core`, `connector`, `descriptive`, `technical`, `none`; `ROLES` its values, an unset role is `None`), `Language`, `View`, `Links`, `DetailLevel`, `Constellations` (`domains` \| `layers`) (declared here only, reused by `payload` and `classify`), `Text` (a string; a YAML number becomes its text: `title`, rule `label`), `merge_config(preset, file_config) -> Config` (defaults < preset < file, merged as dicts, validated once; `_inherited_roles`: a file kind rule without a role takes its preset kind's role by key), `ConfigError`. The command line overrides through `model_copy`. Presets (D-030): `Preset`, `PresetRule`, `PresetKindRule`, `PresetDomainRule`, `PresetUniverse`, `PRESET_SETTINGS`, `NOT_IN_PRESET` (`preset`, `output`, `layout_file` and why), `check_preset(data)` (the same dict if valid, else `ConfigError`), `is_preset_path(value)` (a `preset:` value holding `/` or `\` or ending with one of `PRESET_SUFFIXES`, `.yml` / `.yaml`) |
| `payload.py` | The Python → JavaScript contract: `DetailPayload`, `UniversePayload`, `PagePayload` and their parts, in page key order (`UniverseDefaults.fold`, default true, is the last key of the universe defaults, after `constellations` (default `domains`, D-048), D-063; `UniverseNode.parent`, default `""`, is the last key of a node, D-062; `UniverseKind.role`, default `none`, is the last key of a universe kind, D-059; `UniverseDomain.system`, default `false`, is the last key of a domain, D-068). No logic |
| `classify.py` | Rules shared by both views: `in_scope`, `group_of`, `first_rule`, `key_columns`, `background` (a kind colour tinted by `TINT`, for a table body), `TINT`, `BuiltinKind` (with its `role`), `OTHER` |
| `detail.py` | Detail view: `select(tables, relations, config, root)` (tables and relations drawn), `detail_data` → `DetailPayload` |
| `fold.py` | The parent of a descriptive table (D-062): `Member` (id, role, stem, domain, layer), `stem(table, rule)` (the name without the fixed part of the kind's name glob), `parents(members, relations)` (relation, then name; same domain and layer; ties give none; independent of input order), `PARENT_ROLES`. Used by `universe_data` now, by the detail skeleton later (M8.5) |
| `universe.py` | Universe view: `domain_of` (the domain key of a table, `""` for none), `flow_rank` (a default layer's position from its folder-name prefix, `FLOW_PREFIXES`; any other name `UNRANKED`, 4.5, between marts and report), `is_source_system(roles, override)` (a domain is a source system when `override` says so, else when it holds tables and every one has the role `technical`; the override is the first rule of `config.domains` with the domain's key that sets `system`, D-068), `universe_data` → `UniversePayload` (builds one `fold.Member` per node and sets `UniverseNode.parent` from `fold.parents`; sets `UniverseDomain.system` from the roles per domain), `TYPE_KINDS` (built-in source, seed and snapshot kinds, role `technical`; seed `#c62a36`, D-042), `NO_DOMAIN` (its label, en / fr), `NO_DOMAIN_COLOR`, `DESCRIPTION_LIMIT` (characters of a description kept), `PALETTE`, `FLOW_PREFIXES`, `UNRANKED` |
| `layout.py` | `LAYOUT_FORMAT`, `LAYOUT_VERSION` (1; a layout without `version` is accepted), `LAYOUT_SECTIONS` (`universe`, `detail`: mappings when present, any scope accepted, so the `layers:*` scopes of D-048 need no change), `LAYOUT_HINT`, `check_layout` (a file exported by the page that the page can read), `LayoutError` |
