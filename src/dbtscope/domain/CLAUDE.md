# domain/ — rules

- Pure business logic. No file system, no network, no database, no model calls, no environment variables, no current time read implicitly (pass `now` as an argument). Ids and random tokens come from callers.
- Imports allowed: the standard library, declared pure libraries (`pydantic` v2, D-025), and other `domain` modules. Nothing else from `dbtscope` (`tests/unit/test_layering.py`).
- Every public function has unit tests in `tests/unit/test_<module>.py`.
- Before adding a function, check the responsibility map in `docs/architecture.md`. If the responsibility exists, reuse or extend it. If you add a cross-cutting responsibility, add it to the map.
- Errors derive from `errors.DomainError`; the CLI turns them into exit code 1. A pydantic `ValidationError` becomes a message only through `errors.validation_message`.
- Tables are `model.Table` (built in one place, `manifest._table`); the input models of `manifest_schema` are read only by `manifest.py`. Three model configs only (D-028, D-030): `model.DOMAIN` (frozen, `extra="forbid"`) for everything dbtscope builds, reused by `payload` and `classify.BuiltinKind`; frozen with `extra="ignore"` for what users and dbt write (`config.SETTINGS`: `Config` / `Rule` / `UniverseSettings`; `manifest_schema.INPUT`); frozen with `extra="forbid"` for presets (`config.PRESET_SETTINGS`: `Preset` / `PresetRule` / `PresetUniverse`, subclasses of the config models, validators only). Sequences are tuples; `meta` is never mutated.
- Selector field names map to `Table` attributes only through `selectors.ATTRIBUTES` (`field_value`).
- The page JSON is byte-identical to `tests/fixtures/m3-reference-pages/`: a change of a payload field, its order or its type changes the page; regenerate the reference only for an intended page change, in the same commit.
- User-visible labels produced here (`Other`, `No domain`…) exist in every page language (`en`, `fr`).

## Modules

| Module | Owns |
|---|---|
| `errors.py` | `DomainError(ValueError)`, base of every module's error class; `in_words(values)`: `a, b or c`, the one way messages and the CLI help list choices; `lower_first(text)`: a reason or problem quoted inside a message; `validation_message(error, prefix, first)`: the one-line `<location>: <problem>` of a pydantic `ValidationError` (`nodes['model.x'].columns: must be a mapping`, `+ (and N more problems)`; an extra key is `unknown key`; `first`, an error type shown first when present) |
| `selectors.py` | Selector syntax (`name`, `tag`, `path`, `schema`, `database`, `package`, `type`; `,` = and, list = or) on a `Table`: `matches`, `matches_any`, `ATTRIBUTES` (field → attribute), `field_value`, `glob` (case-insensitive fnmatch), `SelectorError` (an unknown field lists the fields in words) |
| `manifest_schema.py` | Input models of the manifest fields read (`ManifestFile`, `NodeHeader`, `TableNode`, `SourceNode`, `RelationshipTest`…; `TableType`, the drawn `nodes` types; unknown fields ignored, optional fields nullable). No logic |
| `model.py` | Frozen domain models: `Column`, `Table`, `Relation` (with `origin`), `LineageEdge`, `Group`, `Project`; `DOMAIN`, the config of every model dbtscope builds |
| `manifest.py` | `parse_manifest(dict) -> Project`: tables, relations (`relationships` tests, FK constraints), lineage (`depends_on`), dbt groups (owner: name, else email or emails joined), root project; errors are `<location>: <problem>` without the file (storage prefixes `manifest <path>: `); a relationships test without `attached_node` takes its child from its two `depends_on` tables; entries of `nodes` dispatched on `NodeHeader` (others skipped unchecked); `ManifestError`, `NODE_TYPES` (= `TableType`), `RELATIONSHIP_TESTS` |
| `config.py` | `Config` (field defaults are the defaults; every kind rule gets a colour, `DEFAULT_KIND_COLOR` when unset; `offline`, a bool: embed the libraries in the page), `Rule`, `UniverseSettings`, `CONFIG_FILE`, `DEFAULT_KIND_COLOR`, `GROUP_BY_RE`, `HEX_COLOR_RE` (a rule `color` is `#rrggbb` or `#rgb`, written out; D-041), the literals `Language`, `View`, `Links`, `DetailLevel` (declared here only, reused by `payload` and `classify`), `Text` (a string; a YAML number becomes its text: `title`, rule `label`), `merge_config(preset, file_config) -> Config` (defaults < preset < file, merged as dicts, validated once), `ConfigError`. The command line overrides through `model_copy`. Presets (D-030): `Preset`, `PresetRule`, `PresetUniverse`, `PRESET_SETTINGS`, `NOT_IN_PRESET` (`preset`, `output`, `layout_file` and why), `check_preset(data)` (the same dict if valid, else `ConfigError`), `is_preset_path(value)` (a `preset:` value holding `/` or `\` or ending with `.yml` / `.yaml`) |
| `payload.py` | The Python → JavaScript contract: `DetailPayload`, `UniversePayload`, `PagePayload` and their parts, in page key order. No logic |
| `classify.py` | Rules shared by both views: `in_scope`, `group_of`, `first_rule`, `key_columns`, `background` (a kind colour tinted by `TINT`), `BuiltinKind`, `OTHER` |
| `detail.py` | Detail view: `select(tables, relations, config, root)` (tables and relations drawn), `detail_data` → `DetailPayload` |
| `universe.py` | Universe view: `domain_of` (the domain key of a table, `""` for none), `flow_rank`, `universe_data` → `UniversePayload`, `TYPE_KINDS`, `PALETTE`, `FLOW_PREFIXES` |
| `layout.py` | `LAYOUT_FORMAT`, `LAYOUT_VERSION` (1; a layout without `version` is accepted), `LAYOUT_SECTIONS` (`universe`, `detail`: mappings when present), `LAYOUT_HINT`, `check_layout` (a file exported by the page that the page can read), `LayoutError` |
